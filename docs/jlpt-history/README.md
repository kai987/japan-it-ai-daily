# 語彙の同一性と原始カードの保存

`identity-rules.json` は語彙の重複検査に使う明示的な表記・活用の対応表です。意味が近いだけの語を統合したり、任意の名詞化・助詞の語尾を一律に削ったりしません。

| 語彙としての識別名 | 保存する原始形と収録日（2026年） |
| --- | --- |
| 一律 | 一律に：08-13／一律：11-01 |
| 賄う | まかなう：09-18／賄う：10-30 |
| 据え置く | 据え置く：09-03／据え置き：09-22 |

| 抜ける | 抜け：08-21／抜ける：10-12 |
| 一気通貫 | 一気通貫で：09-10／一気通貫：09-22 |
| 誤る | 誤り：09-02／誤って：09-05 |

同一の語彙として数える一方、原始カードの形・読み・例文・日付・順序・当時の新規ラベルを保存します。既存カードの進捗IDと録音を辞書形へ付け替えません。「誤り」「誤って」を表示上「誤る」へ書き換える処理も行いません。

`historical-variants.json` はこの7組・14枚だけの確認記録です。日付、原始形、変更前のカード識別名、中日それぞれのカード全体のSHA-256を固定します。検査は14枚をすべて確認し、7件の歴史的な再収録だけを認めます。変更・欠落・余剰の記録、同日重複、未登録の日付での再収録は失敗します。将来の重複を許可する語彙の除外リストではありません。

追加後の基準値は、82日分の原始カード1,314枚、語彙として1,307種類、確認済みの歴史的な再収録7件です。新しい日報はすべて新しい同一性規則で検査するため、これらを別の新語として再収録できません。

## カード参照と語彙の識別

- `identity` / `firstIntroducedDate` は既存カード・録音・N1学習進捗の参照を維持します。
- `lexicalIdentity` / `lexicalFirstIntroducedDate` は同じ語彙の識別名と最初の収録日です。今回の7組は、それぞれ共通の頻度を持ちます。
- snapshotの `firstVocabulary` は従来のカード参照を保ち、`firstLexicalVocabulary` が語彙としての初出日を示します。`vocabularyFrequency` は元の識別名・原始形・語彙の識別名から同じ集計を参照できます。

2026-11-01までの本文復習は、修正前の照合・順位付けを使って選択と例文を保存し、その後で語彙別の頻度を統合します。2026-11-02以降の復習は、本文に根拠がある同じ語彙から1枚だけを選び、最初の原始カードとその実在する録音を参照します。後の形の例句を、最初の形の録音へ誤って結び付けません。

## 検証

`npm run jlpt:check` と `npm run content:integrity:check` が履歴と固定記録を検査します。`scripts/lexical-history-compat.test.mjs` は元のカード・復習選択・録音参照の保存、共通の頻度、将来の重複拒否と復習の語彙単位重複除去を検証します。N1の公開snapshot更新は従来の出典付き同期を使用し、この修正だけでN1原稿・教材・録音や定時設定を書き換えません。

完了済みの一回限りの移行器`repair-jlpt-history.py`は当時の識別名で原始カードを検証し、再実行で歴史教材を改変しません。日々の新規重複の判定には使用せず、上記の現行ゲートを使用します。
