# 新学・本文復習・出現頻度・号数

適用日：2026-09-18。新規項目の全履歴重複禁止を維持し、当日から不足分を明示的な復習で補う。過去の新規教材を復習に書き換えない。過去ページにも現在の全集計による頻度・号数を表示する。

## データ契約

- `src/content/japanese/*.md` と `japanese-ja` の vocabulary / grammar は引き続き**新規**のみ。4ファイル間の厳格な既存チェックを維持。
- 生成する復習は `scripts/learning-review.mjs` の `reviewVocabulary` / `reviewGrammar`。新規不足時だけ、それぞれ合計20語・7文型になるまで補充。新規が目標以上なら既存内容を削らない。
- 同日内・新規との重複は禁止。復習は必ず earlier firstIntroducedDate と当日の日本語用例 `reviewEvidence` を持つ。原文未確認の作文を外部記事の引用と偽らない。
- 対象はその日の日本語本文・Top5推薦理由・原有学習例文で確認できる**既習**項目。N1/N2優先、参照レベルを改竄せず必要時はN3等も保持。別義・別接続を混同しない。十分な候補がなければ理由を表示し、未出現項目を捏造しない。
- 当該日までの頻度・参照レベル・初出日で決定的に選ぶ。後日の記事追加で過去の選択を入れ替えない。
- 新規と復習のラベルを必ず分け、「本文で復習できる既習語彙」「本文で復習できる既習文法」を表示。従来のC-4必背選択は新規の重点部分として維持し、別枠の復習を新規に混入させない。

## 出現頻度

`appearedDays / totalDays * 100`。小数第1位表示、分子・分母および出現日一覧も開示。

分母はそのビルドに存在する全4ファイルが揃った日報の**異なる日付数**。欠番は自然日で補完せず、日中鏡像・同日の再生成・同日に多数出た回数は二重計上しない。N1サイトもこのIT日報分母を利用し、N1のDay番号を分母にしない。

分子のコーパスは保存された日本語日報の本文（A/B）、Top5推薦理由、および学習カードの日本語フィールド・例文・独立語/文型。見出しテンプレート、URL、コードブロックを除外する。外部リンクの記事全文は対象外。初回カード自体と本文での自然な出現を数えるため、初めて教材にした日でも頻度が1日分とは限らない。

`makeLexicalKey` / `makeGrammarKey` の既存正規化・明示的な表記/接続/活用変体で照合する。同形異義などの完全な自然言語解析を保証する指標ではない。復習選定を先に固定してから復習カードの日本語本文も頻度に反映し、再選定の循環を作らない。語彙や文型の頻度は日報追加ごとに全ページで更新する。

## 号数

最初に存在する日報を第1号とし、日付昇順の連番を用いる。2026-08-12=第1号、2026-09-18=第38号。タイトルは `日本語学習｜2026年9月18日（第38号）` の形。号数は表示時に計算し、同日再実行で増やさない。N1計画のDayとは別。

## 検証とN1同期

`npm run content:integrity:check` は新規語彙/文法の厳格な全履歴検査に加えて `study:check` を実行する。頻度の日付集合、分母、算式、号数、復習の初出日/当日用例、日中一致を検証。`npm test` とブラウザ回帰も必須。

各ビルドで `/study-index.json` を生成する。正式Pages workflowは同じJSONを `it-study-snapshot` artifact（sourceCommit=そのworkflowのhead_sha）として保存する。11:00 N1同期は同日資料・上流Deploy成功・sourceCommit一致を確認した上で取得し、`src/data/it-study-snapshot.json` へ保存する。

N1サイトは原始日別JSONの新規重点カードと9時本文/読解/誤答復習を残し、表示時にこの検証済みsnapshotの新規＋復習20語/7文型を重ねる。2026-09-18以前は元のカード数を変えず頻度・号数だけ付ける。新規と復習は別の状態情報であり、ユーザーの「未学習/要復習/習得済み」を勝手に変更しない。既存の同日同項目同例文のIDは維持し、異なる項目には内容由来の新IDを使う。

ブラウザー音声と収録済みMP3は従来通り本文一致で照合する。復習が増えたからといって旧配列番号の音声を流用しない。
