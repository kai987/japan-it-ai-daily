# Reliability first pass

Scope: interview playback ownership, post-deployment publication verification,
and a single-date structured-interview pilot. No dependency upgrades, account
system, database, visual redesign, historical prose rewrite or audio regeneration.

## Playback

`InterviewStaticAudio.astro` owns a monotonically increasing request number.
Stop, switch and every `pagehide` invalidate older manifest, media and speech
callbacks. The selected button is set before awaiting the manifest, so the same
button can cancel a pending request. Loading uses a reduced-motion-aware ring inside the existing button plus a
screen-reader-only status and `aria-busy`; no loading text expands the small
control. The original label is restored when loading ends. Manifest loading
has a 10-second timeout with the existing browser-speech fallback. Old media is
paused before fallback. Old utterance completion cannot clear a newer request
on the same button.

The new Playwright race cases run against built zh/ja report pages with controlled
fetch/media implementations. They test state and cancellation, not voice quality,
physical speaker output or every browser's autoplay policy. Mobile loading and
structured-interview screenshots are retained in the existing CI image artifact.

## Publication is a separate gate

`study-index.json` remains the public learning snapshot. The build produces a
small **job output**, not another public snapshot, containing its source commit,
last report date and SHA-256 hashes of the snapshot and both report HTML files.

After `deploy-pages`, `verify-deployment.mjs` reads the public snapshot and both
report URLs. Success requires schema, exact commit, expected issue/date, snapshot
bytes and both HTML hashes to agree with the artifact. Cache-busting, per-request
timeouts and at most eight attempts handle propagation without an endless loop.

The expected date is the artifact's last date, never today's date. Historical
repairs and code-only releases are valid. Verification failure marks the workflow
failed; it does **not** claim to roll back the already uploaded Pages site. An
artifact uploaded before deployment proves build validity, not publication.
Downstream consumers should prefer a successfully verified release.

Local preparation (Node 24):

```sh
GITHUB_SHA=$(git rev-parse HEAD) npm run build
GITHUB_SHA=$(git rev-parse HEAD) npm run deployment:prepare
# Check a published release using the exact JSON emitted above:
node scripts/verify-deployment.mjs --url https://kai987.github.io/japan-it-ai-daily/ --expected 'EXPECTED_JSON'
```

The PR workflow prepares expectations from its real build without asserting that
the PR commit is already public. Only the main deployment runs the online gate.

## Structured-interview pilot

`src/data/interviews/2026-09-18.json` preserves the existing five questions and
answers, three review questions, zh/ja review points and article references.
It is a validated, versioned canonical record for the shared interview page and
interview-audio parsers. Text and order remain unchanged, so no recording or
manifest is regenerated by this change.

The schema validator is shared by the build/authoring reader. Unknown fields,
invalid versions/dates, missing localized points and duplicate IDs are rejected.
The filesystem reader is build/authoring-only, not client code. Legacy dates
without a record retain their existing parsers. Dates listed in
`docs/structured-interview-policy.json` cannot silently fall back if their JSON
is deleted or invalid.

During this pilot the daily Markdown still contains display mirrors. `npm run
interview:check` (also part of `content:integrity:check`) verifies required files,
article identity/order and normalized mirror text/order in both languages.
This check does not use Markdown heading labels as business identifiers; it is
not a semantic fact checker of other report prose. Original-source evidence and
content-quality gates remain mandatory and unchanged.

When editing a migrated date, edit the JSON as canonical and keep both report
mirrors consistent. A later phase can generate these mirrors from structured
content; this first pass does not rewrite historical reports or remove the
legacy adapter. Add a date to `requiredDates` when migrating it. Do not remove a
required date to hide a broken migration, and do not edit audio manifests to
mask changed speech text.

## Validation

```sh
npm run check
npm run content:integrity:check
npm run evidence:check && npm run evidence:pilot
npm run bilingual:check-interview
npm run quality:check
npm test
npm run build
npm run test:browser
npm run security:check
```

New tests cover stale/cancelled audio work, metadata/HTML publication mismatches,
bounded failure and historical releases, structured-schema failures, missing
required data, original-vs-structured text parity and zh/ja rendering at desktop
and mobile widths. Browser tests use the repository's existing Playwright setup.
