### 1. [アップデート] Web Answer on Amazon Bedrock AgentCore がリリースされました！

**原文：** https://dev.classmethod.jp/articles/bedrock-agentcore-web-answer-try-harness/

**发布时间：** 2026-11-08 16:53:36 JST

做资料核查时，可以把检索、读网页和写带引文的答案交给同一个工具。作者在 AgentCore Gateway 上挂接 Web Answer，由使用 Claude Haiku 5.5 的 Harness 经 MCP 调用。它返回带行内引用的 Markdown 和按内容块关联的出处。Web Search 则提供候选链接、摘要和日期，外层模型要自己决定读哪些结果、是否继续查找。相应版本的 Web Answer 可按站点和日期限制范围，方便缩小候选集。

作者用同一批五个问题各跑一次。查作者最新文章时，两套配置都没找到 11 月 3 日那篇。Web Answer 只调用一次，外层输入为 2,185 个 token，Web Search 调了五次，输入为 39,195。另一项要求枚举指定日期后的文章，即便用上域名和日期筛选，作者核出的 12 篇也只被列出 4 篇。较短的上下文与检索覆盖率是两项不同指标。

读工具轨迹还发现，一个书评的作者身份在工具输出里写对了，外层模型汇总时却算进被评论作者的文章。引用在这一层也可能丢失。补充保留出处的提示后，重问公司信息的一次试验保住了链接。几项样例只能说明工作流的分工和错误如何传递，要做有完整性要求的清单仍需对照可验证的作者目录。

**阅读价值：** 可以沿工具调用和最终回答两层，分别核查覆盖率、归属和链接。

### 2. 並列 Claude Code セッションは何回ぶつかったか：2週間のログを hook に再生して数えた

**原文：** https://zenn.dev/dooly6276/articles/9863fac3b3e3c2

**发布时间：** 2026-11-09 09:59:44 JST

并行开几个 Claude Code 会话后，工作树隔开了文件，却没有隔开开发服务器和系统资源。作者的 Node 钩子接在 PreToolUse，执行 shell 前读取命令语法，再查目标进程和端口归属、可用内存以及当前 Git 树。发现冲突时，钩子返回拒绝原因与可选操作。比如给出定位本会话进程的方法，避免一条广域终止命令杀掉邻近会话的服务。

实测取作者个人 Mac 上两周日志，总量 7.0 GB，约十万条 shell 命令。只读扫描花了 39 秒，重放中 507 条命令会被拦下。最高同时运行 13 个会话。其中 25 条是在他人仍编辑同一树时暂存全部改动，随后提交混进了其他会话的变更。重放按同一分钟里活跃的会话和工作树还原这类场景。

日志不含过去的端口占用和内存信息，因此这两个守卫没有参加重放。结果给出这台机器、这份历史和相应规则下的拦截候选数量，并未观察实际阻止事故后的结果。需要强隔离的任务仍需独立运行环境，因为钩子只在受管命令入口执行检查。

**阅读价值：** 明确工作树边界与系统资源边界，有助于复盘并发开发事故。

### 3. AWS Network Firewall の Reject と Alert のドメインリストを Allow と組み合わせ、ルールの評価順序ごとに確かめてみた

**原文：** https://dev.classmethod.jp/articles/network-firewall-domain-list-reject-alert-rule-order/

**发布时间：** 2026-11-08 14:33:38 JST

作者在东京区域用一台 EC2，对配置相同的 Allow、Reject 和 Alert 域名组，分别测试动作顺序与严格顺序。规则根据 HTTPS 的 TLS SNI 或 HTTP 的 Host 匹配。默认动作顺序的 Allow 会对不匹配的域名加上丢弃规则。严格顺序没有这一自动拒绝，实验另加了已建立连接后的丢弃和告警动作。

从 curl 看，两套配置均让获准域名返回 200，让 Reject 域名立即重置连接，并让监视域名和未列入的地址超时。日志却给出更多信息。以连接标识比对，同一条流可同时出现默认丢弃与 Reject 或 Alert 日志。严格顺序那次则能看到更多已建立连接的后续包。第一次动作顺序共读到七条，严格顺序读到三十四条，不能按这个数字推断多拦了多少连接。

部分 HTTP 事件在第一次读取中没有出现。读取在最后一次请求约 75 秒之后，而作者引用的 CloudWatch Logs 平均交付时间为 3 到 6 分钟。要评估监视规则，需给日志留出足够到达时间，并把终端结果、判定动作和连接标识对应起来。这项实验只覆盖指定三组规则、单客户端和有限的请求轮次。

**阅读价值：** 区分网络结果与遥测覆盖，可避免把日志条数直接当成被拦连接数。

### 4. CloudWatch が PromQL 対応したので、Amazon Managed Grafana から接続してみた

**原文：** https://dev.classmethod.jp/articles/cloudwatch-promql-endpoint-amazon-managed-grafana/

**发布时间：** 2026-11-08 14:42:05 JST

这次接线把采集与查询拆成了两端。EKS 1.37 上的应用每收到请求就递增计数器，CloudWatch 代理用 OTLP 收集并转发。作者在 Amazon Managed Grafana 13.2 的 CloudWatch 数据源里选 PromQL，显示了自定义指标。日志仍走 Logs Insights，轨迹则在加装 Application Signals 后才显示。三个面板背后的读取方式各自独立。

Grafana 插件兼容性会改变连法。支持 PromQL 的 CloudWatch 数据源沿用工作区 IAM 和区域设置。把该数据源的公共设置固定为监控端点，原文中的日志接口就报了 404，因为日志与指标需要各自的服务端点。对还不能直接选择 PromQL 的 AMG 12.4，作者指出可由 AMP 数据源签名，把请求发到 CloudWatch 的监控端点，无需另外将数据存进 AMP。

选型还要查查询时间跨度。文章列出 CloudWatch 单次最多七天，与 AMP 可查 95 天的规格对照。它与底层保留几个月是两回事。用时间偏移并排放几张图可以对比周期；若要在一次表达式中做长区间分析，需要确认能否达到要求。这篇实测验证了配置和出图，未比较大规模负载下的吞吐或总费用。

**阅读价值：** 展示从应用计数到面板的完整路径，特别适合定位“指标可用、日志报错”这类不一致。

### 5. 「文字数 < 6 はスキップ」という英語前提の閾値が、和文の重複削除を壊していた話

**原文：** https://zenn.dev/recdnd/articles/kiln-dedupe-cjk-threshold-bug

**发布时间：** 2026-11-09 09:00:12 JST

作者在 kiln 去重工具里输入几种重复的短中文购物清单，发现六行原样通过。放入对应的较长英文，重复行能删除。顺着执行顺序看，少于六个字符的行没有进过去重集合，直接写到结果。这个例外原先想保护项目符号、序号等片段，却把字数少但信息完整的中文一起放过。

普通行需要先提取层级和归一化文本，再用组合键查 Set。短行绕开整段逻辑，所以只改归一化函数不能解决这一例。降低全局阈值也会扩大原本应保留的片段范围。作者把中日韩字符与英文混在同一行时应怎样计算长度列为未解决的问题。

目前实际采用的是限制演示语料，让 CJK 行至少有六个字符，同时把原始问题写入审计与决策记录。演示能通过，并未改变短行的处理路径。可从原文的失败样例扩展回归条件，把短内容的去重和符号行的保留分别设为可检查结果，再决定用什么判定。

**阅读价值：** 一个可复现的跨语言故障，能说明输入约束为何不能替代实现修复。

## 4. 技术主题：用可复现条件定位处理边界

先找影响结论的边界。检索与最终写作分开验，客户端的连通结果则和延迟到达的防火墙日志对应。

### 1. 空く（あく）｜N3

- 词性：動詞・五段・自動詞
- 含义：原来占用的空间或时间变得可以使用。
- 搭配：ポートが空く / 席が空く / 時間が空く
- 文章语境：并行开发原文用「空いているポート」表示未占用的端口。
- 例句：テスト用のポートが空いてから、開発サーバーを起動します。
- 例句含义：等测试端口空出来再启动开发服务器。
- 辨析：「ポートが空く」描述端口变为可用，「ポートを空ける」表示人为腾出端口。

### 2. 残る（のこる）｜N5/N4

- 词性：動詞・五段・自動詞
- 含义：处理或变化结束后仍然保留。
- 搭配：ログに残る / 出典が残る / 記録が残る
- 文章语境：Web Answer 原文指出最终回答未必保留工具输出中的出处。
- 例句：ツールの出力をまとめ直した後も、元の記事へのリンクが残るか確かめます。
- 例句含义：改写工具输出后，检查原文链接是否还在。
- 辨析：这是描述保留状态的自动词。主动保留出处用「出典を残す」。参考等级为 N4，站内归入 N5/N4。

## C-2. IT/AI专业词汇

1. **MCP（モデルと外部ツールを接続するプロトコル）**：用于发现和调用外部工具的协议。 AgentCore Gateway 将 Web Answer 提供给外层调用者。

2. **PreToolUse（ツール実行前のフック）**：工具执行前可检查请求的扩展点。 在 shell 命令生效前检查会话的进程和端口。

3. **TLS SNI（TLS接続時に示すサーバー名）**：客户端建立 TLS 连接时提供的服务器名称。 实验用它判断 HTTPS 请求匹配哪个域名规则。

4. **OTLP（OpenTelemetry Protocol）**：传输遥测数据的协议。 示例中的应用计数器通过代理送到 CloudWatch。

5. **SigV4（AWS署名バージョン4）**：AWS API 请求的签名认证方式。 AMP 插件可用它向 CloudWatch 监控端点查询。

6. **Set（集合）**：用于记录不同值的集合结构。 kiln 用它检查当前层级的归一化文本是否出现过。
