### 1. 遅い外部依存 1 つで全 Worker が止まる — タイムアウト・サーキットブレーカー・バルクヘッドを実測で使い分ける

**原文：** https://zenn.dev/kyrenzk/articles/external-dependency-async-boundary-design

**公開日時：** 2026-11-17 08:45:36 JST

Go の仮想時間で、20本の Worker が二つの依存先を兼務する状況を作っています。A と B に毎秒200件ずつ到着し、A は20msで応答します。B は10秒間応答せず、各呼び出しが時間切れまで Worker を握ります。空いた Worker は、上限に達していない依存先から古い仕事を選びます。

タイムアウトが2000msのとき、A は2000件中100件しか完了しません。200msに縮めても914件です。5回連続の失敗で開く回路遮断だけでは A は1996件まで戻る一方、p95 は1580msです。バルクヘッドで B の同時実行を4本に抑えると、A は1996件で p95 が基準と同じ20msでした。終了までに間に合わない4件は、B が正常でも同じです。

上限だけを入れた構成では、B 側に1980件が残ります。遮断も併用した実験では1990件を退避させ、B の残りはゼロになりました。ただし、その再処理は実装されていません。実ネットワーク、即時エラー、複数プロセスで状態を共有する条件でも同じ数字になるとは限りません。

**読む価値：** 障害を検出するまでに、正常な処理にもどのくらい影響が及ぶかを数字で追えます。

### 2. MMMの入口として、広告費・季節性・外部要因を用いた需要予測をDataRobotで試す

**原文：** https://zenn.dev/nttdata_tech/articles/c872346ff107f2

**公開日時：** 2026-11-17 09:35:37 JST

NTTデータの筆者は、戸建て、マンション、家財の保険を想定し、2021年から2026年までの商品別・週次データを Python で作りました。契約件数には引越しや台風の時期、競合キャンペーンなどの仮定が入っています。広告費も当週の値だけでなく、1週前と4週前をラグ特徴量として用意します。

DataRobot には年ごとの区分を指定し、一つの年をずらしながら比較する3組の分割を用意します。例に使った fold3 は2023年と2024年を学習、2025年を検証、2026年をテストにします。説明画面の Feature Impact では競合キャンペーンの合計、イベントの有無、広告費総額、約4週前のテレビ広告費などを確認できます。

可視化した寄与度は、モデルがどの入力を予測に使ったかの手掛かりです。ただし、仮想データは生成時点で要因の関係を組み込んでおり、実際のキャンペーンの増分効果を検証していません。広告効果の残存や逓減、チャネル別の費用対効果も範囲外です。実務なら予測を出す日までに入手できた変数だけで評価する必要があります。

**読む価値：** 需要を当てるための入力と、広告の効果を推定するための検証を区別できます。

### 3. Apple Pencilの複数筆を一括確定する設計：草稿・世代検証・Undo

**原文：** https://zenn.dev/sponge841841/articles/2026-11-08-pencil-multistroke-atomic-undo

**公開日時：** 2026-11-16 11:13:13 JST

刺しゅう図案アプリの実装記録です。線を描くたびに編集へ移ると、次の線を続けて描けません。そこで入力中の Stroke、複数の線を持つ DraftBatch、保存に使う正本を分けます。ベジェ曲線や筆圧を線ごとに残せば、離れた線に不要な接続が入るのを避けられます。

MainActor 上の処理例では、採用する全ての線を変換して次の文書を作り、UndoManager に前の文書を一度だけ登録して反映します。時間のかかる生成には GenerationTicket を発行し、文書ID、世代、草稿セッションIDを結果の採用直前に照合します。Undoで以前と同じ見た目になっても、文書の世代は新しくします。

描画領域と設定フォームで Scribble の扱いを分ける案も示されます。記事の条件では Core テスト1306件と関連 App テスト50件の成功が記録されています。ただし、コードは設計説明用で、ディスクへの原子的保存を保証しません。物理 Apple Pencil、最小対応OS、ミシン実機での確認は未実施です。

**読む価値：** 未確定の線、保存する図案、古い非同期結果の三つをどう扱うかが分かります。

### 4. dbt + TerraformでCortex Searchを構築し，最小権限を目指すためにハマったこと

**原文：** https://zenn.dev/finatext/articles/cortex-search-least-privilege-dbt-terraform

**公開日時：** 2026-11-17 09:19:31 JST

筆者の Snowflake 構成では、データベースとスキーマは Terraform、表は dbt で管理します。Cortex Search を dbt で作ると、ウェアハウスが見える実行ロールでもエラーが出ました。ON_SCHEDULE にすると作成は通りましたが、更新は SKIPPED になりました。

権限を調べると future grant で OWNERSHIP が Database Role に移っていました。このロールは同じデータベース内の権限を扱うため、外にあるウェアハウスの USAGE を持てません。今回の managed access スキーマでは、作成後に所有権を専用のアカウントロールへ移す案にも階層の制約がありました。Terraform の provider alias でその専用ロールを選び、最初から所有者にする構成へ変えました。

索引が参照する表の change tracking は、表を管理する dbt の post_hook で先に有効にします。検索用の所有ロールに表の所有権まで与えずに作成できた事例です。ただし、内部 Dynamic Table とサービスの所有者が同じかどうかは、筆者が動作から推定した点で、公式な保証としては扱えません。

**読む価値：** 作成に使う権限と、作成後の索引更新に必要な権限を、同じエラーから切り分けられます。

### 5. 国立国会図書館の書誌をGitHub Actionsで毎日取り込む：止まっても次の回で続きを取る仕組み

**原文：** https://zenn.dev/noriyuk/articles/1ef9eb3ca98f3d

**公開日時：** 2026-11-17 07:33:19 JST

BookConnect は、有効な ISBN があり、条件を確認した約385万件の図書書誌を、検索時に外部へ問い合わせないよう自分のデータベースに置きました。本棚や書評とは表を分け、書誌削除を連鎖させる外部キーを張っていません。

GitHub Actions の処理は、最後に取り終えた UTC 日付の翌日から差分を取得します。ページを取り切って書き込んだ日だけ記録を一日進め、同じ書誌 ID は upsert で扱います。11月6日の回は11月5日の途中で止まり、次の回が5日を最初から処理しました。一度に追いつくのは7日までです。手動で先の日を指定しても、日付の穴を飛び越えて記録を進めません。

最初の取り込みでは責任表示を保存せず、カタカナの著者名で検索できない本が残りました。全体を取り直すのに約100GBの通信が必要になり、以後は原本を保管しています。ただし、責任表示まで英字しかない本はカタカナで当たらず、発売直後の本は元の書誌が入るまで検索に出ません。

**読む価値：** 定刻実行が抜けても、その日の全ページが終わる前に取り込み位置を進めない設計が参考になります。

> 共有 Worker で一つの依存先が応答しないとき、もう一つの依存先をどう守りますか。

> 共有の Worker では、応答しない B が枠を使い切るので、タイムアウトを短くしても正常な A が待ちます。この実験ではバルクヘッドで B を四本に絞ると、A の p95 は基準と同じ二十ミリ秒でした。回路遮断も併用すれば滞留を減らせます。ただし、退避した仕事は実験では捌いていないので、実装では保管の上限と戻し方まで決めます。

**関連プロジェクト例：** 複数の配送先に通知するサービスで、宛先別の上限と期限を変え、正常側の待ち時間と再試行キューを測る。

**キーワード：** Go、仮想時間、バルクヘッド、p95

### 3. Apple Pencilの複数筆を一括確定する設計：草稿・世代検証・Undo

**関連プロジェクト例：** ホワイトボードで未確定の線をプレビューし、確定、破棄、文書切替後の遅延通知をテストする。

### 5. 国立国会図書館の書誌をGitHub Actionsで毎日取り込む：止まっても次の回で続きを取る仕組み

**関連プロジェクト例：** 公開の施設データを日別に取り込み、途中のページで故意に失敗させ、翌回の再開と重複件数を確認する。

## 4. 今日の技術テーマ

### 準備中の結果を、いつ確定させるか

Apple Pencil の記事では、画面に見える草稿をいつ保存の正本へ移すかが問題です。書誌の取り込みでは、どのページまで取ったかと、どの日まで取り終えたかを分けます。どちらも、途中の処理が成功したことと、利用者が次の操作へ進んでよいことを同じ記録で決めない構成です。

実装の境界は同じではありません。図案の例はメモリー内での履歴の単位を示し、日次処理では再実行しても増えない書誌キーが必要です。練習なら、途中で一回失敗させ、草稿や未完の日付を保ったまま戻れるかを見ます。

また、遅延結果が届いたときだけでなく、通知が来ない時間も考えます。共有 Worker の実験と組み合わせるなら、待てる時間、並行して使える枠、受理した後の保存先をそれぞれ測ると、どこで判断を見直すべきかが分かります。

# B. 面接につながる要点

### 1. 遅い外部依存 1 つで全 Worker が止まる — タイムアウト・サーキットブレーカー・バルクヘッドを実測で使い分ける

1. タイムアウトは一件が枠を使える時間を制限します。依存先の上限は、その相手が使える枠の数を制限します。

2. 同じ完了数でも、最初の失敗を待つ間の遅れは p95 に現れます。正常側と障害側を別々に測ります。

3. 退避先を作るなら、保管量と再試行の上限を決めてから負荷試験を組みます。

### 2. MMMの入口として、広告費・季節性・外部要因を用いた需要予測をDataRobotで試す

1. 年をずらす分割なら、予測時点より後の実績が学習に混ざっていないかを点検しやすくなります。

2. 予測への寄与を見ても、同じ予算を別の媒体へ移した場合の効果は決まりません。

3. 年次の実務を想定するなら、広告費と外部指標がいつ確定し、どこまで使えるかもデータ仕様に含めます。

### 3. Apple Pencilの複数筆を一括確定する設計：草稿・世代検証・Undo

1. 三本をまとめて採用するなら、一回の Undo で三本を戻せる単位にします。

2. 処理を取り消すだけでなく、結果が返った時点で文書の世代と草稿を照合します。

3. 入力の抑止は対象の画面領域に絞り、フォームへの文字入力が残ることも検証します。

### 4. dbt + TerraformでCortex Searchを構築し，最小権限を目指すためにハマったこと

1. 作成が成功しても更新できるとは限りません。作成後の実行ロールとウェアハウス利用権限を確かめます。

2. 索引の所有者は元のデータを読めるため、検索に含めてよい範囲から権限を逆算します。

3. 基表の変更追跡と検索サービスの作成を別の役割に任せ、適用順を確認します。

### 1. 損害（そんがい）｜N3

- 品詞：名詞
- 意味：事故や災害などによって生じた被害や不利益です。
- 連語：損害を受ける / 損害を補償する
- 記事文脈：記事では、火災保険を扱う損害保険会社を想定しています。
- 例文：大雨で倉庫が損害を受け、保険会社へ連絡しました。
- 例文の意味：大雨で倉庫が被害を受けたため、保険会社に知らせました。
- ニュアンス：損失は失われた利益や金額に、損害は何らかの原因から受けた被害に焦点を当てます。

### 2. 諸々（もろもろ）｜N1

- 品詞：名詞・副詞的用法
- 意味：種類の違う複数の事柄をまとめて指す言い方です。
- 連語：諸々の手続き / 諸々の事情
- 記事文脈：記事では列挙しなかったTerraformの担当項目をまとめて示しています。
- 例文：検索を始める前に、権限や費用など諸々の条件を確認しました。
- 例文の意味：検索の前に、権限や費用といったさまざまな条件を確認しました。
- ニュアンス：「その他諸々」は残りをまとめる表現です。仕様書では対象を個別に明記する方が確実です。

### 3. 写す（うつす）｜N5/N4

- 品詞：五段・他動詞
- 意味：もとの形や内容を別の場所に再現することです。
- 連語：データを別の表に写す / 図をノートに写す
- 記事文脈：元の書誌を別のデータベースに複製する文脈になります。
- 例文：確認に使う行だけを別の表に写しました。
- 例文の意味：調べるのに必要な行だけを、別の表にコピーしました。
- ニュアンス：「書き写す」は書く方法を明示します。「写す」はデータなどにも広く使えます。

### 4. 発売（はつばい）｜N3

- 品詞：名詞・サ変
- 意味：新しい商品を売り出すことです。
- 連語：発売日を調べる / 新刊を発売する
- 記事文脈：発売日と図書館の書誌に反映される時期の差を説明しています。
- 例文：発売された本でも、書誌に載るまで少し時間がかかります。
- 例文の意味：本が売り出されてから書誌に登録されるまでには時間差があります。
- ニュアンス：「販売」は売る行為全般を指します。「発売」は売り始める時点に焦点があります。

### 5. 後ろ（うしろ）｜N5/N4

- 品詞：名詞
- 意味：前の反対側を表す名詞で、並びや進み具合についても使います。
- 連語：列の後ろ / 後ろに戻る
- 記事文脈：記事では日別の取り込み位置を過去へ戻さないという意味です。
- 例文：手動で古い日を取り直しても、完了日は後ろに戻りません。
- 例文の意味：古い日を読み直しても、連続して処理が済んだ日付は過去へ戻りません。
- ニュアンス：場所の「後ろ」と、進捗の向きを表す「後ろに戻る」は、対象によって読み分けます。

## C-2. IT/AI専門用語

1. **Bulkhead（バルクヘッド）**：共有処理枠の一部しか特定の依存先に渡さない仕組み。 四本の上限で正常なAが待つのを防ぎました。

2. **Lag feature（ラグ特徴量）**：過去の値を現在の行に対応づける入力。 週次の保険データでは一週前と四週前を用意しました。

3. **Generation ticket（生成チケット）**：非同期結果を始点の状態に結びつける照合用情報。 文書と世代、草稿が揃って初めて結果を採用します。

4. **Change tracking（変更追跡）**：データの変更を後続処理から参照できるようにする機能。 索引を作る前に基表で有効にします。

5. **Upsert（更新または挿入）**：既存キーなら更新し、なければ行を追加する操作。 書誌IDを使うため再取り込みで行が増えません。
