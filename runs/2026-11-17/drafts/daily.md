### 1. 遅い外部依存 1 つで全 Worker が止まる — タイムアウト・サーキットブレーカー・バルクヘッドを実測で使い分ける

**原文：** https://zenn.dev/kyrenzk/articles/external-dependency-async-boundary-design

**发布时间：** 2026-11-17 08:45:36 JST

这篇实验特意让 B 一直不响应，而不是立刻返回错误。两端各每秒投递 200 个任务，20 个 Go Worker 共用同一个调度池。A 只需 20 毫秒就能完成，但 B 的一次等待可能持续两秒。作者以一毫秒为一个虚拟时钟刻度，观察 10 秒内两端的处理情况。

仅设两秒时限，正常端 A 也只完成 100 项。缩短至 200 毫秒后完成 914 项，积压仍在。相比之下，把 B 的并行量限制为四，A 完成 1996 项，完成耗时 p95 回到 20 毫秒。单用连续失败熔断同样完成 1996 项，但 p95 达 1580 毫秒，早期的阻塞仍可见。

隔离把资源留给了 A，却给 B 留下 1980 项排队任务。加上熔断时，作者记录到 1990 项被转入暂存，未实现后续重投。该实验是确定性的虚拟时间模拟，没有实测供应商连接、间歇性高延迟或多实例熔断状态。

**推荐理由：** 同一套模拟让读者看清超时、熔断和并发隔离各在什么时候起作用。

### 2. MMMの入口として、広告費・季節性・外部要因を用いた需要予測をDataRobotで試す

**原文：** https://zenn.dev/nttdata_tech/articles/c872346ff107f2

**发布时间：** 2026-11-17 09:35:37 JST

营销团队希望提前看到各保险产品下一年的签约量走势。作者用合成周度数据建模，产品分为独栋住宅、公寓和家财三类。除了电视、网络、社交媒体和代理店费用，还加入节日、产品、竞品活动与时间特征。广告变量既有当周投入，也保留前一周及前四周的取值。

示例将问题设为 DataRobot 连续值预测，并用标记列划分训练、验证和测试集合。第三组以 2023 至 2024 年训练，2025 年验证，2026 年测试。结果页展示了竞争活动总量、事件标志、广告费总额和滞后电视广告费的模型贡献，供分析员进一步选择想检查的变量和产品。

这里的季节和渠道关系由合成规则预设。文章没有用真实合同数据验证预测收益，也没有估计增量、广告衰减、回报率或预算最优分配。外部数据可能晚于预测时点发布，实际复用这种切分前还需验证该时点能取得的字段。

**推荐理由：** 这个教学案例适合练习时序切分，也展示了怎样避免把预测贡献当广告收益。

### 3. Apple Pencilの複数筆を一括確定する設計：草稿・世代検証・Undo

**原文：** https://zenn.dev/sponge841841/articles/2026-11-08-pencil-multistroke-atomic-undo

**发布时间：** 2026-11-16 11:13:13 JST

在这个未发布的 iPad 刺绣图案编辑器里，每抬一次笔就完成编辑，会妨碍用户继续添加多条分离的线。作者让输入中的笔迹、待确认的一组笔迹和已经保存的文档分别存在。各笔自己的路径、压力和闭合信息不应消失，否则拼接点产生的连线可能被当成多余的缝线。

示例在主执行域构造下一份文档，统一提交，同时注册一条撤销操作。耗时任务携带文档 ID、版本标记和草稿会话 ID。返回时，三者仍指向当前编辑状态才接收结果。恢复到以前的外观也分配新版本号，以便拒绝先前启动的工作。表单和画布则各自处理手写识别。

作者报告核心测试通过 1306 项、相关应用测试通过 50 项。文章只展示内存里的一次文档替换，无法证明写盘事务的耐久性。实体笔输入、最低系统版本和真实绣机输出仍未核实。

**推荐理由：** 这个例子提供了能直接用于设计评审的测试场景，例如切换文档后收到旧结果。

### 4. dbt + TerraformでCortex Searchを構築し，最小権限を目指すためにハマったこと

**原文：** https://zenn.dev/finatext/articles/cortex-search-least-privilege-dbt-terraform

**发布时间：** 2026-11-17 09:19:31 JST

问题出在 Snowflake 搜索索引。作者用 dbt 建表、用 Terraform 管数据库与模式。运行角色可见计算仓库，创建搜索服务还是失败。把初始化方式改成按计划触发后，服务能建出来，可计划更新仍被跳过。排查登记权限发现，自动授权把搜索服务所有权转给了数据库角色。

数据库角色权限只能覆盖所在数据库，计算仓库的使用权限无法授给它。作者也不愿继续用读取范围较广的 dbt 角色作为索引所有者。受管理访问模式的所有权转移规则限制，改为用 Terraform 的 provider alias，以专门的账户角色直接创建搜索服务，并将可读输入和仓库使用范围收窄。

服务创建时还可能尝试开启基表变更跟踪，这需要修改表的权限。作者让持有表管理权限的 dbt post_hook 提前完成该动作，搜索角色即可继续保持受限。此次排查观察到刷新行为，但内部动态表和服务所有者的关系属于作者推断。

**推荐理由：** 把索引建立和索引更新区分开，可以解释为什么创建成功后依然报仓库不可用。

### 5. 国立国会図書館の書誌をGitHub Actionsで毎日取り込む：止まっても次の回で続きを取る仕組み

**原文：** https://zenn.dev/noriyuk/articles/1ef9eb3ca98f3d

**发布时间：** 2026-11-17 07:33:19 JST

BookConnect 把许可条件明确、带有效 ISBN 的日本国会图书馆书目落到自有库，共约 385 万条。用户检索不必在线调用图书馆。书目集合与书评、本架业务分表，因此上游删除书目时，不会通过书目外键级联删除用户内容。

日常增量从最后完整的 UTC 日期之后开始。每一天有多页，只有全页处理成功才推进日期，重跑时按书目 ID 更新而不增加重复记录。作者经历过 11 月 5 日数据有一部分处理失败，下一次从当天第一页继续重做。每次最多追七天，手工补抓较远的日期也不会把缺口标成已完。

首次解析只保存了规范名称及读音，没有留下责任表示，使部分外文作家无法用片假名命中。因为本地原文件已经删除，返工重新下载约 100 GB。保留原始文件和将更正查询字段解耦后，可在本地再次解析。仍有约束：如果源数据本来只有拉丁拼写，或者新书尚未编目，搜索无法凭空补齐。

**推荐理由：** 这篇记录具体说明了如何用连续日期和幂等更新弥补漏跑，也说明何时值得保留原始文件。

## 3. 面接で使えるポイント

### 1. 遅い外部依存 1 つで全 Worker が止まる — タイムアウト・サーキットブレーカー・バルクヘッドを実測で使い分ける

**面试问题：**

> 共有 Worker で一つの依存先が応答しないとき、もう一つの依存先をどう守りますか。

**约30秒回答：**

> 共有の Worker では、応答しない B が枠を使い切るので、タイムアウトを短くしても正常な A が待ちます。この実験ではバルクヘッドで B を四本に絞ると、A の p95 は基準と同じ二十ミリ秒でした。回路遮断も併用すれば滞留を減らせます。ただし、退避した仕事は実験では捌いていないので、実装では保管の上限と戻し方まで決めます。

**相关项目示例：** 以邮件和短信两类外部依赖举例，模拟其中一项不响应，检查另一项的延迟和积压水位。

**关键词：** Go、虚拟时间、舱壁隔离、p95

### 2. MMMの入口として、広告費・季節性・外部要因を用いた需要予測をDataRobotで試す

### 3. Apple Pencilの複数筆を一括確定する設計：草稿・世代検証・Undo

**面试问题：**

> 複数の筆跡をまとめて保存し、古い生成結果から文書を守るにはどうしますか。

**约30秒回答：**

> 描きかけの線は DraftBatch に置いて、確定するときは全て変換してから文書を一度だけ置き換えます。UndoManager に前の文書を一件だけ登録すれば、まとめて元に戻せます。非同期処理では文書と世代、草稿の識別子を採用直前に照合します。ただし、例の置き換えはメモリー上なので、書き込みの途中で端末が落ちた場合は別に設計します。

**相关项目示例：** 做小型矢量批编辑器，验证三条路径一起撤销，以及切换文档后的异步结果是否被忽略。

**关键词：** DraftBatch、UndoManager、GenerationTicket、Apple Pencil

### 4. dbt + TerraformでCortex Searchを構築し，最小権限を目指すためにハマったこと

**面试问题：**

> 検索サービスを作成できても索引が更新されない場合、どこの権限を調べますか。

**约30秒回答：**

> 作ったときのロールだけでなく、OWNERSHIP を持つロールを確かめます。記事ではデータベースロールに所有権が移り、ウェアハウスを使えず更新が止まりました。provider alias で検索専用のアカウントロールを選び、基表の追跡は dbt の post_hook で先に有効にします。ただし、内部テーブルの所有者については動作からの推定です。

**相关项目示例：** 用一张最小数据表检查搜索服务的创建、计划刷新和不同角色的查询覆盖。

### 5. 国立国会図書館の書誌をGitHub Actionsで毎日取り込む：止まっても次の回で続きを取る仕組み

**面试问题：**

> 公開書誌の取り込みが一日の途中で止まったら、次回はどこから再開しますか。

**约30秒回答：**

> UTC で最後に取り終えた日の翌日からやり直します。全ページが書き込めるまでは日付を進めず、同じ書誌 ID は upsert するので途中まで入れた行が増えません。BookConnect では一回で追うのは七日までです。ただし、発売された本がまだ図書館に登録されていなければ、毎日更新していても検索には出てこないので、取得漏れと区別します。

**相关项目示例：** 为开放目录建一个按日期回放的导入流程，记录断点和每次实际更新量，并演练缺页恢复。

**关键词：** GitHub Actions、UTC 检查点、幂等更新、责任表示

## 4. 今日技术主题

### 把处理中和已接受拆成两个状态

如果把屏幕上已经画出的线当成已经保存的图案，用户取消操作时就难以回到一个清晰的状态。对书目批处理而言，写入了某天的一部分也不能等同于处理完当天。两个实例都要求先规定一个完整单元，再让它成为后续操作的基准。

实际项目可以先做一个失败演练：让第三条路径转换出错，或让某日第二页的数据下载失败，检查既有版本和进度指针能否保持原值。画图恢复的核心是撤销单元，目录恢复还要考虑重复写入、原始文件是否可再解析与对上游的请求压力。

结合第一篇的模拟，还可以在演练时测量故障对其他任务的影响。需要分别验证同时等待多少项、能等多久，以及暂存项最后是否可重新处理。

**回答要点：** 预测留出后续年份验证，搜索服务则分别核对创建后的刷新和查询权限。

# B. 重点总结与可用于面试的知识

### 1. 遅い外部依存 1 つで全 Worker が止まる — タイムアウト・サーキットブレーカー・バルクヘッドを実測で使い分ける

1. **中文：** 延迟不返回时，缩短超时能减少每项占用时间，却未必把流入率降到可处理范围。
   **日本語：** タイムアウトは一件が枠を使える時間を制限します。依存先の上限は、その相手が使える枠の数を制限します。

2. **中文：** 分别记录正常端的延迟、完成数以及故障端的队列长度。这样可以发现完成数相同但用户等待时间悬殊的情形。
   **日本語：** 同じ完了数でも、最初の失敗を待つ間の遅れは p95 に現れます。正常側と障害側を別々に測ります。

3. **中文：** 限制并发的同时安排失败端队列的上限与后续处理。
   **日本語：** 退避先を作るなら、保管量と再試行の上限を決めてから負荷試験を組みます。

### 2. MMMの入口として、広告費・季節性・外部要因を用いた需要予測をDataRobotで試す

1. **中文：** 按商品和周组织合成样本之前，先明确拟预测的年度及当时能取得的字段。
   **日本語：** 年をずらす分割なら、予測時点より後の実績が学習に混ざっていないかを点検しやすくなります。

2. **中文：** 检查时间切分与滞后特征一起使用时是否泄漏未来数据。模型解释可以提出验证假说，广告效果另需实验或因果分析。
   **日本語：** 予測への寄与を見ても、同じ予算を別の媒体へ移した場合の効果は決まりません。

# C. 日语学习

## C-1. 新学JLPT词汇

查对全97期的388份文件，本次只收录在原文用法及参考等级均可确认的五个新词。已有词汇留作复习。

### 1. 損害（そんがい）｜N3

- 词性：名詞
- 含义：因事故、灾害等遭受的损害或不利后果。
- 搭配：損害を受ける / 損害を補償する
- 文章语境：文章中出现在「損害保険会社」一词中。
- 例句：大雨で倉庫が損害を受け、保険会社へ連絡しました。
- 例句含义：仓库因大雨受损，于是联系了保险公司。
- 辨析：「損失」可侧重失去的金额或利益，「損害」侧重受到的侵害或损害。

### 2. 諸々（もろもろ）｜N1

- 词性：名詞・副詞的用法
- 含义：把不同种类的事项统称为“种种”“各项”。
- 搭配：諸々の手続き / 諸々の事情
- 文章语境：原文用「その他諸々」概括未一一列出的 Terraform 管理项。
- 例句：検索を始める前に、権限や費用など諸々の条件を確認しました。
- 例句含义：开始搜索前，确认了权限、费用等各项条件。
- 辨析：「その他諸々」总括其余事项。在规格文档中若范围重要，应明确列出。

### 3. 写す（うつす）｜N5/N4

- 词性：五段・他動詞
- 含义：把原有形状或内容在别处复现、抄入或复制。
- 搭配：データを別の表に写す / 図をノートに写す
- 文章语境：在书目导入一文里指把书目复制到另一套数据库。
- 例句：確認に使う行だけを別の表に写しました。
- 例句含义：只把用于核对的行复制到了另一张表。
- 辨析：「書き写す」明确是书写抄录。「写す」也可以泛指复制数据。

### 4. 発売（はつばい）｜N3

- 词性：名詞・サ変
- 含义：把新产品推出市场、开始销售。
- 搭配：発売日を調べる / 新刊を発売する
- 文章语境：文章区分书籍开始销售和图书馆书目录入的时间。
- 例句：発売された本でも、書誌に載るまで少し時間がかかります。
- 例句含义：书已经上市，也需要等一段时间才会进入书目。
- 辨析：「販売」泛指销售，「発売」特别指开始销售。

### 5. 後ろ（うしろ）｜N5/N4

- 词性：名詞
- 含义：后方、后面，也可指顺序或进度回退的方向。
- 搭配：列の後ろ / 後ろに戻る
- 文章语境：原文用「後ろに戻る」说明导入进度不会回退至更早日期。
- 例句：手動で古い日を取り直しても、完了日は後ろに戻りません。
- 例句含义：即使手工补抓旧日期，完工日期也不会往回走。
- 辨析：既可指物理位置，也可像原文一样描述进度中的退回。

## C-2. IT/AI专业词汇

1. **Bulkhead（バルクヘッド）**：把故障依赖最多能占用的并发容量限制在总容量的一部分。 文中规定 B 最多占用四个 Worker。

2. **Lag feature（ラグ特徴量）**：把过去时点的取值对齐到当期样本的输入变量。 文中准备了一周前和四周前的广告费。

3. **Generation ticket（生成チケット）**：标明异步任务启动状态的一组标识。 对照文档、版本和草稿会话后才接收结果。

4. **Change tracking（変更追跡）**：为后续处理提供源表变更信息的功能。 搜索索引创建之前由建表流程启用。

5. **Upsert（更新または挿入）**：根据键选择更新现有记录或插入新记录。 书目导入按 ID 重跑，避免产生重复行。
