### 1. ローカルLLMのRAGが『資料からはわかりません』ばかり返す原因は、検索ではなかった（M1 Mac・25問で実測）

**原文：** https://zenn.dev/hoshihoshi/articles/5f07aa9a13f042

**公開時刻：** 2026-11-11 08:44:11 JST

社内規程を検索して回答するRAGでは、根拠が取れていても「分かりません」と返ることがあります。記事はメモリー16GBのM1 MacBook上で、Ollamaのqwen3:8bとLangChain、FAISSを動かし、架空の就業規則3ページから25問を作りました。うち20問には根拠があり、残り5問は資料からは答えられません。渡した断片に根拠があるかと、回答が正しいかを別々に数えています。

検索は最大4件を渡した設定で、根拠のある20問すべてに命中しました。500文字区切りでは断片が3個しかなく、事実上全文を渡した条件です。それでも初期の3設定の誤答12件のうち、11件では根拠がすでに渡っていました。質問の表現と資料の表現にずれがあり、同じ意味でも推測扱いしたと著者は見ています。

500文字区切りで最大4件を渡す条件で、根拠があれば言い換えを許す指示に変えると、正解は21問から24問に増えました。答えのない5問は引き続きすべて回答を控えています。初期の指示のまま思考モードを使うと25問正解ですが、中央値は1.4秒から22秒に延びました。ただし、各設定は一度の実行で、判定はキーワードと目視です。長い文書での検索性能や回答の説明力までは測っていません。PDFの行末で語が分かれる落とし穴も指摘していますが、改行処理の効果は一定ではありませんでした。

**読む価値：** 根拠の未取得と回答側の過度な慎重さを分けて説明でき、改善対象の見当違いを防げます。

### 2. Cloudflare D1で読み取り上限超過！NOT INの罠と99.8%削減・オフラインキャッシュ戦略

**原文：** https://zenn.dev/feedge/articles/cloudflare-d1-query-optimization-and-offline-cache

**公開時刻：** 2026-11-11 09:01:26 JST

RSSリーダーfeedgeの開発チームは、Cloudflare D1の日次読み取り上限に達してサービスが止まった経緯を報告しています。D1の分析では、記事一覧の47回で約334万行を読み取っていました。画面へ返すのは20件でも、実行計画では記事を広く読み、公開日時の並べ替えに一時Bツリーを使っていました。

チームは購読の条件をEXISTS、後で読むために一時的に隠した記事の除外をNOT EXISTSに変え、外側の記事と購読・除外テーブルの照合条件を明示しました。購読側の利用者とフィード、除外側の利用者と記事の複合主キーを使います。この構成では公開日時インデックスの降順走査が選ばれ、表示条件を満たす20件が見つかると止まりました。

記事は変更前後を約7万1000行から20〜30行、110ミリ秒から2ミリ秒と報告しています。見出しの削減率はその行数からの単純計算とは一致しないため、比較には記事に記された行数と時間を使います。ローカルに保存する最近100件と30秒のTTLは別の対策で、短時間の再表示と停止中の閲覧を支えます。ただし実行計画は分布や索引次第です。NOT INからの書き換えではNULLや購読の偏りも含め、表示される記事と順序を比較する必要があります。

**読む価値：** 戻り件数、読み取り行数、停止中に提供できる範囲を分けて説明できます。

### 3. テストが通っても YAML フィクスチャは壊れている — JSON Schema と yajsv で実行前に検出する

**原文：** https://zenn.dev/kyrenzk/articles/yaml-testdata-json-schema-yajsv

**公開時刻：** 2026-11-11 09:08:11 JST

Goの構造体に通貨を追加しても、以前のテスト用YAMLがそのまま通ることがあります。記事の実測はGo 1.24.7とyaml.v3 v3.0.1で、正常な注文と、通貨が欠けたうえに余分なキーに誤字がある注文を比べています。既定のデコードは未知のキーを捨て、通貨の欠落は空文字になります。既存のValidはIDと金額しか調べないため、二つともgo testを通過しました。

記事はdraft-07のJSON Schemaに通貨を含む必須キー、型、値の範囲、通貨の候補を指定し、未知キーも禁止しました。Makeからyajsvを呼び出すと、正常なファイルは通り、もう一方には必須項目の欠落と未知キーの両方がファイル名付きで出ました。GoのKnownFieldsだけでも誤字には気づけますが、記事の例では通貨が必須という意味までは伝えられません。

この方法は、挙動を試す前に入力の形が仕様に合うか確かめるものです。金額と通貨の関係など、業務上の意味の検査はアプリケーション側に残ります。ただし、記事が試したのは1ファイル1ドキュメントです。複数文書や参照で分割したスキーマ、大量ファイルでの実行時間は未検証で、スキーマとGoの型の更新をそろえる作業も残ります。

**読む価値：** テストが緑でも、入力の必須条件が検査されたとは限らない理由を示せます。

### 4. 縦動画の文字のはみ出しを、ffmpeg と Python の標準ライブラリだけで落とす

**原文：** https://zenn.dev/tarowhitey/articles/ffmpeg-vertical-video-frame-check

**公開時刻：** 2026-11-11 08:24:53 JST

短い縦動画では、後から重ねる字幕が正しくても、映像に焼き込まれた見出しが切れることがあります。記事の方法はffmpegから毎秒4枚、270×480のグレースケールの画素を取り出します。画像ライブラリーを使わず、背景と明るさが一定以上異なる画素を、端や右側の操作ボタンが重なる帯などで数えます。

一瞬の切り替えを拾いすぎないよう、条件を満たすフレームが2枚以上続いたときに区間として報告します。左右の偏りを調べるCENTERと、1080幅換算で片側が140ピクセル未満か調べるMARGINも分けています。左右が同じように狭い見出しは、差だけでは検出できません。字幕用の帯では白い枠も拾えるよう、外周の明るさから背景を見積もり、別のしきい値を使っています。

合成した正常・異常例と読めないファイルを合わせた14例は期待どおりで、4コア環境の3回の自己テストは9.4〜9.5秒でした。画素を一枚も取れないときはUNMEASUREDとして失敗します。ただし、この条件は画面端や帯の問題を拾うためのものです。文字同士の重なりや不自然な改行は別途、人や画像を読めるモデルで確認します。

**読む価値：** 片寄りと余白不足を区別し、未計測を通過にしない検査を考えられます。

### 5. Snowflake Dashboards 2.0が最高な理由と、これからBIに求められること

**原文：** https://zenn.dev/dataheroes/articles/snowflake-dashboards-2-and-future-of-bi

**公開時刻：** 2026-11-11 09:21:10 JST

Snowflake上の定型指標をチームで見ながら質問したい、という利用者の視点からDashboards 2.0を紹介した記事です。Snowsight Workspacesではダッシュボード定義を拡張子が.dashのファイルとして管理します。タイルはSQLを持ち、チャートにはVega-Liteが使われます。利用者のフィルターを集計前のクエリに反映するので、選んだ地域の合計を元データから計算できます。

完成した画面は読み取り専用のアーティファクトとしてロールに共有し、CoWorkで見ながら質問できます。タイルのSQLは閲覧者自身のデータ権限で動きます。共有用のロールと元の表を読める権限を確認すれば、画面を開ける人と数値を見られる人を分けて試せます。公式仕様では同じ閲覧者の以前のスナップショットを返す場合もあるため、表示されるたびに新規実行されるとは限りません。

記事は定型レポート用のアプリを個別に動かさなくてよい点を評価しています。ただし、閲覧者ごとのウェアハウス計算や更新頻度には費用があり、記事は他製品との比較測定を示していません。要件にしっくり来るかどうかは、同じ指標の定義、ロールごとの見え方、フィルターや会話から確認できる範囲を実際のレポートで試すと判断しやすくなります。

**読む価値：** 共有リンクの閲覧とデータの参照を別々に試し、導入時の確認項目を具体化できます。

## 4. 技術テーマ：途中の確認結果を残す検査

検査を設計するときは、画面の結果だけでなく、途中で何が確認できたかを残します。規程RAGは根拠の到着と回答の正しさを分け、注文のフィクスチャはYAMLの構造と注文処理の挙動を分けます。どの条件を確かめたかが記録にあれば、同じ失敗を再現して修正箇所を絞れます。

手掛かりのない状態も結果の一つです。動画のフレームが取れなければ未計測とし、根拠がない質問ならその事実を示します。障害中のD1の代わりに端末の一覧を見せる場合は、最後に取得した時刻を表示する設計が考えられます。最新データを取得したと誤解されると、復旧状況まで判断しにくくなります。

日本の業務チームを想定すると、最初に小さな規程集や定型レポートを選び、担当者と、承認や確認に使う場面をそろえると比較しやすくなります。導入前には、部署別の参照権限、規程の改定、誤った形式の入力、画面に出るデータの鮮度をそれぞれ試します。今回の単一サービスや小規模資料で得た数字は、そのまま社内の達成目標には使わず、必要な測定を選ぶための参考にします。

3. 30秒以内の再利用と障害時の古いデータの表示は別の条件として扱います。

### 3. テストが通っても YAML フィクスチャは壊れている — JSON Schema と yajsv で実行前に検出する

1. デコードに成功しても、必須の文字列が空のままになることがあります。

2. JSON Schemaで必須と未知キーを別々に検査し、ファイル名を付けて失敗を返します。

3. データの構造と業務上の正しさをそれぞれの検査に割り当てます。

### 4. 縦動画の文字のはみ出しを、ffmpeg と Python の標準ライブラリだけで落とす

1. 画素の固定幅が分かれば、グレーの生データをフレーム単位に切り分けられます。

2. 左右の差と、両側それぞれの最低余白は別々に確かめます。

3. 空ファイルと合格すべき動画も用意し、測れない場合と過剰に拒否する場合を検査します。

### 5. Snowflake Dashboards 2.0が最高な理由と、これからBIに求められること

1. タイルのSQLで集計する前に、利用者が選んだ絞り込みを適用します。

2. 共有された定義は読み取り専用で、元データのクエリは閲覧者自身の権限で動きます。

3. 定型集計を開く速さと、閲覧者ごとの実際のクエリ費用を別々に確認します。

### 1. しっくり（しっくり）｜N1

- 品詞：副詞
- 意味：物や考えがうまく合い、違和感がない様子。
- 連語：しっくり来る / しっくり合う / しっくりしない
- 記事文脈：ダッシュボードの記事は、これまでの選択肢が利用目的に合わなかったと述べます。
- 例文：今の画面は、毎朝数字を見る使い方にしっくり来ます。
- 例文の意味：今の画面の使い方が、毎朝の確認という目的に自然に合っています。
- ニュアンス：「ぴったり」は寸法や数量にも使います。「しっくり」は感じ方や関係のなじみのよさを表しやすい言葉です。

### 2. 落ちる（おちる）｜N5/N4

- 品詞：動詞・上一段・自動詞
- 意味：合格とされず、次の段階へ進めない。
- 連語：検査で落ちる / 試験に落ちる / 審査に落ちる
- 記事文脈：動画の記事は、測れない入力を合格させず失敗として扱います。
- 例文：空の動画は、未計測として検査で落ちます。
- 例文の意味：空の動画を読み取れなかったため、次の確認段階へは進めません。
- ニュアンス：ここでは物が下へ移る意味ではなく、判定を通過しない用法です。参考レベルはN4です。

### 3. 見せる（みせる）｜N5/N4

- 品詞：動詞・下一段・他動詞
- 意味：相手が目で見られるようにする。
- 連語：数字を見せる / 根拠を見せる / 画面を見せる
- 記事文脈：ダッシュボードの記事では、何を誰に見せるかと元データの権限が関係します。
- 例文：権限を確かめてから、利用者に数字を見せます。
- 例文の意味：利用者が参照してよいと確認してから、画面に数値を出します。
- ニュアンス：相手に見える状態を作る動作です。「表示する」は機械が画面へ出力する操作を述べる場合にも使います。参考レベルはN5です。
