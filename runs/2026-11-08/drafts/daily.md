### 1. Referrer-Policy: no-referrer を付けたら、Next.jsのServer Actionsが500になった

**原文：** https://zenn.dev/snape_works/articles/nextjs-no-referrer-origin-null

**发布时间：** 2026-11-08 09:35:17 JST

一次保护邮件登录链接的改动导致确认按钮返回500。作者在Vercel上运行Next.js 16.3.8，把包含一次性令牌的确认页设为no-referrer，希望后续请求不会泄露该地址。页面错误看起来像令牌已过期，服务端却记录了另一条线索。确认操作触发的POST中，Origin为null，没能通过与x-forwarded-host的比较，请求在Server Actions的CSRF检查处被拦下。

参照地址策略也可能影响来源标头。常见表单产生的非CORS POST，在no-referrer下可能送出null来源。浏览器用CORS模式发出的fetch不宜套用这条推论。作者把确认页改成strict-origin，保留协议、主机和端口这一层的来源信息，路径与查询参数不会出现在参照地址里。文章中的Chrome登录随后恢复，站点默认的same-origin仍用于其他页面。

Vitest回归测试覆盖了所配置的策略。这里还缺少失败请求实际走哪条提交路径的证据，也没有解释另一个Chrome环境为何能通过。排查时应从网络面板追到服务端拒绝点，并分别验证敏感参数的去向及登录结果。

**阅读价值：** 同一项隐私设置可能改变防伪校验的输入，这个案例给出了如何沿请求找到拒绝点的线索。

### 2. BigQuery の TabFM と LightGBM を Diamonds で比較

**原文：** https://zenn.dev/ttomo_tommy/articles/tabfm-vs-lightgbm-diamonds

**发布时间：** 2026-11-08 00:36:09 JST

比较从钻石价格回归开始。原文选OpenML的Diamonds，以九个特征预测价格的对数，再转换回价格后计算绝对相对误差的中位数。LightGBM先拟合一组树，BigQuery里的TabFM在预测调用中接收带标签的样例。作者用五个随机种子跑比较，并事先约定，调参后的LightGBM至少赢四次才算交叉点。

训练样例只有250行时，TabFM的误差是7.99%，LightGBM为15.78%。各用1万行时两者是4.80%和4.97%，LightGBM只赢了两次。用51,794行训练的LightGBM降到4.22%，但相对的一方仍只用1万行。作者也试过给TabFM 2万行训练样例，把推断拆成每批500行仍有四次内存超限。这说明比较受运行条件影响，无法把2万行当成产品公布的上限。

作者另做了按克拉切分的外推评估。训练集只放小于1.51克拉的记录，测试从被留出的大颗粒钻石中抽样。各取2千训练行时，误差是9.87%和20.22%。LightGBM改用约4.8万训练行后仍是20.19%。这组结果对评估超出训练范围的预测有价值，单一数据集、未比较费用和没有测到更大TabFM配置也限定了结论。

**阅读价值：** 模型选择除了看误差，还要看两方拿到了多少数据、能否跑完以及将来会遇到怎样的输入。

### 3. ISUCON2026 ソロ参加記：自作ハーネスで Claude Code をほぼ無人運転した

**原文：** https://zenn.dev/5alt_nacl/articles/isucon2026-solo-ai-agent

**发布时间：** 2026-11-08 08:35:44 JST

这次ISUCON独自参赛记录把工程操作拆成短循环。Windows端启动代理，读取磁盘上的状态，完成一步后保存操作与结果并预约下一次唤醒。服务仍跑在比赛分配的机器上，主循环停止才由备用机制接手。参赛者也亲自登录、补充指令及解除冻结。作者报告70次基准测试，最终208,983分，从起始的2,139分上升到579组第38位。

涨分对应若干具体瓶颈。重新看计分规则后，作者改为直接投递通知。计算图像签名消耗大量区域节点CPU，预计算能省掉请求路径上的工作。日志加入请求体大小后才发现，巨大的无效图片占接收量的66%，于是提前拒绝。存储侧把新图像移出数据库，历史182万张图像也从大量独立文件改成数据文件加索引，缓解了初次迁移撞到的IOPS限制。

同一套配置的基准分数也会在195,198到206,400间波动，单跑一次很难归因。两次重启检查都通过，补充了分数之外的可恢复性证据。比赛中能持续推进的工作流，只能说明这些条件下的经验，要进入生产还需重新验证权限、停止与人工接管。

**阅读价值：** 可跟着每一次观测找到性能工作从何开始，以及代理交接时需要留下什么。

### 4. 外ループは「いつ動かし、いつ止め、何を引き継ぐか」で設計する ― Sentry→Webhook→Codexの実例から

**原文：** https://zenn.dev/tmiyachi/articles/outer-loop-sentry-webhook-codex

**发布时间：** 2026-11-08 09:51:28 JST

文章里的故障调查从Sentry的事件归组开始。Webhook把通知交给接收端，后者以Sentry的课题编号标识一个Codex任务。代理调查后输出是否需要修复，结论留在任务列表里供人查看。这个编号把某一组错误与对应的调查连起来，让后续接手的人知道该查哪一条记录。

作者用“外循环”描述运行条件和交接，用“内循环”描述一次任务里的分析。对团队而言，接到什么通知、何时停止、输出放到哪里，都可在调查开始前设计。重复事件是否合并、重试能进行几轮以及哪些操作需审批，也应在这层定边界。原文提出了这些控制手段，没有给出它们都已在该示例启用的证据。

这套记录展示的是检测、发起调查、保留判断的连接方式。没有公开具体故障样本，也没有调查准确率或耗时。可分别用重发通知检验触发层，用人工复核检验分析层，避免把任务出现视为故障已经排除。

**阅读价值：** 为把人工调查接到事件通知上提供了一个可审计的最小流程。

### 5. AS/400環境のPUB400.COMで、5250端末からDb2 for iでSQLを実行してみた

**原文：** https://dev.classmethod.jp/articles/pub400-db2-for-i-5250/

**发布时间：** 2026-11-08 04:30:37 JST

作者从Mac上的tn5250j进入PUB400提供的IBM i 7.5。这个Java客户端模拟5250终端，终端会话与数据库操作都发生在远端主机环境里。文章选择TLS端口992连接，进入后按提示改初始密码。连接通了，只说明终端会话已建立，还可以单独做一次数据库验证。

接下来在IBM i启动STRSQL并选择SQL命名方式，库名与表名就能用点号连接。查询SYSIBM下的SYSDUMMY1后，结果只有一行，IBMREQD显示为Y。这个返回值证明示例在远端Db2 for i执行了SQL。文章还介绍可查QSYS2的系统目录了解表对象，实际做练习时要注意库的范围。

PUB400用于非商用学习，资源由多位用户共享。这个过程适合熟悉终端、命令与SQL之间的关系，练习时应限于自己的区域或明确公开的样例，避免上传敏感数据。一次查询成功无法推出容量、响应时间或迁移适用性。

**阅读价值：** 可以把一次主机上手练习拆成网络、终端与数据库三个可检查的阶段。

## 4. 技术主题：沿证据核对处理到达的位置

先为结论确定能追溯的证据。浏览器的界面提示要与服务器日志对应，终端连通要用数据库返回值补上下一环。

模型评估与性能调优都要列出变化的条件。保留各次运行、失败次数和测量边界，才能看清差异究竟来自输入规模、数据分割还是运行波动。

事件自动化也需要清楚的交接条件。告警如何进入、重复如何收束、调查判定交给谁，都可以分别用样例检验。

### 1. 占める（しめる）｜N3

- 词性：動詞・五段・他動詞
- 含义：某一部分在整体中占有一定比例。
- 搭配：半数を占める / 大部分を占める / 全体の三割を占める
- 文章语境：ISUCON原文用这个动词描述巨大无效图片在接收量中占66%。
- 例句：大きな画像が受信量の半分を占める場合は、送信元を調べます。
- 例句含义：如果大图片占接收量的一半，就排查发送来源。
- 辨析：这里是比例义。同音的「閉める」指关门等，「締める」可指拧紧，均属于不同词。

### 2. 試す（ためす）｜N3

- 词性：動詞・五段・他動詞
- 含义：实际使用或运行来检验性质或结果。
- 搭配：小さなデータで試す / 方法を試す / 別の条件で試す
- 文章语境：TabFM原文讨论为何值得在少量训练数据的条件下尝试。
- 例句：先に二百五十行で試し、誤差と実行時間を記録します。
- 例句含义：先拿二百五十行试跑，记录误差和执行时间。
- 辨析：侧重检验对象表现。既学的「試みる」在「改善を試みる」等搭配中侧重尝试采取行动。

## C-2. IT/AI专业词汇

1. **Referrer-Policy（参照元ポリシー）**：规定请求可传送多少参照地址信息的HTTP标头。 登录确认页用它限制含令牌的路径与查询参数外传。

2. **CSRF（クロスサイトリクエストフォージェリ）**：利用已登录浏览器替用户发出非预期操作的攻击。 Server Actions的来源检查在本例中先于令牌验证。

3. **TabFM（表データ向け基盤モデル）**：利用带标签的表格样例来预测未知行的模型。 钻石实验的运行情况随训练行数及推断批大小变化。

4. **外挿（がいそう）**：对超出训练观测范围的输入作预测。 测试特意抽取训练时不见的高克拉记录。

5. **IOPS（毎秒の入出力操作数）**：存储设备或服务每秒可处理的输入输出操作数。 比赛将历史图像从大量独立文件改为数据文件加索引。

6. **Webhook（イベント通知用HTTP呼び出し）**：事件发生时主动向指定接收端发送HTTP通知的机制。 本例用Sentry事件启动对应的Codex调查。

7. **5250（IBM iの端末インターフェース）**：用于收发主机屏幕及按键操作的终端接口。 Java终端模拟器通过TLS接入共享学习主机。
