# 日本 IT/AI 日报｜2026年11月26日（第107号）

本期覆盖日本时间 11 月 25 日 10:00 到 26 日 10:00。五篇原文都记录了实际观察，适合练习如何把观察结果写成可以复查的工程证据。

# A. 详细文字版

## 1. 今日推荐的五篇原文

### 1. Corpus2Skillに近づけた「階層ナビゲーション型RAG」と、ベクトルDB版RAGを「どの段階で失敗したか」まで比べてみた

**原文：** https://zenn.dev/aiforall/articles/133752ce2d97ad

**发布时间：** 2026-11-25 11:35:47 JST

作者用 130 篇 Bedrock 文档和 40 道题，比较向量检索与借鉴 Corpus2Skill 的层级导航。后者让代理在分组目录内自己选文档，也允许读完一篇后回到其他分组。题目分为直接、改述、跨文档和语料无答案四类，各十道。作者为题目要点标了 86 个原文片段，用来区分找不到文档、证据未保留、答案不满足要点三种失败。

按复查后的评分，向量方案总正确率约 0.63，代理方案约 0.80–0.85。差距主要来自跨文档问题，向量方案仅答对十题中的一道，代理方案答对六到八道。只检查最终五篇且截到 8000 字符，会漏掉代理前段已经读过的证据。作者还将 84 个判错案例重新与原文对照，发现 9 个误判都来自代理方案。

价格和时间有明显差异：作者记录的单题费用约为向量方案的 15 倍，耗时约 7 倍。实验规模和评委模型都限制结果的外推，新增实体索引等特性在这里也没有显示超出运行波动的收益。选择检索策略时，可单独给跨文档问题做多次试验，同时记录证据与成本。

**推荐理由：** 除了总分，文章还逐层展示为什么会答错，便于决定应该改检索、上下文截断还是评分。

### 2. Amazon API Gateway の API Portal で REST API の探索と管理 API への昇格を試してみた

**原文：** https://dev.classmethod.jp/articles/api-gateway-api-portal-discovery-managed-api/

**发布时间：** 2026-11-25 23:58:28 JST

作者在东京创建 REGIONAL 和 PRIVATE 两种 REST API，以 MOCK 集成部署后测试 API Portal。区域发现配置建成后仍显示 STOPPED，显式启动后才看到 RUNNING。库存的观察单位是部署阶段下的 HTTP 方法和路径，同一个 REST API 可以对应多个条目。

制造这组测试数据后，作者按约一分钟间隔查询，第三次看到三个条目。公开与私有 API 被分别标作 PUBLIC 和 PRIVATE，新发现时的分类为 SHADOW。把条目加入管理库存后可看到九项安全评估，原有 REST API 的设置和更新时间经前后对照没有变化。

限制在于两分钟多的检测时间只来自一次轮询，受发现何时启动、扫描与请求等条件影响。文档对 REST、HTTP 和 WebSocket 的发现范围也不同，报告中的指标来自 REST API。需要改变认证或日志策略时，应另从 API 的原控制面实施并验收。

**推荐理由：** 适合讲清发现、纳管和配置变更是三个动作，方便制定存量 API 盘点的验收条件。

### 3. Snowflake の CoCo for Excel を Microsoft 365 管理センターから組織配布して使ってみた

**原文：** https://dev.classmethod.jp/articles/cortex-code-for-excel-org-deployment/

**发布时间：** 2026-11-26 08:29:03 JST

CoCo for Excel 在工作簿侧边栏接入 Snowflake。作者用测试 Microsoft 365 租户和 Excel 网页版，验证预览阶段通过 XML 清单分发扩展。组织管理员指定用户，Snowflake 侧建立针对客户端的 OAuth 集成。查询按使用者自身角色执行，仍受 Snowflake 的访问策略约束。

作者先只把扩展分配给自己，约两小时后在 Excel 网页版看到它。试验中，显示登录面板并登录后，用户提交数据查询，在真正写入工作簿之前还会看到预览并选择是否接受。随后把一般使用者加入分配范围，也看到了扩展并验证了已配置单点登录的用户能接通。

文档称分发传播可能最多需要 72 小时，单次观察无法为新用户保证两小时内生效。扩展可见、能进入 Snowflake、能查询相应行以及允许写入是不同条件。这次限定于预览版和测试租户，正式推广还要为最小权限、传播延迟和退出流程另外验收。

**推荐理由：** 从租户分配一直验证到数据进入表格，给桌面扩展的可见性与数据访问提供两条证据。

### 4. AIが速く作っても人の待ちが残っていた —— 開発プロセス全体で減らした合意と、残した確認

**原文：** https://tech.smarthr.jp/entry/2026/11/25/182704

**发布时间：** 2026-11-25 18:27:04 JST

SmartHR 的四至五人团队已有 AI 辅助实现，开发仍会等负责人准备材料或等全员集中确认。团队把一周作为一个 Sprint，将单个工单的完成责任交给担当，功能负责人维持目标和验收条件。起票和细化时，AI 读取仓库中的准备、完成和估点准则来提出草案，最后由人确认。

团队保留了实施者之外的复核流程，复核人检查设计目的和测试证据，必要时补操作或探索性测试。作者用可投入开发的时间作为分母，它从工作时间里扣除会议、休假和其他事务。全队每周约从 69 小时升到 93 小时，同期每小时完成的故事点两段都约为 0.14。

结果的适用条件是这一个团队的流程和估点方式，前后工单粒度也有变化。可投入时间增加能描述工作分配的变化，质量效果和每小时效率还没有被证实。继续评估时，可同时追踪等待、返工和评审负担，再判断变更带来的收益。

**推荐理由：** 给出了工单责任、评审证据和度量口径，适合解释为什么 AI 代码生成加速后，团队交付仍可能卡在交接。

### 5. Kiro Mobile アプリがリリースされたので試してみた

**原文：** https://dev.classmethod.jp/articles/kiro-mobile-android-iphone-cloud-session/

**发布时间：** 2026-11-26 02:19:39 JST

Kiro Mobile 连到与 Web 版同一类的云端会话。作者用组织身份在 Android 端开启 Build with spec，在没有连接仓库的会话里为一个 Python 示例生成要求、设计和任务三个文件。之后从手机回复确认进入实现，示例和测试文件生成，pytest 三项通过。

同账号在 Kiro Web 能看到这条需求会话和任务状态。作者另在 Android 建了一个文章搜索会话，用 iPhone 打开并看到内容。两项检查分别说明需求会话连到 Web、搜索会话跨手机可见，不应合并成在 iPhone 重跑了全部实现过程。

试验的限制是 Python 例子在没有连接 Git 仓库的工作区，未提交或推送。移动端也没有用来设置 GitHub、GitLab 连接或浏览会话文件树的入口，那些操作由 Web 承担。需要审核开发成果时，可分别核对任务完成状态、测试输出与远端仓库。

**推荐理由：** 把跨设备接续、云端运行以及向团队仓库交付拆成可观察的事实。

## 3. 面接で使えるポイント

### 1. Corpus2Skillに近づけた「階層ナビゲーション型RAG」と、ベクトルDB版RAGを「どの段階で失敗したか」まで比べてみた

**面试问题：**

> 複数の文書が必要なRAGで、答えが違ったら何を調べますか。

**约30秒回答：**

> まず必要な文書に届いたかを見ます。次に、八千文字に切った後も、答えに必要な箇所が残っていたかを調べます。記事では、最後の五文書に絞ると早く読んだ根拠を見落とす例がありました。根拠があれば、元の文章と採点理由を照らし合わせます。ただし、百三十文書の試験なので、別の規模でも同じ結果になるとは限りません。

**相关项目示例：** 给技术手册问答构造需要两个文档的查询，分别记录命中文档、保留的依据与答案得分。

**关键词：** Corpus2Skill、层级导航、证据片段、LLM-as-a-Judge

### 2. Amazon API Gateway の API Portal で REST API の探索と管理 API への昇格を試してみた

**面试问题：**

> API Portalで、発見したAPIを管理対象にできたかどう確認しますか。

**约30秒回答：**

> まず東京の例と同じように探索を開始し、実行中になってから、ステージとパスとメソッドで対象を探します。記事では未管理の三項目が見つかり、管理対象にすると九つのポスチャが取れました。元の設定と更新時刻も前後で見比べます。ただし、数分で表示されたのは一回の結果で、ほかの環境での反映時刻は個別に確かめます。

**相关项目示例：** 为团队建立 API 清单，比较公开与私有入口的可见性并记录纳管前后的配置哈希。

**关键词：** API Portal、REST API、SHADOW、安全评估

### 3. Snowflake の CoCo for Excel を Microsoft 365 管理センターから組織配布して使ってみた

**面试问题：**

> ExcelのCoCoを組織配布するとき、利用者側で何を試しますか。

**约30秒回答：**

> 管理画面にマニフェストを登録し、まず少数の利用者に割り当てて、エクセルのウェブ版で表示を確かめます。次に、利用者自身のスノーフレークのロールで接続して、書き込みのプレビューを承認すると表ができるかを試します。対象外の人に出ないことも見ます。ただし、記事で二時間後に見えたのは一例です。反映を待つ時間とデータの権限は別々に確認します。

**相关项目示例：** 给分析组试点分发数据扩展，将未分配用户、非高权限角色、写入预览和撤回访问列为验收案例。

**关键词：** CoCo for Excel、XML manifest、Snowflake OAuth、角色访问

### 4. AIが速く作っても人の待ちが残っていた —— 開発プロセス全体で減らした合意と、残した確認

**面试问题：**

> AIを導入したチームで待ち時間が減ったことを、どう測りますか。

**约30秒回答：**

> チケットごとに完了まで担当する人を決め、受け入れ条件とレビューの証跡を残します。その上で、会議などを引いた開発時間と、時間あたりの完了量を別々に見ます。記事では週に使える時間は約六十九時間から九十三時間に増えました。ただし、時間あたりの完了量はほぼ同じで、品質への効果は手戻りなどを別に測って確かめます。

**相关项目示例：** 试行单工单负责制，把可用开发小时、等待审核时长和返工分别列入 Sprint 回顾。

**关键词：** 工单责任、Definition of Ready、评审证据、故事点

### 5. Kiro Mobile アプリがリリースされたので試してみた

**面试问题：**

> スマホで始めた開発タスクを別の端末に引き継ぐ前に、何を見ますか。

**约30秒回答：**

> 同じ組織アカウントでウェブ版を開き、要求、設計、タスクが見えるか確かめます。記事ではアンドロイドから作った仕様と、三件のパイテストの結果を確認できました。アイフォーンでは別の検索会話を開けています。ただし、仕様を試した場所はリポジトリの外でした。チームに渡すときは、テストに加えてコミットが残ったかを確認します。

**相关项目示例：** 测试手机发起的规格任务如何在 Web 接续，检查规格文件、测试日志和是否确实形成 Git 提交。

**关键词：** Kiro Mobile、Build with spec、云端会话、pytest

## 4. 今日技术主题

### 把中间状态和可交付结果拆开检查

RAG 的文档命中只说明检索找到了位置，判断结果还需要看原文片段是否进入上下文。API 从库存变为纳管只增加管理可见性，需要另行确认既有配置。Excel 看到扩展后，也要按用户角色试验真实查询和写入。

同样，团队可用时间增加只回答了分母怎样变化，移动端会话能继续则回答了工作状态是否同步。把各阶段预期结果、观察方法和未覆盖条件写到同一份验收记录，下一位接手者就能从实际进度继续验证。

### 1. 照らす（てらす）｜N2

- 词性：五段他動詞
- 含义：此处指对照某项事实或标准进行判断。
- 搭配：原文に照らす / 規定に照らして判断する / 事実に照らして考える
- 文章语境：作者按既定要点和原始文章重新查看判错的回答。
- 例句：判定に疑問があれば、回答を元の資料に照らして確かめます。
- 例句含义：如果对评判有疑问，就依据原始资料核对答案。
- 辨析：「見比べる」可比较对等对象，「原文に照らす」则把原文作为判断依据。

### 2. 配る（くばる）｜N2

- 词性：五段他動詞
- 含义：分发，把物品或信息交给多个接收者。
- 搭配：資料を配る / 参加者へ案内を配る / 利用者にアドインを配る
- 文章语境：管理员将 Office 扩展分发给指定用户。
- 例句：説明会の前に、担当者が登録手順を書いた資料を配りました。
- 例句含义：说明会开始前，负责人发放了写有注册步骤的资料。
- 辨析：「届ける」侧重到达目的地，「配る」侧重把东西分发给多个对象。

### 3. 応じる（おうじる）｜N3

- 词性：一段自動詞
- 含义：接受请求，或根据条件和情境调整做法。
- 搭配：依頼に応じる / 条件に応じて手順を変える / 状況に応じて対応する
- 文章语境：案例按收到的需求选择使用 AI 的调查、实现和验证步骤。
- 例句：作業の規模に応じて、確認する項目を変えます。
- 例句含义：按任务规模调整需要检查的项目。
- 辨析：「応える」常指回应期待或呼唤。「条件に応じて」强调依据不同条件作相应调整。
