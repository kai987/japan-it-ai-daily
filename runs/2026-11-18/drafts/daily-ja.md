### 1. ESLint から oxlint へ。lint が 50 倍速くなるまでの移行の記録

**原文：** https://zenn.dev/rimo/articles/12d6a7b1c58fcd

**公開日時：** 2026-11-18 09:51:16 JST

RimoはNext.jsとTypeScriptのコードでESLintを使っていました。編集後のPostToolUseで自動修正を実行すると、一ファイルで3.3秒かかったそうです。そこでまずこの処理にoxlintを入れ、同じ計測で0.36秒になりました。対応範囲は当時のESLintルールのおよそ八割だったため、段階を踏んで切り替えています。

プリセットのルールを照合すると、比較した版では115個がoxlintに見当たりませんでした。非推奨品や代替可能な検査を除き、この棚卸しで要検討とした三つをESLintに残しました。react/jsx-no-leaked-renderのように、本来画面へ出すつもりのない数字のゼロを検出するルールが含まれます。記事ではこの三つのほかにも、Nxの境界チェックなどをESLintの担当にしています。

3091ファイルを対象にキャッシュなしで三回測った中央値は、271.5秒から5.4秒でした。CIのlint工程では146秒から32秒です。ただし、--type-awareを忘れると型を使うルールを飛ばしても成功扱いになる例がありました。jsPluginsの構成によって処理時間も延びます。速度と検査の実効性は別々に確かめる必要があります。

**読む価値：** 速度を上げつつ、機械的な移行で失う検査を見つける方法が分かります。

### 2. PLaMo 3 TranslateをDockerで動かしてDeepLと翻訳精度を比較してみた

**原文：** https://zenn.dev/aiforall/articles/8aa2637ea04da4

**公開日時：** 2026-11-17 16:30:10 JST

筆者は日英翻訳を手元で行うため、Docker内のLinuxでllama.cppをCPU実行しました。モデルにはPLaMo 3 Translateの2BをQ4_K_M形式で使い、CLIは1.2.0、llama.cppはb11960です。ホスト側のPythonから翻訳方向と入力ファイルを指定して、コンテナ内のCLIに渡します。

比較ではことわざ三つとビジネスメールを英訳し、出力された英文を日本語に戻しました。例えば出る杭のことわざは、両サービスの英訳が同じでした。日本語へ戻すと、PLaMoは定型句を使い、DeepLは釘を打つ場面を字面に近い形で表しました。メールでは結びの挨拶の表し方にも違いがありました。

逆翻訳は元の表現がどう戻るかを観察する手段です。ただし、この検証は少数の例で、日英の片方向で意味を保つ力や分野別の誤り率は分かりません。慣用句が自然に戻るかという観点と、原文の数字や条件が保たれるかという観点を分けると、実際の用途に合わせて評価できます。

**読む価値：** 同じ英訳から再び日本語にしたとき、訳し方にどんな差が出るかが見えます。

### 3. S3のデータを Databricks に取り込むために、データ基盤チームが用意したもの

**原文：** https://zenn.dev/guri_03/articles/ad28087e995349

**公開日時：** 2026-11-17 18:39:05 JST

依頼元のAWSアカウントには、検証用と本番用のS3バケットがあり、JSON Linesのログが置かれます。依頼元チームが取り込み処理を保守し、データ基盤チームは接続先と実行環境を用意しました。宣言型パイプラインにGitを直接指定できなかったため、コードと設定の届け方を決める必要がありました。

今回は接続元IPに制限があり、GitHub Actionsのランナーをすぐ用意するのは難しい状況でした。開発者がVPNからDABsを使い、共通のフォルダに配布します。誰がデプロイしても同じ場所を使う設計です。実行はrun_asで指定したサービスプリンシパルが担い、担当者の異動や退職から切り離しています。

External Locationは読み取り専用とし、利用できるワークスペースも絞りました。書き込み先は一つのカタログの中で検証用と本番用に分け、作成者と参照者の権限をグループに付けます。ただし、一つのワークスペースとリリース時点の制約に合わせた構成です。デプロイが増えれば、CIでの自動化を改めて検討します。

**読む価値：** コードを届ける人と、ログを読む実行者の権限をどう切り分けたかが具体的です。

### 4. スクリーンショット5枚から作るアニメーションWebP：sharp の delay と99KBの実測

**原文：** https://zenn.dev/sakidori/articles/20261031-headless-screenshot-animated-webp

**公開日時：** 2026-11-18 06:12:16 JST

サービス紹介の画像を更新しやすくするため、筆者はPlaywrightのChromiumで公開デモの画面を撮りました。表示領域は720×480、deviceScaleFactorは1です。五枚をsharpでまとめた比較では、WebPが99KB、GIFが246KB、APNGが320KB、PNG五枚は合計378KBでした。Node 22、sharp 0.35.5、libvips 8.18.7での計測です。

コマはjoinにanimatedを指定してつなぎます。delayに1200という数値を一つ渡すと、調べたWebPでは最初のコマにしか効きませんでした。残りは100ミリ秒です。メタデータを読み返すと設定の違いが見え、同じ値でも五要素の配列として渡せば、各コマに適用できました。

qualityを70にそろえ、effortを4から6に上げると、101KBから99KBになる一方、生成時間は212ミリ秒から2879ミリ秒になりました。筆者は4を選んでいます。ただし、五枚の内容と寸法に依存する値です。本番で掲載している画像は150〜330KBで、横幅や内容を変えれば同じ圧縮比になるとは限りません。

**読む価値：** 画質の感想だけで判断せず、出力バイト数とコマの時間を調べています。

### 5. WordPressを廃止し、静的サイト＋Pagefindに移行した

MAMORIO Laboでは、既存の文章を読めることと、サイト内で探せることが主な要件でした。筆者は独自のPythonスクリプトで公開ページと付随ファイルを保存しました。HTMLを再シリアライズせず、139記事に固定ページや一覧を加え、324個のHTMLを扱いました。取得失敗、URLとハッシュも記録しています。

移行前後で本文とURLだけでなく、メタタグやJSON-LDも突き合わせました。サイト検索にはPagefindを使い、記事の本文と見出しを索引に入れます。繰り返し文章のある一覧を対象から外し、日本語の検索とヒットしない場合の画面、検索フォームからたどれることを確認しています。

非公開S3とCloudFrontで配信し、旧URLを確認してから動的環境を撤去しました。記事が報告するインフラ費用の減少は、月に約1万5千円です。ただし更新はGitHubを通す形になり、編集者向けの管理画面は使えなくなりました。費用と運用の利点は、既存記事の公開が中心という条件と合わせて読みます。

**読む価値：** 記事と検索を残しながら、更新経路と配信基盤を変えた事例です。

### 3. 土台（どだい）｜N1

- 品詞：名詞
- 意味：建物を支える下の部分や、何かを始めたり続けたりするためのよりどころです。
- 連語：土台を作る / 議論の土台
- 記事文脈：基盤チームが分析側に先立って用意した、環境と権限の前提を指します。
- 例文：共通のデータ形式を決め、次の分析の土台を作りました。
- 例文の意味：共通のデータ形式を決め、次の分析に取りかかれる状態にしました。
- ニュアンス：「土台」は何かを下から支えるイメージです。「基盤」は組織や技術の継続的な仕組みにもよく使います。

### 4. 異動（いどう）｜N2

- 品詞：名詞・サ変
- 意味：組織の中で担当や勤務地などが変わることです。
- 連語：部署を異動する / 人事異動
- 記事文脈：担当が替わっても、取り込みジョブを実行できる権限が残るようにします。
- 例文：担当者が別の部署に異動しても、集計は続きます。
- 例文の意味：担当者が別の部署へ移っても、集計は止まりません。
- ニュアンス：物や人が場所を移す「移動」と読みは同じですが、仕事上の所属・職務の変更には「異動」を使います。

### 5. 退職（たいしょく）｜N1

- 品詞：名詞・サ変
- 意味：仕事や勤め先を辞めて、その職を離れることです。
- 連語：会社を退職する / 定年退職
- 記事文脈：個人のアカウントが退職で使えなくなっても、ジョブを回せる設計を説明しています。
- 例文：担当者が退職する前に、作業手順を後任に引き継ぎました。
- 例文の意味：担当者が勤め先を離れる前に、後任に作業方法を伝えました。
- ニュアンス：「退職」は職を離れること全般を表し、自分から辞めたかは語だけで決まりません。

### 6. 撤去（てっきょ）｜N1

- 品詞：名詞・サ変
- 意味：設置してあった設備や物を取り除くことです。
- 連語：旧設備を撤去する / 仮設の案内板を撤去する
- 記事文脈：既存URLが新しい環境で動くのを確かめてから、不要になったクラウド設備を取り除きました。
- 例文：新しい配信経路で記事を開けると確認し、旧設備を撤去しました。
- 例文の意味：新しい環境から記事が読めるのを調べ、古い配信設備を取り外しました。
- ニュアンス：「撤去」は置かれていた物や設備に使います。制度をなくす場合には「撤廃」がよく使われます。

## C-2. IT/AI専門用語

1. **Type-aware lint（型情報を使う静的検査）**：型推論の情報を利用してコードの問題を検出する検査です。 移行先では起動時のフラグが必要でした。

2. **Q4_K_M（四ビット系の量子化形式）**：重みを低い精度で表して、モデルの保存や実行に必要な容量を減らす形式です。 比較した二十億規模のモデルがこの形式です。

3. **External Location（外部ロケーション）**：クラウドの保存先とアクセスに使う認証情報をカタログに結びつける定義です。 S3 の読み取り対象を絞って登録しました。

4. **Animation frame delay（コマごとの表示時間）**：一つのコマを表示してから、次へ移るまでの時間です。 先頭だけ長く止めるため、コマ数と同じ長さの配列を渡しました。

5. **Pagefind（静的サイト向け検索）**：生成済み HTML から検索データを作り、ブラウザで結果を探せる仕組みです。 記事の本文や見出しに索引の対象を限りました。
