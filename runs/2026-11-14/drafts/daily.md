### 1. 止まったら最初からやり直すERP移行バッチを再開可能にするまで

**原文：** https://zenn.dev/yutaka8484/articles/kobayashi-20261114-resumable-erp-migration

**发布时间：** 2026-11-14 09:03:50 JST

作者回顾了2022年7月至2025年1月负责的一次ERP更新。受注、生产、采购、库存和会计等业务要迁移多年数据。原流程按顺序读取全量记录、转换后写入新表。哪怕只在末尾遇到一条异常业务编码或字符编码，夜间批次也要重头执行，甚至等到下一个停机窗口。

文章提出两层进度：用业务表向各部门报告完成范围，用逐条保存的旧系统主键记录表内位置。写入按旧主键选择更新或创建。数据库写入成功后再推进检查点，若两步之间发生中断，重跑这一条也可以覆盖同一记录。

该项目实际采用的是全量重跑，文中的恢复方案是事后设计。实现时可给旧主键加唯一约束，并在数据库里原子地执行更新或插入；分开检查和写入时，并发执行仍可能产生冲突。文章没有提供新方案的恢复耗时。

**阅读价值：** 复盘把重跑范围和跨部门交接放进同一设计，便于讨论恢复点应该给谁用。

### 2. モダンLinuxデスクトップをゼロから学ぶ（1）― Westonで最小限のWayland環境を動かす

**原文：** https://zenn.dev/catatsumuri/articles/903bcb16def75b

**发布时间：** 2026-11-14 09:51:29 JST

作者用一台装有 Debian 13 的 Surface Laptop 4 搭建最小图形环境。机器原来可以通过 SSH 登录，未安装 GNOME 或 KDE。安装 Weston 14.0.2 和诊断工具后，他确认有 DRM 设备以及位于 seat0 的本地登录会话。测试是在笔记本控制台启动的。

Weston 选择 DRM 后端，把输出接到 Linux DRM/KMS，不经过 X 服务器。内核提供显示输出和模式设置，Weston 负责合成各应用的画面及处理输入。原文展示了启动终端、同时打开多个 GUI 程序和移动窗口。

weston.ini 里的 keyboard 段改变 Weston 管理的键盘布局，terminal 段只影响附带的 weston-terminal。作者验证了日文键位和终端字体。不过，日语假名汉字转换需要输入法，本次未实现；这个最小环境也省略了供 X11 程序使用的 XWayland。

**阅读价值：** 用实机实验区分显示内核、窗口合成器、单个应用和输入法各自负责的功能。

### 3. Amazon Data Firehoseのコスト節約を検証

**原文：** https://zenn.dev/kkoch5t2/articles/firehose-direct-put-cost

**发布时间：** 2026-11-14 08:00:32 JST

作者用 Windows 上的 Python 和 Boto3，把合成日志经 Direct PUT 送入两个 Firehose 流。两边都向同一 S3 存储桶的不同前缀交付，缓冲统一为60秒或5 MiB，未启用压缩。每秒产生一条200字节JSON，60秒各发送60行；两端实际传输的数据量同为12,000字节。

逐行发时 Firehose 收到60个记录，每个记录向上取整到5 KiB，共计307,200计费字节。把60行拼成一个12,000字节记录时只取整一次，计15,360字节；S3 里两边仍各有60条有效且不重复的JSON。只把多条记录塞入一次 PutRecordBatch 调用，无法改变记录级的取整。

约95%的减少对应这组小日志和批次大小；日志尺寸变化后取整阶梯也会变。发送端等待凑满可以额外增加约60秒延迟，还要考虑 Firehose 交付时间。实验没有给待发内存缓冲加持久化，进程退出前尚未发送的记录需要独立的恢复设计。

**阅读价值：** 同时观察 API 调用、摄取记录与交付行数，可以明确优化究竟改变了哪一层。

### 4. nullに頼らずドメインの意味を型で表す ─ 7言語の履修モデルとC#・F#の比較

**原文：** https://zenn.dev/jtechjapan_pub/articles/decider-validation-csharp-fsharp

**发布时间：** 2026-11-14 07:55:29 JST

作者用七种语言建模课程选修，本文展开 C# 和 F# 的比较。输入先由值对象检查；随后 Decider 根据已有事件形成的状态，判断前置课程、名额或是否已开课。拒绝时不会追加事件；输入非法时连读取历史都不开始。

前置条件用 NoPrerequisite 或 PassedCourse 等分支明确表示。C# 以 closed record 限定可用分支，F# 用判别联合 DU；结果和拒绝理由也有显式类型。文章给出了76个 Given/When/Then 案例，另有直接判断、值对象复原和并发测试。

持久化是另一处差异：示例的 F# 用 JIT 路径复原 DU，C# 配合生成的 JSON 和校验代码。Native AOT 的支持边界要按作者的实际构建配置判断。文中的行数和类型表达比较不能证明某门语言普遍更快。

**阅读价值：** 同一业务规则下可以分开比较领域表达、失败位置与部署适配。

### 5. AI が読んだ日付は、印刷された曜日で検算する（給食の献立が 1 日ずれた話）

**原文：** https://zenn.dev/hiroyamayu/articles/ai-date-weekday-check

**发布时间：** 2026-11-14 08:00:05 JST

在把纸质午餐表转成数据时，Gemini 似乎跳过了9月8日空白栏，然后按顺序补日期。结果9日菜单进了8日的位置，此后一直提前一天。因为缺行此前会被系统解释成当天无餐，日期错误还会改变最终回答。

修订后，提示词要求返回印刷的 day 和 weekday，再用 Python 的日期运算核对。单行不符时记录并丢弃；不符超过两成或出现重复日期时，整份判为失败，夜间最多重读三次。作者重查已导入的七张表，只有最初发现的9月表发生偏移。

日期和星期若同时被模型改得自洽，仍可能通过；原表不印星期时也无法使用这条校验。可以按作者建议抽对月末原件，并在缺行时提示可能漏读。七张表的观察不能当作一般性准确率。

**阅读价值：** 这是一次可复核的输入校验案例，可以区分内部一致和原件一致。

## 4. 技术主题：明确处理边界和校验依据

核对系统边界时，要把逻辑单位写出来。业务表可用于报告进度，旧主键适合定位重跑；Firehose 里合并 API 调用和重组摄取记录也会得到不同结果。

测量时也应区分读取、判定和实际交付。在 Weston 上要分别确认显示输出、窗口合成和键盘配置。遇到读表错误时要回看原件，模型输出自洽也可能有偏差。

当某一步拒绝继续，需要明确可保留的结果。课程选修拒绝后不追加事件，菜单行无效时可以隔离一行，而重复日期会让整张表失败。

### 1. 当てはめる（あてはめる）｜N3

- 词性：動詞・一段・他動詞
- 含义：把具体对象代入一个框架、条件或公式。
- 搭配：条件に当てはめる / 式に値を当てはめる / 基準を事例に当てはめる
- 文章语境：作者推测模型跳过空白栏后，按位置给后续菜单套上日期。
- 例句：読み取った値を既存の判定基準に当てはめます。
- 例句含义：把读出的数值代入现有判断标准。

## C-2. IT/AI专业词汇

1. **checkpoint（チェックポイント）**：持久化记录已执行位置。 保存迁移批次的旧主键。

2. **idempotency（冪等性）**：相同操作重试后仍取得相同状态。 用固定旧主键更新或创建对应记录。

3. **DRM/KMS（ディーアールエム／ケーエムエス）**：Linux 内核的显示设备管理与显示模式设置接口。 Weston 通过它直接使用本机显示器。

4. **Direct PUT（ダイレクトプット）**：生产者直接向 Firehose 投递记录的方式。 用于两条合成日志流的对照。

5. **Decider（デサイダー）**：从状态和命令判断要发出的事件。 用于校验前置课程和名额。

6. **weekday validation（曜日照合）**：把印刷星期与日期推算的星期比较。 识别模型读表后一日偏移。
