### 1. 約9Bまでの日本語 Decision Model 13種を公開データで比べた（精度・較正・順序頑健性）

**原文：** https://zenn.dev/tatsuyaaaaaaa/articles/74ec715380cf61

**发布时间：** 2026-11-10 07:49:44 JST

把日本语工单交给判定模型，常见设计是只自动处理置信度足够高的请求。上线前需要分别知道答得对不对、概率有没有参考价值，以及选项顺序会不会改变结论。作者固定了13个小型公开模型的版本，在 S1MB-japanese-v1 和 bench_ja 上做零样本评测。S1MB 主比较留下17项，剔除的10项与 saihai-v1 模型卡公开的训练来源相关。其他模型多数未公布训练语料，因此不能将这17项视作对所有模型都无污染。

官方平均成绩的覆盖面本身就是一项结果。13种模型里仅8种有正式 Task Avg，其余5种因输入长度或选项数量限制有未完成样本。d3-flash 的0.477来自禁用 Hub 附加内核的推理路径，属于参考值。另一个实验对每道选择题最多置换5种顺序，按原始选项 ID 判断是否翻转。saihai-v1-8b 与 Nox-4B 的 Task Avg 接近，翻转率分别是0.235和0.150。置换实验排除了失败组，对部分模型的统计样本不同。

概率校准使用 S1MB 的分组切分，30%拟合温度，70%检验，避免同组样本跨集合。在该留出集上，13种模型的 ECE 和 NLL 均下降。换到 bench_ja 后情况改变，sokudan 在紧急度任务中的 ECE 从0.060升到0.480。限制在于本次评测没有业务样本、延迟或显存数据。面试可据此说明候选筛选、业务复测和人工兜底各自解决的问题。

**阅读价值：** 先用公开结果筛候选，再用业务数据确定置信度阈值和转人工范围。

### 2. AIが書いたテストでは変異の半分を検出できなかった

**原文：** https://zenn.dev/meursyphus/articles/5c2641c2bade16

**发布时间：** 2026-11-10 09:42:00 JST

要判断一条测试能不能发现故障，可以先把实现改坏一个小地方，再重跑与之相关的断言。作者在含451条测试的项目中挑了10个已有测试的模块，用 StrykerJS 生成局部变异，用 Vitest 执行对应测试。一次初测耗时1分5秒，550个变异中273个被检出，161个执行后仍通过，另116个没有覆盖到修改位置。这是所选变异体的比例，不能推导出全项目中有多少缺陷。

最直观的例子来自相对日期格式化函数 kstRelativeTime。已有11个测试调用它，六处把小于改成小于等于的变异仍然存活。区分两种比较的输入必须落在等号边界上，比如恰好48小时前。仅从源码字符串寻找标识符的测试还能被插入的测量代码干扰，作者将这类检查排除在该次运行之外。

变异测试能把代码评审从增加测试数量，推进到逐条讨论预期行为。它的局限包括外部可观察行为相同的等价变异，也包括实现和测试共享同一种错误理解。项目可从改动附近的计算和分支入手，把业务认可的预期值写进测试，并将未覆盖与已执行但不敏感分开处理。

**阅读价值：** 用能区分两种行为的具体输入讨论断言价值，避免只展示覆盖率。

### 3. サーバーが速くても Next.js の画面遷移が遅く感じる理由

**原文：** https://zenn.dev/meursyphus/articles/aea1056a619236

**发布时间：** 2026-11-10 09:39:44 JST

用户点击链接后界面停顿，先应判断浏览器在等哪一类资源。App Router 的 JavaScript 即便已到本地，仍可能缺少下一个页面的 React Server Components 输出。这个 RSC 载荷含服务端组件树的序列化结果、客户端组件引用和所需属性。首个必要载荷如果点击后才开始下载，服务器再快也省不掉往返。

文章把旧式路由预取与共享壳分开讲。常规生产环境中，Link 进入视口时可预取；静态路由默认拿整页，动态路由则在存在 loading.js 时预取到相应边界。开发服务器默认不执行自动预取，需用生产构建对照。把慢组件放入 Suspense 可以在首批响应发出后流式填入内容，但尚未到达浏览器的占位界面无法提前显示。

启用 Cache Components 后，可以让可预渲染的 App Shell 与占位内容先到，把读取请求信息的部分留在边界内。Next.js 16.3 的 partialPrefetching 让相同路由模式的链接复用壳。若在上层立即等待 URL 参数，整个页面依赖该 URL 的范围会扩大。作者在 Next.js 16.2 和 Cloudflare/OpenNext 的迁移经历中还检查了中间件与认证读取，最终更换托管后开启该功能。证据属于个案实践，没有跨应用延迟基准。

**阅读价值：** 把点击前可复用的界面与点击后才请求的数据分开测量，才能找到停顿位置。

### 4. 候補を全件Pythonで判定するAPIは、判定に使う列だけ読み、返す行だけORMで取り直す

**原文：** https://qiita.com/itaraiguma/items/6d0c1720f5abb09e8cbc

**发布时间：** 2026-11-10 08:17:21 JST

相关文章接口最多返回10篇，不意味着数据库只会读10条。DevPick 要从同主题与同类别的记录里优先挑出正式摘要，旧数据的布尔列有时缺值，必须解析摘要 JSON 才能知道质量。数据库排序若不能复现应用判定，提前截断会漏掉靠后的合格文章。主题合并之前截断还可能导致返回的主题不足。

作者用 SQLAlchemy 的列选择先取 ID、主题、日期和摘要等判定字段，结果是 Row。这样仍能读完候选，却省去了逐条构造完整 ORM 实例。选完后才按 ID 批量查询模型，并在应用中恢复选出顺序，因为数据库的 IN 查询不承诺按参数列表排序。两次读取之间删除的文章会跳过，空选择则省去二次查询。

部署后的暖态观测中，响应由每次1.0至1.9秒降到约0.12秒。31个候选、最多返回2项的回归用 InstanceEvents.load 计数，要求目标文章加入选文章最多3个实例，同时确认排在后面的正式摘要仍会胜出。两个断言分别守住资源使用和排名语义。该数据只覆盖作者的服务和部署后的局部观测，持续负载下的工作进程健康仍需观测。

**阅读价值：** 从候选行的读取成本着手，既保住原来的选出规则，也能写出可执行的回归断言。

### 5. cascadio で STEP を glTF にするときの単位・許容差・B-rep 情報（0.1.1 で確認）

**原文：** https://zenn.dev/grok_prtex/articles/cascadio-step-to-gltf

**发布时间：** 2026-11-10 09:00:07 JST

把机械设计文件放到网页预览时，先用已知尺寸的零件做验证。文章在 Debian 13、Python 3.13.5 与 cascadio 0.1.1 上转换了一块100×50×20毫米、带直径20毫米通孔的板，并额外测试了组装件。STEP 生成的 GLB 三轴尺寸为0.1、0.05和0.02米。同一板的 IGES 测试仍保留输入数值，两条路径因此得到相差1000倍的坐标尺度。

输出坐标的单位也不等于网格化阈值的单位。作者调整 tol_linear，取0.01时孔周有100段、最大弦偏差为0.0049毫米，取0.1时是32段和0.0482毫米，据此判断绝对阈值按输入模型的毫米处理。阈值提高到1.0后仍有26段，限制分段数的其他设置未定位。要比较转换精度，应同时记录输入单位、相对模式、角度设置和真实偏差。

圆孔还可以从拓扑属性核验。开启 include_brep 后，这一版将三角形对应的原始面和圆柱属性放进图元的 TM_brep_faces 扩展，而文档给出了不同位置。示例圆柱半径为0.01米。错误处理也须覆盖返回码与空字节，因为文中列出的坏输入未抛出异常。这些是有限样品与版本的实测，导入契约可用已知外寸、实际扩展字段和非空产物共同验证。

**阅读价值：** 用同一试件把缩放、离散误差和形状属性分开验证，定位看起来相似的三种异常。

## 4. 技术主题：分段度量与结果不变性

本期技术主题是让优化前后的验收对象保持一致。推荐接口可以换查询形态，但入选规则和顺序要单独验证。模型评测要保存缺测、参考推理路径和样本来源，再判断两个得分能否比较。界面切换则应跟踪完整时间线，分辨是数据尚未到达、占位尚不能显示，还是浏览器已拿到内容却还未渲染。

以日本企业内部技术知识库为例，首轮可用现有文档分类和反馈工单做基线。将模型得分按类别和人工确认结果拆开，前端记录生产构建中点击到首次反馈的耗时，后台并列检查读入列数与排序变化。使用同一批已知条件的样本对照，容易发现提速是否伴随结果漂移。

短时暖态观测适合排查，发布还需要持续流量与边界用例。几何导入同样可用已知外寸的试件卡住单位错误。团队交接时，将输入、版本、预期结果和误差限放在一起，后来的人才能在同一条件下复查。

# B. 重点总结与可用于面试的知识

### 1. 約9Bまでの日本語 Decision Model 13種を公開データで比べた（精度・較正・順序頑健性）

1. **中文：** 选择模型时把处理失败率和得分分列，保留不同模型所用样本范围。
   **日本語：** 入力上限で処理できない件を、判定の得点とは別に数える。

2. **中文：** 温度应在与生产分布相近的校准集拟合，另用独立样本复测。
   **日本語：** 本番に近い分布で温度を決め、別のデータで確かめる。

3. **中文：** 展示顺序可变化时，用选项 ID 追踪是否发生实质翻转。
   **日本語：** 選択肢の表示位置が変わっても、同じIDを選んだかを調べる。

### 1. 届く（とどく）｜N3

- 词性：動詞・五段・自動詞
- 含义：传送的物品或信息到达目的地。
- 搭配：応答が届く / 通知が届く / 端末に届く
- 文章语境：前端文章关注载荷何时到达浏览器。
- 例句：最初の応答が届いたら、読み込み中の表示を出します。
- 例句含义：第一批响应到达后，显示加载中的界面。
- 辨析：到达的信息作主语。「受け取る」从接收方的动作描述同一过程。

### 2. 通る（とおる）｜N5/N4

- 词性：動詞・五段・自動詞
- 含义：满足规定条件而通过。
- 搭配：テストが通る / 審査が通る / 申請が通る
- 文章语境：原文用测试通过来描述变异未被断言发现。
- 例句：古い実装でもテストが通るので、境界の値を検証し直します。
- 例句含义：旧实现也能通过测试，所以重新验证边界上的取值。
- 辨析：说明检查结果通过。「通す」以使某物通过的行动者为主语。参考为N4，站内归入N5/N4。

### 3. 飛ばす（とばす）｜N3

- 词性：動詞・五段・他動詞
- 含义：沿顺序处理时跳过其中一项。
- 搭配：行を飛ばす / 手順を飛ばす / 一段飛ばす
- 文章语境：原文遇到两次查询之间删除的行便跳过。
- 例句：削除された行を飛ばし、残りは選んだ順に表示します。
- 例句含义：跳过已删除的行，其余按选出顺序显示。
- 辨析：突出在处理序列里越过一个位置。「省略する」也用于简化说明或不写某段内容。

## C-2. IT/AI专业词汇

1. **ECE（期待較正誤差）**：按置信度区间汇总预测概率与实测正确程度的差异。 跨数据集使用同一温度可能令该指标上升。

2. **変異体（ミュータント）**：对原代码施加一个小变化得到的待测试版本。 修改比较边界后重跑相关测试。

3. **RSC payload（サーバーコンポーネントの出力）**：包含服务端组件输出与客户端组件引用的数据。 点击前是否拿到它影响切换时的等待。

4. **Row（クエリ結果の一行）**：只包含本次选出列值的结果行。 先用轻量行判定，入选后才构造完整对象。

5. **B-rep（境界表現）**：用曲面、边等边界定义实体的方式。 扩展字段让三角形可以关联原始圆柱面。

6. **弦のたわみ（円弧と弦の離れ）**：用直线段近似圆弧时两者的最大间距。 比较圆孔分段数变化后的几何误差。
