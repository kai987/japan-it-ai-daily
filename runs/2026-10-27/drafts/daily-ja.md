### 1. Cloudflareの製品別MCPサーバーで/sseが410 Goneになった：/mcpへの切り替えとClaude Codeでの見え方を確かめる

**原文：** https://dev.classmethod.jp/articles/cloudflare-mcp-sse-retired-mcp-migration/

**公開時刻：** 2026-10-26 23:52:04 JST

接続先の廃止を認可エラーと取り違えると、設定を直すべき場面で再試行を続けてしまいます。DevelopersIOの西村祐二氏は、Cloudflareの製品別MCPサーバーで旧経路のSSE提供が終わったことを受け、旧接続先と新接続先の応答、Claude Codeでの表示を調べています。原文が紹介する10月22日の変更は、製品別の接続先をStreamable HTTPの経路へそろえるものです。全APIを扱う統合MCPサーバーは対象外とされています。

著者は10月25日、macOS 26.6.1のarm64環境とClaude Code 2.1.300で検証しました。READMEに載る17個の製品別サーバーでは、旧接続先がすべて410 Goneでした。返されたJSONには移行先のURLがあり、Linkヘッダーにも代替先が付いています。新しい接続先へ認可なしで初期化を要求すると、docs・blog・demo-dayの3個は200、OAuthが必要な14個は401でした。401は新しい経路が応答した証拠にはなっても、認可して利用できた証拠ではありません。

Claude CodeのSSE設定では、接続一覧に410と接続失敗が出ても、本文にある移行先は表示されませんでした。同じ旧URLでもHTTP方式として登録すると、エラーのJSON本文が見えたという差があります。移行では接続先だけでなく通信方式も変更し、どの設定範囲に登録したかを確認します。チーム共有の設定ファイルにある場合も、URLと方式をそろえる必要があります。17個のうち10個は非推奨とされるため、単に新経路へ移すか、統合APIのサーバーへ移るかも別の判断です。

原文は、OAuthライブラリの1.x系が認可対象の資源を一つしか持てないことを、関連PRの設計理由として紹介しています。認可を新経路へ結び付け、既存の新経路向け認可を守るため、旧経路をリダイレクトで残す方式にはしていません。ただし著者はログインもOAuthの認可も実行しておらず、再認可の画面、以前からあるセッション、共有設定を書き換えた後の接続まで検証したわけではありません。私たちも移行を実行したのではなく、この観測範囲を読んでいます。

**読む価値：** 失敗の種類を接続方式・移行先・認可に分けて説明でき、企業のAIツール連携で設定変更後に何を確かめるかが具体的になります。

### 2. Python 3.15のTypedDictはどこまで閉じるべきか

**原文：** https://zenn.dev/techstudiolab/articles/python-315-typeddict-closed-api-boundaries

**公開時刻：** 2026-10-27 09:14:01 JST

APIから受け取る辞書と、自分たちで作る内部コマンドでは、変更できる範囲が違います。TechStudioLab氏は、Python 3.15向けのPEP 728を題材に、TypedDictをどこまで閉じるかを説明しています。従来も、辞書をその場で書いた場合の余分なキーは検出できました。しかし、必要なキーに加えて別のキーを持つ型の値を、少ないキーを求める型へ渡せる構造的な互換性は別です。辞書リテラルの検査だけを見て、未知キーがない型だと理解すると境界を誤ります。

PEP 728のclosed=Trueは、宣言していないキーを型として許さない指定です。追加のキーを認めつつ、その値を同じ型にそろえる指定がextra_itemsです。原文は文字列の追加値を許す例を示しています。両方を同時には指定できません。何も指定しない開いた型も、明示的に追加値をobject型へする指定と完全に同じではなく、書込みや代入互換性の規則が違うと説明します。

設計案では、生成側と受信側を一緒に変えられる内部コマンドを閉じ、外部APIの応答はフィールド追加を受け入れられる型にします。プラグインの追加設定のように、名前は自由でも値の型に共通の条件があるときはextra_itemsを選びます。追加キーごとに全く違う構造が必要なら、型を分けるか明示的な拡張領域を設ける方が読みやすい場合があります。外部応答から必要な値だけ取り出し、閉じた内部型へ変換する方法もあります。

ただしTypedDictは実行時の検証器ではありません。型エラーを想定した代入でも、Pythonでは通常の辞書として処理されます。原文の入力検証例では、キー集合と値の型を明示的に確かめ、boolがintのサブクラスである点にも注意しています。文中の比較コードは10月7日時点のRC版と対応するmypy・pyrightを前提にした説明で、型チェッカーの具体的な版や実行ログを並べた測定結果ではありません。型の仕様、期待する静的診断、外部入力を実際に拒否する処理を分けて読みます。

**読む価値：** PythonやAPI連携の面接で、追加フィールドへの互換性と厳密な内部契約を両立させ、型注釈に任せられない入力検証も説明できます。

### 3. PDFページ並び替えツールをpdf.jsとpdf-libの二刀流で作った話 — プレビューと編集でライブラリを分ける

**原文：** https://zenn.dev/sktt_panda/articles/pdf-reorder-pdfjs-preview-pdf-lib-rebuild

**公開時刻：** 2026-10-27 09:57:26 JST

ブラウザでPDFを並び替えるには、利用者へ見せる画像と、保存する文書の構造を別々に扱う必要があります。サクッとぱんだ氏は、自作のPDFページ並び替え・削除ツールで、サムネイルの描画をpdf.js、出力文書の編集をpdf-libへ分担しています。pdf-libにはページを画像に描く機能がなく、pdf.jsを文書の並び替え・保存のために無理に使うのでもありません。表示と編集を素直に分けた実装経験です。

プレビューはpdfjs-distのワーカーを使い、ページを縮尺0.4で描いてJPEG品質0.7にしています。等倍の画像を大量に抱えない意図ですが、この数値が最適だという計測は示されていません。出力には、保つ元ページの番号を希望順に並べた配列を渡し、copyPagesで新しいPDFへページを複製します。サムネイル画像を集め直す処理ではなく、画像やフォントを再エンコードしない構造のコピーです。

削除を別の編集手順にせず、ページを出力対象から外す操作として扱う点も特徴です。画面上ではページごとの有効・無効を切り替え、最終的に有効な元ページの番号だけを順に集めます。これにより、並び替えと除外を同じ順序リストへ落とし込めます。ドラッグ中の位置はuseRefで持ち、ドロップ時に一度だけ配列のstateを更新します。高頻度のdragoverのたびに、描画用のstateを変えない構成です。

サムネイルのBlob URLも解放が必要です。文書の交換時とアンマウント時にrevokeObjectURLを呼び、終了処理が古いページ一覧を参照しないよう、最新の一覧を別のrefで保持しています。ただし記事に性能比較やメモリ使用量の実測はありません。また画像・フォントを再圧縮しないことから、署名、フォームなど全PDF機能の保持まで保証したとは言えません。この点は本稿の検証上の注意であり、実際に扱う文書による出力確認が必要です。

**読む価値：** Reactの一時状態と描画用stateの使い分けを、ファイル編集のデータ設計、メモリ上の参照の寿命まで具体的に説明できます。

### 4. Dockerのビルドを遅くしたコミットをGrafana Tempoのトレースで見つける

**原文：** https://zenn.dev/ymotongpoo/articles/20261027-buildkit-traces-tempo

**公開時刻：** 2026-10-27 09:00:08 JST

ビルドが一回遅かった理由と、どの変更から継続的に遅くなったかは、必要な記録が違います。Grafana LabsのYoshi Yamaguchi氏は、BuildKitが出すOpenTelemetryのトレースをTempoへ集め、Gitのコミットと結び付けて調べています。Dockerfileの手順がスパンになり、BuildKitの履歴だけでも一回分を確認できます。ただし原文で使う版の既定の履歴は48時間か50回分です。使い捨てのCIでは環境ごと履歴がなくなるため、長く比べる記録の置き場を別に用意します。

確認日は10月20日で、Ubuntu 26.04.1、Docker Engine 29.0.0、buildx 0.29.1、BuildKit 0.33.1などを固定しています。ローカルでは開発用のotel-lgtmへOTLPで送り、クライアントとビルド側のスパンを一つのトレースとして見ます。コミットを示すリソース属性vcs.ref.head.revisionが付くのはbuildx側で、すべてのスパンへ付くわけではありません。Dockerfileの変更で手順名も変わるため、変更前後の総時間は構築全体のルートスパンで比べています。グラフは30秒区間の最大値で、ヒストグラムから近似する中央値とは区別しています。親トレースを渡す環境変数TRACEPARENTがあれば、構築のスパンが根にならない点にも注意が必要です。

小さなGoのHTTPサーバーを使い、著者は意図的にキャッシュマウントを外し、ソース全体のコピーを依存取得より前へ移しました。元のビルドは1.9〜2.5秒、変更後は20.3〜21.7秒です。間にはラベルだけを変えるコミットも混ぜています。トレースとコミットの対応から、単に近くにあった変更を疑うのでなく、所要時間が跳ね上がった変更と、長くなった処理を追える構成です。この測定は二つの設定を一緒に変えたデモであり、あらゆるアプリに同じ倍率の差が出るという結果ではありません。なお、グラフから外した最初の構築は、空のキャッシュから38.1秒かかっています。1.9〜2.5秒を初回のコールドビルドの時間と取り違えないことも条件です。

エージェントはmcp-grafanaでトレースを検索・比較し、キャッシュ利用とコピー順を戻しました。後から加えたラベルは残し、修正後の新しいトレースで2.31秒への回復を確認しています。作業は約3分で、約1分半は検索に新しいトレースが出るのを待つ時間でした。クラウドへ送った20回分の構築と確認用1回は、21本とも到着したと報告します。Grafana Assistantも17回の問い合わせと132秒で原因を答えましたが、時間上の順序とGitの親子関係を区別する限定を付けています。

ただしローカルのotel-lgtmは開発・デモ用で、削除すれば記録も消えます。永続化、CIからの接続、認証情報の保持先は別途設計する必要があります。ビルドとCIジョブ全体のトレースを親子につなぐ案は今後の構成として述べられ、この記事で実証された部分ではありません。原文の修正デモは、修正できたという報告だけで終わらず、新しい観測で回復を確かめる事例として読みます。

**読む価値：** CI改善を思い付きのDockerfile変更で終わらせず、保存した観測、コミット、修正後の再測定をつなげて説明できます。

### 5. 日本語の文字起こしモデル11個を無料GPUで比べたら、読み上げ1位が放送音声で8位だった

**原文：** https://zenn.dev/yukobayashi500/articles/849115a7c596f7

**公開時刻：** 2026-10-27 08:44:11 JST

読み上げ音声で良いモデルを選んでも、会議や放送で同じ結果になるとは限りません。JA Model Bench氏は、日本語を扱う公開音声認識モデル11個を無料ColabのT4で比較しています。読み上げはFLEURSの日本語650発話、約2.4時間、放送はReazonSpeechテストの先頭1,000発話です。順位表だけでなく、発話ごとの出力と95%信頼区間も公開先に載せたと説明しています。

Qwen3-ASR-1.7Bは読み上げの文字誤り率が5.36%で1位でしたが、放送は25.98%で8位でした。二つの順位の相関は0.24です。放送の最小値はreazonspeech-nemo-v2の11.00%ですが、同じコーパスで学習したモデルに有利な条件を含みます。同じコーパスを使っていない候補では、parakeet-tdt_ctc-0.6b-jaが放送11.21%、読み上げ6.37%でした。コーパス名が同じことから、テスト発話そのものの重複まで証明したという話には広げません。

測定はfp16、日本語指定、初期プロンプトなしです。原則は貪欲法で、ReazonSpeechだけ公式パッケージ既定のビームサーチを使っています。採点ではNFKC正規化後に句読点・記号・空白を除きますが、数字の読み方はそろえません。「2つ」と「二つ」は不一致なので、表記の癖もCERへ入ります。依存ライブラリがぶつかるため、各方式のランタイムは分け、合計約2時間半かかったとのことです。同一GPUでも、推論条件まで完全に同一だったという意味ではありません。

Whisperでは少数の異常出力にも注意が必要です。large-v3は88文字の正解文に対して506文字を繰り返し出し、turboにも別の繰返しがありました。一件が総誤りの22〜25%を占めます。large-v3からその一件を除くと4.58%になりましたが、これは結果を見た後の追加指標です。異常を除いた値だけを主結果へ置き換えると、実際に困る性質を隠してしまいます。

読み上げの2〜5位付近は信頼区間が重なり、細かな順位差を強く解釈しにくいと著者は述べています。用途ごとの標本、学習元、出力の暴走、採点上の正規化を一緒に見ることが大切です。ただし放送は先頭1,000件の部分集合で、実務の会議・通話・配信を網羅してはいません。自分の用途に近い音声で候補を比べる判断につなげ、私たちが11モデルを追試したという説明にはしません。

**読む価値：** 日本語AIの評価で、平均の精度、利用領域、異常な出力、採点条件を分け、順位表をそのまま導入判断にしない説明ができます。

### 2. Python 3.15のTypedDictはどこまで閉じるべきか

**面接質問：**

> 外部APIのデータ型を定義するとき、未知のキーはすべて拒否すべきですか。

**約30秒回答：**

**関連プロジェクト例：** 学習用の案：外部プロフィール応答を受け入れる型と、更新操作に渡す内部型を分ける。キー不足、型違い、未知キーを別々に入力検証し、静的解析の結果と区別して記録します。

## C-2. IT/AI専門用語

1. **Streamable HTTP（MCPのHTTP通信方式）**：MCPの要求をHTTPで扱う通信方式。 移行時はURLとクライアントの通信方式を合わせます。

2. **OAuth resource（認可を結び付ける資源）**：認可の対象になる保護された資源。 対象を新しいMCP経路へそろえる説明で、ブラウザ認可の再試験はしていません。

4. **copyPages（PDFページの構造コピー）**：選んだページを新しいPDFへ複製する操作。 保持する元ページの順序を使い、サムネイルを文書に変換しません。

5. **Blob URL（メモリ上のデータへの参照URL）**：ブラウザ内のバイナリデータを参照するURL。 文書の交換時とアンマウント時に古い参照を解除します。

9. **domain shift（音声領域の違い）**：評価に使う音声と利用する音声の性質が異なること。 読み上げとテレビ放送ではモデルの順位が変わりました。
