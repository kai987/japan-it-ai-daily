# 日本 IT/AI 日报｜2026年11月21日（第102号）

本期收录日本时间11月20日10:00至11月21日10:00公开的五篇原文。第一篇在家用电脑上检验票据识别，另外四篇通过可复查的实验，讨论追踪一次跨调用的任务、使用闲置算力、迁移写入端以及切换内部服务。

# A. 详细文字版

## 1. 今日推荐的五篇原文

### 1. 日本のレシートを自宅PCでOCRする：15構成を実レシート11枚で比べた

**原文：** https://zenn.dev/chaki/articles/4545be3475fdb4

**发布时间：** 2026-11-20 13:33:15 JST

原作者为本地费用录入挑选 OCR 方案，用含有 43 项商品的 11 张真实日本小票，对照了 15 种配置。被测方案包括日语专用 OCR、通用 OCR 和视觉语言模型。设备是一台带 AMD 集成显卡的迷你电脑，容器分配了 8 个 CPU 线程与 16 GB 内存。

YomiToku 的两遍方案先用轻量模型识别，再用普通版重读置信度低于 0.7 的文字。该组测试中，商品名称逐字吻合率为 93%，原票印刷金额被识别出来的比例为 100%，热身后平均约 1.8 秒一张。另测两张手写收据时，Qwen3-VL 4B 等视觉语言模型在手写项上表现较好。

不过，有 21 项商品集中在一张票上，全样本的分数很容易受它影响。金额复算程序贴合 YomiToku 的输出，横向结果也受后处理差异影响。作者将其列为非商用选项。要给企业挑方案，还需把候选版本的授权、票据格式与人工复核成本纳入比较。

**推荐理由：** 同一篇实测同时公开了按字段的准确率、速度与样本分布，有助于排查模型跑分与业务验收不一致的原因。

### 2. AWS Lambda durable functions の OpenTelemetry サポートを試してみた

**原文：** https://dev.classmethod.jp/articles/lambda-durable-functions-opentelemetry-tracing/

**发布时间：** 2026-11-21 03:43:50 JST

作者在东京用 Python 3.13 和 ADOT 层观察 durable functions 的执行。一个父函数任务因等待、回调和子任务等环节分成五次 Lambda 调用，CloudWatch Logs 中仍可用同一个 trace ID 串起来。这样可以沿任务进度查找各段，而不必按单次调用手工拼时间线。

在刻意失败一次的步骤中，可以分别定位失败与成功的 Attempt span，步骤自身还包含约五秒重试间隔。另一段试验比较了两种视图。执行视图将五秒等待画作一段，调用视图则将开始和完成分别挂在执行它们的 Lambda 调用下。

本次实验使用固定 SDK 版本、东京的 ADOT 层和已有的追踪记录设置。实际发生的重试间隔受这次采用的默认策略约束，也要结合等待发生的位置解释。为其他函数配置采集时，需要单独核对相应区域可用的层版本、日志接收配置与实际采集结果。

**推荐理由：** 可用同一条任务样本练习辨认调用、步骤和重试之间的关系，再决定应在哪个层级设置告警。

### 3. Amazon EMR Serverless の新機能「Flex execution」を試してみた

**原文：** https://dev.classmethod.jp/articles/amazon-emr-serverless-flex-execution/

**发布时间：** 2026-11-21 03:36:31 JST

弹性执行把 Spark 的执行器放在闲置计算容量上，仍用 Standard 工作者承载驱动程序。原文在东京的 EMR Serverless 7.14.0 应用里，两次提交相同的 PySpark 聚合程序。程序自行生成 2,000 万行，避免外部输入影响这次对照。

两种执行都返回 1 万个键及相同的合计结果。此次并行各运行一次，Standard 约 54 秒，Flex 约 68 秒，记录的 vCPU 用量分别为 0.267 和 0.276 小时。接口给出的用量是该作业各类工作者的总和，缺乏单独按费率拆算的明细。

但这组执行时间和资源量无法证明生产账单能省多少。Flex 可用于 Spark 批作业，有单独配额，Spark 流式任务不在适用范围内。提交后 20 分钟若仍没有执行器加入驱动程序，作业会失败，需由运维方决定用原设置重试还是改用 Standard。

**推荐理由：** 文章同时给出了作业实际输出、运行资源与失败条件，便于判断哪些延迟可以纳入成本优化。

### 4. [アップデート] Amazon S3 Tables のレプリカを書き込み可能なテーブルに昇格できるようになったので試してみた

**原文：** https://dev.classmethod.jp/articles/20261120-amazon-s3-tables-replication-writable-tables/

**发布时间：** 2026-11-21 02:12:58 JST

S3 Tables 的只读副本现在可以解除复制关系，直接成为可写表。实测将东京表复制到大阪，再以 Athena 验证连接。解除关联后，原来的 ARN、命名空间和表名得到保留，所以改接大阪目录后可以沿用已有 SQL。

切换前应暂停旧位置的写入，等到副本处理完最后一次更新，再把 lastSuccessfulReplicatedUpdate 的 metadataLocation 与源表现值对齐。原文的一次大阪写入在解除关联约 17 秒后成功，随后的东京新行没有再同步到大阪。

这次验证没有执行向东京的反向复制。原关联无法恢复，两个位置继续各写各的就可能出现分叉。解除关联后有时会短暂返回 403，目标区的查询权限也可能单独出错，因此要保留试写与试读两类结果。

**推荐理由：** 它把故障切换中最容易遗漏的工作落到了具体检查项，包括最后一次元数据同步、目标权限以及回切的前提。

### 5. Amazon Route 53 の Private Endpoint Health Checks を試してみた

**原文：** https://dev.classmethod.jp/articles/route53-private-endpoint-health-checks/

**发布时间：** 2026-11-20 23:02:33 JST

Route 53 的新机制允许把 VPC 内的端点可达性用于 DNS 故障切换。作者在东京配置两个内部 ALB，使主端的别名记录关联 HTTPS 健康检查。这里的检查每 30 秒执行一次，以连续失败 3 次为阈值。

阻断检查到主端的通信约 90 秒后，test-dns-answer 返回备用端地址；VPC 内实际发请求的 Lambda 约 135 秒后才读到备用端正文。恢复时也出现了两种观测相差约 45 秒的情况。测量操作每隔约四到五秒进行一次。

这两个结果只适用于本次网络配置和观测方法。服务仍需结合用户侧的名称解析和应用行为来定义恢复时间。文章按最低三个可用区和 30 天计算，检查来源的费用约为 270 美元，此外还要考虑独立的检查费用。

**推荐理由：** 同时测 DNS 与业务响应可以发现监控已切换、调用方仍未恢复的间隔，为验收条件提供具体依据。

## 4. 今日技术主题

### 恢复是否完成，取决于在哪一层测量

两个内部负载均衡器的测试给出了具体例子。DNS 侧看到答复变更后，VPC 内的请求仍需几十秒才收到备用端正文。定义恢复时间时，可以先约定由谁发请求、需要拿到什么结果，再同时记录控制面和客户端的数据。表的跨区迁移同样需要在目标区实测查询与写入，光看复制状态不足以决定切换。

在票据录入中，可以把识别出的金额与小计、税金和总额做校验，无法确认时再交给人复核。这里的两遍识别和手写对照还说明，印刷长票与少量手写字段值得单独取样。凡是采用日本门店票据的数据集，都要记录每家店的占比、拍摄质量和任务要交付的字段。

批作业按完成期限安排算力，长任务按等待原因衡量耗时。东京的 Spark 样本是一组并行运行，东京到大阪的是一次单向表迁移。将方法用于团队项目时，可以先确定可重复的输入和可测的完成条件，再重复跑并保留失败记录。这样既能核对实验预期，也能查到造成额外等待的位置。

1. **中文：** 解除前以源端当前元数据核对目标端最后复制的版本。
   **日本語：** 複製完了の状態表示と最終メタデータの一致を確認してから切り離します。

### 1. 合計（ごうけい）｜N3

- 词性：名詞・サ変動詞
- 含义：把多笔数字相加得到总数，也可指进行相加。
- 搭配：合計を出す / 合計金額 / 費用を合計する
- 文章语境：原文将小票总额是否识别正确，与依品目复算能否通过分别计分。
- 例句：読み取った金額を合計して、レシートに印字された額と比べます。
- 例句含义：将识别出的金额相加，再和小票上印的金额核对。
- 辨析：「集計」还包括分类汇总和计数，「合計」突出加总。

### 2. 対話（たいわ）｜N1

- 词性：名詞・サ変動詞
- 含义：交换信息，并根据对方的回应继续进行。
- 搭配：対話を続ける / 対話の場 / 対話セッション
- 文章语境：原文说 Flex 不支持可在连接中一边执行一边查看响应的交互会话。
- 例句：対話セッションでは前の実行結果を見ながら、次の処理をその場で選べます。
- 例句含义：在交互会话中，可以看着上一条执行结果，当场选下一步操作。
- 辨析：「会話」常指日常交谈，「対話」突出回应往来，也可说人与系统的交互。

### 3. 停止（ていし）｜N2

- 词性：名詞・サ変動詞
- 含义：正在运行的服务、进程或动作停下，或让它停下。
- 搭配：書き込みを停止する / 一時停止 / 処理を停止する
- 文章语境：解除副本关联后，来自旧源表的复制处理随即停止。
- 例句：切り替えの直前に書き込みを停止し、コピーの完了を待ちます。
- 例句含义：切换前先停写，再等复制完成。
- 辨析：「中止」可指打消原定计划。「停止」着眼于正在运转的过程停下来，能否恢复取决于语境。
