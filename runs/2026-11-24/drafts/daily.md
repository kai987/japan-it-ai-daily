# 日本 IT/AI 日报｜2026年11月24日（第105号）

本期覆盖日本时间 11 月 23 日 10:00 至 11 月 24 日 10:00 内发布的五篇文章。读完可以拿来讨论三个容易混淆的状态：用户刚刚确认的条件、系统已经收到的指令，以及系统最终完成的处理。

# A. 详细文字版

## 1. 今日推荐的五篇原文

### 1. [アップデート] Amazon Bedrock AgentCore Memoryでセッション全体の要約が作られるようになりました！

**原文：** https://dev.classmethod.jp/articles/agentcore-memory-full-session-summary/

**发布时间：** 2026-11-24 08:29:03 JST

AgentCore Memory 的同一套摘要策略现在会保存两种长期记忆。局部摘要随对话推进陆续新增，已经产出的片段保持原样。全会话摘要则用一条可更新的记录描述当前状态。作者在弗吉尼亚北部建了只含摘要策略的 Memory，把旅行咨询按每次两轮对话分为三批发送，最后一批调整了行程和住宿预算。

头一条片段仍记录两晚三天和每晚两万日元，后续片段另行记下变更。全会话记录保留原 ID 并更新内容，既记得最初的计划，也注明最后改为三晚四天、每晚上限两万五千日元。作者通过记录类型 FULL_SESSION 筛出全会话摘要，再把这一条交给模型尝试恢复对话，模型复述出修改后的条件。

旧记录的覆盖范围仍有边界。作者查看了弗吉尼亚北部 79 个 2026 年的会话，都已有全会话摘要；俄勒冈 40 个 2025 年会话都没有。往旧会话补充对话后出现了全会话摘要，但只含新加入的交流。地区与会话年代同时变化，样本无法区分究竟是哪一项影响了结果。

**推荐理由：** 适合用来拆解代理的会话恢复，比较一次读取当前状态与按需检索片段时需要做的额外校验。

### 2. Amazon CloudWatch の PromQL でサポートされた 30 日幅のクエリを試してみた

**原文：** https://dev.classmethod.jp/articles/cloudwatch-promql-30day-query-window/

**发布时间：** 2026-11-24 00:25:45 JST

CloudWatch 面向 OpenTelemetry 指标的 PromQL 支持更长的查询。作者在东京的测试账号开启 OTel enrichment，从一个应用负载均衡器读取 AWS 指标。小时步长的区间请求覆盖 30 天，返回 721 个点。以测试中的简单查询继续拉宽区间，31 天返回 745 个点，31 天再加一秒返回 400。

查询起止时间的宽度与表达式内的回看时间各有限制。作者试到单个范围选择器可用 24 小时，25 小时即失败。做按周同期比较时，当日的 24 小时窗口加上七天偏移，使用了八天输入跨度。把结果区间收为 23 天后，这条表达式在观测到的 31 天总边界内通过。

计算 30 天的 SLO 指标时，作者把三十个 24 小时窗口按天偏移，在同一评估时刻合计 RequestCount 和负载均衡器自身的 5XX。试验得到约 99.9053% 的可用性，按 99.9% 目标计算时约剩 5.3% 错误预算。口径限于样本中的负载均衡器错误，应用自身失败和缺测是否应计入，需要由业务另行定义。

**推荐理由：** 一篇文章同时给出了输出时间轴、回看跨度与失败边界，适合面试时解释月底 SLO 计算为什么会触发查询上限。

### 3. Amazon Cognito のマルチリージョンレプリケーションで、東京のユーザープールのレプリカを大阪に作ってみた

**原文：** https://dev.classmethod.jp/articles/amazon-cognito-mrr-osaka-replica/

**发布时间：** 2026-11-24 01:45:35 JST

为了在日本境内给 Cognito 做区域冗余，作者把东京的 Essentials 用户池复制到大阪。实验先准备一对客户管理的多区域 KMS 密钥，再创建主用户池和辅助副本。副本仍为 INACTIVE 时，两处可用相同的用户池 ID，作者已经可以在大阪读取池设置和测试用户。

副本建立后，作者在东京再建一个用户和一个应用客户端。约两秒后进行的首次大阪列表查询已看到两项变更。之后作者激活副本，从大阪端点取得了测试用户的认证令牌，而 ID 令牌的签发者仍指向含东京区域代码的 URL。业务客户端需要分别验证请求路由和令牌校验配置。

这次只测了一个账户的创建、同步和显式激活，副本创建约五分钟及首次列表结果都只是观测值。INACTIVE 仅开放一部分读取和配置操作。文章没有模拟东京故障后的整体切换过程，切换用时和应用恢复指标仍需专门测量。

**推荐理由：** 用一个实测把副本同步、认证可用以及令牌签发者这三件事分别讲清楚，便于列出跨区演练检查项。

### 4. Googleが実践するSTAMP/STPAとは何か？ 私たちのSREにも使えるのか

**原文：** https://zenn.dev/maruloop/articles/7ff108e29741b5

**发布时间：** 2026-11-23 15:56:43 JST

STPA 从系统需要防止的损失出发，把有危险的状态写成约束，再画出控制方、控制指令和反馈关系。原文用一个假想的订阅续期提醒说明：两个批处理分别找出不活跃用户和下月续期者，随后求交集、发送通知。作者将同一用户和续期周期内不得重复发出通知指令写作约束。

在这套模型里，发送未完成、发送太早以及已发状态不明时重发，都是要检查的危险控制动作。原文举例，一批 100 人里面有 80 人的指令已被接收，进程随后异常退出。整批重跑可能重复通知那 80 人。如果请求在本端超时，也应先辨认平台已经受理但响应未到的情况。

建议的观察量有三份集合：预计应通知的人、实际发出指令的人、以及投递平台已受理的人。方案来自作者的假想案例，未给出生产测量。重复提醒和漏发之间怎么权衡取决于业务选择，控制模型漏掉的依赖也可能继续隐藏风险。

**推荐理由：** 把全绿的作业状态拆成可核对的名单和反馈，让设计评审能找到跨作业的漏发、误发与重发。

### 5. 伝説の「VZ Editor」を Rust + egui で現代の Linux (x86_64 / ARM64) 向けに蘇らせた話

**原文：** https://qiita.com/Tamane/items/f67fb1745ad81480f75f?utm_campaign=popular_items&utm_medium=feed&utm_source=popular_items

**发布时间：** 2026-11-23 13:14:00 JST

LZ Editor 用 Rust 和 eframe/egui 在 Linux 上实现了 VZ 风格的键盘编辑。可用 ESC 在编辑器和左右双栏文件管理之间切换，也保留菱形光标键和多缓冲区切换。作者另外做了 Markdown 编辑与预览、字体缩放和剪贴板集成。

字号从 10 到 36 点变化时，输入法候选框需要跟着插入点移动。作者按实际字体测量更新行高、行号栏宽度和光标位置，并在每帧把对应矩形反馈给 egui 的 IME 接口。应用标识也与 .desktop 文件名统一，加上 StartupWMClass 配置，以处理桌面环境将同一应用拆成两个图标的问题。

原文给出的发布构建约 5.1 MB，图标和轻量 Markdown 解析采用自有实现，GitHub Actions 打包 x86_64 和 ARM64 的 Linux 版本。体积是作者构建的结果；Markdown 语法兼容范围、输入法差异和各桌面组合的表现，仍受实现和实际环境限制。

**推荐理由：** 把键盘手感落实成焦点、字体几何和应用身份三个可以独立验证的实现细节。

## 4. 今日技术主题

### 在系统交界处核对状态

这五篇文章都需要跨过某个边界才能拿到证据。摘要里讲的是此前对话，由新的对话检查恢复结果。监控公式有查询时刻和实际读取窗口，两个跨度都要写进验收条件。区域副本读到用户与使用副本登录也要各测一次。

同样，通知批处理的运行状态只能反映进程，受理列表才能回答平台已经接到哪些指令。客户端的字号变化要把新光标位置传到 IME。写面试答案时可以明确列出输入、观察点与无法由这次实验确认的行为。

# C. 日语学习

## C-1. 新学JLPT词汇

查对全104期的416份文件，本次收录原文用法及参考等级均可确认的三个新词。已有词汇留作复习。

### 1. 軽快（けいかい）｜N1

- 词性：名詞・形容動詞
- 含义：动作流畅轻盈，做起来利落。
- 搭配：軽快な操作 / 軽快な足取り / 軽快に切り替える
- 文章语境：指按一下键就能在两种画面间切换的操作感。
- 例句：キーだけで画面を切り替えられるので、操作が軽快です。
- 例句含义：可以只用键盘切换页面，操作很轻快。
- 辨析：「軽量」说重量或体积小，「軽快」侧重动作和操作感。

### 2. 蘇る（よみがえる）｜N2

- 词性：五段自動詞
- 含义：曾消失或淡忘的事物重新出现。
- 搭配：記憶が蘇る / 伝統が蘇る / 昔の道具を蘇らせる
- 文章语境：标题用使役形「蘇らせた」，让旧编辑器的操作在现代环境重新可用。
- 例句：古い写真を見ると、当時の記憶が蘇ります。
- 例句含义：看到老照片，当时的记忆又浮现出来。
- 辨析：「再現する」侧重重造某状态，「蘇る」带有消逝事物恢复的意味。

### 3. 慣れる（なれる）｜N5/N4

- 词性：一段自動詞
- 含义：反复接触后适应某事，做起来不再生疏。
- 搭配：操作に慣れる / 新しい環境に慣れる / 手順に慣れる
- 文章语境：作者估计小型工作坊用时，前提是组织者熟悉分析方式。
- 例句：毎週使っているうちに、新しい手順に慣れてきました。
- 例句含义：每周用一次，渐渐适应了新流程。
- 辨析：「見慣れる」专指看习惯，「慣れる」可指适应操作、环境等。

## C-2. IT/AI专业词汇

1. **FULL_SESSION（全体要約のレコード種別）**：识别归纳整个会话的长期记忆记录。 可在相同命名空间内与分段摘要区分读取。

2. **range selector（範囲セレクター）**：指定 PromQL 在每次评估时回看样本的窗口。 它不同于输出各时间点所用的查询区间。

3. **Cognito MRR（ユーザープールのマルチリージョンレプリケーション）**：把用户和设置同步到另一 AWS 区域。 文中先激活大阪副本才使用它的认证端点。

4. **Unsafe Control Action（危険な制御アクション）**：在指定对象和时序下会引入危险的控制动作或缺失动作。 用于分析过早发通知、状态不明时重发等场景。

5. **IME cursor rectangle（IMEカーソル矩形）**：把候选框定位所需的光标矩形传给输入法。 文中随显示倍率变化更新字体测量和坐标。
