### 1. SpannerのRepeatable Readによるレイテンシ改善効果と仕組み

**原文：** https://zenn.dev/google_cloud_jp/articles/b112447edb6af8

**发布时间：** 2026-11-19 08:00:06 JST

订单事务先读商品主表，再写入独立的订单表。默认 Serializable 会给普通查询取得共享锁。默认 Repeatable Read 的普通查询从同一个快照读取，纯参照的单元格不参加提交时的普通读范围核验。写入目标和 SELECT FOR UPDATE 指定的范围仍需在提交时核验。

作者用 Go SDK 从东京的虚拟机直连同区域的 Spanner。前台有 12 路任务读商品后追加订单，后台有 4 路反复更新读到的商品。前台事务的 p99 从 41.08 毫秒降至 20.09 毫秒，表明这组事务受益于减少主表上的读写互等。

换成八路并发更新 20 个商品库存后，采用 Repeatable Read 的 p99 从 34.02 毫秒上升至 65.68 毫秒，480 次试行有 80 次中断。读到一个单元格并据此写入其他单元格还可能产生写偏差。分离级别须按所需一致性和负载条件选择。

**推荐理由：** 实测同时给出减少读锁的收益和争用同一写入目标时的代价。

### 2. Nodeの重い計算でヘルスチェックが6秒止まった。worker_threadsのプールで踏んだ落とし穴

**原文：** https://zenn.dev/playpark/articles/nodejs-heavy-compute-worker-threads-pool

**发布时间：** 2026-11-19 03:58:31 JST

两个各需三秒的同步任务占住 Node.js 主线程，原本轻量的健康检查六秒才返回。只给同步函数套上 async 无法把运行转移到别处。作者用常驻的 worker_threads 池承接计算和加载开销。

池限制活跃线程数，容量满时把任务排队。异常线程会终止并按需替换。十核 Mac 的双任务实验中，用单个线程时分别在第三秒和第六秒完成，健康接口最长延迟降至 0.01 秒。

实际任务在 2 vCPU、1 GiB 的容器中运行。两项任务的完成时间从单线程的 13.2 秒降到双线程的 7.75 秒，三项以上尚无测量。传递大数组和第二个工作线程首次加载会增加费用，进程层的故障隔离也须单独评估。

**推荐理由：** 这组样本把服务是否及时响应和计算任务何时完成分开记录。

### 3. 小さな GPT で Engram を試す

**原文：** https://zenn.dev/tosshi/articles/35ef2467d84b63

**发布时间：** 2026-11-19 08:41:39 JST

Engram 用当前 token 结尾的二元、三元序列计算表地址。示例每种序列取八行，拼接成一组输入后投影出 key 和 value，比较 key 与已有隐藏状态，决定将多少 value 加回模型。

两种十二块的 GPT 模型在 WikiText-103 各训练约 2.36 亿 token，使用三组同样的种子。查表组在第 400 次更新时的验证损失低 0.20 至 0.23，LogitLens 观察到首块后就确定最终第一候选的位置占 14.5%，另一组为 4.8%。

最后的测试困惑度分别为 29.40 和 29.36。比较受参数预算限制，两组相差约 6821 万个参数，无法单独判断查表机制的贡献。测试把各位置一起处理，逐 token 解码速度也在测量范围之外。

**推荐理由：** 把查表过程、早期训练曲线及最终评估放在同一份记录里，可看清实验边界。

### 4. キーボードを開かない音声入力を作ったら、大変だったのは音声認識じゃなかった

**原文：** https://zenn.dev/susiyaki/articles/voicefloat-floating-voice-input

**发布时间：** 2026-11-19 09:30:05 JST

VoiceFloat 是 Android 输入法。没有编辑器时，TYPE_NULL 通知仍会到达。它把已识别的文句临时放在气泡里，悬浮窗保持不取焦点，等编辑器出现才提交已经确认的部分。

说话开始时保存一个 epoch 值。用户发送并让输入框变空等情况会使代数前进，迟到的识别结果如果仍带旧值就会被丢弃。Parakeet 负责本地识别，端侧可选 Gemma 4 E2B 做文字补正，固定格式处理由规则完成。

字母数字消失、问题变陈述时，应用拒绝相应补正。开发集和保留集分开后，缩短提示词在该保留集上把遗漏数由 90 降到 32。受样本限制，且作者仍无法可靠处理说话人中途改口的时刻。

**推荐理由：** 在手机输入框、语音结果和发送按钮之间，案例给出了可重现的异步顺序。

### 5. 別のサービスから移した計測が、ブログでは4日間1件も届いていなかった話

**原文：** https://zenn.dev/itaraiguma/articles/gtm-web-vitals-zero-events

**发布时间：** 2026-11-19 08:46:36 JST

作者将 Web Vitals 采集从 Next.js 迁到 WordPress 博客。前者直接载入 gtag，后者经 GTM 管理。博客的 window.gtag 未定义，让发送前的判断一直提前退出。四日内 GA4 的 web_vital 事件为零。

诊断时，作者看到普通浏览及滚动事件仍正常。修复保留原自定义指标格式，将同形命令写入 dataLayer，由现有 Google 标签处理。在实际页面上只有附加 send_to 的测量 ID 后才看到相应发送。

修正后三天范围的查询返回两条 LCP 和两条 CLS。数量足以确认事件抵达，尚不足以评价站点的性能变化。send_to 的实际表现也受该部署的接入条件限制。

**推荐理由：** 把监测验收到后台可查询的记录，能及时发现浏览器里的静默返回。

### 2. Nodeの重い計算でヘルスチェックが6秒止まった。worker_threadsのプールで踏んだ落とし穴

**约30秒回答：**

**相关项目示例：** 构造并发计算测试，把请求峰值响应、全部任务完成时间和最大内存一同记录。

**关键词：** worker_threads、事件循环、预热

## 4. 今日技术主题

### 从实际使用端定义验收

同一种技术在不同环节的收益差异很大。用事务检查业务状态，再用工作线程检查轻请求的尾延迟，能辨明性能是从哪个等待点节省下来的。

语音输入的最终去向是具体的编辑框，指标的最终去向是分析系统。可以记录队列、回调、发送和接收的结果，重放一次切换输入框或标签配置发生变化的场景。

东京区的数据库测试说明环境参数是结果的一部分。采用端侧工具或小型查表模型时，也应复现当地设备、语言输入和部署负载，注明阶段性改进与最终效果的证据。

## C-1. 新学JLPT词汇

查对全99期的396份文件，本次只收录在原文用法及参考等级均可确认的六个新词。已有词汇留作复习。

### 1. 埋まる（うまる）｜N1

- 词性：五段・自動詞
- 含义：空位或空当被占满。
- 搭配：席が埋まる / 予定が埋まる
- 文章语境：文章用咖啡馆的座位讲解锁的持有时间，先占下的座位不能再用。
- 例句：昼前に予約枠が埋まったので、午後の枠を追加しました。
- 例句含义：中午前预约名额就满了，于是增加了下午的名额。
- 辨析：「埋まる」描述空位被填满，主动填入安排则用他动词「埋める」。

### 2. 継ぎ目（つぎめ）｜N2

- 词性：名詞
- 含义：两部分衔接的地方，也可指过渡环节。
- 搭配：布の継ぎ目 / 継ぎ目が目立つ
- 文章语境：作者希望语音输入与普通键盘来回切换时没有明显的断点。
- 例句：切り替えの継ぎ目で、入力欄が一瞬空になりました。
- 例句含义：切换方式的一瞬间，输入框里的文字空了。
- 辨析：「継ぎ目」既可表示接缝，也可表示流程的衔接点。

### 3. 溜まる（たまる）｜N3

- 词性：五段・自動詞
- 含义：物品、任务或感受逐渐累积。
- 搭配：入力が溜まる / 疲れが溜まる
- 文章语境：暂时没有输入目标的语音文本先堆在气泡里。
- 例句：送信できなかった文が、下書きに少しずつ溜まりました。
- 例句含义：没能发出去的句子逐渐积存在草稿里。
- 辨析：「溜まる」描述积累的状态，刻意存起来用「溜める」。

### 4. 行き先（いきさき）｜N1

- 词性：名詞
- 含义：人或物要前往的地方，也表示传递的目的地。
- 搭配：電車の行き先 / データの行き先
- 文章语境：原文指语音识别文字还没有可写入的输入框。
- 例句：入力を確定する前に、文字の行き先を表示します。
- 例句含义：提交输入前显示文字将进入哪里。
- 辨析：除了人的去向，也可口语化描述数据的接收位置。

### 5. 先行（せんこう）｜N2

- 词性：名詞・サ変
- 含义：较早行动或在进度上走在前面。
- 搭配：開発が先行する / 先行研究
- 文章语境：查表模型在早期用更少训练更新达到同一损失。
- 例句：検証では新方式が先行しましたが、最後の成績はほぼ同じでした。
- 例句含义：验证时新方法率先改善，但最终成绩差不多。
- 辨析：「先行」常指时间或进度领先，「上位」着重排名靠前。

### 6. 割る（わる）｜N3

- 词性：五段・他動詞
- 含义：求除法的商或余数。
- 搭配：数を割る / 合計を人数で割る
- 文章语境：文章用除以素数所得余数定位表中的一行。
- 例句：番号を七で割ると、余りはゼロから六までのどれかになります。
- 例句含义：编号除以七，余数一定在零到六之间。
- 辨析：「七で」表示除数。同一个动词也能表示打碎玻璃，计算语境下是相除。

## C-2. IT/AI专业词汇

1. **Snapshot isolation（スナップショット分離）**：让事务的普通读取基于一致的时间点。 提交时仍会按规则核验存在冲突的写入。

2. **Worker thread pool（ワーカースレッドプール）**：复用有限数量的工作线程来接收计算任务。 池的并行上限决定何时排队。

3. **LogitLens（途中層の予測の読み出し）**：把中间层的隐藏状态映射到输出候选，用以观察排序。 文章统计预测第一名何时稳定。

4. **Input epoch（入力状態の世代番号）**：用状态代数核对异步结果是否属于同一段编辑会话。 发送后到达的旧发话结果可据此拦截。

5. **dataLayer（タグにデータや命令を渡す配列）**：网页向标签交付事件、参数或命令的队列。 写入命令后还要核对后台是否收到。
