# A. 详细文字版

今天围绕成功任务成本、评审分流、MCP 网关、Claude 供给路径和 OS 代理，区分功能说明、实际验证与作者建议。

## 1. 今日最值得看的 5 篇

### ① 「安いモデルで3回やり直し」と「高いモデルで一発完了」　コストが低いのはどっち？：従来の評価基準は通用しない　OpenAIが提唱するAI時代のROI算定法

**来源：＠IT**

**原文：** https://atmarkit.itmedia.co.jp/ait/articles/2609/01/news018.html

＠IT 介绍 OpenAI 七月提出的 AI 投资评价框架：从 seat 数和活跃人数转向真正完成的工作。便宜模型若需多次重跑和人工纠错，可能比高单价模型一次完成更贵；标题的三次对一次不是已报告的具体实验。

先固定一个流程的质量和完成条件，再把模型、计算、人力确认、修正和失败重试费用加总，除以合格成功任务数。失败成本不能丢掉，否则会低估不可靠方案；高价也不保证在所有任务上更划算。

四个问题是完成多少有用工作、单成功任务总成本、可靠程度、扩量后价值是否改善。可靠性分直接可用、需修正、需人工接手三类，便于看到监督负担。轻重模型分工是选项，需在同一质量标准下比较。

持续追踪同一业务的成功量、总费和单价，确认成果增长快于费用；代理开始实际操作前还要明确访问、修改和审批条件。限制是框架论述，没有企业普遍收益率试验。面试可以先定义“完成”，再解释为何不以 token 单价选模型。

**关注点：★★★★★**

可以把模型选择落到合格任务总成本。

### ② 実装が AI に移ったあと、レビューで人間に残る判断は何か - 読む対象をコードから AI の判断へ移した記録

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/pr-review-judgment-left-after-ai/

作者重数四个月69份评审记录、64个 PR，其中36份即52%无重大问题，仍写了98,546字解释为什么没问题。样本是单项目记录，未测量评审耗时，因此不能编成节省工时比例。

新 skill 把结果分为需人判断、可暂不看、未确认。证据分执行日志、全量搜索、文档、变更后代码结构、仅凭印象；最后一档留未确认。即使事实有 path:line 或完整计数支撑，也不代表风险已可接受，尤其不能把“确定没有测试”当作无需审核。

历史搜索围绕目的、为什么现在需要、未采纳选项及既有方针，找到带来源答案即可结束；额外上限是12次搜索获取、8份新文档、5个历史 PR。未解项变成明确问题。执行命令另用核准清单，不能直接跑 CI run，也不能凭 get/describe 判安全；清单是实验后补入的设计。

对一个六文件、+198/-18行 PR 做三种输出比较，需判断4/3/2项、暂不看27/20/17项。但 commit 范围、skill 和人工修改不同，不是严格受控试验；第三组未确认0只是没有该栏目。给错资料会让 AI 跟着改错结论，只有实际读取 AWS 条件发现配置差异。

仍有把测试缺失误归无需看、自己报的数量与实际条目不符等问题。限制为单仓两 PR、调整中方法，不能宣称自动放行或已量化降时。面试应说明怎么把必要判断、依据和未验证内容呈现清楚。

**关注点：★★★★★**

可具体说明评审分流而不是泛谈 AI Code Review。

### ③ MCP Gatewayとは何か？業務システムのデータをAIに聞く入口としてOSSのContextForgeを触ってみた

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/what-is-mcp-gateway-trying-contextforge/

MCP Gateway 将散在各客户端和业务系统间的认证、审计、限流集中到入口。REST 转 MCP 本身用 wrapper 也能完成，区别在共通治理；若保留绕过入口的直连，那部分不会自动受控制。

作者固定 ContextForge v1.0.8，以单容器、SQLite、两 worker 验证，用无认证 SampleAPIs coffee/hot 代替公司 API。启动检查 JWT/加密 secret 强度，手工开启默认关闭的管理 UI/API，并首次改密码。客户端到网关的 JWT 与网关到后端的凭据是两层。

发出带到期日及 tools.read/tools.execute 的 token，注册 REST GET，归入 virtual server。underscore 会规范化成 hyphen，调用名必须核对。云端 remote connector 无法访问本机 localhost，因此采用本地 stdio 经 mcp-remote 桥到 HTTP。UI 返回 isError false 和咖啡列表。

Metrics 看到了次数、成功率与平均响应；Audit Logs 因未启用仍为零，OTel 默认也关闭。缓存、限流和插件是能力说明，不能说作者已测试所有治理路径。限制为 HTTP 单机 SQLite，未验证 TLS、冗余和扩展；面试应分清两层认证及哪些日志真正启用。

**关注点：★★★★★**

能讲清网关不等于所有治理自动开启。

### ④ Claudeの利用経路について整理してみた

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/slug-claude-aws-bedrock-marketplace/

原文按八月公开资料区分 Bedrock、Claude Platform on AWS、直接契约三种服务，以及横跨服务的 Marketplace 合同计费层。AWS 收钱不等于 AWS 处理推理，Platform 由 Anthropic 运行；PrivateLink 是连接方式，不会改变数据处理主体。

功能必须按 endpoint 与 model 组合核对。runtime 的 Converse/InvokeModel 不同于 mantle Messages 兼容；缺兼容 count_tokens 不能写成无独立 CountTokens。Platform 不支持特定 computer/browser toolset 也不代表所有旧 beta computer use 都被禁用。

费用包括地域差、batch 支持、cache 读写、tokenizer、CCU 换算及个别报价。原文列 Sonnet 5 直 API 输入2/输出10美元维持、Bedrock batch 未列该模型、部分地域端点10%差，但明确未确认所有路径同价。这些是历史条件，不能作为当前统一报价。

Platform 从 Start tier 开始、不自动升级，需找担当提高。文章所列月500美元 tier cap 与用户自设 spend limit 不同；原文后者文档矛盾未解决。此次[官方复核](https://platform.claude.com/docs/en/build-with-claude/claude-platform-on-aws#spend-limits)已经说明可设组织/workspace 上限，故不保留“不能设置”的结论。用量统计有延迟，超出部分仍可能收费。

旧 private offer 不自动转移，批准前费用无追溯折扣，API 与 seat 订阅也需分开。限制是机上资料整理，未实机验证，认证范围与模型清单都需按实际组合确认。面试可讲处理主体、功能和有效成本三轴，而不是只按账单品牌判断。

**关注点：★★★★★**

可明确解释为何同样 AWS 账单仍有不同处理边界。

### ⑤ DHH氏が開発するLinux OS「Omarchy Quattro」リリース。AIエージェントとをOSと統合、スキルによりAIエージェントがOSの設定や操作、プラグイン作成まで支援

**来源：Publickey**

**原文：** https://www.publickey1.jp/blog/26/dhhlinux_osomarchy_quattroaiosaios.html

Publickey 九月一日报道 Omarchy4.0 Quattro，引用的发布消息在八月十四日，不能把新闻日期当发布日。系统以 Arch Linux、Hyprland、Quickshell 为基础，由 DHH 预选工具及外观。原文 Hyperland 拼写调整为实际名称 Hyprland。

Claude、Codex、Copilot 等代理读取 Omarchy skill，可解释快捷键、安装应用、改配置、主题和生成 Quickshell 插件，示例包括番茄钟及 XP 风主题。不是宣称 OS 内含模型或所有推理离线运行。

崩溃后读日志并提供修复建议也在介绍范围，但无所有故障自动修复率。键盘、shell、平铺窗口为主，文章推测主要用户是开发运维人员。修改方便仍需和可恢复性分开评估。

Windows dual boot、Omarchy 内 Windows VM、社区 Try Omarchy for Windows 是三件事；后者用 Windows Hypervisor Platform 与 QEMU，不能等同 WSL。限制是产品介绍而非性能、兼容性实验。面试可用备份、差分、重启后验证和回退方案说明怎样委托系统配置。

## 3. 面接で使えるポイント

### 話題1：AI ROI / LLM Cost / Evaluation

**面试问题：**

> 安いモデルと高いモデルの費用を、どう比べますか。

**约 30 秒自然日语回答：**

> 品質を満たした仕事一件の総費用で比べます。記事は、推論料金に確認や修正、再実行の人件費を加え、成功件数で割る考え方です。出力も、そのまま使えるもの、修正が要るもの、人へ引き継ぐものに分けます。ただし高いモデルなら必ず一度で終わるわけではありません。同じ仕事と完了条件を決め、失敗した試行の費用も含めて、継続して比較します。

**関連Project（学習用）：** 制作单成功任务成本表。

**キーワード：** `成功タスク単価` / `手戻り` / `三つの信頼性区分`

### 話題2：AI Review / Claude Code / Human-in-the-Loop

**面试问题：**

> AIレビューで指摘が増え、人の確認が減らない場合はどうしますか。

**约 30 秒自然日语回答：**

> 指摘を、判断が必要なもの、根拠付きで解決済みのもの、未確認に分けます。記事のスキルはpathと行番号、実行ログ、全件検索の数を添え、印象だけの結論を未確認へ残します。ただし、テストがないと確認できても、それを許容する判断は人の仕事です。経緯と実環境も照合し、先に読むべき項目を絞ります。件数はAIの自己申告をそのまま信じません。

**関連Project（学習用）：** 配对 PR 未确认项与证据。

**キーワード：** `Review Triage` / `path:line` / `未確認` / `全件検索`

### 話題3：MCP / Gateway / Governance / Cost

**面试问题：**

> MCP Gatewayを置けば、認証や監査はすべて整いますか。

**约 30 秒自然日语回答：**

> 機能があることと、有効にしたことを分けます。ContextForgeの例は、クライアントのJWT認証と、業務API側の認証を二層で扱っています。実行回数は見えても、監査ログは無効だったためゼロでした。ただし検証は一コンテナとSQLiteの最小構成です。本番では接続元と権限を確認し、必要なログを有効にして、拒否した呼び出しも追えるか確かめます。

**関連Project（学習用）：** 画网关认证与日志设置。

**キーワード：** `ContextForge` / `JWT` / `Audit Logs` / `SQLite`

### 話題4：Claude / Amazon Bedrock / Compliance / Cost

**面试问题：**

> ClaudeをAWS経由で使う場合、何から利用経路を選びますか。

**约 30 秒自然日语回答：**

> 誰がデータを処理するかを見ます。BedrockはAWS、Claude Platform on AWSはAnthropicが推論を運用し、請求先が同じでも境界は異なります。モデルとAPIの組で機能も確かめます。ただし単価だけでは比較できません。キャッシュやbatchの対応、CCUへの換算、利用上限も確認します。既存の割引が移るとは考えず、適用開始を調整します。

**関連Project（学習用）：** 分列 Claude 处理方和收款方。

**キーワード：** `Data Processor` / `Marketplace` / `CCU` / `利用経路`

### 話題5：AI Agent / Developer OS / Skills

**面试问题：**

> AIにOSの設定変更を任せるとき、どのように確認しますか。

**约 30 秒自然日语回答：**

> 元の設定と変更差分を残し、戻せる状態で試します。Omarchyはスキルを通じて設定や操作を伝え、Quickshellのプラグイン作成まで支援する例があります。ただしログを読めることと、全障害を直せることは別です。テーマ変更なら表示だけでなく、キー操作や再起動後の動作も確認します。意図しない変更があれば元へ戻し、必要な範囲だけを改めて依頼します。

**関連Project（学習用）：** 记录配置修改的恢复条件。

**キーワード：** `Omarchy` / `Quickshell` / `スキル` / `設定差分`

# C. 日本語学习｜JLPT + IT日本語

例句和关联项目是围绕当天主题制作的学习材料，不是原文引文或已证实的企业案例。JLPT 等级为学习参考。

## C-1. JLPT词汇（20个）

共20词，已与全部历史收录词核对。JLPT等级为学习参考。

### 1. 成果（せいか）
**品詞：** 名詞｜**意味：** 成果、产出｜**目安：N2**  
**コロケーション：** 成果を測る / 具体的な成果 / 成果物に変える / 成果を上げる  
**文脈：** ＠IT 的 AI ROI 文章把评价重点从购买席位和 Token 消耗转向真正完成的工作与成果。  
**例：** `AIの利用回数ではなく、業務で得られた成果をKPIとして測定します。`  
**中文：** 不以 AI 使用次数，而以业务中取得的成果作为 KPI 测量。  
**ニュアンス：** 「結果」只表示结果本身；「成果」通常带有通过工作取得的有价值产出这一积极语感。

### 2. 手戻り（てもどり）
**品詞：** 名詞｜**意味：** 返工、回退后重做｜**目安：N1**  
**コロケーション：** 手戻りが発生する / 手戻りを減らす / 手戻りによるコスト / 手戻りになる  
**文脈：** ROI 文章把模型重试、人类修正和返工时间都纳入成功任务的真实总成本；Review 文章也用它描述错误判断造成的追加工作。  
**例：** `安いModelでも手戻りが多ければ、Task全体のCostは高くなります。`  
**中文：** 即使模型便宜，如果返工很多，整个任务的成本也会变高。  
**ニュアンス：** 日本软件开发现场高频词，强调已经推进的工作因为问题而退回前一步重新处理。

### 3. 経緯（けいい）
**品詞：** 名詞｜**意味：** 事情经过、背景脉络｜**目安：N1**  
**コロケーション：** 経緯を調べる / これまでの経緯 / 経緯が分からない / 経緯を共有する  
**文脈：** PR Review 实践把‘为什么现在需要这个变更、过去有哪些决定’等经纬作为判断是否继续调查的重要 Context。  
**例：** `変更の経緯が分からない場合は、PRとDecision Recordを確認します。`  
**中文：** 如果不清楚变更经过，就确认 PR 和 Decision Record。  
**ニュアンス：** 比「理由」范围更广，包含时间上的发展过程、背景与决策脉络。

### 4. 費やす（ついやす）

## C-3. JLPT语法（2项）

全历史查重后，本日保留及补充2项未在更早日期收录的语法；已介绍的语法不再当作新项目。原文中已核实的新项目不足时，不为凑满5～8项而重复收录。

### 1. ～にとらわれず
**学习参考：** N1  
**含义：** 不拘泥于……、不被……限制  
**接续：** `名詞 + にとらわれず`  
**使用说明：** 用于说明模型选择不能只盯着单价，而要看成功任务的整体经济性。  
**例句：** `Token単価だけにとらわれず、成功Task一件当たりの総CostでModelを比較します。`  
**译文：** 不拘泥于 Token 单价，而按每个成功任务的总成本比较模型。  
**辨析与注意：** 适合面试表达‘不要只看单一指标’。当天 ROI 文章明确使用了‘特定モデルの単価にとらわれず’这一逻辑。  

### 2. ～しかない
**学习参考：** N3  
**含义：** 只能……，没有其他可行选择。  
**接续：** `動詞辞書形＋しかない`  
**使用说明：** 用于说明仍须由人判断的部分，必须确认没有合适的替代办法。  
**例句：** `根拠が足りない部分は、担当者が直接確認するしかありません。`  
**译文：** 证据不足的部分，只能由负责人直接确认。  
**辨析与注意：** 不同于「一件しかない」的数量限定；这里跟动词说明选择受限。 当天Top 2原文形式：しかない。例句为学习用原创。  
**原文出处：** [Top記事](https://dev.classmethod.jp/articles/pr-review-judgment-left-after-ai/)
