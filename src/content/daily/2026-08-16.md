## A. 详细文字版

### 今日最值得看的 5 篇

1. **AGENTS.md 分层规则**：大规模 Monorepo 不应把所有规范塞进一个 Prompt。全局规则放 Root，Frontend / Backend 规则放子目录，在访问对应区域时动态加载。
2. **可验证开发**：AI 能高速生成代码，但真正可靠的是 Type Check、Compile、Lint、Test 给出的确定性反馈。
3. **Agent Guardrail**：IAM 决定 Identity 拥有什么权限，Agent Guardrail 再限制 AI 实际能够自主使用哪些 Action。
4. **Remote Control Server mode**：Agent Session 可以并行运行，但同目录并行编辑会产生冲突，因此 Worktree / Workspace Isolation 很重要。
5. **Long-horizon Evaluation**：Coding Model 的能力不应只用 HumanEval 类短题评价，还要看 Terminal Operation、Task Completion、Token Efficiency 和 Security Capability。

### 面接で使えるポイント

> 大規模なRepositoryでは、共通ルールとFrontend・Backend固有ルールを分け、現在のTaskに必要なContextだけをAgentへ与えることが重要です。

> AIが生成したコードは、型チェック、Lint、自動テストなどの決定的なFeedbackを使ってSelf-correction Loopを回すことが有効だと思います。

### 今日の技術テーマ：Agent Context Scoping

Context Scoping 的目标是控制“当前任务到底需要哪些规则”。分层 Context 可以降低 Token 消耗和规则冲突，也让团队规范跟随目录结构管理。局限是父子规则仍可能冲突，规则文件也会过时，因此应把 AGENTS.md 当作 Repository 工程规范的一部分纳入 Review。

### 面试复习卡

- `モノレポでAI Agentのルールをどう管理しますか。` → Global Rule / Directory Rule / Scope。
- `なぜType CheckがAI Codingに重要ですか。` → Machine-verifiable Feedback。
- `IAMとAgent Guardrailの違いは何ですか。` → Identity Permission vs Agent Action Boundary。

## B. 重点总结和面试可用的知识点

### AGENTS.md
**中文：** Agent 指令应按适用范围分层，减少无关 Context 和不同技术栈规则冲突。

**日本語：** AI Agentへの指示は適用範囲ごとに分け、Taskに必要なRuleだけをContextへ入れることが重要です。

### 可验证 AI Coding
**中文：** AI Coding 的核心安全网是 Compiler、Type Check、Lint、Test 等机器反馈，而不是相信一次模型输出。

**日本語：** AI Codingでは、生成速度よりも、型チェックやTestで正誤を機械的にFeedbackできることが重要です。

### AWS Guardrail
**中文：** IAM 与 Agent Guardrail 是两层控制，前者定义主体权限，后者定义 AI 自主行为范围。

**日本語：** IAM権限とAgent Guardrailを分けることで、Identityの権限とAIの実行可能範囲を別々に制御できます。

### Multi-session / Worktree
**中文：** 多 Session 并行时要隔离 Working Directory，避免文件冲突和 Context 混杂。

**日本語：** 複数Sessionを並列実行する場合、Git worktreeなどで作業環境を分離することが有効です。

### GLM-5.3
**中文：** Coding Model 应以长期任务、Terminal 与 End-to-End Agent 能力评价，而不只看短代码 Benchmark。

**日本語：** Coding Modelでは、短いCode Generationだけでなく、Long-horizon TaskやTerminal操作まで評価する必要があります。
