### 1. AWS Lambda durable functionsがPydantic AIと統合されたので試してみる

**原文：** https://dev.classmethod.jp/articles/aws_durable_execution_pydantic_ai/

**发布时间：** 2026-10-06 11:00:10 JST

文章实测 Lambda durable functions 与 Pydantic AI 的集成。AWSLambdaDurability 配合 durable_agent_handler，自动把模型和工具 I/O 保存为步骤；Agent 必须有 name，装饰器外层为 durable_execution。环境为东京区域、Python 3.13 arm64，harness 0.36.0、slim 2.51.0、SDK 2.0.1，以 Nova Lite 调用模拟天气及汇率工具。正常运行得到两次模型调用、两次工具调用；历史显示两个工具按顺序执行，而非并行。

中断实验将单次 Lambda 上限设为20秒、天气等待设为30秒；约28秒后把等待改为0。第二次调用开始早于设置完成，因此仍超时；第三次才成功，总同步等待约51秒。模型总调用仍为两次，已保存的第一次响应没有重新请求。天气工具只有一次 StepStarted，日志不能直接证明每次重执行；作者从后续超时与成功推断其重试，这与 at-least-once 规格一致。

限制在于完成之后才保存检查点：副作用已发生而保存未完成时可能重复。工具应冪等；不能容忍重复时，原文要求同时设置 AT_MOST_ONCE_PER_RETRY 与 RetryPresets.none()，单设前者不够。默认最多六次尝试和客户端重试也要避免叠加。实验为改变运行中设置使用 $LATEST，生产应固定发布版本和 SDK；工具增删、模型步骤名变化会破坏恢复映射。以上不是真实外部API、支付或可用性保证。

**阅读价值：** 能用完成记录、调用次数和副作用边界解释 Agent 恢复设计。

### 2. DGX Spark 上でリアルタイムに文字起こしや翻訳、話者分離する議事録用 Chrome 拡張機能を作る

**原文：** https://dev.classmethod.jp/articles/reona-shoki-realtime-transcription/

**发布时间：** 2026-10-06 17:47:54 JST

shoki 用 Chrome 扩展把会话标签和麦克风音频经 WebSocket 送至内网 DGX Spark。tabCapture 的流标识交给 offscreen 文档，录音与连接不依附侧面板，关闭面板仍继续。识别使用 Nemotron 话者分离与微调后的 0.6B ASR，清书及翻译交给另一台 DGX 上的 Qwen3.8-27B；本地推理与主动写入 Backlog 是不同的数据边界，不能说所有材料永远不出网络。

话者缓存 speaker_cache 跨音频块保存身份，选择0.64秒分离延迟，ASR先读560ms。更换话者、无声0.6秒或超过15秒确定片段，短于1.2秒的插话作为回应并入。相同视频前10分钟，片段从159降为69，中位长度从2.0变8.7秒；三分钟录音更新258次，约0.7秒一次，但片段结束到确定的中位延迟1.4秒。它们是作者特定材料的测量，不能混成统一实时延迟。

ASR 比较用 FLEURS 日语100句测 CER、社内80段测速度，均非流式。未微调 Nemotron 为14.3%，Whisper large-v3-turbo为3.9%；选择前者是为了流式中间结果。48句作者声音微调不代表其他说话人，在另一组55句 FLEURS 上当前清书 CER仍24.6%。清书可改错也可变成另一个意思，因此保留原始文本，写 Wiki 前可人工编辑。Slack检索实际会议记录尚待试用，不能宣称整条生产链验证完毕。

**阅读价值：** 同时练习录音生命周期、延迟指标、ASR误差与 LLM 改写边界。

### 3. 【PostgreSQL】SELECT FOR UPDATE でロック待ちを発生させて pg_locks で観測してみた

**原文：** https://dev.classmethod.jp/articles/postgresql-select-for-update-lock-waiting-pg-locks/

**发布时间：** 2026-10-06 15:00:32 JST

作者在 AL2023 的 EC2 t3.micro 上使用 PostgreSQL17.10，以 accounts 两行数据和三条连接分离实验：A持锁、B等待、C观察。A在事务内 SELECT FOR UPDATE 锁住 id=1，B对同一行同样请求后没有返回。每个连接用 pg_backend_pid()确定身份，避免把观察连接和等待连接混为一体。这是主动构造的锁冲突，而不是线上慢查询案例。

C查询 pg_locks WHERE NOT granted，看到 B 的 PID6481 在 transactionid76445 上等待 ShareLock；按相同 transactionid 查全记录，A的 PID6475持有 ExclusiveLock，granted=true。此处看到的是事务ID锁，不应仅按“行锁”字样猜待谁。A执行 COMMIT 后 B立即返回，原有等待记录消失，完成了阻塞与解除的因果对照。

本次验证的限制在于，它只证明该例的等待关系和事务结束后的解锁，没有测等待时间或吞吐，也没有制造死锁。实际排查可以据此先定位事务与会话，再查业务为何长时间不提交；不能把“还有等待”自动判为死锁，更不能不看业务就结束会话。这些是基于实验的排查建议，作者明确把死锁留为后续验证。

**阅读价值：** 适合把“查询卡住”变为可证实的等待关系，解释事务边界。

### 4. cfコマンドを使ってViteで作成したReactアプリをCloudflare Workersにデプロイする

### 5. [アップデート] Ruby アプリから Amazon Aurora のフェイルオーバーを速くする「AWS Advanced Ruby Driver Wrapper」が GA になったので使ってみた

**原文：** https://dev.classmethod.jp/articles/aws-ruby-driver-wrapper-available/

**发布时间：** 2026-10-06 12:00:38 JST

Ruby Driver Wrapper1.0.0对pg和mysql2包装，需Ruby3.3以上；ActiveRecord可用aws_postgresql或aws_mysql2适配器。作者测试Aurora PostgreSQL17.6的Writer+Reader配置，用WrapperPgConnection代替PG连接，开启failover和initial_connection，以TLS verify-full校验证书。每秒查询pg_is_in_recovery()与inet_server_addr()，主动触发集群切换，观察角色和地址，而非只看连接对象是否创建。

wrapper识别通信错误后寻找并连接新Writer，约6秒恢复；连接成功会抛FailoverSuccessError，应用仍需恢复会话状态并安全重放最后语句。该例是事务外的轮询查询，不能据此把付款或不明提交结果的事务直接重复。标准pg在一例约36.4秒恢复，作者认为等待端点DNS更新有关；另一次Reader升为Writer约10秒，显示切换模式影响很大。

结果支持“该少数场景下更快重连”，不提供多次分布或统一恢复SLA。连接类及Rails适配器迁移方便，也不消除应用重试设计、会话状态和数据一致性责任。面试应先说驱动如何找到新Writer，再说明成功例外如何处理，并明确6秒与36秒是文章观察，不是所有故障的保证。

**阅读价值：** 可练习连接恢复、SQL重试、事务副作用和单次比较的证据边界。

## 4. 技术主题：恢复之后，什么可以重试，什么必须重新核实

恢复是一条带状态的链。Agent检查点保存模型结果，事务锁要等持有者提交，驱动先找新Writer，再由应用处理成功例外与SQL。UI也有类似分层：侧面板关闭不该等于录音结束，深链接访问与站内跳转是不同入口。这是对五篇文章的设计归纳，不声称它们使用同一技术。先明确边界和保存单位，就能解释一次成功究竟证明了什么。

好处是重试可精确定位：完成且可复用的结果不用重做，尚未确定的副作用不能盲目重复。连接恢复不等于事务已提交，清书流畅不等于发言正确，部署成功不等于API与所有路径正常。验收可以分别保存执行日志、事务关系、连接角色、原识别文与最终展示。没有必要把相邻层的成功替代本层证据。

日本团队导入时，可按社内音频处理政策决定DGX的边界，明示Backlog共享前的人工确认；云端Agent则确认东京环境、固定版本与重试责任；React项目保留beta组合及路由验收，Ruby应用设置安全重放判据。原文没有日本企业普及率或统一性能统计，这些仅是根据实验提出的采用问题。实际故障、语言和利用人数仍需各团队核实。

## 5. 面试复习卡

### Q1

> 保存済みの復元と、副作用の安全な再試行はなぜ別ですか。

**回答要点：** 检查点保存前副作用可能已发生；驱动重连也不确定旧事务的提交结果。先判断冪等和安全重放条件。

### Q2

> 文字起こしの速さと清書の正しさを、どう分けて評価しますか。

**回答要点：** 中间更新、片段确定和清书各自计时；非流式CER不能替代流式验收；保留ASR原文核实语义。

### Q3

> 状態を確認するとき、比較する入口をどう選びますか。

**回答要点：** 数据库按同一transactionid对照等待与持有，再检查COMMIT后状态；SPA分别访问API和深链接，而不是只看首页。


# B. 重点总结与可迁移知识

### 1. AWS Lambda durable functionsがPydantic AIと統合されたので試してみる

**知识点1：** 自动保存的单位是模型与工具 I/O，执行历史要与实际调用次数区分。

**知识点2：** 恢复已完成步骤不等于副作用恰好发生一次；保存前失败仍可能重复。

**日本語：** 完了済みの復元は副作用の一回保証ではありません。

**知识点3：** 版本固定、直列调用和重试层级属于采用条件。

**日本語：** バージョン固定・直列実行・再試行の重なりを導入前に確かめます。

# C. 日语学习

## C-1. 新学 JLPT 词汇

全历史查重后保留14项原文有据的新词，优先N1/N2；冪等标IT/AI、軽い标N3，未升级难度或增加常见同义形式来凑20项。七个名词、四个动词、两个副词与一个形容词分别结合文章语境；例句均为独立教学例。其余由当日有据的既习复习层补充。

### 1. 冪等（べきとう）｜IT/AI

- 词性：名詞・な形容詞
- 含义：重复相同操作仍保持同样的最终效果
- 搭配：冪等な処理 / 冪等にする / 冪等性を保つ
- 文章语境：Lambda原文要求有副作用的工具保持冪等。
- 例句：冪等な処理なら、同じ要求が重なっても二重に請求しない。
- 例句译文：冪等处理可以避免同一请求重复扣费。
- 语感区别：冪等不等于“只执行一次”；操作可能多次发生而效果受控。

### 2. 清書（せいしょ）｜N2

- 词性：名詞・サ変動詞
- 含义：把草稿或粗略文字整理成正式、清楚的文本
- 搭配：清書する / 清書前の文 / 清書を見直す
- 文章语境：DGX文章用LLM整理ASR文本，保留清书前内容。
- 例句：清書した議事録も、元の発言と比べて確認する。
- 例句译文：整理后的会议记录也应与原发言比较核实。
- 语感区别：不是要约；原文明确要求不言い換え、不追加内容。

### 3. 雑音（ざつおん）｜N2

- 词性：名詞
- 含义：妨碍目标声音辨识的无关声音
- 搭配：雑音を除く / 雑音が入る / 雑音だけの区間
- 文章语境：DGX原文说明键盘和环境音可诱发伪文字。
- 例句：雑音だけの区間を、会議の発言として保存しない。
- 例句译文：不要把只有噪声的片段保存为会议发言。
- 语感区别：和小声不同；音量低并不能证明不是有效发言。

### 4. 語尾（ごび）｜N2

- 词性：名詞
- 含义：词或句子末尾的部分
- 搭配：語尾を聞く / 語尾が弱い / 語尾を落とす
- 文章语境：DGX原文的音量阈值将小声语尾误判为无声。
- 例句：語尾の小さな声を切ると、文の意味を取り違えることがある。
- 例句译文：切掉句末的小声可能误解整句意思。
- 语感区别：语尾既可指词尾变化，也可指句末语气，此处是声学分段。

### 5. 相づち（あいづち）｜N2

- 词性：名詞
- 含义：对对方发言作出的简短附和或回应
- 搭配：相づちを打つ / 短い相づち / 相づちを含める
- 文章语境：DGX分段将1.2秒未满的插话视为附和。
- 例句：短い相づちを含める設定が、長い発言の境界に影響する。
- 例句译文：并入短回应的设置会影响较长发言的边界。
- 语感区别：回应不必表示赞同；这是听话过程的互动。

### 6. 昇格（しょうかく）｜N1

- 词性：名詞・サ変動詞
- 含义：提升到更高的资格、地位或角色
- 搭配：Writerへ昇格する / 昇格の条件 / 昇格後の状態
- 文章语境：Aurora实验区分Reader升为Writer的模式。
- 例句：Readerの昇格後に、接続先が書き込み可能か確かめる。
- 例句译文：Reader提升后核实连接目标是否可写。
- 语感区别：与扩容不同，强调角色等级变化而不是资源增加。

### 7. 抜粋（ばっすい）｜N1

- 词性：名詞・サ変動詞
- 含义：从全文抽取的一部分
- 搭配：本文の抜粋 / 抜粋を載せる / 要点を抜粋する
- 文章语境：DGX原文清书提示词及skill说明只展示节选。
- 例句：抜粋だけで、文章全体の条件を読んだことにはしない。
- 例句译文：不要因看了节选就视为已读全文条件。
- 语感区别：保留原片段；摘要则用新的表达概括。

### 8. 読み上げる（よみあげる）｜N2

- 词性：下一段動詞
- 含义：把写好的内容出声读出来
- 搭配：文を読み上げる / 名前を読み上げる / 声に出して読み上げる
- 文章语境：DGX原文用作者声音读48句微调。
- 例句：用語を読み上げる練習だけでは、別の人の声まで評価できない。
- 例句译文：只练习朗读术语不能评价其他人的声音。
- 语感区别：读取数据的読み取る不同；强调发声。

### 9. 包む（つつむ）｜N2

- 词性：五段動詞
- 含义：包围、包裹；用外层结构覆盖处理
- 搭配：ハンドラを包む / 外側から包む / 紙で包む
- 文章语境：Lambda用专用装饰器包裹handler。
- 例句：専用のハンドラで包むことが、処理を保存する前提になる。
- 例句译文：专用handler包装是保存处理的前提。
- 语感区别：比喻用法不等于源码复制或合并。

### 10. 流す（ながす）｜N2

- 词性：五段動詞
- 含义：让液体、声音或数据沿着某路径连续通过
- 搭配：音声を流す / チャンクを流す / 録画を流す
- 文章语境：DGX把到达的音频块逐步送入模型。
- 例句：届いた音声を順に流すことで、途中経過を表示する。
- 例句译文：依次送入到达的音频来显示中间结果。
- 语感区别：与泄露的漏えい不同，此处是受控数据传递。

### 11. 繰り返す（くりかえす）｜N2

- 词性：五段動詞
- 含义：重复同一动作或过程
- 搭配：操作を繰り返す / 要求を繰り返す / 何度も繰り返す
- 文章语境：Lambda说明已保存模型响应无需再次调用。
- 例句：確認のたびに同じ処理を繰り返すと、負担が増える。
- 例句译文：每次确认都重复同一处理会增加负担。
- 语感区别：持续活动的継続与同一动作反复不同。

### 12. 早速（さっそく）｜N2

- 词性：副詞
- 含义：马上、立即开始
- 搭配：早速試す / 早速確認する / 早速取りかかる
- 文章语境：Lambda原文在介绍条件后说早速試してみます。
- 例句：条件を確かめてから、早速小さな例で試す。
- 例句译文：核实条件后立即用小例子试验。
- 语感区别：语气突出主动开始，不等于性能的瞬时。

### 13. ほぼ（ほぼ）｜N2

- 词性：副詞
- 含义：几乎、大体接近完整状态
- 搭配：ほぼ同じ / ほぼ終わる / ほぼ正しく分かれる
- 文章语境：DGX目测会议说话人几乎正确分离，非完整准确率。
- 例句：ほぼ正しいという観察でも、誤りの件数は別に調べたい。
- 例句译文：即使观察称几乎正确，也希望另行统计错误数。
- 语感区别：不能把ほぼ改成100%保证。

### 14. 軽い（かるい）｜N3

- 词性：い形容詞
- 含义：重量轻；负担或处理量不大
- 搭配：処理が軽い / 負担が軽い / 動作が軽い
- 文章语境：DGX原文称对21分钟录音全量分离约1秒较轻，但长会议仍增长。
- 例句：軽い処理でも、何度も全体を読むと時間が増える。
- 例句译文：轻量处理也可能因多次全量读取而增加时间。
- 语感区别：此处计算负担，不指轻微缺陷的軽微。

## C-2. IT/AI 专业词汇

1. **durable step（保存可能な実行段階）**：保存结果、可恢复的执行单位 模型和工具调用可各自保存。

2. **at-least-once（少なくとも一回）**：重复执行仍可能发生的至少一次语义 保存前的副作用需冪等。

3. **speaker_cache（話者情報のキャッシュ）**：跨音频块保存说话人状态 保持同一人的编号。

4. **CER（文字誤り率）**：以字符为单位评价识别错误的比例 离线评价与流式更新时间不同。

5. **offscreen document（画面外ドキュメント）**：Chrome扩展后台承载音频流的文档 关闭侧面板仍保持录音。

6. **transactionid lock（トランザクションIDのロック）**：以事务结束为等待对象的锁 pg_locks的ShareLock与ExclusiveLock对照。

7. **SPA fallback（SPAのフォールバック）**：深链接无对应静态资源时交给前端入口 API应先由Worker处理。

8. **FailoverSuccessError（切替成功を示す例外）**：驱动重连成功后发出的例外 成功连接仍需会话恢复和安全重放。

## C-3. 新学语法

本期新语法2项：「～ほど」与「～ようとする」，均保留原文的真实N3层级。核对56日全历史后，其他出现形式多为已学项目，不将新例句算作新语法。复习由共享learning-review按当日自然正文和原有例句的证据独立选择，不计入这2项或C-4。

### 1. ～ほど｜N3

- 含义：越是前项，后项的程度越高或越低
- 结构：形容詞普通形／動詞普通形＋ほど
- 用法：描述输入程度和结果的关联；此处先读块越短，精度越低。
- 原文形态：短いほど
- 原文依据：[短いほど途中経過が細かく出ますが、精度は下がります。](https://dev.classmethod.jp/articles/reona-shoki-realtime-transcription/)
- 独立例句：チャンクが短いほど表示は細かくなるが、正確さとの兼ね合いがある。
- 例句译文：音频块越短，显示越细，但需权衡准确度。
- 注意：区别于“につれて”的变化过程，此处强调程度相关；不独立证明因果。

### 2. ～ようとする｜N3

- 含义：尝试、正要进行某动作
- 结构：動詞意向形＋とする
- 用法：原文为尝试使用稳定版，结果发现不兼容；意图不能视为成功。
- 原文形态：使おうとしたところ
- 原文依据：[検証中に安定版のv1系を使おうとしたところ、v2 betaが必要だとエラーが出ました。](https://dev.classmethod.jp/articles/deploy-vite-react-to-cloudflare-workers-with-cf/)
- 独立例句：安定版を使おうとしたが、実行環境との互換を先に調べる必要があった。
- 例句译文：尝试使用稳定版，却需要先核实与运行环境的兼容。
- 注意：としたら是条件假设，不是动词意向形加とする的尝试。
