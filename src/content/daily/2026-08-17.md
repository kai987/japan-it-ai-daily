## A. 详细文字版

### 今日最值得看的 5 篇

1. **Secure RAG / MCP**：用户身份、Tenant ID 和权限 Filter 应从认证后的 Token 中由可信代码注入，而不是让 LLM 自己生成，否则 Prompt Injection 或 Hallucination 可能变成跨租户数据泄露。
2. **Agent Browser Runtime**：Agent Browser 不需要 Bookmark、Theme 等人类 UI，更关注启动速度、并发密度、资源占用和不可信网页输入带来的安全问题。
3. **AI Coding Traceability**：Repository 状态之外，Prompt、讨论、Decision 和 Agent 修改理由也会成为未来维护代码的重要 Context。
4. **GraphRAG**：普通 Vector RAG 擅长“某条规定是什么”，GraphRAG 更适合“这些文档整体在讨论什么、实体之间如何关联”。
5. **Specialized Router Judge**：Router 自己也可以通过 Post-training 专门优化，重点评价实际 Routing Accuracy 和业务 Workload。

### 面接で使えるポイント

> マルチテナントRAGでは、User IDをLLMに生成させず、認証済みTokenから取得し、GatewayやPolicyで決定的に検証する設計が重要です。

> 通常のRAGは局所的なFact Searchに適し、GraphRAGは複数文書にまたがるRelationshipやGlobal Themeの分析に有効です。

### 今日の技術テーマ：Secure RAG / MCP

核心原则是：**LLM 可以决定“搜什么”，但不能决定“自己是谁、自己有权看什么”。** Identity、Tenant、Permission 应由 Authentication / Policy 层确定，再通过 ACL、Metadata Filter、Interceptor 和 Policy 做 Defense in Depth。

### 面试复习卡

- `マルチテナントRAGのAccess Controlをどう設計しますか。` → JWT / ACL / Metadata Filter / Policy。
- `GraphRAGと通常RAGの違いは何ですか。` → Local Fact vs Global Relationship。
- `LLM Routerをどう評価しますか。` → Routing Accuracy / Holdout / Cost / Weak-model Success。

## B. 重点总结和面试可用的知识点

### Secure RAG / MCP
**中文：** 权限上下文必须由确定性认证系统提供，不能让 LLM 决定 Tenant 或 User Identity。

**日本語：** RAGの認可情報はLLMに任せず、認証済みIdentityとPolicyで決定的に保証する必要があります。

### Agent Browser
**中文：** Agent Browser 是专用 Runtime，优化目标是并发、轻量和安全，而不是人类交互体验。

**日本語：** Agent向けBrowserでは、UIよりも軽量性、同時実行性、Prompt Injection対策が重要です。

### Zed Delta
**中文：** AI Coding 需要保存 Prompt、讨论和 Decision History，使代码的“为什么”也可追溯。

**日本語：** AI Codingでは、CodeだけでなくPromptや議論、変更理由を残し、Decision Historyを追跡できることが重要です。

### GraphRAG
**中文：** GraphRAG 通过 Entity、Relationship、Community Summary 支持跨文档的全局问题，但 Index 成本和实体规范化更复杂。

**日本語：** GraphRAGはEntityとRelationshipを使ってGlobal Questionに対応できますが、Index CostとEntity Qualityの管理が必要です。

### Specialized Routing Judge
**中文：** Router 是独立 ML 组件，应使用真实业务 Request 和 Holdout Data 评价，而不是只看格式是否正确。

**日本語：** LLM Routerは独立したML Systemとして、実WorkloadとHoldout DataでRouting品質を評価する必要があります。
