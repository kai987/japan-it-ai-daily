### 1. 起動スクリプトが落ちても、デプロイは成功する

**原文：** https://zenn.dev/miyakona/articles/ec2-replacement-waits-for-user-data

**发布时间：** 2026-11-16 09:01:46 JST

一次 VPN 镜像升级更换了两台 EC2。内核日志显示，内存不足导致 dnf 进程中止，启动脚本停在依赖安装阶段，尚未恢复密钥与启动 WireGuard。CloudFormation 却已将栈标记为 UPDATE_COMPLETE，Elastic IP（EIP）移到新实例，旧实例被删除。作者把内核、启动脚本和栈事件串起来，定位到部署流程少了应用就绪这一条件。

作者在每台替换实例上配置 CreationPolicy，要求一次成功信号，等待设置为 PT15M。启动脚本在退出时通过 SignalResource 报告状态，EIP 关联引用对应新实例，使切换顺序受创建完成约束。配合 userDataCausesReplacement，修改初始化脚本也可走创建路径。临时交换空间和最多三次依赖安装尝试用来应对启动时的短暂压力，必要步骤继续报错时仍保留失败状态。

改造后的实际部署中，两台就绪信号先到，随后分别迁移了 EIP，作者也核对了连接配置。故意让一台在真实部署中失败的回滚路径未实测。在同一栈、启用自动回滚的前提下，若一台已切换而另一台失败，前者的 EIP 可能往返迁移，仍要预算中断时间。15 分钟是等待配置，完整部署和外部连通性仍单独检查。

**推荐理由：** 用栈事件和应用状态对照，解释何时才可迁移固定 IP。

### 2. Cloudflare Workers のテスト40項目を Node で動かす構成：D1 と R2 の代替

**原文：** https://zenn.dev/sakidori/articles/20261030-workers-test-d1-r2-fake-node

**发布时间：** 2026-11-16 06:14:48 JST

一个 Worker 承载多项小服务，共用提醒规则和视频模块。改动一处条件可能影响其他服务的写入或通知。作者用 node:test 在部署前执行 40 项检查，其中 30 项测试路由、认证和写入行为等，10 项通过浏览器验证页面与保存流程。案例中的处理程序主要是普通 TypeScript，所以作者选择了手写替代件。

D1 替代件提供 prepare 和 bind，对预先登记的 SQL 正则匹配返回行，保存实际调用的参数。测试可比较同一用户在同一天、同一时段重复提交时是否使用相同的写入键。R2 替代件观察 createMultipartUpload、uploadPart、complete 的调用，项目按 20 MB 切块上传视频，可以测试漏分片和编号。两类断言聚焦接口调用和副作用。

这个测试集无法执行真正的 SQL，也看不到部署端绑定生效的时序。作者举出的实际失误包括 R2 启用后立即部署时绑定尚不可用。索引命中需要在真实 D1 看查询计划，浏览器检查也只针对指定的 Edge 操作路径。要检查 Workers 运行时特性，可用官方测试工具起真实运行环境。

**推荐理由：** 从 D1 的实参和 R2 的分片列表出发，为测试指定可观测的结果。

### 3. Astro 5から7へ上げたら、Tailwindの1行でビルドが落ちた

**原文：** https://zenn.dev/a1221/articles/astro-7-upgrade-build-failures

**发布时间：** 2026-11-16 08:36:39 JST

作者把一个静态工具站从 Astro 5.16 升到 7.4.12。旧的内容集合配置迁到 src/content.config.ts，用 glob loader 读取，模板通过 render(entry) 渲染。为了保持已有 Markdown 插件的输出，他显式配置了 unified 处理器。布局内一个多余的 frontmatter 分隔线引出了 48 条检查错误，删去该行后得以通过。

样式故障发生在 Vite 8 的 lightningcss 压缩阶段，报错指向拼接后的 CSS。暂时取消压缩后，作者找到 Tailwind v3 在 @layer 内展开 .border 的变体，导致伪元素 file-selector-button 后接结构伪类 first-of-type。将 .border 改写为同等选择效果的 token 属性选择器 [class~='border']，可以保留匹配范围，又避免进入该 utility 的变体展开。

迁移验收比较了全部 506 页的归一化 HTML，发现同日文章的排列变化，最终用条目 id 固定同日内容的顺序。另对六个关键页面测了主题和宽度的组合，共 24 种条件。深色手机首页有 2.2% 的像素差，原因尚未核实。试升 Tailwind 4 时深色模式差异达 5% 至 20%，所以这次发布继续使用 Tailwind 3.4。

**推荐理由：** 沿生成后的 CSS 反查输入规则，再用构建产物和界面两条证据验收迁移。

### 4. 【100本ノック実測】和暦・漢数字・結合セル…日本の泥臭い業務データを最新LLM 3モデルに構造化させて見えた「現場の壁」

**原文：** https://zenn.dev/ai_nexus_jp/articles/dirty-jp-data-extraction-benchmark

**发布时间：** 2026-11-16 08:35:42 JST

这项个人基准用 100 道自制日语业务题，覆盖和历、混合汉数字金额、收件公司、错位表格和口语改量。三种模型分别根据同一结构输出。Pydantic Strict 用来检查 JSON 结构及字段类型，例如日期、明细行、确认税额和表示含糊的标记。

作者报告 300 个结果均通过结构检查，Gemini 4 Hydrogen、GPT-6.1 Sol 和 Claude Sonnet 5.5 的完全匹配率分别为 93%、90% 和 89%。尤其能说明问题的是日期区间。题目标签采用区间第一天，有的回答却因无法确定单日，把 issue_date 设为 null，并标为含糊。希望预算与已确认小计的混用也会让类型正确的结果进入不相干的字段。

样本为作者自制，分数取决于提示词、标签规则和类别构成。即使某类 20 条全对，也不能直接估计真实账单上的准确率。试用于日本业务时，可先约定期间日期的归一化、报价意向字段与转人工条件，再拿脱敏实际样本实测错误归属。

**推荐理由：** 用日期区间和预算字段说明，类型门禁通过后还要核对标注规则。

### 5. 「止まっても書き出せる」から選んだ停止検知が、高負荷の夜にワーカーを落としていた話

**原文：** https://zenn.dev/itaraiguma/articles/faulthandler-stall-watchdog-segfault

**发布时间：** 2026-11-16 07:09:42 JST

DevPick 在一台可用内存不到 1 GB 的 VPS 上跑两个 uvicorn worker，并和博客共用主机。此前为了记录停顿，代码每秒重新设置三秒的 faulthandler.dump_traceback_later 定时器。停顿导致续约停止时，C 端监视线程可以在未取得 GIL 的条件下尝试写出调用栈。

11 月 14 日晚有集中访问，50 分钟内记录了五次 SIGSEGV。作者检查留存的三个核心转储，都定位到监视线程输出其他线程栈的过程中。其解释是并发更新的执行帧可能在遍历中改变。每次崩溃又要新建工作进程并重新加载应用，作者观察到这会再占约 100 MB，容易与内存压力形成反馈。

替代方案让 Python 监视线程取得 GIL，并把每个 worker 的栈输出限制在三次。它放弃了持锁期间的即时采集，恢复后可追记停顿长度。若持锁已超出父进程的 30 秒等待，旧进程可能在记录前就被替换。原文发布时，原规模的集中负载尚未再验证。

**推荐理由：** 结合核心转储与重启开销判断，诊断采样是否加剧了服务停顿。

### 1. 起動スクリプトが落ちても、デプロイは成功する

**面试问题：**

> EC2 の起動スクリプトが終わるまで、固定 IP の移動をどう待たせますか。

**约30秒回答：**

> 今回は dnf がメモリ不足で落ちたのに、固定 IP が新しい台に移りました。そこで CreationPolicy で一台につき一件の成功通知を待たせ、EIP はその台の完了に依存させます。通知がなければ待機上限で失敗します。ただし、成功通知は起動時の確認なので、外からつながるかは切り替え後に別途確かめます。

**相关项目示例：** 做一个带固定入口的演示栈，记录初始化成功、失败与无通知时的事件顺序，再从栈外验证健康。

**关键词：** CreationPolicy、SignalResource、Elastic IP

### 2. Cloudflare Workers のテスト40項目を Node で動かす構成：D1 と R2 の代替

**面试问题：**

> 素の Node で D1 と R2 の代替を使う場合、どこまで確かめられますか。

**约30秒回答：**

> D1 の代替は、prepare と bind を受けて、登録した正規表現に合う行を返します。引数が残るので、同じ入力で書き込みのキーが変わらないかを確認できます。R2 側では uploadPart と complete の間でパートの順序を見ます。ただし、本物の SQL は実行しないので、索引の効き方は実環境で調べます。

**相关项目示例：** 在通知服务测试中捕获同一业务键的两次写入，再在真实测试库用唯一约束验证幂等。

**关键词：** node:test、D1 binding、multipart upload

### 4. 【100本ノック実測】和暦・漢数字・結合セル…日本の泥臭い業務データを最新LLM 3モデルに構造化させて見えた「現場の壁」

### 5. 「止まっても書き出せる」から選んだ停止検知が、高負荷の夜にワーカーを落としていた話

**面试问题：**

> Python の監視を GIL を取る方式に変更したのはなぜですか。

**约30秒回答：**

> 元の faulthandler は一秒ずつ予約をかけ直し、三秒止まるとスタックを出します。高負荷の夜には監視スレッドの途中で落ちた記録が三件ありました。そこで GIL を取る側へ移し、記録も三回までに絞ります。ただし、GIL が長く解放されない間は書けないので、止まっていた長さは復帰時にもログに残します。

**相关项目示例：** 在测试环境分别注入可恢复停顿与内存压力，核查监视输出比例、进程存活和复原时间。

**关键词：** faulthandler、GIL、core dump

## 4. 今日技术主题

### 怎样给发布验证定义可观察的成功条件

把同一次变更拆成可以单独观测的事件。EC2 资源创建后记录应用就绪信号，再从客户端核对连接。对 Workers 的写入，先记录确定的参数和预期副作用，之后用真实绑定验证查询语义。对于静态站，存档同一输入下的构建标识和页面，以便把模板、压缩器和浏览器差异拆开定位。

实验数据通常有适用条件。提取器的严格 schema 能早期排除结构错误，业务层还需要字段值的检查。线上诊断要给采集频率和内存留出预算，避免增加负载。用于日本项目的一个可实践起点，是给和历区间或希望预算建立标注表，并让维护者批准具体规则。只将带有部署标识、对象字节或用户可见结果的检查纳入发布结论。

## C-1. 新学JLPT词汇

核对全96期、384个历史文件后，保留七个用法和参考等级均已确认的新词。既有词汇由复习栏目提供。

### 1. 落ち着く（おちつく）｜N2

- 词性：五段・自動詞
- 含义：恢复平稳，安定下来。
- 搭配：負荷が落ち着く / 事態が落ち着く
- 文章语境：文章中等 EC2 启动时的负载缓下来，才手动再试安装。
- 例句：アクセスが落ち着いてから、残りのデータを移します。
- 例句含义：等访问量平稳下来后，再迁移剩余数据。
- 辨析：可说人恢复冷静，也可说流量或局势趋稳。

### 2. 区切る（くぎる）｜N2

- 词性：五段・他動詞
- 含义：划出界限，分段或限定时间。
- 搭配：時間を区切る / 段落で区切る
- 文章语境：给等待信号的过程设一个上限。
- 例句：作業時間を三十分で区切り、終わらなければ担当者に知らせます。
- 例句含义：把作业限定为三十分钟，未完成就通知负责人。
- 辨析：强调划出时间或结构的分界，常与「時間」「文」搭配。

### 3. 寄りかかる（よりかかる）｜N1

- 词性：五段・自動詞
- 含义：身体倚靠，亦指强烈依赖某人或某种机制。
- 搭配：壁に寄りかかる / 特定の機能に寄りかかる
- 文章语境：作者讨论代码依赖 Workers 运行时特有行为的情形。
- 例句：特定のブラウザの挙動に寄りかかると、移行の際に思わぬ手間がかかります。
- 例句含义：若依赖某个浏览器的特有行为，迁移时可能多出意料之外的工作。
- 辨析：在技术语境中是比喻性的「依赖」，助词用「に」。

### 4. はっきり（はっきり）｜N5/N4

- 词性：副詞
- 含义：清楚、明确地。
- 搭配：はっきり伝える / 違いがはっきりする
- 文章语境：原文强调替代件的检测边界很明确。
- 例句：代替で確認できる範囲を、レビューの最初にはっきり伝えます。
- 例句含义：一开始评审就说清楚替代件能验证哪些情况。
- 辨析：可以修饰说明方式，也可描述差别明朗。参考等级为 N4。

### 5. 揺れる（ゆれる）｜N5/N4

- 词性：一段・自動詞
- 含义：晃动，引申为波动、不稳定。
- 搭配：順序が揺れる / 気持ちが揺れる
- 文章语境：文章中指显示顺序可能随构建而改变。
- 例句：同じ日付の記事は識別子で並べ、表示の順序が揺れないようにします。
- 例句含义：同日文章按标识符排序，使显示顺序稳定。
- 辨析：自动态强调状态发生变化，可用于顺序或决心。参考等级为 N4。

### 6. 途絶える（とだえる）｜N2

- 词性：一段・自動詞
- 含义：原本持续的联络、流程等中断。
- 搭配：通信が途絶える / 記録が途絶える
- 文章语境：事件循环停顿时，重新设置诊断定时器的动作中断。
- 例句：通信が途絶えた時刻を記録し、復帰までの時間を測ります。
- 例句含义：记录通信中断的时刻，测量直到恢复的时间。
- 辨析：语义包含此前在持续，与只描述一次停止的「止まる」相比更强调延续性。

### 7. 残す（のこす）｜N5/N4

- 词性：五段・他動詞
- 含义：留下、保存以便之后使用。
- 搭配：証拠を残す / 経過を残す
- 文章语境：为之后定位故障保存停顿或恢复时的记录。
- 例句：測った値とそのときの条件を、後で読める形で残します。
- 例句含义：把测量值和当时条件保存成日后可读的形式。
- 辨析：在记录语境用「を」说明保留对象。参考等级为 N4。

## C-3. 新学文法

核对全96期既有语法后，原文中有两个可独立确认的新用法，分别表达每单位分配和固定时间间隔。复习另列。

### 1. ～につき｜N2

- 含义：按每个单位分配、计量。
- 接续：数量名词 ＋ につき ＋ 数量
- 用法：用于说明每份费用、人数额度、配给数等。
- 例句：作業者一人につき、一枚の入館証を用意します。
- 例句含义：为每位作业人员准备一张入馆证。
- 辨析：这里是「每人」的量化用法，区别于「工事中につき」表达原因。

原文用法 「1台につき」 [Zenn](https://zenn.dev/miyakona/articles/ec2-replacement-waits-for-user-data)

### 2. ～ごとに｜N5/N4

- 含义：每隔一定间隔执行同一动作。
- 接续：时间、距离等名词 ＋ ごとに
- 用法：用于指定重复动作的间隔。
- 例句：五分ごとに、処理待ちの件数を集計します。
- 例句含义：每五分钟统计一次待处理件数。
- 辨析：可以直接接时间名词，区别于用「时间过去」等事件从句接「たびに」。参考等级为 N4。

原文用法 「1秒ごとに」 [Zenn](https://zenn.dev/itaraiguma/articles/faulthandler-stall-watchdog-segfault)
