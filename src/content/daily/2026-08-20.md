## 4. 今日の技術テーマ

# LLMOps

LLMOps 的核心不是“保存日志”，而是 **Prompt → Trace → Evaluation → Failure Dataset → Improvement** 的闭环。Production Failure 应转化成测试资产，Prompt 应有 Versioning、Audit 和 Rollback；Trace 可能包含客户机密，因此 Data Residency、Retention、Access Control 也属于 LLMOps。

```text
Request / User
  ↓
Prompt / Model / Tool Trace
  ↓
Metrics / Cost
  ↓
Evaluation
  ↓
Continuous Improvement
```

### 优点

**第一，减少无关复杂度。** 通过把职责拆成 `Request / User` 到 `Continuous Improvement` 的明确层次，可以让模型只处理概率性判断，而把权限、验证和停止条件交给确定性系统。

**第二，更容易测量与回滚。** 每一层都能单独记录 Input / Output / Cost / Failure，出现异常时可以定位问题，而不是把所有错误都归因于“模型不够好”。

**第三，更适合团队规模化。** LLM 运维需要把请求、模型、Token、延迟、Tool Call 与业务结果放在同一可观测链路中，因此可以把个人技巧转成可复用的 Platform Rule、CI Check 或 Governance Policy。

### 局限

**系统复杂度会上升。** 多一层 Router、Policy、Sandbox、Trace 或 Evaluation 都会带来开发和维护成本，需要确认它解决的是实际风险，而不是为了“架构完整”而堆层。

**确定性 Guardrail 也可能配置错误。** Policy、Test、Metric 与 Retrieval Rule 都需要版本管理和持续校准，不能因为“不是 LLM”就默认它绝对正确。

### 日本企业落地时的注意点

1. 先明确 **Owner、Data Boundary、Permission、Approval、Audit、Rollback**，再扩大 Agent 自治范围。  
2. 把现有的 **CI/CD、SRE、Security Review、Change Management** 继续保留，不因为接入 AI 就另建一套不可追踪的旁路。  
3. 用日本企业实际关心的 **品質、工数、Cost、Security Incident、Business Outcome** 评价，而不是只统计 AI 使用次数。

面试里可以这样总结：

> Request、Model、Token、Latency、Tool Call、User OutcomeをTraceできるようにし、Costと品質を同じDashboardで確認して継続改善につなげます。

## C-3. JLPT语法

### 1. ～にとどまらず
**参考：N1**  
**中文：** 不仅限于……  
**接续：** `名詞 / 普通形 + にとどまらず`  
**使用场景：** 说明 LLMOps 不只管理 Prompt，也覆盖 Trace、Evaluation、Dataset 与 Identity。  
**例句：** `LLMOpsはPrompt管理にとどまらず、TraceやEvaluationの運用まで含みます。`  
**中文：** LLMOps 不仅限于 Prompt 管理，也包括 Trace 和 Evaluation 运维。  
**注意：** 适合范围扩展。

### 2. ～かねない
**参考：N1**  
**中文：** 有可能导致不良结果  
**接续：** `動詞ます形去ます + かねない`  
**使用场景：** 警示 Session / Agent Identity 不清晰可能造成审计和责任问题。  
**例句：** `Agent Identityを記録しないと、責任の所在が不明確になりかねません。`  
**中文：** 不记录 Agent Identity 可能导致责任归属不明确。  
**注意：** 通常用于负面风险。

### 3. ～なくしては
**参考：N1**  
**中文：** 没有……就无法……  
**接续：** `名詞 + なくしては`  
**使用场景：** 强调持续 Evaluation 与 Trace 是 LLMOps 的必要基础。  
**例句：** `Traceと継続的なEvaluationなくしては、LLM品質の改善は難しいです。`  
**中文：** 没有 Trace 和持续评估，就很难改善 LLM 质量。  
**注意：** 语气较强。

### 4. ～に応じて
**参考：N2**  
**中文：** 根据……相应调整  
**接续：** `名詞 + に応じて`  
**使用场景：** Model Routing 和 Effort Control 的典型表达。  
**例句：** `Taskの難易度に応じてModelとEffortを切り替えます。`  
**中文：** 根据任务难度切换 Model 和 Effort。  
**注意：** 强调条件与策略对应。

### 5. ～たうえで
**参考：N2**  
**中文：** 在……之后、在……基础上  
**接续：** `動詞た形 + 上で`  
**使用场景：** 先比较 Evaluation 再选择 Prompt / Model Version。  
**例句：** `複数Versionを評価したうえで、本番Promptを選択します。`  
**中文：** 评估多个版本后选择生产 Prompt。  
**注意：** 前一步是决策依据。

### 6. ～一方で
**参考：N2**  
**中文：** 另一方面……  
**接续：** `普通形 + 一方で`  
**使用场景：** 说明 Quality / Cost / Latency 的 Trade-off。  
**例句：** `高性能Modelは品質が高い一方で、CostとLatencyも大きくなります。`  
**中文：** 高性能模型质量高，但成本和延迟也更大。  
**注意：** 适合面试。

### 7. ～につれて
**参考：N2**  
**中文：** 随着……  
**接续：** `動詞辞書形 / 名詞 + につれて`  
**使用场景：** 说明 Agent 数量和 Session 数增长带来的管理复杂度。  
**例句：** `Agent数が増えるにつれて、IdentityとSession Managementも複雑になります。`
