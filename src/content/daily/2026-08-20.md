## A. 详细文字版

### 今日最值得看的 5 篇

1. **LayerX LLMOps**：Prompt Version、Trace、Evaluation Result 和 Failure Dataset 要能够关联，才能判断修改是否真的提升质量。
2. **Dynamic Model Routing**：企业 AI Platform 正将模型选择从 Application 逻辑抽离到 Gateway / Router，以 Quality、Cost、Speed 做策略化选择。
3. **Claude Code effort**：Model Selection 与 Effort Control 是不同层，前者决定模型，后者决定单次 Request 投入多少计算与 Token。
4. **Kiro Agent Focus**：Local 和 Cloud Agent Session 数量增加以后，需要统一 Control Surface、Status、Priority 与 Human Attention 管理。
5. **Agent Identity**：Agent 会根据 Context 自主决定下一步 Action，因此不能完全照搬固定 Bot 的 Service Account 风险模型。

### 面接で使えるポイント

> LLMの品質を継続的に改善するには、Prompt Version、Trace、Evaluation Result、Failure Datasetを紐付けて回帰評価できる仕組みが重要です。

> AgentごとにIdentity、Owner、Purpose、Permissionを明確にし、行動を継続的に監視できる設計が必要だと思います。

### 今日の技术主题：LLMOps

LLMOps 的核心不是“保存日志”，而是 **Prompt → Trace → Evaluation → Failure Dataset → Improvement** 的闭环。Production Failure 应转化成测试资产，Prompt 应有 Versioning、Audit 和 Rollback；Trace 可能包含客户机密，因此 Data Residency、Retention、Access Control 也属于 LLMOps。

### 面试复习卡

- `LLM品質をどう継続改善しますか。` → Trace / Evaluation / Dataset / Regression。
- `Model RoutingとEffortの違いは何ですか。` → Model Choice vs Request-level Workload。
- `Agent Identity管理で重要なことは何ですか。` → Owner / Purpose / Permission / Revocation。

## B. 重点总结和面试可用的知识点

### LayerX LLMOps
**中文：** LLMOps 要把 Prompt、Trace、Evaluation 和失败样本串成可持续改进的数据闭环。

**日本語：** LLMOpsではPrompt、Trace、Evaluation、Failure Datasetをつなげ、継続的に改善できるLoopを作ることが重要です。

### Dynamic Model Routing
**中文：** Router 负责在质量、成本和延迟之间选择模型，企业还需要 Usage、Quota 和 Spending Limit。

**日本語：** Model Routingでは品質・Cost・Latencyに応じてModelを選択し、QuotaやUsageも含めて管理します。

### Claude Code effort
**中文：** Effort 控制单次请求推理投入，不应与换模型混为一谈；长 Session 中还要考虑 Prompt Cache。

**日本語：** EffortはRequestごとの処理量を調整するParameterで、Model Selectionとは別に管理する必要があります。

### Kiro Agent Focus
**中文：** Multi-agent 环境中，Session Status、Priority 和人的注意力都是需要治理的有限资源。

**日本語：** Multi-agent環境では、Session ManagementとHuman Attentionの管理も重要な運用課題になります。

### Agent Identity
**中文：** Agent 应有独立 Identity Lifecycle，而不是长期共享人类 Credential 或通用 Bot Account。

**日本語：** AI AgentごとにIdentity、Owner、Purpose、Permissionを定義し、監視とRevocationまで含めて管理する必要があります。
