## 4. 今日の技術テーマ

# Agent-friendly Software Architecture

Agent-friendly Architecture 的核心是 **Understand → Generate → Validate → Fix**。项目应提供明确 Convention、结构化 Context、Type Safety、Test、Audit 和机器可验证规则。优点是减少探索成本和 Hallucination；局限是验证规则本身可能不完整，因此 Automated Validation 不能替代 Human Review。

```text
Requirement / Convention
  ↓
Structured Context
  ↓
Generate
  ↓
Type / Test / Audit
  ↓
Fix / Review
```

### 优点

**第一，减少无关复杂度。** 通过把职责拆成 `Requirement / Convention` 到 `Fix / Review` 的明确层次，可以让模型只处理概率性判断，而把权限、验证和停止条件交给确定性系统。

**第二，更容易测量与回滚。** 每一层都能单独记录 Input / Output / Cost / Failure，出现异常时可以定位问题，而不是把所有错误都归因于“模型不够好”。

**第三，更适合团队规模化。** 生产化不能只看 PoC，需要同时验证质量、成本、安全、可观测性与失败恢复，因此可以把个人技巧转成可复用的 Platform Rule、CI Check 或 Governance Policy。

### 局限

**系统复杂度会上升。** 多一层 Router、Policy、Sandbox、Trace 或 Evaluation 都会带来开发和维护成本，需要确认它解决的是实际风险，而不是为了“架构完整”而堆层。

**确定性 Guardrail 也可能配置错误。** Policy、Test、Metric 与 Retrieval Rule 都需要版本管理和持续校准，不能因为“不是 LLM”就默认它绝对正确。

### 日本企业落地时的注意点

1. 先明确 **Owner、Data Boundary、Permission、Approval、Audit、Rollback**，再扩大 Agent 自治范围。  
2. 把现有的 **CI/CD、SRE、Security Review、Change Management** 继续保留，不因为接入 AI 就另建一套不可追踪的旁路。  
3. 用日本企业实际关心的 **品質、工数、Cost、Security Incident、Business Outcome** 评价，而不是只统计 AI 使用次数。

面试里可以这样总结：

> PoCの成功だけで判断せず、品質、Cost、Security、Observability、Failure時のRecoveryを含めて実運用で評価します。

3. **導入判断では、適用条件とTrade-offを明確にし、実際のWorkloadで評価することが重要です。**
4. **本番運用では、変更履歴、監査性、Rollback手段まで含めて設計する必要があります。**

### 中文知识点总结

1. **核心结论：** AI 加速实现以后，QA、Requirement 和 Validation 也要前移，才能防止速度提升转化为返工增加。

### 2. ～かねない

**中文：** 有可能导致不良结果

**使用场景：** 用于警示过度权限和未经验证的 AI 输出。  
**例句：** `自動生成されたIAM Roleをそのまま使うと、過剰権限を許可しかねません。`  
**中文：** 直接使用自动生成的 IAM Role 可能会允许过度权限。  
**注意：** 通常用于负面风险。

### 3. ～なくしては
**参考：N1**  
**中文：** 没有……就无法……  
**接续：** `名詞 + なくしては`  
**使用场景：** 强调 Automated Validation 与 Human Approval 是高风险 Agent 的必要条件。  
**例句：** `自動検証とHuman Approvalなくしては、高RiskなAgent運用は難しいです。`

### 4. ～とは限らない
**参考：N2**  
**中文：** 未必……  
**接续：** `普通形 + とは限らない`

**例句：** `自動生成されたPolicyが最小権限になっているとは限りません。`  
**中文：** 自动生成的 Policy 未必符合最小权限。  
**注意：** 适合表达限制和反例。

### 5. ～に基づいて
**参考：N2**  
**中文：** 基于……  
**接续：** `名詞 + に基づいて`

**例句：** `社内Security Policyに基づいてAgentのTool Accessを制御します。`  
**中文：** 根据公司 Security Policy 控制 Agent 的 Tool Access。

**参考：N2**

### 7. ～一方で
**参考：N2**  
**中文：** 另一方面……  
**接续：** `普通形 + 一方で`
