## A. 详细文字版

### 今日最值得看的 5 篇

1. **Claude Code hooks 与 Observability**：AI Agent 不只需要“能执行”，还要记录执行了什么 Tool、何时调用 MCP、每一步返回了什么。生产环境中的 Agent 应像普通服务一样具有可观测性和审计能力。
2. **BM25 + Codex**：大型代码库中，与其让 Agent 盲目打开大量文件，不如先使用 BM25 等 Retrieval 技术筛选相关文件，再把必要 Context 交给模型。
3. **开放模型 Fine-tuning**：SageMaker AI 对开放模型的支持说明企业 AI 架构正在从单一 Cloud API 扩展为 Open Model、Fine-tuning 和托管基础设施的组合。
4. **Next.js 16.3**：AI Coding 不再只是生成组件，也开始进入性能诊断、测试、修改和验证的完整 Feedback Loop。
5. **Local Agent Model**：本地模型适合对机密信息、低延迟或长期运行任务做补充，Cloud 与 Local 的 Hybrid Architecture 会越来越常见。

### 面接で使えるポイント

> AIエージェントを本番環境で運用する場合、精度だけではなく、実行履歴や監査ログを残し、どのToolをいつ利用したか追跡できる可観測性が重要だと考えています。

> LLMのコスト削減では、安いModelへ変更するだけでなく、検索を使って必要なContextだけを渡す設計も有効だと思います。

### 今日の技術テーマ：Context Engineering

Context Engineering 的核心不是扩大 Context Window，而是让 Agent 在正确的时间获得真正相关的信息。典型流程是 **Request → Retrieval → Relevant Context → Tool / Agent → Evaluation**。它能够减少无关 Token、降低噪声并改善检索效率，但 Retrieval 也可能漏掉重要信息，因此需要实际 Evaluation。

### 面试复习卡

- `AIエージェントの可観測性とは何ですか。` → 実行履歴 / Tool Call / 監査ログ。
- `LLMの利用コストをどう削減しますか。` → Retrieval / Context削減 / Model選択。
- `Cloud LLMとLocal LLMをどう使い分けますか。` → 性能 / 機密情報 / レイテンシ / ハイブリッド構成。

## B. 重点总结和面试可用的知识点

### Claude Code Observability
**中文：** Agent 的执行轨迹、Tool Call 和 MCP Call 应该可追踪，便于故障调查、成本分析和 Security Audit。

**日本語：** AI Agentでは、Tool CallやMCP Callを記録し、実行内容を追跡できる可観測性が重要です。

### BM25 + Codex
**中文：** Retrieval 可以先缩小 Repository 范围，再让 Codex 推理，避免把无关文件塞进 Context。

**日本語：** 大規模Repositoryでは、検索で関連ファイルを絞ってからCodexへ渡すことで、ContextとToken消費を削減できます。

### Open Model / Fine-tuning
**中文：** 企业可以根据数据、安全、成本和业务需求，在闭源 API 与开放模型之间选择。

**日本語：** 企業AIでは、Cloud APIだけでなく、Open ModelやFine-tuningも要件に応じて選択できます。

### Next.js × AI Coding
**中文：** AI Coding 的价值正在从代码生成扩展到性能检测、自动测试和验证闭环。

**日本語：** AI Coding Agentはコード生成だけでなく、性能分析、Test、修正、検証まで支援する方向へ進んでいます。

### Local LLM
**中文：** Local Model 可用于需要 Privacy、低延迟或离线能力的 Agent 场景，并与 Cloud Model 组成混合架构。

**日本語：** Local LLMは機密情報や低レイテンシが重要な場面で有効で、Cloud LLMとのハイブリッド構成が現実的です。
