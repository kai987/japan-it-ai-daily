## 4. 今日の技術テーマ

# AI Agent Resource Governance

AI Agent 需要治理的不只 Token，还包括 **Context Budget、Agent Time、User / Team Budget、Human Attention 和 Approval Level**。成熟的系统应具备 Visibility、Budget、Evaluation 与 Responsibility 四层。Cost Optimization 的目标不是单纯“更便宜”，而是让成本和任务成果建立可解释关系。

```text
User / Team
  ↓
Usage Policy
  ↓
Model / Agent Session
  ↓
Cost / Resource Metering
  ↓
Budget / Outcome Review
```

### 优点

**第一，减少无关复杂度。** 通过把职责拆成 `User / Team` 到 `Budget / Outcome Review` 的明确层次，可以让模型只处理概率性判断，而把权限、验证和停止条件交给确定性系统。

**第二，更容易测量与回滚。** 每一层都能单独记录 Input / Output / Cost / Failure，出现异常时可以定位问题，而不是把所有错误都归因于“模型不够好”。

**第三，更适合团队规模化。** 组织级 AI 导入必须把 Policy、权限、审计、教育和业务 KPI 一起设计，因此可以把个人技巧转成可复用的 Platform Rule、CI Check 或 Governance Policy。

### 局限

**系统复杂度会上升。** 多一层 Router、Policy、Sandbox、Trace 或 Evaluation 都会带来开发和维护成本，需要确认它解决的是实际风险，而不是为了“架构完整”而堆层。

**确定性 Guardrail 也可能配置错误。** Policy、Test、Metric 与 Retrieval Rule 都需要版本管理和持续校准，不能因为“不是 LLM”就默认它绝对正确。

### 日本企业落地时的注意点

1. 先明确 **Owner、Data Boundary、Permission、Approval、Audit、Rollback**，再扩大 Agent 自治范围。  
2. 把现有的 **CI/CD、SRE、Security Review、Change Management** 继续保留，不因为接入 AI 就另建一套不可追踪的旁路。  
3. 用日本企业实际关心的 **品質、工数、Cost、Security Incident、Business Outcome** 评价，而不是只统计 AI 使用次数。

面试里可以这样总结：

> 個人の便利さだけでなく、共通Policy、Permission、Audit、Education、Usage Measurementを整え、最終的には業務KPIで効果を確認する必要があります。

## 5. AI Security：Human-in-the-Loopは「すべての操作を承認」ではない

### 中文知识点总结

1. **核心结论：** 不是所有动作都要人工批准，而应按失败影响、回滚难度和业务责任分级。
2. **工程判断：** 人的参与程度应根据风险、可回滚性和失败影响动态设计。
3. **生产化要点：** 安全性不能只交给 Prompt，应叠加最小权限、Runtime 强制、审计日志和必要的人类批准。
4. **面试表达：** 说明技术价值时，同时给出适用条件、Trade-off 与验证方法，比只介绍“能做什么”更完整。

1. **Human-in-the-Loopは全操作の承認ではなく、RiskやImpactに応じて人間の関与レベルを設計する考え方です。**
2. **ModelへのInstructionだけに依存せず、最小権限、Runtimeでの強制、監査ログ、必要に応じたHuman Approvalを組み合わせてDefense in Depthを設計します。**
