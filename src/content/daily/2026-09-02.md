### ① Claude Code v2.1.257: Fable 5.1追加と権限すり抜け修正まとめ

**来源：Qiita**

**原文：** https://qiita.com/picnic/items/ba95f05d2b78799f238b

v2.1.257 除 Fable 5.1 外，改变项目及 local settings 中 defaultMode bypassPermissions 的处理：和 auto 一样被忽略，用户、管理设置及启动参数是另层来源。含义是仓库配置不能自行强制跳过批准，更新后依赖该配置的自动任务可能开始等待确认。

修复覆盖复合命令 ask 漏检、插件声明路径 symlink 越界、Read/Edit deny 对重定向及读取命令遗漏、shell 条件差异、尾点域名、Remote Control 拒绝误算同意。[官方履历](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)支持这些改动，但未确认原文统称 critical 的官方分级或 CVSS，故不保留为统一严重等级，也不编造受害规模。

auto 的 Containment Escape 对环境未显式认定的云凭据获取、出网规避和跨租户操作不再自动批准；首次目录外读取提示与完全阻止读取选项不同。管理 deny 重载、第三方凭据误发、长 thinking 断线等也分别修复。

Fable5.1 标记1M、历史输入10/输出50及 cache read0.25美元/Mtoken，但 gateway 的 fable/best 暂仍解到5，需要核对显式选型及网关支持。后台恢复、cache 和 VS Code 归档也有变化。限制是发布说明汇总，未逐项实测；面试可讲核对实际配置来源与批准/拒绝案例，而非只说升级更安全。

**关注点：★★★★★**

可以具体说明更新后权限行为为何变化。

### ② VS Code上で開発のセカンドオピニオンを別のAIエージェントから得られる「Rubber Duck」機能が実験的実装

**来源：Publickey**

**原文：** https://www.publickey1.jp/blog/26/vs_codeairubber_duck.html

VS Code1.135 的实验性 Rubber Duck 让主代理向另一模型获取意见，针对计划阶段错误一路带进实现和测试的问题。名称来自向橡皮鸭解释思路的调试方式，产品功能则是另一 AI 参与判断。

四月 Copilot CLI 的实验扩展到 VS Code，可在 Copilot Agent Host session 输入 /rubber-duck。不能泛称所有聊天模式已一致支持。另一模型可能提供不同观察，但不保证错误完全独立或一定发现主模型遗漏。

报道同时总结八月1.132–1.135 的可编辑 Markdown diff、集成浏览器评论与本地 HTML 自动重载，这些不应全部归为1.135独有更新。

限制是功能新闻，没有检出率、组合成本和延迟实验。面试可在计划阶段请对方质疑前提，再把争议回到规格和测试；两模型同意不能代替事实验证。

**关注点：★★★★★**

保留编辑器功能和实际评审方式。

### ③ Amazon Bedrock で Claude Fable 5.1 が利用可能になったので Converse API から呼び出してみた

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/bedrock-claude-fable-5-1-converse/

作者9月2日在 us-east-1、CLI2.36.36 调用 Fable5.1。先读取并把账号 Data Retention mode 从 provider_data_share 改为 aws_review，再读回核对；操作不传 model ID，是账号设置。[AWS 原始发布](https://aws.amazon.com/blogs/machine-learning/introducing-claude-fable-5-1-on-aws/)说明 Covered Model 最多保留30天供 Amazon 人员审查，而非必须共享给模型提供商。

Global profile 的一句问候返回32输入、14输出、服务指标2062ms，US Geo 也成功。模型卡 In-Region N/A，因此 API 入口地区不等于推理仅在该区，模型自称也不代替请求 ID 证据。

相同鸡牛问题分别以默认 high、max 各跑一次：输出382/956、thinking0/410、墙钟8362/13724ms。限制为每条件单次，不能算普遍质量提升或速度比；返回 content 随思考配置变化，应按 type 提取 text，不固定索引。

缓存实验在695token system 后放 checkpoint，首轮写695、约两秒后读695；缩为377输入后两轮都无读写命中，与最少512条件一致。模型最多四 checkpoint，五分/一小时 TTL。面试可讲怎样用实际 usage 验证缓存及按条件检查模型行为，而非只看配置已打开。

**关注点：★★★★★**

具备具体响应与缓存对照数据。

Redshift 集成 Agent Toolkit for AWS，为自然语言 DWH 构建、分析和运维提供 Redshift 知识及调用方式。skill 告诉代理如何理解和计划，MCP server 提供 AWS API 连接，两者不应混为同一个权限工具。

面试应用可以先看 schema、业务粒度和 SQL，再确认扫描量及更新范围，把理解、执行和结果验收分开。这属于使用判断，不是报道已经证明的完整自动分析流程。

**关注点：★★★★★**

## 3. 面接で使えるポイント

### 話題1：Claude Code / Security

**面试问题：**

> 権限の仕様が変わる更新を、どう確認しますか。

**约 30 秒自然日语回答：**

> 設定の場所と、許可・拒否の動作を比べます。Claude Codeでは、プロジェクトのbypassPermissionsが無視され、複合コマンド内のask漏れも修正されました。ただし管理設定や起動時の指定は別です。自動処理が確認待ちになる箇所を調べ、必要な操作だけを通す設定にします。単純なコマンドだけでなく、リダイレクトや設定の再読み込み後も拒否が効くか確かめます。

**関連Project（学習用）：** 按配置来源整理权限。

**キーワード：** `defaultMode` / `bypassPermissions` / `permissions.ask` / `設定源`

### 話題2：AI Coding / Evaluation

**面试问题：**

> 別のAIモデルにレビューさせれば、品質は保証できますか。

**约 30 秒自然日语回答：**

> 見方を増やす助けになりますが、保証にはしません。VS CodeのRubber Duckは、Copilot Agent Hostから別モデルへ意見を求める実験機能です。計画の段階で前提を問い直せば、後の手戻りを減らせる可能性があります。ただし二つの意見が一致しても正しいとは限りません。指摘を仕様とテストで確かめ、追加の確認にかかる時間も含めて使い方を決めます。

**関連Project（学習用）：** 将异模型意见变为测试条件。

**キーワード：** `Rubber Duck` / `Copilot Agent Host` / `計画` / `セカンドオピニオン`

### 話題3：AWS / LLM / Compliance

**面试问题：**

> 新しいモデルでキャッシュが効くか、どう確かめますか。

**约 30 秒自然日语回答：**

> 同じ入力を送り、書き込みと読み取りのtokenを見ます。Fable 5.1ではsystemの695tokenが初回に書き込まれ、次の要求で読み取られました。377tokenへ減らすと命中せず、最小512という条件も確認しています。ただし一組の測定で全業務の削減率は出せません。実際の入力で再利用率と期限切れを調べ、保持や費用の条件も確認します。

**関連Project（学習用）：** 两条件比较缓存读写。

**キーワード：** `cache checkpoint` / `695` / `512` / `cacheReadInputTokens`

### 話題4：AWS / Agent Skills / MCP

**面试问题：**

> データウェアハウスをAIに操作させるとき、スキルは何を担いますか。

**约 30 秒自然日语回答：**

> 製品の知識と注意点を伝えます。RedshiftのスキルにはPostgreSQLとのSQLの違いや、ProvisionedとServerlessの説明があり、実際のAPI呼び出しはMCP側が担います。ただしスキルを読めば権限や集計が正しくなるわけではありません。対象の表と集計の粒度を確認し、実行前にSQLと変更範囲を見ます。結果は既知の集計と比べます。

**関連Project（学習用）：** 解释 SQL 集计粒度。

**キーワード：** `Redshift skills` / `PostgreSQL` / `MCP` / `集計の粒度`

### 話題5：MCP / A2A / Governance

**面试问题：**

> MCPとA2Aを、どのように使い分けて考えますか。

**约 30 秒自然日语回答：**

> ツール接続と、エージェントへの委譲を分けます。MCPは外部ツールやデータの利用、A2Aは相手の能力を知り、別のエージェントへ仕事を渡すための仕組みです。A2Aは商取引専用ではなく、決済のx402とも別です。ただし標準を採用しても、自社の権限やデータ形式は残ります。委譲する範囲と完了条件を決め、失敗時の責任も確認します。

**関連Project（学習用）：** 绘制协议责任分工。

**キーワード：** `MCP` / `A2A` / `x402` / `完了条件`

# C. 日本語学习｜JLPT + IT日本語

例句和关联项目是围绕当天主题制作的学习材料，不是原文引文或已证实的企业案例。JLPT 等级为学习参考。

## C-1. JLPT词汇（20个）

共20词，已与全部历史收录词核对。JLPT等级为学习参考。

### 1. 見失う（みうしなう）
**词性：** 動詞・五段｜**学习参考：** N2  
**中文：** 原本看得到、把握着的目标或方向变得无法继续追踪。  
**常见搭配：** 目的を見失う / 位置を見失う / 全体像を見失う  
**用法：** 当天Top 2原文形式「見失わ」。既可指视觉追踪中断，也可比喻忘了工作目标。  
**原创例句：** 細部の修正に集中して、利用者の目的を見失わないようにします。  
**例句翻译：** 我们会避免因专注细节修正而忘记用户的目的。  
**语感与区别：** 「見落とす」是一开始没注意到；「見失う」强调原本掌握的对象后来丢失。  
**原文出处：** [Top 2](https://www.publickey1.jp/blog/26/vs_codeairubber_duck.html)

### 2. 高める（たかめる）
**品詞：** 動詞・一段｜**意味：** 提高、增强｜**目安：N2**  
**コロケーション：** 精度を高める / 安全性を高める / 信頼性を高める / 効果を高める  
**文脈：** Rubber Duck 的目的就是通过另一个 AI Agent / Model 的 Second Opinion 提高 Review 精度。  
**例：** `別ModelのSecond Opinionを追加して、Architecture Reviewの精度を高めます。`  
**中文：** 通过加入其他模型的第二意见，提高架构审查精度。  
**ニュアンス：** 「上げる」更口语、适用范围广；「高める」更正式，常用于抽象指标。

### 3. 発覚する（はっかくする）
**品詞：** 名詞・サ変動詞｜**意味：** 暴露、被发现、查明｜**目安：N1**  
**コロケーション：** 問題が発覚する / 不具合が発覚する / 後工程で発覚する  
**文脈：** Rubber Duck 文章描述早期 Plan 的错误可能直到后续实现或测试阶段才发觉。  
**例：** `設計ミスがProduction直前に発覚すると、手戻りが大きくなります。`  
**中文：** 如果设计错误到生产前才暴露，返工会很大。  
**ニュアンス：** 多用于原本隐藏的问题被发现，新闻、事故分析和质量管理中很常见。

### 4. やり直す（やりなおす）
**品詞：** 動詞・五段｜**意味：** 重做、重新来过｜**目安：N3**  
**コロケーション：** 計画をやり直す / 作業をやり直す / 最初からやり直す  
**文脈：** Rubber Duck 的价值之一是减少后工程才发现问题导致的重做。  
**例：** `Plan段階で問題を見つければ、実装全体をやり直すRiskを減らせます。`  
**中文：** 在计划阶段发现问题，可以降低整体实现重做的风险。  
**ニュアンス：** 比「再実行する」范围更广，既可指代码再跑，也可指计划、作业从头重来。

### 5. 残存（ざんそん）
**词性：** 名詞・サ変動詞｜**学习参考：** N1  
**中文：** 原应消失或被更新的部分仍然存在。  
**常见搭配：** 古い設定が残存する / 残存する情報 / 残存を確認する  
**用法：** 当天Top 1原文形式「残存」。正式说明中常用，需与有意保留的记录区分。  
**原创例句：** 古い設定が残存していないか、更新後に確認します。  
**例句翻译：** 我们会在更新后确认旧配置是否仍有残留。  
**语感与区别：** 「保存」强调主动保留；「残存」着重变化后仍存在的状态。  
**原文出处：** [Top 1](https://qiita.com/picnic/items/ba95f05d2b78799f238b)

### 6. 混在（こんざい）

## C-3. JLPT文法

### 1. ～にとどまらず
**Level：N1｜意味：** 不止于……、不仅限于……  
**形：** `名詞 + にとどまらず / 動詞辞書形 + にとどまらず`  
**使い方：** 用于说明某项技术影响范围从单一功能扩展到更大的体系。  
**例：** `MCPの価値はTool接続にとどまらず、IdentityやGovernanceの共通化にも広がっています。`  
**補足：** 与 AAIF 对 MCP / A2A 从连接协议向 Agent Infrastructure 扩展的语境高度对应。

### 2. ～を余儀なくされる
**Level：N1｜意味：** 被迫……、不得不……  
**形：** `名詞 + を余儀なくされる`  
**使い方：** 说明 Breaking Change 或外部条件变化迫使团队迁移方案。  
**例：** `Project設定のbypassPermissionsに依存していたTeamは、設定方法の変更を余儀なくされます。`  
**補足：** 对应 Claude Code v2.1.257 的 Breaking Change；适合技术迁移与风险说明。

### 3. ～に至るまで
**Level：N1｜意味：** 从……一直到……、甚至包括……  
**形：** `名詞 + に至るまで`  
**使い方：** 强调 Capability 或影响范围很广。  
**例：** `AI AgentはWeb検索からCode実行、送金に至るまで現実の操作を行う可能性があります。`  
**補足：** 对应 AAIF 文章列出的订票、邮件、代码执行、支付等现实世界操作范围。

### 4. ～たうえで
**Level：N2｜意味：** 在……之后；在……基础上  
**形：** `動詞た形 + 上で / 名詞 + の上で`  
**使い方：** 表示前一步是后续实施的重要前提。  
**例：** `実装計画を立てたうえで、別ModelにSecond Opinionを依頼します。`  
**補足：** Rubber Duck 文章本身使用了‘実装計画を立てたうえで実装とテスト’的语境。

### 5. ～にあたって
**Level：N2｜意味：** 在……之际、在进行……时  
**形：** `名詞 + にあたって / 動詞辞書形 + にあたって`  
**使い方：** 用于正式说明部署、采用、迁移前的注意事项。  
**例：** `Fable 5.1を利用するにあたって、AccountのData Retention設定を確認します。`  
**補足：** 对应 Fable 5.1 Model Card 使用前要求 Retention Mode 的原文语境。

### 6. ～に伴って
**Level：N2｜意味：** 随着……、伴随……  
**形：** `名詞 + に伴って / 動詞辞書形 + のに伴って`  
**使い方：** 描述 Agent 普及扩大后 Security / Governance 同步增长。  
**例：** `AI Agentの利用拡大に伴って、IdentityとAuditの重要性も高まります。`  
**補足：** 适合 AAIF 所描述的 Agent 从开发工具走向金融、医疗等重要业务的趋势。

### 7. ～一方で
**Level：N2｜意味：** 另一方面……、与此同时……  
**形：** `普通形 + 一方で / 名詞・な形容詞 + である + 一方で`  
**使い方：** 用于技术 Trade-off、反常关系与双面影响。  
**例：** `Modelの単価が下がる一方で、Agentの利用量はかえって増える可能性があります。`  
**補足：** 对应 AAIF 文章中 API 价格下降而 Token 使用增长的 Jevons Paradox 语境。
