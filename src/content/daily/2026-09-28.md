## 1. 今日最值得看的5篇

### 1. Claude Code on the web で複数リポジトリを接続する：CLAUDE.md・Skillsの挙動

**原文：** https://dev.classmethod.jp/articles/claude-code-web-multiple-repositories/

这篇原文处理的不是“能不能同时打开两个仓库”，而是两个仓库的规则和技能究竟如何进入同一会话。作者在 Claude Code 2.1.278 的 Web 环境中设置 A→B、B→A 两种连接顺序，每种只运行一次。根目录和 `.claude/CLAUDE.md` 中的独有指示都出现在初始回答里，随后又通过两个仓库各自生成的文件及 Draft PR 差分核对，而不只采信模型的口头报告。该环境还观察到 `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`；这是本次云端环境的条件，不能套用到所有本地 CLI 的默认行为。

技能层面的结果需要单独解释。不同名称的 `probe-a`、`probe-b` 都能被调用，但同名 `shared-probe` 在界面只出现一个候选：A 先接入时调用 A，B 先接入时调用 B。两次单独实验支持“这两次发生了顺序相关的选择”，却不足以建立稳定的优先级合同。显式调用与自动触发也不同；`disable-model-invocation` 限制自动触发，不应被误解为完全无法手动使用技能。

对 React 前端与 API 分仓的团队，编辑建议是采用带仓库前缀的技能名，给规则写明适用目录，并把实际改动路径、内容和测试结果作为验收对象。这样可以讨论指令作用域、命名冲突和可观测性，而不是泛泛地说“AI 能跨仓库开发”。本日报未自行复现实验，也未把截图或外链文档当作独立验证；连接顺序变化和产品版本升级后的行为仍需重新测试。

**为什么值得看：** 从两仓库指令与同名技能实验，学习作用域、命名冲突及真实差分验收。

### 2. Strands Agentsに「Strands harness」が追加されました！

**原文：** https://dev.classmethod.jp/articles/strands-harness-vs-agent/

Strands harness 将常用工具、系统指令、会话保存和记忆管理组合为可直接开始工作的配置。原文使用 Python 3.13.13、`strands-harness 0.1.2`、`strands-agents 1.57.0`，通过 `create_harness()` 得到包含 12 个工具和 `SnapshotSessionManager` 的 Agent；相比之下，未传入工具的 `Agent()` 没有文件访问能力。CSV 示例中，前者完成读取、计算并写出报告，后者要求用户提供数据。这说明默认装配不同，不是同条件下的模型智能高低测试。

会话连续性和跨会话记忆又是两条路径：默认在工作目录 `.agent` 保存，同一会话恢复可以利用历史，新会话则通过 `search_memory` 查找。作者另用 `AgentCoreMemorySessionManager` 替换存储，并设置 `memory=False`，避免把 Harness 自带的长期记忆机制与接管记忆检索的会话管理器混在一起。该例配置 `top_k=5`、相关性门槛 `0.3`，这些是示例的检索参数，不是适合所有业务的推荐常数。

安全验收尤其要看最终枚举，而不只看构造函数参数。原文将 `builtin_tools` 指定为三项后，还存在插件加入的四项辅助工具；`interventions="ask"` 则可以在调用前中断，通过携带 `interruptId` 的 `interruptResponse` 继续或拒绝。面试可据此解释“快速装配、显式授权、持久化边界”之间的权衡。我们没有独立验证原文外引的 28% 成本数字，因此不把它当作本期已证明的收益，也不把初始化方便等同于最小权限或生产安全。

**为什么值得看：** 理解Agent默认装配、会话与记忆职责，并检查审批和最终工具集合。

### 3. Cognito で AdminInitiateAuth を使ったときの SSO を試してみた

**原文：** https://dev.classmethod.jp/articles/slug-aws-cognito-sso-oidc-adminInitiateAuth/

Cognito 的服务器端 API 认证和浏览器 SSO 是两个不同层次。原文用同一用户池中的两个应用验证：A 的自定义登录表单由后端调用 `AdminInitiateAuth`，然后设置自己的 `a_session`；B 是通过 `/oauth2/authorize` 跳转的 OIDC RP。A 已登录后访问 B，仍会出现 Cognito 登录页，因为浏览器从未在 Cognito 域建立已认证的登录会话。取得令牌，不会自动把另一个域的认证状态写进浏览器。

更容易误判的是 Cookie 的“存在”。原文观察到打开登录页就可能收到 `cognito` Cookie，但此时再次授权仍需登录；完成登录后，其值才被替换成已登录状态。再删除 B 自身的会话 Cookie 并重新进入授权流程，就能观察到 Cognito 会话带来的免重复登录。排查时应看 Network 中授权请求实际发给哪个域、携带哪个 Cookie，以及认证后的变化，而不是只检查 B 页的 Application 面板。

面试中可以提出两条产品路径：让 A 也经过托管登录来共享 IdP 会话，或在不能改变 A 登录方式时评估目标 SaaS 另行支持的 SSO 方案。后一条不是任意 SaaS 都通用的承诺。示例 RP 明确省略 JWT 签名校验，并将会话放在内存里，只适用于实验；生产采用时必须另外验证签名、有效期及客户端约束，并安排安全会话存储。前端“显示已登录”、应用会话有效、IdP 会话有效应分别建模。

**为什么值得看：** 区分API令牌、应用Cookie与IdP浏览器会话，解释常见SSO误判。

### 4. Kiro Crew の Auto (Jev) によるモデルルーティングをローカル Kev で試してみた

**原文：** https://dev.classmethod.jp/articles/kiro-crew-auto-jev-model-route-local-kev/

Kiro Crew 的 Auto (Jev) 将“判断问题复杂度”和“生成回答”分成两个阶段。原文在 M4 Pro 上以 MLX 运行 Kev 4B，让 Apple container 内的 Crew 0.7.1／kiro-cli 2.24.0 请求主机 `/v1/systemone`；返回的 `simple`、`medium`、`complex` 再通过 `decisions.model_route` 映射到三个不同模型。`jev-latest` 是兼容接口接受的名称，并不意味着后台仍在调用远端 Jev。

配置边界比“本地运行”四个字更重要。作者把判定超时从 1000ms 增至 5000ms，并让用户同意的 endpoint 与实际配置绑定；改换 endpoint 后需要重新同意。容器访问主机服务时使用可达地址，原文为扩大监听范围的 Kev 加上 Bearer 认证，同时明确 HTTP 明文仅用于可信网络。这里不能推广为“开启认证就可以安全暴露到公网”，更不能将文中的沙箱兼容性处理照搬为普遍的关闭隔离建议。

三种请求的日志分别记录 367ms、433ms、1291ms 的判定耗时，并用 `model_chosen`、`applied`、`model_used` 验证选择是否真正生效。这是三条样例，不是吞吐、P95 或整体准确率基准；日志时间还早于文章发布日期，不能写成当天才发生的实验。面试价值是如何设计分层路由、超时回退和审计：本地的是判定部分，后续回答仍可能发往云端；`tool.risk` 的安全标签也不是执行授权或绝对安全证明。

**为什么值得看：** 把复杂度判定、模型执行与外部传输分开观测，不把本地路由夸成全本地。

### 5. AWS Backupの復旧ポイントからEC2を別のAZへ、プライベートIPを指定してリストアする

**原文：** https://dev.classmethod.jp/articles/202609-aws-backup-ec2-restore-to-another-az/

这篇实操文章给出一个明确的恢复目标：将东京区同一 VPC 内的 EC2 从一个 AZ 恢复到另一个 AZ 的子网，并指定目的子网里尚未使用的私有 IP。控制台可以选择目的子网，但原文所述流程无法指定该私有 IP，因此使用 `get-recovery-point-restore-metadata` 取得恢复元数据，再通过 `start-restore-job` 提交。原文示例将 `10.2.1.54` 改为 `10.2.2.54`；这是跨子网换址，不是保留一个不属于目标 CIDR 的旧地址。

关键实现细节是元数据的类型。`Placement` 和 `NetworkInterfaces` 不是可直接修改的嵌套对象，而是 JSON 字符串，需先用 `fromjson` 展开、修改后再序列化。除设置目标 AZ、子网和主私有 IP 外，还要清理原 ENI 的 `NetworkInterfaceId` 以及冲突的外层网络字段。该例保留接口内的安全组配置；不要由此推断每一种复杂多网卡拓扑都能原样套用。

提交后的 `RestoreJobId` 用于查询状态，`COMPLETED` 之后仍要用 EC2 与 EBS 查询核对实际 AZ、子网、IP 和卷的位置。原文特别提醒停止保护、自动恢复、标签等未继承设置还需补齐。编辑建议把应用健康检查、DNS 或负载均衡切换、连通性以及恢复时间另列为验收项；这些并未被原文的任务完成状态证明。幂等标识也需区分“重试同一意图”和“发起新的恢复”，不能因为暂时看不到结果就不断生成新的恢复任务。

**为什么值得看：** 通过JSON字符串元数据和恢复后验收，建立可操作的跨AZ恢复思路。

## 4. 今日技术主题｜不要把中间状态当作业务完成

可以用“输入与配置 → 决策 → 执行 → 业务验收”建立一张检查表。Claude Code读取了规则，不代表同名技能必定按预期选择；Harness接收了工具参数，不代表最终工具集合只有那几项；Cognito发放API令牌，不代表浏览器已经有IdP会话；Crew选中了模型，还需证明该模型实际执行；AWS恢复任务结束，也还没有证明Web服务恢复。五篇文章的共同点是，需要为每个阶段找到不同的证据。

在React或Next.js的管理界面中，可以将这些状态分开呈现：规则来源与作用域、待审批的操作、会话归属、选中与实际使用的模型、基础设施状态与业务健康检查。好处是问题发生时能找到具体断点；代价是必须管理状态一致性、日志保留、敏感字段脱敏与人工确认成本。该界面设计是本期的工程推导，不是原文已经实施的功能。

面向日本团队的落地，不必凭“日本企业普遍采用”来包装文章。更可靠的讨论是先选择一个受控项目，明确权限、数据送往何处、谁有权批准，以及成功与失败各保存什么证据。通过同一组业务场景比较实施前后，再决定是否扩大使用；目前原文没有提供日本市场采用率或我们团队的节约工时。

## 5. 面试复习卡

### Q1

> エージェントに指示やツールを渡したことと、安全に実行できることをどう区別しますか。

**回答要点：** 多仓库实验只证明两种顺序下的观测结果，同名技能不能据此当成稳定优先规则。Harness的工具白名单也未必等于最终工具集合；分别检查实际文件差分、工具枚举、审批中断和恢复。

### Q2

> 認証やモデル選択で、途中の成功を最終結果と誤認しないために何を追跡しますか。

**回答要点：** Cognito的API令牌、应用Cookie与IdP认证会话应分开观察，Cookie存在本身不能证明已登录。路由应对照model_chosen、applied和model_used；判断模型在本地并不代表回答生成和所有数据传输也在本地。

### Q3

> 別AZへの復旧訓練を、リストアジョブの成功だけで終了してはいけないのはなぜですか。

**回答要点：** COMPLETED只说明恢复任务完成；还要核对EC2与EBS所在AZ、目的子网的未占用IP、连通性以及未继承的停止保护和标签等设置。业务健康、DNS或负载均衡切换与恢复时间是另外的验收项，原文没有证明这些均已完成。

# B. 重点总结与面试知识点

### 1. 从文章1、2提炼：可用功能与授权范围分开

**中文：** 多仓库测试检查指示是否作用于实际文件，Harness测试检查最终工具集合及中断恢复。不要把规则已加载或工具参数已填写，作为安全执行的充分证据。面试回答应点出重名冲突、插件追加工具，以及具体的差分或审批记录。

**日本語：** 指示の読み込みと実ファイルへの反映、指定ツールと最終的なツール集合を区別します。同名スキルの衝突や追加ツールを確かめ、差分と承認記録で実行の範囲を説明します。

### 2. 从文章3提炼：认证状态有明确归属

**中文：** AdminInitiateAuth的返回令牌、A或B应用Cookie、Cognito认证会话是三个不同观察对象。Cookie存在但未登录的实验反例，适合说明为什么SSO排查需要看浏览器到认证域的真实请求。

**日本語：** APIで得たトークン、アプリ独自のCookie、Cognitoのログイン済みセッションは別です。Cookieがあるだけではログイン済みと判断せず、認可先へのリクエストと認証後の変化を確認します。

### 3. 从文章4、5提炼：选择与完成都要落到实际对象

**中文：** 路由要核对model_chosen与model_used，恢复要核对实际EC2/EBS位置和IP。三条判定日志不能算整体准确率，恢复COMPLETED也不能代替业务健康检查。面试时应分别说明已经验证什么、还缺哪项证据。

**日本語：** モデルは選択と実利用を、復元はジョブ状態と実際の配置を照合します。少数の判定ログから全体の精度を出さず、復元後の業務確認を完了表示に置き換えません。検証済みの範囲と未確認事項を分けて述べます。

## C-1. 本期新学词汇

### 1. 統合する（とうごうする）

**词性：** 名詞・サ変動詞　**参考级别：** N1

**中文：** 将原本分开的部分整合为一个体系。

**常用搭配：** 保存先を統合する ／ 認証基盤を統合する ／ 情報を統合する

**IT语境与用法：** 在记忆保存、认证和监控场景中，不只表示“放在一起”，还意味着统一接口或管理方式。本期对应Harness的会话与记忆职责。

**原创例句：**

> 会話と長期記憶の保存先を統合する前に、それぞれの管理責任を決めます。

**例句中文：** 整合会话与长期记忆的保存位置之前，先确定各自的管理责任。

**语感与辨析：** 与「集約する」相比，更突出整合后作为整体运作；不要把存储位置统一写成权限也已统一。

### 2. 推奨する（すいしょうする）

**词性：** 名詞・サ変動詞　**参考级别：** N1

**中文：** 认为某种做法合适而加以推荐。

**常用搭配：** 設定を推奨する ／ 方式を推奨する ／ 利用を推奨する

**IT语境与用法：** 适用于技术文档和设计审查。推荐某项配置时应附适用条件，而不是把一次成功实验写成普遍标准。

**原创例句：**

> 単発の成功だけを根拠に、同じ設定を全社へ推奨することは避けます。

**例句中文：** 避免仅以单次成功为根据，向全公司推荐同一配置。

**语感与辨析：** 比日常的「おすすめする」正式；推荐不等于强制，强制要求应另写「必須」。

### 3. 誤認する（ごにんする）

**词性：** 名詞・サ変動詞　**参考级别：** N1

**中文：** 把事物的身份、状态或意义认错。

**常用搭配：** 状態を誤認する ／ 成功と誤認する ／ 別人と誤認する

**IT语境与用法：** 本期用来描述把Cookie存在误当成已认证，或把局部测试当成稳定规格。关键是明确误认前后的两个状态。

**原创例句：**

> Cookieが存在するだけで、利用者が認証済みだと誤認してはいけません。

**例句中文：** 不能仅因为Cookie存在，就误认为用户已经通过认证。

**语感与辨析：** 「誤解する」范围更广，可指理解错了他人的话；「誤認」侧重身份或事实状态的认定错误。

### 4. 読み込む（よみこむ）

**词性：** 動詞・五段　**参考级别：** N2

**中文：** 把文件或数据读入程序；也可指深入阅读。

**常用搭配：** 設定を読み込む ／ 履歴を読み込む ／ ファイルを読み込む

**IT语境与用法：** IT场景中多指load或read。本期关注规则文件、会话历史和恢复元数据；读入成功不等于后续处理正确。

**原创例句：**

> 履歴を読み込んだ後に、保存先が想定したセッションのものかを確認します。

**例句中文：** 读入历史后，检查保存位置是否属于预期的会话。

**语感与辨析：** 「読む」仅表示读；「読み込む」强调导入处理或充分阅读，应由对象判断含义。

### 5. 書き込む（かきこむ）

**词性：** 動詞・五段　**参考级别：** N2

**中文：** 将内容写入文件、存储位置或已有栏位。

**常用搭配：** ファイルに書き込む ／ 設定を書き込む ／ 結果を書き込む

**IT语境与用法：** 本期可用于生成代码、恢复配置和审计记录。句型「何を、どこに」有助于把写入目标说明清楚。

**原创例句：**

> 生成した設定を本番ファイルに書き込む前に、差分の承認を受けます。

**例句中文：** 把生成的配置写入生产文件之前，先获得差分审批。

**语感与辨析：** 「書き出す」突出输出到外部或新文件；「書き込む」突出向指定位置写入，两者不应只当同一操作的不同拼写。

### 6. 持ち出す（もちだす）

**词性：** 動詞・五段　**参考级别：** N2

**中文：** 把物品或信息从原来的范围带出去；也可指提出话题。

**常用搭配：** 資料を持ち出す ／ 社外へ持ち出す ／ 話題を持ち出す

**IT语境与用法：** 安全与数据治理中常指把文件带到公司外部。示例代码“拿到生产环境用”也可以这样表达，但不要混同另一个“提起话题”的意思。

**原创例句：**

> 検証用の認証コードを、確認せずに本番環境へ持ち出すことはできません。

**例句中文：** 不能不经检查，就把实验用的认证代码拿到生产环境使用。

**语感与辨析：** 必须标明从哪里到哪里；「問題を持ち出す」表示提起问题，不能套用文件传输的解释。

### 7. 使いこなす（つかいこなす）

**词性：** 動詞・五段　**参考级别：** N1

**中文：** 熟练而恰当地运用工具或功能。

**常用搭配：** ツールを使いこなす ／ 機能を使いこなす ／ 複数の環境を使いこなす

**IT语境与用法：** 不仅是能启动工具，也包含知道限制和适用场景。面试中与其自称“熟练使用AI”，不如给出具体的验证与失败处理例子。

**原创例句：**

> エージェントを使いこなすには、成功例だけでなく拒否された場合の動きも理解します。

**例句中文：** 要熟练运用Agent，还应了解被拒绝时的行为，而不只看成功案例。

**语感与辨析：** 比「使う」强调掌握程度；不是把原有「使い込む」换个例句，后者强调长期或深入地使用。

### 8. 簡便（かんべん）

**词性：** 形容動詞　**参考级别：** N1

**中文：** 手续不复杂，使用方便。

**常用搭配：** 簡便な手順 ／ 簡便に試す ／ 簡便な設定

**IT语境与用法：** 用于描述开发体验或操作步骤，而不是安全性结论。本期Harness的一行初始化很方便，但最终工具和权限仍需核对。

**原创例句：**

> 簡便な初期設定であっても、実行できるツールの範囲は点検します。

**例句中文：** 即使初始配置很方便，也要检查可以执行的工具范围。

**语感与辨析：** 比「簡単」更偏书面，常同时表达省事和便利；与“简略而不充分”不同。

### 9. 堅実（けんじつ）

**词性：** 形容動詞　**参考级别：** N1

**中文：** 不冒进，以可靠步骤稳妥推进。

**常用搭配：** 堅実な運用 ／ 堅実に進める ／ 堅実な設計

**IT语境与用法：** 可用于恢复训练、设计与运维方针。不是“慢”的同义词，而是强调确认和可回退的依据。

**原创例句：**

> 復元後の通信と設定を確かめる手順が、堅実な復旧を支えます。

**例句中文：** 核验恢复后的通信和配置，是稳妥恢复的基础。

**语感与辨析：** 「慎重」侧重谨慎态度，「堅実」强调做法可靠、脚踏实地，两者可以同时成立。

### 10. 余裕（よゆう）

**词性：** 名詞　**参考级别：** N2

**中文：** 时间、容量或能力上超过最低需要的宽裕部分。

**常用搭配：** 時間に余裕がある ／ 容量に余裕を持たせる ／ 余裕を持って進める

**IT语境与用法：** 工程上可指内存、超时或恢复日程的余量。给参数留余量仍需依据实测，不能把无限放宽超时当成解决故障。

**原创例句：**

> 判定時間のばらつきを調べ、応答期限に余裕があるかを評価します。

**例句中文：** 先调查判断耗时的波动，再评估响应期限是否有余量。

**语感与辨析：** 也可表示心理上的从容；技术说明应写明具体是哪种余量以及限制。

## C-2. IT／AI术语

以下8项为技术术语，单独学习，不冒充词汇新学或复习数量。

### 1. Instruction scope｜指示の適用範囲

某项开发指示适用于哪些目录、仓库或操作。

**文章语境：** 开发规则出现于会话不等于所有改动都遵守它；仍需核对目标路径和差分。

### 2. Skill name collision｜スキル名の衝突

两个技能使用相同名称，使选择目标产生歧义。

**文章语境：** shared-probe两次实验的选择与连接顺序相关，不能直接宣称稳定优先规则。

### 3. Harness｜エージェントの実行基盤

把工具、指令、上下文和会话等组织起来的Agent运行框架。

**文章语境：** create_harness装配默认工具和保存机制；业务侧仍需检查权限与存储职责。

### 4. Interrupt / resume｜中断と再開

暂停某一步，取得外部输入后从对应位置继续执行。

**文章语境：** 审批流程用interruptId关联响应，界面应区分待审批、拒绝和已继续。

### 5. IdP session｜認証基盤のセッション

身份提供方在浏览器登录流程中维护的认证状态。

**文章语境：** Cognito的认证会话与应用自己的a_session/b_session和API令牌分别观察。

### 6. Model routing｜モデルの振り分け

按照请求特征或策略选择负责生成回答的模型。

**文章语境：** Kev判断复杂度，Crew按对应表选择模型；最终实际使用结果需再看日志。

### 7. Restore metadata｜復元メタデータ

恢复操作使用的实例配置、位置与网络参数。

**文章语境：** AWS Backup例中的Placement与NetworkInterfaces是JSON字符串，不是直接可编辑的嵌套对象。

### 8. Idempotency token｜冪等性の識別子

将重复提交关联为同一个操作意图的标识。

**文章语境：** 同一恢复任务重试与创建新恢复任务要区分；不要为了看不到结果就持续换标识重复恢复。
