### 1. ESLint から oxlint へ。lint が 50 倍速くなるまでの移行の記録

**原文：** https://zenn.dev/rimo/articles/12d6a7b1c58fcd

**发布时间：** 2026-11-18 09:51:16 JST

Rimo 希望减少编辑一个文件后的反馈等待，先在 PostToolUse 试用 oxlint。案例里的单文件计时由 3.3 秒缩至 0.36 秒。彼时工具能承担约八成的 ESLint 规则，团队并行整理规则后才调整主检查器的职责。

以迁移前同一组 3091 个文件为样本，关闭缓存跑三回，ESLint 和 oxlint 的中位数是 271.5 与 5.4 秒。CI 的整个 lint 步骤降至 32 秒，原来为 146 秒。作者核对指定版本的预设后发现 115 个规则没有直接对应项，其中三个暂无好替代的检错规则继续交给 ESLint。

进程返回退出码 0 时，类型感知规则仍可能被跳过，文章展示了漏加 --type-aware 的经历。显式指定根配置还可能跳过自动寻找的局部配置，Node 插件会增加检查成本。约 50 倍的差距只适用于这组文件及测量条件，规则和插件的组合改变后需要重测。

**推荐理由：** 迁移记录把时间差、规则兼容和实际检出能力放在同一篇报告里。

### 2. PLaMo 3 TranslateをDockerで動かしてDeepLと翻訳精度を比較してみた

**原文：** https://zenn.dev/aiforall/articles/8aa2637ea04da4

**发布时间：** 2026-11-17 16:30:10 JST

作者用 Linux 容器的 CPU 运行 llama.cpp，以 2B 的 PLaMo 3 Translate Q4_K_M 作为推理权重。Python 包装器提交文本文件和日英方向，容器内 CLI 读取输入。这样，示例可以在本机处理文本，并可记录模型和推理程序的精确版本。

对照材料由三条谚语和一封商务邮件组成，先英译再将输出译回日语。一条关于突出木钉的谚语，两种服务产生的英文相同，然而 PLaMo 回译选择了日语固定表达，另一结果更接近按英语字面还原。商务信的收尾也呈现不同的语气。

有限样本只说明这些例子中能看到的措辞差别。报告没有给出多领域盲评、速度或硬件对照，也没有单独测量是否遗漏原文信息。实际选型宜根据文书种类查看词义、数字和语气分别保留了多少。

**推荐理由：** 小规模的回译对照能练习如何记录环境，以及如何描述样本能支持的结果。

### 3. S3のデータを Databricks に取り込むために、データ基盤チームが用意したもの

**原文：** https://zenn.dev/guri_03/articles/ad28087e995349

**发布时间：** 2026-11-17 18:39:05 JST

业务团队需要把自己 AWS 账号中 JSON Lines 日志接入现有数据分析。源桶按环境分开，业务团队维护管道，平台团队搭好可读的数据位置及写入目标。受网络来源限制且交付时间有限，团队采用开发者经 VPN 用 Databricks Asset Bundles 到共享路径部署。

平台团队用 IAM 角色建立 Unity Catalog 的只读 External Location，并限制可以使用它的工作区。管道由 run_as 指向的服务主体运行，具备读源、写目录及在部署文件夹执行的权限。部署者则获得编辑目录和指定执行主体所需的授权。

目标是一个专用目录并划分测试、生产两个模式。作者的组织只有一个工作区，这个划分和实用部署方式建立在该前提上。文章比较了 Actions、Git folder 作业与 VPN 手工部署三种方案，没有报告三者的吞吐或运行时性能对照。

**推荐理由：** 这里可以看到团队边界怎样转换成部署、运行、源数据和表权限的边界。

### 4. スクリーンショット5枚から作るアニメーションWebP：sharp の delay と99KBの実測

**原文：** https://zenn.dev/sakidori/articles/20261031-headless-screenshot-animated-webp

**发布时间：** 2026-11-18 06:12:16 JST

产品演示图要随着界面更新，作者用 Chromium 自动拍摄五个步骤。测量固定窗口为 720×480，缩放系数为 1。在 Node 22、sharp 0.35.5 和 libvips 8.18.7 下，对同样五帧比较，动画 WebP 为 99 KB，GIF 为 246 KB，APNG 为 320 KB，分别保存为 PNG 合计 378 KB。

实际播放时第一帧停留较久、后面很快掠过。元数据表明，WebP 的 delay 设为单个 1200 时只影响首帧，后四帧为 100 毫秒。改为逐帧的数组后，设定的显示时长才都出现在文件中。

质量档保持在 70 时，作者测得 effort 4 输出 101 KB、耗时 212 毫秒，effort 6 输出 99 KB、耗时 2879 毫秒。作者因此选择 4。线上的成品为 150–330 KB，取决于画面和宽度。99 KB 是这组五帧截图的参考值，实际发布时要按最终宽度和内容测量。

**推荐理由：** 同一批截图的输出数据，展示了帧时长和压缩参数为何需要单独核对。

### 5. WordPressを廃止し、静的サイト＋Pagefindに移行した

**原文：** https://zenn.dev/iototaku/articles/2328447c65a9c8

**发布时间：** 2026-11-17 19:56:38 JST

旧站主要用来阅读已有文章，维护动态运行时的成本逐渐显得过高。作者抓取公开交付的原始 HTML 及 CSS、图像、脚本和 PDF，保留出错清单与文件哈希。最终覆盖 139 篇文章，加栏目索引与固定页在内的 HTML 有 324 个。

发布到非公开 S3 后由 CloudFront 对外提供访问。站内搜索改成 Pagefind，以文章正文和标题构建检索文件，数据在客户端按需加载。作者避免把列表中反复出现的文字重复加入索引，并测试了日语词、无命中结果和旧搜索表单的导向。

切换前对照元标签、JSON-LD 和不带扩展名的既有地址，旧站停机验证后再撤下动态组件。作者报告云基础设施每月减少约 1.5 万日元。改用 GitHub 管理更新后，维护人员需要调整发布流程。费用估算只在这个站点的用量和部署条件下成立。

**推荐理由：** 站点迁移涉及检索入口和已有引用。作者记录了需要逐一验收的对象。

## 4. 今日技术主题

### 为迁移约定可观察的行为

迁移后有哪些东西必须和原来一样，可以先写成具体的核对项。代码检查要能检出约定的错误，检索要找到应出现的文章。只看进程是否成功结束，会漏掉没运行的规则或索引缺失。

部署和日常执行的参与者也可能不同。日志导入按权限检查读取及落表，图像流水线按输出验证帧时长和大小。保留一小组可重复输入，可以让前后结果更容易比对。

本地回译给出了第三种验收方式。先确定必须保留的事实、约束与语气，再把明显的风格变化和信息丢失分别记录。这样可以知道某项改动是否真的满足当前用途。

### 1. 諦める（あきらめる）｜N5/N4

- 词性：一段・他動詞
- 含义：判断继续也难以实现原来的目标，于是放弃。
- 搭配：計画を諦める / 途中で諦める
- 文章语境：作者放弃采用视频，改用静态截图表现界面的操作过程。
- 例句：短い動画は諦めて、操作の順序を五枚の画像で示しました。
- 例句含义：放弃了短视频方案，用五张图片演示操作顺序。
- 辨析：「諦める」常见于日常会话，「断念する」更常用来正式说明放弃某项计划。

### 2. 結び（むすび）｜N2

- 词性：名詞
- 含义：文章或致辞中起到收束作用的部分。
- 搭配：結びの言葉 / 手紙の結び
- 文章语境：商务邮件回译实验对比了结尾礼貌用语的自然程度。
- 例句：取引先へのメールは、結びに次回の連絡予定を書きました。
- 例句含义：在发给客户的邮件结尾写了下次联系的计划。
- 辨析：「末尾」只说明位置，「結び」还强调收束全文或致辞的作用。

### 3. 土台（どだい）｜N1

- 词性：名詞
- 含义：支撑建筑的底座，也可比喻开展或延续某件事所依托的基础。
- 搭配：土台を作る / 議論の土台
- 文章语境：文中指分析团队接手前，基建团队准备好的环境和权限条件。
- 例句：共通のデータ形式を決め、次の分析の土台を作りました。
- 例句含义：确定了统一的数据格式，为后续分析打下基础。
- 辨析：「土台」保留从下方支撑上层的形象。「基盤」常用于组织或技术长期运行的设施和机制。

### 4. 異動（いどう）｜N2

- 词性：名詞・サ変
- 含义：在组织内改变部门、职位或工作地点。
- 搭配：部署を異動する / 人事異動
- 文章语境：作者把运行权限交给独立的服务身份，降低换岗对任务的影响。
- 例句：担当者が別の部署に異動しても、集計は続きます。
- 例句含义：即使负责人调到其他部门，汇总任务也会继续运行。
- 辨析：读音和「移動」一样。物理位置变化常写「移動」，人事调动使用「異動」。

### 5. 退職（たいしょく）｜N1

- 词性：名詞・サ変
- 含义：离开原有的工作岗位或结束雇佣关系。
- 搭配：会社を退職する / 定年退職
- 文章语境：原文解释如何让任务在负责人离职、个人账户失效后仍有运行身份。
- 例句：担当者が退職する前に、作業手順を後任に引き継ぎました。
- 例句含义：在负责人离职前，已把操作步骤交接给继任者。
- 辨析：「退職」概括离职，单凭这个词无法判断本人是否主动提出。

### 6. 撤去（てっきょ）｜N1

- 词性：名詞・サ変
- 含义：移除已设置好的设备或物件。
- 搭配：旧設備を撤去する / 仮設の案内板を撤去する
- 文章语境：在新站能够打开旧链接之后，作者再拆除闲置的云端设施。
- 例句：新しい配信経路で記事を開けると確認し、旧設備を撤去しました。
- 例句含义：确认新分发路径能打开文章后，拆除了旧设备。
- 辨析：常用于已经设置的器材和设施。取消制度时常用「撤廃」。

## C-2. IT/AI专业词汇

1. **Type-aware lint（型情報を使う静的検査）**：利用类型推断信息检查代码问题。 文章中迁移后的检查程序需要显式启用对应参数。

2. **Q4_K_M（四ビット系の量子化形式）**：用较低的数值精度表示权重以减少模型的存储及运行开销。 本次在 CPU 上比较的是使用这种格式的 20 亿参数模型。

3. **External Location（外部ロケーション）**：在目录层把云存储路径与访问凭据绑定起来。 文中用它登记受限的 S3 读取范围。

4. **Animation frame delay（コマごとの表示時間）**：决定动画保持当前帧多久再推进到下一帧。 作者逐帧设置时间，把开头停留和后续切换分别控制。

5. **Pagefind（静的サイト向け検索）**：从静态 HTML 构建搜索索引，查询发生在浏览器中。 文章将索引范围收拢到各篇正文和标题。
