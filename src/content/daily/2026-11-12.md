### 1. AIの望まない動作を減らしたのは、禁止でも依頼でもなく「していい範囲」を決める1文だった。Claude Codeの返事が英語になる問題で検証

**原文：** https://zenn.dev/murooka_az/articles/claude-reply-switches-to-english

**发布时间：** 2026-11-12 09:13:04 JST

作者关注的是开发助手在日语会话中突然用英语回复。排查时把一份真实对话截在异常回复之前，每组保留相同的会话起点，在 Claude Code 2.1.318、Opus 5.5 medium 下变更 CLAUDE.md 对输出语言的描述。比较的对象包括短进度和完整报告，使用复制出的记录反复生成。

原有配置逐项列出允许英语的内容，100 次重放有 15 次用英语回复。追加一条提醒后为 19 次，删除那段允许英语的文字后为 7 次。换成按读者划定范围的描述后为 1 次。读者规则把用户会看到的短句和最终报告归入同一类，代码、日志原文等有各自用途的输出仍可保留原语言。

作者使用双侧 Fisher 精确检验比较频数，结论限于主实验的单个会话断点。重放也没有完全复原原始工具环境和思考上下文，另一场景重放 10 次均未复现英语回复，因此没有纳入条件比较。团队可以把实际失败的对话状态留作回归样本，同时覆盖不同模型、消息长度和工作流，再决定采用哪种约定。

**阅读价值：** 适合用来解释如何把输出语言写成可观察的要求，并通过多次重放区分偶发行为与稳定变化。

### 2. Worker の結果を transfer で返したら写すより遅かった（Chromium で小さな配列 30 万個）

**原文：** https://zenn.dev/openedfile/articles/worker-transfer-small-buffers

**发布时间：** 2026-11-12 08:00:06 JST

浏览器内的 DXF 查看器用 Web Worker 组装几何数据，再让主页面绘制。原文测试的图纸为 6.4 MB，每根线单独占一层，最后得到 30 万个小型 TypedArray，数据仅 2.4 MB。把每个底层 ArrayBuffer 都列为可转移对象，能避免拷贝字节，但也会产生逐对象的处理开销，且发送方失去对缓冲区的访问。

在 Chromium 151 的 Linux 环境，作者以三次中位数对比打开到绘完的总时间，全部转移为 13.6 秒，只转移至少 64 KB 的缓冲区为 2.8 秒。64 字节的小数组另测时，30 万个对象的转移耗时约 10.7 秒，复制约 0.41 秒。转移所花时间主要出现在 Worker 的 postMessage 调用内部，定位范围因此缩到交接阶段。

阈值的作用是限制大列表中的可转移对象数，仍要付出小数组复制的代价。64 MB 总量、16 KB 一组的测量反而是转移更快，WebKit 的图纸对比则没有同量级的差距。文章未确定 Chromium 内部原因，而且两种浏览器使用了不同机器。需要分别基于目标引擎和真实数据分布重测。

**阅读价值：** 可用总字节、对象数和交接时延三项观测，把优化判断落实到数据形状。

### 3. 【CSSだけ】スクロールでふわっと表示するアニメーションを作る

**原文：** https://zenn.dev/h_aso/articles/css-scroll-driven-animations-baseline

**发布时间：** 2026-11-12 08:00:06 JST

文章用一个咖啡馆示例，把卡片渐现、阅读进度条和页头变色绑定到滚动。CSS 的 view() 关注元素在视图中的相对位置，scroll() 关注滚动容器本身的进度。渐现卡片通过 animation-range 指定运动区间。Chrome 157 的实验记录了随滚动位置增加、透明度从 0 经多个中间值到 1 的过程。

有两处样式细节会改变执行结果。animation 简写若写在 animation-timeline 之后，会把先前的时间轴重置，示例在 Chrome 中回到 DocumentTimeline，打开页面就播放。父容器使用 overflow: hidden 也可能改变 view() 参照的最近滚动容器。文章里换成 overflow: clip 后，裁切效果保留，测得的参照回到页面。

作者还复现了旧 Firefox 149 中页头文字难读的情况。修正后的基础样式直接给出白底和可读内容，支持检测与用户的减少动态效果偏好共同决定是否加动画。限制是目前只验证示例及列出的浏览器条件，嵌套容器、其他设备和实际页面流畅度需要各自检查。

**阅读价值：** 从可读的基础样式出发，再检查简写顺序、时间轴与最近滚动容器，便于定位前端展示差异。

### 4. Python 3.15の新プロファイラーTachyonの紹介

**原文：** https://gihyo.jp/article/2026/11/monthly-python-2611

**发布时间：** 2026-11-12 09:00:00 JST

Tachyon 随 Python 3.15 提供，通过外部定期采集调用栈估计运行时间分布。采样型分析适合先找耗时集中在哪些行或函数，结果表示样本命中的情况。文章区分了运行新脚本的 run 和连接既有进程的 attach，后者还要核对目标解释器版本、构建类型和平台权限。

示例脚本先做质数计算，再等待两秒。按墙钟时间采样时，等待所在行约占 61％，切换到 CPU 模式后，这行没有进入统计，质数判定行成为主要开销。pstats 表的 direct 计数关注当时直接执行的行，cumulative 还纳入该调用路径下的工作。两个模式的百分比使用不同样本总数，适合回答不同的问题。

需要给别人复查时，可把一次采样保存成二进制，再用 replay 生成火焰图或逐行热图，免于为了换展示形式重测。统计采样的局限在于短任务可能只有少量命中，示例中的比例也会波动。团队可先拉长或重复代表性的负载，再根据待查问题选择墙钟或 CPU 口径。

**阅读价值：** 可以用同一段程序解释等待为什么在墙钟指标中明显，却不占用 CPU 样本。

### 5. 【日本株分析プラットフォーム】過去の株価の自動修正が、出来高の1株の違いで止まった話(前半): 四捨五入と切り捨て(2026-11-12)

**原文：** https://zenn.dev/stagea_tech/articles/20261112-pj8-devlog

**发布时间：** 2026-11-12 09:21:24 JST

一个行情历史维护程序先生成更正计划，再用保存的参考值独立复算。11 月 9 日批次涉及 147 家公司的 2643 行，写入前发现同一证券的七行成交量各差一股，于是停住。开盘、最高、最低和收盘价都对得上，这将排查范围缩到成交量的换算。

该证券发生过股份合并和拆分，系统用 10 作为净倍率换算旧成交量。规划端在换算后四舍五入，复算端和可比的已存记录则舍去小数。原文举了 23,113.5 的例子，四舍五入得到 23,114，截断得到 23,113。该批次端数低于 0.5 的记录不会表现出差异，因此边界样本比仅看普通整除记录更能定位规则冲突。

作者修正计划生成方式，保持原有拦截，使用已存输入重建计划，没有重新请求参考站。新旧计划 2643 行一一对应，只有那七行的成交量各减少一股。相关判定的 110 项和整体的 53 项测试均通过，之后还查了目标之外的数据。这个做法适用于文中已核对的历史口径，其他数据源的舍入契约须另行确认。

**阅读价值：** 适合说明数据修正要验证规则、重放范围与外部数据稳定性，即使差异只有最小计量单位。

### 5. 【日本株分析プラットフォーム】過去の株価の自動修正が、出来高の1株の違いで止まった話(前半): 四捨五入と切り捨て(2026-11-12)

**相关项目例：** 为整数计量的历史修正准备可重复的 dry run，以边界输入核对计划和实际变更。

## 4. 技术主题：用固定条件复查失败边界

度量前先确定自己要解释哪一种失败。开发助手需要统计用户可见文本的语言，图纸查看器要同时量端到端和消息交接。Python 的等待与 CPU 执行同样需要分别计量，才能区分该缩短计算，还是该减少等待。

回归样本应保留会区分两种实现的条件。动效的基线要包含旧浏览器和减少动态效果，数据更正要覆盖整数换算的边界。固定输入重放后，再按结果的实际差分验证作用范围。

在日本企业内部试点时，可以先用一份日语进度模板、一条真实图纸链路或一批已存的历史数据进行小规模验证。让业务人员确认可接受的输出与计算口径，让开发侧保存版本、负载和数据形状，以便日后复查。扩大范围前再为新增设备、角色或数据源补测。
