## 4. 今日の技術テーマ

# Deterministic Agent Orchestration

确定性 Agent Orchestration 的目标是让 **Workflow Engine 决定当前 Stage，Agent 只完成 Stage 内的推理或生成**。它提升 Reproducibility、Auditability 和测试能力，但复杂流程可能显得过重，而且长期 Agent Memory 仍需要整理和生命周期管理。

```text
Goal
  ↓
State Machine
  ↓
Agent / Tool Step
  ↓
Acceptance Check
  ↓
Next State / Stop
```

### 优点

**第一，减少无关复杂度。** 通过把职责拆成 `Goal` 到 `Next State / Stop` 的明确层次，可以让模型只处理概率性判断，而把权限、验证和停止条件交给确定性系统。

**第二，更容易测量与回滚。** 每一层都能单独记录 Input / Output / Cost / Failure，出现异常时可以定位问题，而不是把所有错误都归因于“模型不够好”。

**第三，更适合团队规模化。** 生产化不能只看 PoC，需要同时验证质量、成本、安全、可观测性与失败恢复，因此可以把个人技巧转成可复用的 Platform Rule、CI Check 或 Governance Policy。

### 局限

**系统复杂度会上升。** 多一层 Router、Policy、Sandbox、Trace 或 Evaluation 都会带来开发和维护成本，需要确认它解决的是实际风险，而不是为了“架构完整”而堆层。

**确定性 Guardrail 也可能配置错误。** Policy、Test、Metric 与 Retrieval Rule 都需要版本管理和持续校准，不能因为“不是 LLM”就默认它绝对正确。

### 日本企业落地时的注意点

1. 先明确 **Owner、Data Boundary、Permission、Approval、Audit、Rollback**，再扩大 Agent 自治范围。  
2. 把现有的 **CI/CD、SRE、Security Review、Change Management** 继续保留，不因为接入 AI 就另建一套不可追踪的旁路。  
3. 用日本企业实际关心的 **品質、工数、Cost、Security Incident、Business Outcome** 评价，而不是只统计 AI 使用次数。

面试里可以这样总结：

> PoCの成功だけで判断せず、品質、Cost、Security、Observability、Failure時のRecoveryを含めて実運用で評価します。

2. **Benchmarkだけで決めず、Task Quality、Latency、Cost、Failure Rateを同じ評価セットで比較し、必要なら弱いModelから強いModelへ段階的に切り替えます。**
3. **導入判断では、適用条件とTrade-offを明確にし、実際のWorkloadで評価することが重要です。**
4. **本番運用では、変更履歴、監査性、Rollback手段まで含めて設計する必要があります。**

## C-1. JLPT词汇

### 1. 順番（じゅんばん）
**词性：** 名詞

**参考：N3**  
**搭配：** `順番に処理する` / `実行順番` / `順番を守る`

**例句：** `各Stageを決められた順番に実行します。`  
**中文：** 按规定顺序执行各 Stage。  
**细微区别：** 更正式可用「順序」。

### 2. 状態（じょうたい）
**词性：** 名詞  
**中文：** 状态  
**参考：N3**  
**搭配：** `現在状態` / `状態遷移` / `状態を保存する`  
**技术语境：** State Machine 用显式 State 表示 Workflow 当前执行位置。  
**例句：** `Workflowの現在状態をState Storeに保存します。`  
**中文：** 把 Workflow 当前状态保存到 State Store。  
**细微区别：** 系统工程高频词。

### 3. 閾値（しきいち）
**词性：** 名詞  
**中文：** 阈值  
**参考：N1**  
**搭配：** `判定閾値` / `閾値を設定する` / `閾値を下回る`  
**技术语境：** Router、Judge Model 与 VLM Confidence 都可通过阈值决定下一路径。  
**例句：** `Confidenceが閾値を下回るとHuman Reviewへ切り替えます。`  
**中文：** Confidence 低于阈值时切换到人工审核。  
**细微区别：** 标准读音为「しきいち」。

### 4. 例外（れいがい）
**词性：** 名詞  
**中文：** 例外  
**参考：N2**  
**搭配：** `例外処理` / `例外Case` / `例外を扱う`  
**技术语境：** Human Fallback 最适合处理自动化难以覆盖的例外 Case。  
**例句：** `自動化しにくい例外Caseだけ人間が処理します。`  
**中文：** 只有难以自动化的例外案例由人处理。  
**细微区别：** 技术语境常对应 exception。

### 5. 費用（ひよう）
**词性：** 名詞  
**中文：** 费用  
**参考：N3**  
**搭配：** `費用を抑える` / `費用対効果` / `推論費用`

**例句：** `簡単なTaskは小さいModelへRouteして費用を抑えます。`  
**中文：** 简单任务路由到小模型以控制费用。  
**细微区别：** 比「お金」正式。

### 6. 進む（すすむ）
**词性：** 動詞・五段  
**中文：** 前进、推进（自动词）

**搭配：** `処理が進む` / `次へ進む` / `Workflowが進む`

**中文：** 满足条件后 Workflow 进入下一 Stage。

### 7. 遷移する（せんいする）

**例句：** `Successの場合だけ次のStateへ遷移します。`  
**中文：** 只有 Success 时才转移到下一 State。  
**细微区别：** 比「移る」正式，特别适合状态机。

### 8. 分岐する（ぶんきする）

### 9. 固定する（こていする）

## C-2. IT/AI专业词汇

### 1. Deterministic Workflow
**日本語：** 決定論的Workflow  
**中文：** 确定性工作流  
**当天语境：** 用固定 State、Rule 与 Transition 控制关键流程，减少 Agent 随机行为。

### 2. State Machine
**日本語：** 状態機械 / State Machine  
**中文：** 状态机  
**当天语境：** 以 State 和 Transition 显式定义 Workflow 的执行路径。

### 3. LLM Router
**日本語：** LLM Router  
**中文：** LLM 路由器  
**当天语境：** 根据任务难度、成本或风险选择适合的模型。

### 4. Judge Model
**日本語：** 判定Model  
**中文：** 评审模型  
**当天语境：** 使用模型对输出质量、路由或通过条件进行自动判定。

### 5. VLM
**日本語：** Vision Language Model  
**中文：** 视觉语言模型  
**当天语境：** 结合图像与文本理解，可用于 UI、文档、视觉检查等任务。

### 6. Human Fallback
**日本語：** 人間Fallback  
**中文：** 人工兜底  
**当天语境：** 自动系统低置信度或失败时转交人类处理。

### 7. Retry Policy
**日本語：** 再試行Policy  
**中文：** 重试策略  
**当天语境：** 规定失败后是否重试、次数、间隔和回退路径。

### 8. Cost-aware Routing
**日本語：** Cost考慮Routing  
**中文：** 成本感知路由  
**当天语境：** 把任务成功率与模型成本一起纳入 Routing 决策。

## C-3. JLPT语法

### 1. ～にとどまらず
**参考：N1**  
**中文：** 不仅限于……  
**接续：** `名詞 / 普通形 + にとどまらず`  
**使用场景：** 说明 Workflow 设计不只关注成功路径，还覆盖失败、Retry、Fallback 与 Human Review。  
**例句：** `Workflow設計では正常系にとどまらず、失敗時のRetryやFallbackも定義します。`  
**中文：** Workflow 设计不仅限于正常流程，也定义失败时 Retry 和 Fallback。  
**注意：** 适合范围扩展。

### 2. ～かねない
**参考：N1**  
**中文：** 可能导致不良结果  
**接续：** `動詞ます形去ます + かねない`  
**使用场景：** 警示把高风险流程完全交给动态 Agent 可能导致不可控行为。  
**例句：** `Criticalな処理を完全にAgent任せにすると、予期しないStateへ進みかねません。`  
**中文：** 把关键处理完全交给 Agent 可能进入非预期 State。  
**注意：** 通常用于负面风险。

### 3. ～なくしては
**参考：N1**  
**中文：** 没有……就无法……  
**接续：** `名詞 + なくしては`  
**使用场景：** 强调明确 State / Transition 是确定性 Workflow 的基础。  
**例句：** `明確なState定義なくしては、Workflowの再現性を高められません。`  
**中文：** 没有明确 State 定义，就无法提高 Workflow 可复现性。  
**注意：** 语气较强。

### 4. ～に応じて
**参考：N2**  
**中文：** 根据……相应调整  
**接续：** `名詞 + に応じて`  
**使用场景：** Router 按难度、Cost、Risk 选择 Model / Path。  
**例句：** `Taskの難易度に応じてModelを切り替えます。`  
**中文：** 根据任务难度切换模型。  
**注意：** Routing 面试高频。

### 5. ～た上で
**参考：N2**  
**中文：** 在……之后、在……基础上  
**接续：** `動詞た形 + 上で`  
**使用场景：** 自动系统先判定，再由 Human 做最终确认。  
**例句：** `VLMの結果を確認した上で、人間が最終判断します。`  
**中文：** 确认 VLM 结果后，由人类最终判断。  
**注意：** 流程说明很实用。

### 6. ～一方で
**参考：N2**  
**中文：** 另一方面……  
**接续：** `普通形 + 一方で`  
**使用场景：** 比较确定性 Workflow 与动态 Agent 的 Trade-off。  
**例句：** `State Machineは再現性が高い一方で、自由度が下がることがあります。`  
**中文：** State Machine 可复现性高，但自由度可能降低。  
**注意：** 适合 Trade-off。

### 7. ～にかかわらず
**参考：N2**  
**中文：** 不论……都……  
**接续：** `名詞 + にかかわらず`  
**使用场景：** 表达所有 Route / Model 都要遵守共同 Audit 与 Safety Rule。  
**例句：** `利用するModelにかかわらず、実行履歴を必ず保存します。`  
**中文：** 无论使用哪个模型，都一定保存执行历史。  
**注意：** 适合统一 Policy。
