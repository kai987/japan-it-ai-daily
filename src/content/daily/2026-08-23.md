# A. 详细文字版

今天讨论 AI 主导开发、远程会话稳定性、模型路由、限时价格及视觉检查。共同重点是对生成的计划、预测概率和检验规格建立独立验收条件。

## 1. 今日最值得看的 5 篇

### ① 「AI-DLC の紹介」というタイトルでゆるWeb勉強会@札幌で登壇しました #ゆるWeb札幌

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/yuruweb-31-iwasa/

这份札幌8月22日分享会报告，将 **AI-DLC** 的开发理念与 `awslabs/aidlc-workflows v2` 工具实现分开说明：AI 提出计划，人批准后推进。作者在会后查阅代码和文档补答现场问题，因此证据是源码调查与初用体验，并非企业收益实测。

v1 已存在阶段概念。按文中对比，v2 从3个 phase 扩展为含 Initialization、Ideation 的5个，从十多个 stage 扩展为33个，由单代理改成14个角色；流程从 LLM 自行判断转向确定性的 TypeScript 状态引擎。变化在控制粒度和可机器验证范围，而不是简单新增“分阶段”三个字。

**`team.md`、`project.md`** 保存当前有效规则，历史另存 audit shard 和各 stage 的 memory.md；cid 标记去重，与 `org.md` 冲突的学习内容被排除。但作者未找到大小上限和自动整理，且下轮会全量读取，所以长期积累仍可能需要人工清理。去重不能等同容量治理。

若希望人负责某些步骤，可以跳过 stage 或在批准关口拒绝后重写，但文中未确认按单个文件分配人与 AI 的功能。生成资料包括 `requirements.md`、`components.md`、`contract-summary.md`、`stories.md` 等多个文件；`OUTCOMES.md` 是收尾交接包，不是统一规格书。

面试可围绕角色责任、状态迁移、审核内容及知识维护解释设计。多角色可能提升质量是作者期待，不能把14个角色的数量当作已验证质量指标。

**关注点：★★★★★**

同时解释确定性流程控制与长期知识维护的责任。

### ② Claude Code v2.1.238～2.1.239：Reliability / Security / Hidden Billing

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/20260822-cc-updates-v2-1-239/

文章把 Claude Code **v2.1.238—v2.1.239** 的98项变化分为59项修复、20项改进、8项新功能、8项安全、2项性能和1项破坏性变化，集中于 Remote Control、跨会话通信、全屏与插件市场。这是作者对更新日志的分类，不等于逐项独立复现实验。

**Remote Control** 可容忍最多3分钟的临时 HTTP403，持续阻断时提示来源，并修复瞬断认证、远端模型切换和 Stop 未传达、消息消失、崩溃后复用及标题同步风暴。长 SessionStart/Setup hooks 期间继续 keepalive，重点是连接保持和两端操作状态一致。

作者实际展示 Mac 启动 `/remote-control`、手机扫码、iPhone 发指令并在终端反映的过程。但执行仍依靠本地进程，关闭终端会离线。文中列有套餐、普通 claude.ai 登录、直连与组织开关等前提，API key、Bedrock 等接入不能直接套用。远程查看并不代表任务迁入云端执行。

Bedrock 修复涉及代理删除 Content-Type 后，将流式请求静默重跑为非流式，造成计费调用增加；SSO 预检查也改为遵守 HTTPS_PROXY。跨会话拒收及队列丢弃会通知发送方。长会话内存、WebFetch 过期内容滞留、续接错误目录以及 Linux worktree 配置读取等也在修复范围。

**`keybindingFlavor: readline`** 将 Ctrl+W 改为空白边界删除，并扩展到词级移动与删除，classic 默认行为保留。唯一破坏性变化是全屏 Ctrl+L/Cmd+K 双击不再清空会话，需要显式 `/clear`。另修复掩码内容被粘贴或进历史、点击聚焦误触批准等问题。

**`headersHelper`** 生成短期令牌等请求头，用于目录及同源包下载，在安装更新时展示命令并确认；项目来源须通过信任检查，凭据继承也受限制。美国限定推理1.1倍费用计入估算、额度错误及时失败、goal 检查间隔变化等，都需要结合实际部署条件理解，不能将更新日志当成所有环境已验证稳定的证明。

**关注点：★★★★★**

区分远程控制界面、本地执行位置与重试造成的计费影响。

### ③ NeMo Switchyard Prefill Router

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/dgx-spark-switchyard-prefill-router-vs-judge/

**NeMo Switchyard prefill router** 不让判定模型生成文字，而读取冻结 LLM 处理输入时的 hidden states，经过层选择、pooling、标准化、**PCA 和浅层 MLP** 预测各候选模型答对的概率。生成式 judge 可返回带理由 JSON，却有生成延迟和格式风险；预测式省去这部分，但不能同样利用中途工具结果或提供生成理由。

标签来源决定路由含义：人类偏好、实际答对与任务类别不能混为一谈。此方法从候选正误学习，encoder 与被预测对象分离，因此也能为闭源模型评分。所引论文在11模型池报告回收最强单模型到 oracle 差距的45.6%、节费74.3%，同时分布外精度下降11.43点。它们是论文实验，不是作者本地复现得出的统一收益。

本地训练混合 DeepSeek V4 Flash-0731 的 LiveCodeBench167道实测正误和1,608条蒸馏 judge 的合成任务。评估分成237条保留集、weak连续两败而strong通过的14题、日常47条独立提示。210条合成保留问题在训练侧存在同生成批次近亲，因此总体 AUC 可能反映文风，必须单列27道实测代码题和14道鉴别题。

Qwen3.6-35B 配置 AUC 为0.938，生成 judge 为0.903；对237条做2,000次配对 bootstrap，差的95%区间为0.002—0.070，其他 encoder 差值区间跨零。14道难题中 judge 仅5题送strong，prefill为10—12题；但日常47题仅31—38题，与全选strong的31题基线相近。排序能力尚在，概率却缩到0.4—0.6，遇0.80阈值就过度上送。仅用合成标签还会把代码题普遍判难，显示真实正误数据不可被蒸馏数量替代。

v0.2.0 尚无正式 prefill route type。历次 PR 改写后，当时 **PR506** 只约定与 `8a9d3509` 特征抽取一致，未实现 PCA、MLP、checkpoint 加载及路由。作者临时用兼容 HTTP 的 shim 坐在 judge 位置，固定类别后设 `threshold_step = 0`，没有放入生产配置。

87次判断中 judge 为82/87、shim38/87；其中40条开头相同但中间工具结果不同，前者可读过程而40/40，后者只读开头而0/40。p50约0.9—1.0秒对1.93秒也不是同条件：前者62GB BF16、HF eager，后者21GB NVFP4、vLLM。不能仅用速度宣布可替代。

DGX Spark 的128GB共享内存还使 Qwen 的 HF 加载因 CPU/GPU 合计占用失败，转成21.8GB NVFP4/vLLM；该路径层编号与量化不同，不属于 PR506 的逐张量一致。其他基准抽取路径通过 parity test 和 checkpoint 回读，但未来加载格式仍未定。面试可据此提出准备真实标签、固定且区分分布的评估集和 encoder 部署，并保留处理会话中途变化的其他路由机制。

**关注点：★★★★★**

分别审查 AUC、概率校准、输入信息和实现阶段。

### ④ GPT-5.6 Sol API値下げとUsage Governance

**来源：ITmedia AI＋**

**原文：** https://www.itmedia.co.jp/aiplus/article/2608/23/2000000700/

ITmedia 报道 **GPT-5.6 Sol** 在8月21日调价：Standard 每百万输入 token 从5美元降至4美元，输出从30降至20美元，对应20%和约33%。官方 changelog 也确认价格及至少延续到11月21日的促销期限。它不代表永久价格，更不能自行推算之后恢复或再降的安排。

文中短上下文条件是输入不超过272,000 token；缓存读取0.40美元、写缓存5美元单列。超过阈值时整个请求的输入按2倍、输出按1.5倍，分别8与30美元。Batch/Flex 按短标准价格半价、Fast 按两倍介绍。估算必须区分输入长度、输出、缓存和处理等级，不能只比较每请求次数。

ChatGPT Work、Codex 的相应信用消耗逐步下调，与 Pro、Plus、Business 订阅内含使用量不变是不同事项。Terra、Luna 不属于这次调整。报道还涉及 API key 维度 Usage/Costs 及 API、组织和项目的支出控制，但单价降低不能直接推出所有业务月账单同比例下降。

面试可说明如何保存带日期和处理条件的价目，再乘以实际输入、输出和缓存量建立预算。证据是价格发布，不是模型质量或端到端成本实验，促销到期后的条件须重新确认。

补充核验：[OpenAI API changelog](https://developers.openai.com/api/docs/changelog) 的8月21日记录。本日报保留当时价格边界，不保证未来费率。

**关注点：★★★★★**

将价格、输入长度、服务等级与期限分开建模。

### ⑤ Bedrock × VLM外観検査：Strong Model + Cheap Model + REVIEW

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/bedrock-vlm-visual-inspection-generated-prompt/

Bedrock 视觉检验实验从“外观描述比专业缺陷分类名更有效”的观察出发，让 **VLM 生成检验规格**。Claude Opus 5 根据正常和异常图片输出缺陷说明、正常特征、inspection_prompt 与 output_schema，Nova 2 Lite 或 Claude Haiku 4.5 逐张执行。前段只按产品运行一次，后段反复执行，因此可以使用不同成本的模型。

位置不再返回 bbox 坐标，而将 **3×3或4×4网格与单元名称** 烧进图片。输出 OK/REVIEW/NG，默认三次多数决，未过半交给目视；标记尺寸也要避免遮住缺陷。实现分别是 Python/Pillow 本地加工和浏览器 Canvas 加工后经 Lambda 调 Converse API，后者省去 Lambda Pillow 层。

检测阶段使用东京区 `jp.` 推理配置，但当时 Opus 5 规格生成走 `global.`，不能声称全链路都在日本。NEU-DET 从200×200扩至600×600，正常样本为缺陷图的无缺陷裁剪区，不是真实同产品良品。跨物体锈蚀测试虽有结果，仍错位约一格；实际需同产品、相近相机照明与距离的样本。

**Converse content 顺序** 测试固定一张纵向划伤、4×4、Nova2 Lite、temperature=0，各八次：图片前无对象提示为0/8，加入短句为8/8。因果机制是作者解释，不能推广所有图片。另一次参照图对比发现，模型把仅存在于缺陷参考图的纹理混入待检图；去掉参考后输入从4,023降至2,122 token，该例误报减少。

网格定量比较使用四张缺陷、两张正常、三次多数决和 Nova。最初单规格的4×4无漏检，重新每种网格生成三份规格后，平均 recall 为3×3的45%、4×4的71%，后者内部范围44%—100%。文案和格数同时变化，不能把首份零漏检归因给网格本身；必须用带答案的样本评价生成规格再选用。

模型比较中 Nova 漏掉低对比缺陷，Haiku 将部分不确定项输出 REVIEW。单张耗时分别1.1—1.5秒和3.4—4.9秒；三次投票合计输入/输出约4,500/400和6,100/1,000 token。按当时 Nova 单价与150日元/美元估计每图0.34—0.54日元，生成规格47—111秒。作者没有用猜测补上未查到的 Haiku/Opus 区域价格。

评估内 JSON 解析失败为零不等于检测零漏报。部分新 Claude 不接受 temperature，Fable 因该账户保留配置不能调用。实验定位于初筛与抽检，未证明能替代高速产线全检。面试可将规格生成、输入编排、真实良品和人工复核共同纳入评价，而非只比较模型名。

**关注点：★★★★★**

把自动规格的波动纳入独立检验，避免仅以单次成功判定效果。

## 3. 面接で使えるポイント

### 話題1：Agent Orchestration

**面试问题：**

> AI主導の開発フローを導入するとき、何を設計しますか。

**约 30 秒自然日语回答：**

> 進行条件と、人が承認する対象を明確にします。AI-DLC v2はTypeScriptのエンジンでステージを管理し、team.mdとproject.mdに学びを残します。ただし重複防止があっても、サイズの自動整理は記事では確認されていません。役割を分けるだけでなく、蓄積したルールを誰が見直すかまで決めて運用したいです。有効な規則と履歴も分けます。

**関連Project（学習用）：** 定期审查学习规则的开发流程练习

**キーワード：** `AI-DLC` / `TypeScript` / `team.md` / `project.md`

### 話題2：Claude Code / Reliability

**面试问题：**

> AI開発ツールを遠隔から使う際、どの不具合を優先して確認しますか。

**约 30 秒自然日语回答：**

> 接続できるだけでなく、停止やモデル変更が実行側へ届くかを確認します。Claude CodeのRemote Controlでは、Stopの不反映や一時的な403への対応が修正されています。ただし実行はローカルプロセスなので、端末を閉じればオフラインです。自社の接続条件で再接続と操作反映を試し、表示上の成功だけで判断しないようにします。

**関連Project（学習用）：** 检查远程停止与重连的开发环境

**キーワード：** `Remote Control` / `Stop` / `403`

### 話題3：Model Routing

**面试问题：**

> 学習型のモデルルーターを、生成型の判定役とどう比較しますか。

**约 30 秒自然日语回答：**

> 速度だけでなく、入力情報と確率の較正を比べます。prefill routerはhidden statesをPCAとMLPへ通し、判定文の生成を省きます。ただし記事の単発47問では確率が縮み、0.80のしきい値でstrongへ偏りました。会話途中の結果も読めません。実測の正誤ラベルを集め、分布内外と途中経過を別々に評価して役割を決めます。

**関連Project（学習用）：** 按分布评估路由概率的实验

**キーワード：** `prefill` / `hidden states` / `PCA` / `MLP`

### 話題4：AI Cost / Governance

**面试问题：**

> APIの値下げを、自社の費用見積もりへどう反映しますか。

**约 30 秒自然日语回答：**

> 値下げ率を月額へそのまま掛けず、処理条件ごとに計算します。GPT-5.6 Solは入力四ドル、出力二十ドルですが、272,000トークンを超える入力では料金条件が変わります。キャッシュとBatchも分けて集計します。少なくとも11月21日までの期間付き価格なので、期限後の見積もりは固定せず、APIキー別の実績で更新します。

**関連Project（学習用）：** 管理限时单价与实绩的费用表

**キーワード：** `GPT-5.6 Sol` / `Batch` / `272000`

### 話題5：VLM / Human Fallback

**面试问题：**

> VLMに検査プロンプトを作らせる場合、どこを検証しますか。

**约 30 秒自然日语回答：**

> 生成した仕様書自体を、正解付き画像で評価します。Bedrockの例ではセル名で位置を返し、OK、REVIEW、NGで人へ回す判断も残します。ただし4×4の同じ設定でも、仕様書によってrecallが44%から100%へ変わりました。グリッドの効果と文面の差を混同せず、同じ製品の正常品と低コントラストの欠陥を含めて確かめます。

**関連Project（学習用）：** 用同产品良品和缺陷筛选检验规格的练习

**キーワード：** `Bedrock` / `REVIEW` / `recall` / `グリッド`

## 4. 今日技术主题

**生成的判断标准也需要独立验收。**

`计划、概率、检验规格 → 独立评价对象 → 固定条件测量 → 批准、选择或退回`

积累规则仍需清理，高 AUC 仍可能校准失败，成功生成规格仍会漏掉低对比缺陷。要区分产出了什么，以及凭什么证据接受它。

## 5. 面试复习卡

### Q1

> 重複しない学習ファイルなら、長期運用でも整理は不要ですか。

**回答ポイント：** 重複防止と容量制御は別です。全量読み込みの負荷と古いルールを見直します。

### Q2

> AUCが高いルーターなら、固定しきい値でも正しく振り分けられますか。

## C-3. JLPT文法

### 1. ～にとどまらず
**Level：N1｜意味：** 不仅限于……  
**形：** `名詞 / 普通形 + にとどまらず`  
**使い方：** 说明 Workflow 设计不只关注成功路径，还覆盖失败、Retry、Fallback 与 Human Review。  
**例：** `Workflow設計では正常系にとどまらず、失敗時のRetryやFallbackも定義します。`  
**補足：** 适合范围扩展。

### 2. ～かねない
**Level：N1｜意味：** 可能导致不良结果  
**形：** `動詞ます形去ます + かねない`  
**使い方：** 警示把高风险流程完全交给动态 Agent 可能导致不可控行为。  
**例：** `Criticalな処理を完全にAgent任せにすると、予期しないStateへ進みかねません。`  
**補足：** 通常用于负面风险。

### 3. ～なくしては
**Level：N1｜意味：** 没有……就无法……  
**形：** `名詞 + なくしては`  
**使い方：** 强调明确 State / Transition 是确定性 Workflow 的基础。  
**例：** `明確なState定義なくしては、Workflowの再現性を高められません。`  
**補足：** 语气较强。

### 4. ～に応じて
**Level：N2｜意味：** 根据……相应调整  
**形：** `名詞 + に応じて`  
**使い方：** Router 按难度、Cost、Risk 选择 Model / Path。  
**例：** `Taskの難易度に応じてModelを切り替えます。`  
**補足：** Routing 面试高频。

### 5. ～た上で
**Level：N2｜意味：** 在……之后、在……基础上  
**形：** `動詞た形 + 上で`  
**使い方：** 自动系统先判定，再由 Human 做最终确认。  
**例：** `VLMの結果を確認した上で、人間が最終判断します。`  
**補足：** 流程说明很实用。

### 6. ～一方で
**Level：N2｜意味：** 另一方面……  
**形：** `普通形 + 一方で`  
**使い方：** 比较确定性 Workflow 与动态 Agent 的 Trade-off。  
**例：** `State Machineは再現性が高い一方で、自由度が下がることがあります。`  
**補足：** 适合 Trade-off。

### 7. ～にかかわらず
**Level：N2｜意味：** 不论……都……  
**形：** `名詞 + にかかわらず`  
**使い方：** 表达所有 Route / Model 都要遵守共同 Audit 与 Safety Rule。  
**例：** `利用するModelにかかわらず、実行履歴を必ず保存します。`  
**補足：** 适合统一 Policy。
