## 1. 今日最值得看的 5 篇

### ① MCP最新Roadmap：Agent Identity、非同期Task、Progressive Tool Discovery

**来源：＠IT**

**原文：** https://atmarkit.itmedia.co.jp/ait/articles/2608/25/news095.html

MCP 核心维护团队在8月22日提出五项发展重点，解决长任务中途干预、异步结果传递及企业授权等问题。传统请求—响应不足以覆盖持续运行的代理；服务端会话状态也会增加多实例调度的复杂度。

要先划清已发布与计划中的功能。官方说明7月28日规范已取消协议级会话和初始化握手，加入 `server/discover` 与列表缓存；Tasks 当前为 SEP-2663 官方扩展。新路线图准备完善 Webhook、channel 和进度通知的组合，并推动 Tasks 成熟后进入主体规范，不能写成这些计划已全部实现。

通信方向考虑将 Streamable HTTP over stdio 用于本地，减少两端重复逻辑。身份方向涵盖 DPoP、工作负载身份联合及更窄权限的委托。基础能力方向处理 `tools/call` 输出契约和工具逐步发现，避免一次暴露庞大目录；SDK 方向强调规范一致性、清晰 API 和准确文档。

证据是维护者发布的规划，不是兼容性或性能实测。限制在于具体交付仍取决于提案与实现，相关 SEP 获优先审查也不等于其他提案被拒绝。面试中可以据此说明协议版本、SDK 支持和扩展成熟度应分别确认。[官方发文](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)用于补充核对状态。

**关注点：★★★★★**

可以把协议兼容、身份授权和工具发现拆开讨论，避免按路线图假定已上线能力。

### ② Next.js 16.3とCritical RCE Patch

**来源：Publickey / GitHub Advisory**

**原文：** https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36

官方公告 **GHSA-p293-qw3h-jr36 / CVE-2026-75604** 描述 Windows 文件系统承载的 Next.js 服务存在未认证远程代码执行风险。其影响说明涉及 Pages Router 和未使用 Cache Component 的 App Router，判断对象应是服务器部署环境，不能仅看开发电脑。

受影响版本为 `>=13.4 <15.5.24`、`>=16.0 <16.3.3`，修复版为15.5.24与16.3.3。公告归类 CWE-22，即路径可能越过受限目录范围，但没有公开具体攻击链，因此详细版不补写无法核实的内部触发步骤。

官方证据给出 Critical、CVSS 9.0，攻击向量为网络，无需权限或用户操作，同时攻击复杂度为 High。对受影响 Windows 应用，公告明确没有已知绕过性缓解方案并要求升级。这些条件不能扩展成所有平台均受同一漏洞影响，也不能解释为该修复版消除了全部风险。

面试可说明如何依据资产清单核对版本和部署条件，再验证升级后的实际产物与功能回归。这是应用公告的工程判断，原文没有提供升级实验或漏洞复现数据。

**关注点：★★★★★**

将前端依赖升级与真实运行环境、部署产物和回归验证连接起来。

### ③ Claude Code Runtime Governance

**来源：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/20260825-cc-updates-v2-1-245/

DevelopersIO 汇总 v2.1.240〜v2.1.245 区间的五个已发布版本；v2.1.244 未在 npm 发布，v2.1.242 无变更日志。63项中的60项集中于 v2.1.243，不能把版本编号跨度当成六次完整发布。

`modelPicker` 用有序 `options` 配置模型项，每项要求 `model`，可加 `label` 和 `description`；`replaceBuiltInOptions` 控制替换或追加。作者通过临时设置实际确认两行顺序和默认列表替换。它支持 Vertex、Bedrock ID，但选项展示配置本身不能证明具备强制禁止模型的授权效果。

`promptCacheTtl`、`subagentPromptCacheTtl` 让 API key 和云提供商用户分开设置主会话与子代理缓存，例如一小时与五分钟。`/usage` 的 Loops 展示运行次数、总 token、单次 token、最后执行时间，可定位高消耗循环。收益受重用间隔等条件影响，原文没有测出固定节省比例。

稳定性更新包括 API 约三分钟无响应后超时并重试一次，非交互及 SDK 会话的远端 MCP 自动重连或报错，以及命令返回0仍保留网络拒绝详情。会话间消息 socket 在三十秒内收不到完整一行将断连，调用方应先准备数据再连接，这是需检查自有脚本的破坏性变化。

约340→75MB下载量及每会话约40〜70MB内存减少来自官方变更说明，与作者的选择器操作实验须区分。v2.1.245 修复 glibc 2.44 环境启动崩溃。面试价值在于把配置、成本观察和故障反馈分别验证，不能仅凭更新说明宣称自家任务更快。

**关注点：★★★★★**

能区分配置能力与实际收益，并检查运行失败是否被正确呈现。

### ④ MCP Tool DefinitionのContext Cost

**来源：Zenn**

**原文：** https://zenn.dev/kazu_aiengineer/articles/mcp-server-tool-definition-token-cost

Zenn 作者把七个 MCP 服务的 `tools/list` 结果转换成 OpenAI function JSON，用 `o200k_base` 逐项计数，得到131个工具、23,964 token。除以20万上下文窗口约为12%，这是目录规模的估算，不是抓取 Claude 实际请求后的精确读数。

实验环境为 Node 24.14.1、Python 3.13.12，只读取工具定义，无需连接 Azure 订阅。Azure MCP 3.0.0-beta.37 单独占14,709，即样本总量61%；总量包含演示用 server-everything，去掉后是118工具、22,806。description 与 schema 之外还有 JSON 包装，因此两项不能直接相加充当总值。

Azure 的 single/namespace/consolidated/all 分别为1/68/132/449工具，对应298/14,709/24,338/122,221 token。all 与 single 相差约410倍；consolidated 比默认 namespace 更大，还超过文章引用的128工具上限。文档推荐不能替代本版实测，作者因此使用 `--namespace storage` 或 `--tool` 缩小范围。

一工具的 sequential-thinking 达858，九工具的 memory 为953，说明工具数不能代表负担。限制包括 OpenAI 计数器与 Claude 差异、名称前缀和提供商格式化，以及客户端过滤或延迟加载。原文对全量发送的下界说明不适用于已裁剪目录的所有请求，更不能直接推导账单。面试可以说明怎样固定版本和口径，检查缩减目录后任务选择是否仍正确。

**关注点：★★★★★**

用定义规模、版本与实际客户端行为解释上下文开销。

### ⑤ AI Vulnerability DiscoveryとTriage

**来源：＠IT**

**原文：** https://atmarkit.itmedia.co.jp/ait/articles/2608/25/news036.html

＠IT 根据 Epoch AI 的 CVE 数据工具报道，主要21家组织的 High/Critical 公布数量从六月约1,550增至七月约2,500，后者约为 Mythos 发布前月度纪录的五倍，环比约60%。分母是这一组选定机构的历史公开纪录，不是全球漏洞实际总存量。

CVE 按公开日统计，不等于发现日期。CNA 的编号政策和对历史修复的处理也会改变数量，例如 Linux 在2024年2月成为 CNA 后，对回移修复赋予较多编号，推高后续统计。全体 CNA 数据与21组织比较是不同观察范围，不能混用。

Mythos Preview、Project Glasswing 与数量增长的时间相关，不能证明新增漏洞全由 AI 发现，更不能推出风险本身扩大五倍。限制来自发布流程和制度差异；厂商关于发现能力的陈述也不是因果实验。真正新增的运营负担包括验证、筛选影响、通知、修复和分发。

原文建议将 CVSS 与实际使用产品、外网可达性、认证条件、业务重要度及已知利用结合，并关联资产台账、SBOM、云和终端信息。缓解替代措施必须逐漏洞确认，不能据泛用建议声称今天的 Next.js 漏洞已有绕过方案。面试可据此解释为何要按自家暴露面分诊，而非按编号数量平均分配资源。

**关注点：★★★★★**

区分统计增幅与自身风险，用资产背景确定优先级。

## 3. 面接で使えるポイント

### 話題1：MCP / AI Agent

**面试问题：**

> MCPの新しい仕様を業務へ取り入れるとき、何を確認しますか。

**约 30 秒自然日语回答：**

> まず、公開済みの仕様と今後の計画を分けます。MCPではserver/discoverによる機能確認が入り、Tasksは公式拡張になっています。一方、段階的なツール発見や権限委譲の整備はロードマップの重点です。利用するSDKと接続先の対応版を照合し、長い処理の進捗通知と認可を実際に試します。計画だけを根拠に本番の機能を約束しません。

**関連Project（学習用）：** 维护规范支持表的 MCP 连接

**キーワード：** `server/discover` / `SEP-2663` / `DPoP`

### 話題2：Next.js / Security

**面试问题：**

> Next.jsの重大な脆弱性情報を受け取ったら、どう対応しますか。

**约 30 秒自然日语回答：**

> 公告の条件を、実際の配備環境と照合します。今回の問題はWindowsのファイルシステム上の対象構成で、修正版は15.5.24と16.3.3です。認証なしでのコード実行が問題となり、公式は既知の回避策がないとしています。依存一覧だけで判断せず、稼働中の版とルーター構成を確認して更新し、主要画面と配備物まで検証します。

**関連Project（学習用）：** 核对部署环境的 Next.js 更新

**キーワード：** `CVE-2026-75604` / `Windows` / `16.3.3`

### 話題3：Claude Code

**面试问题：**

> 開発エージェントのコストを設定で調整するとき、何を測りますか。

**约 30 秒自然日语回答：**

> 会話とサブエージェントの使い方を分けて測ります。Claude CodeではpromptCacheTtlとsubagentPromptCacheTtlを別に設定でき、主会話を一時間、短い処理を五分にできます。ただし、長くすれば必ず安くなるわけではありません。再利用の間隔を確認し、usageのLoopsで実行回数と一回当たりのトークンを見て、不要な反復から調整します。

**関連Project（学習用）：** 计量缓存与循环的开发环境

**キーワード：** `promptCacheTtl` / `subagentPromptCacheTtl` / `Loops`

### 話題4：MCP / Context

**面试问题：**

> MCPを増やして入力が重くなった場合、どう調べますか。

**约 30 秒自然日语回答：**

> tools/listの説明とスキーマを、版と計数法を固定して数えます。記事ではAzure MCPのsingleとallで約410倍の差があり、ツール数だけでは重さが分かりません。ただし約12%はOpenAI系の計数器による近似で、Claudeの実測値ではありません。必要なnamespaceへ絞り、実際のクライアントが送る範囲と、ツール選択の正確さを確かめます。

**関連Project（学習用）：** 对比工具定义的输入测量

**キーワード：** `tools/list` / `o200k_base` / `namespace`

### 話題5：Security

**面试问题：**

> 公開されるCVEが急増したら、対応の優先順位をどう決めますか。

**约 30 秒自然日语回答：**

> 件数だけで危険度を決めず、自社の資産と照合します。記事の約五倍は主要21組織の公開件数で、発見日やAIによる因果を示す値ではありません。CNAの割り当て方も影響します。SBOMから対象の依存を探し、外部からの到達性、認証の要否、業務への影響を重ねて修正順を決めます。対応後は修正版の稼働も確認します。

**関連Project（学習用）：** 结合资产与 CVE 的响应台账

**キーワード：** `CVE` / `CNA` / `SBOM`

# B. 重点知识与面试应用

## 1. MCP最新Roadmap：Agent Identity、非同期Task、Progressive Tool Discovery

1. Tasks 扩展与主体规范不是同一状态。
2. 工具发现和返回值契约分别解决输入规模与输出一致性。
3. 路线图不能证明已实现。

## 2. Next.js 16.3とCritical RCE Patch

1. 核对服务端 OS 与路由配置。
2. 精确读取版本区间。
3. 不臆造未披露攻击机制。

## 3. Claude Code Runtime Governance

1. 模型选择界面不等于权限强制。
2. TTL 要与重用间隔配合。
3. 退出码0不必然表示网络请求成功。

## 4. MCP Tool DefinitionのContext Cost

1. 工具数量不等于输入大小。
2. 混合不同模型口径的比率是近似。
3. 过滤和延迟加载会改变真实发送量。

## 5. AI Vulnerability DiscoveryとTriage

1. 公开日期不等于发现日期。
2. CNA 政策影响时间序列。
3. 数量增长无法证明 AI 的因果作用。

# C. 日本語学习｜JLPT + IT日本語

例句和关联项目是围绕当天主题制作的学习材料，不是原文引文或已证实的企业案例。JLPT 等级为学习参考。

## C-1. JLPT語彙

### 1. 影響（えいきょう）
**品詞：** 名詞｜**意味：** 影响｜**目安：N2**  
**コロケーション：** 影響範囲 / 影響を受ける / 影響を評価する  
**文脈：** Security Advisory 与 Version Upgrade 的第一步是确认自家 Service 是否受影响。  
**例：** `脆弱性が自社Serviceに与える影響を調査します。`  
**中文：** 调查漏洞对自家服务造成的影响。  
**ニュアンス：** 常与「範囲・与える・受ける」搭配。

### 2. 運用（うんよう）
**品詞：** 名詞｜**意味：** 运行、运维｜**目安：N2**  
**コロケーション：** 本番運用 / 安定運用 / 運用Cost  
**文脈：** MCP Server 与 Claude Code Runtime 进入生产后都需要长期治理。  
**例：** `AI Agentの本番運用では監査ログを保存します。`  
**中文：** 生产运行 AI Agent 时保存审计日志。  
**ニュアンス：** 不仅是“使用”，还包含持续维护与治理。

### 3. 依存（いぞん）
**品詞：** 名詞｜**意味：** 依赖｜**目安：N1**  
**コロケーション：** 依存関係 / 特定Versionへの依存 / 外部Serviceへの依存  
**文脈：** MCP Roadmap、Framework Patch 与 Dependency Risk 都需要了解依赖关系。  
**例：** `特定MCP Serverだけに依存しない構成を検討します。`  
**中文：** 考虑不只依赖特定 MCP Server 的架构。  
**ニュアンス：** 「依存関係」对应 dependency。

### 4. 監査（かんさ）
**品詞：** 名詞｜**意味：** 审计｜**目安：N1**  
**コロケーション：** 監査ログ / 監査証跡 / 定期監査  
**文脈：** Claude Code Runtime 的 Tool Call 与 Permission Change 应可追溯。  
**例：** `Tool CallとPermission変更を後から監査できるように記録します。`  
**中文：** 记录 Tool Call 和 Permission 变更，以便事后审计。  
**ニュアンス：** 强调合规、责任链和追溯。

### 5. 緊急（きんきゅう）
**品詞：** 名詞｜**意味：** 紧急情况、紧急性｜**目安：N2**  
**コロケーション：** 緊急対応 / 緊急Patch / 緊急度  
**文脈：** Critical Vulnerability 可能需要紧急 Patch 与加速 Triage。  
**例：** `RCE Riskが高い場合は緊急対応を行います。`  
**中文：** RCE 风险高时进行紧急处理。  
**ニュアンス：** 也可作な形容词，如「緊急な対応」。

### 6. 管理する（かんりする）
**品詞：** 動詞・サ変｜**意味：** 管理｜**目安：N3**  
**コロケーション：** Modelを管理する / 権限を管理する / Token Budgetを管理する  
**文脈：** 企业 Runtime 需要持续管理 Model、Tool、Permission 与 Token Budget。  
**例：** `利用できるModelとToolをRuntime側で管理します。`  
**中文：** 在 Runtime 侧管理可使用的 Model 与 Tool。  
**ニュアンス：** 强调持续控制和规则化运用。

### 7. 確認する（かくにんする）
**品詞：** 動詞・サ変｜**意味：** 确认、核实｜**目安：N3**  
**コロケーション：** Versionを確認する / 影響を確認する / 設定を確認する  
**文脈：** Security Advisory 发布后要核对 Version、Exposure 与 Asset。  
**例：** `Advisoryが公開されたら利用中のVersionを確認します。`  
**中文：** Advisory 发布后确认正在使用的版本。  
**ニュアンス：** 比「見る」正式，含核对正确性的意味。

### 8. 制御する（せいぎょする）
**品詞：** 動詞・サ変｜**意味：** 控制｜**目安：N2**  
**コロケーション：** Accessを制御する / Policyで制御する / 実行を制御する  
**文脈：** MCP Tool 与 Claude Code Runtime 应在执行层控制权限和网络访问。  
**例：** `MCP ToolへのAccessをRuntime Policyで制御します。`  
**中文：** 通过 Runtime Policy 控制对 MCP Tool 的访问。  
**ニュアンス：** 比「管理する」更强调系统逻辑层面的限制。

### 9. 検証する（けんしょうする）
**品詞：** 動詞・サ変｜**意味：** 验证｜**目安：N2**  
**コロケーション：** Patchを検証する / 影響を検証する / 自動的に検証する  
**文脈：** Patch 不能只 Apply，还要用 Regression / E2E 验证已有功能。  
**例：** `Patch適用後はE2E Testで既存機能への影響を検証します。`  
**中文：** 应用 Patch 后通过 E2E Test 验证对现有功能的影响。  
**ニュアンス：** 强调通过测试和证据确认。

### 10. 把握する（はあくする）
**品詞：** 動詞・サ変｜**意味：** 掌握、准确了解｜**目安：N1**  
**コロケーション：** 利用状況を把握する / Token量を把握する / 影響範囲を把握する  
**文脈：** Context Engineering 需要掌握 Tool Definition / History 实际占用了多少 Token。  
**例：** `MCP Server追加前にTool Definitionが消費するToken量を把握します。`  
**中文：** 添加 MCP Server 前掌握 Tool Definition 消耗的 Token 量。  
**ニュアンス：** 比「見る」更强调系统性掌握。

### 11. 考慮する（こうりょする）
**品詞：** 動詞・サ変｜**意味：** 考虑、顾及｜**目安：N1**  
**コロケーション：** Costを考慮する / Securityを考慮する / 将来性を考慮する  
**文脈：** 技术选型不能只看 Feature，还需纳入 Cost、Security 与 Future Roadmap。  
**例：** `Model選定では精度だけでなくCostとSecurityも考慮します。`  
**中文：** 模型选择不仅考虑精度，也考虑成本与安全。  
**ニュアンス：** 比「考える」正式，强调纳入决策因素。

### 12. 絞り込む（しぼりこむ）
**品詞：** 動詞・五段｜**意味：** 筛选、缩小范围｜**目安：N1**  
**コロケーション：** 脆弱性を絞り込む / 候補を絞り込む / 対象を絞り込む  
**文脈：** Vulnerability Triage 要从大量 CVE 中筛出真正影响当前 Asset 的项。  
**例：** `Asset情報を使って対応が必要なCVEを絞り込みます。`  
**中文：** 使用 Asset 信息筛选出需要处理的 CVE。  
**ニュアンス：** 强调从大量候选逐步缩小。

### 13. 照合する（しょうごうする）
**品詞：** 動詞・サ変｜**意味：** 核对、对照｜**目安：N1**  
**コロケーション：** Versionを照合する / Assetと照合する / 一覧と照合する  
**文脈：** SBOM / Inventory 与 CVE Feed 要进行对照才能快速判断影响。  
**例：** `CVE対象VersionをAsset Inventoryと照合します。`  
**中文：** 将 CVE 目标版本与 Asset Inventory 核对。  
**ニュアンス：** 比「確認する」更强调两个数据源之间对照。

### 14. 重要（じゅうよう）
**品詞：** な形容詞｜**意味：** 重要的｜**目安：N3**  
**コロケーション：** 重要な脆弱性 / 重要な判断 / 重要性が高い  
**文脈：** Triage 的本质是区分哪些 Issue 对当前资产真正重要。  
**例：** `Internet公開Assetに影響する脆弱性を重要な対象として扱います。`  
**中文：** 把影响互联网公开资产的漏洞作为重要对象处理。  
**ニュアンス：** 比「大事」正式。

### 15. 脆弱（ぜいじゃく）

**コロケーション：** 脆弱なVersion / 攻撃に脆弱 / 脆弱性  
**文脈：** Next.js Security Patch 直接涉及存在 Vulnerability 的 Version。

**ニュアンス：** 名词「脆弱性」对应 vulnerability。

### 16. 適切（てきせつ）

## C-3. JLPT文法

### 1. ～恐れがある
**Level：N1｜意味：** 有……风险  
**形：** `動詞辞書形 / 名詞 + の + 恐れがある`  
**使い方：** 用于 Security Advisory 和 RCE 等正式风险提示。  
**例：** `脆弱なVersionを使い続けるとRemote Code Executionにつながる恐れがあります。`  
**補足：** 正式风险表达。

### 2. ～にとどまらず
**Level：N1｜意味：** 不仅限于……  
**形：** `名詞 / 普通形 + にとどまらず`  
**使い方：** 说明 Vulnerability Triage 不只看 CVSS，也要结合 Asset Context、Exposure 和 Exploitability。  
**例：** `TriageではCVSSにとどまらず、Assetの公開範囲やExploitabilityまで確認します。`  
**補足：** 适合范围扩展。

### 3. ～かねない
**Level：N1｜意味：** 可能导致不良结果  
**形：** `動詞ます形去ます + かねない`  
**使い方：** 警示无筛选地加载 Tool / Context 会造成 Cost 或 Security 问题。  
**例：** `不要なTool Definitionを大量に読み込むと、Context Costを増やしかねません。`  
**補足：** 用于负面风险。

### 4. ～に応じて
**Level：N2｜意味：** 根据……相应调整  
**形：** `名詞 + に応じて`  
**使い方：** 根据 Risk、Asset、Context 调整优先级和策略。  
**例：** `Riskの高さに応じて対応優先度を変えます。`  
**補足：** Triage 语境自然。

### 5. ～た上で
**Level：N2｜意味：** 在……之后、在……基础上  
**形：** `動詞た形 + 上で`  
**使い方：** 确认影响后再 Patch / Rollout。  
**例：** `影響範囲を確認した上でPatchを適用します。`  
**補足：** 流程说明高频。

### 6. ～に基づいて
**Level：N2｜意味：** 基于……  
**形：** `名詞 + に基づいて`  
**使い方：** Triage 应依据 SBOM、Asset Inventory 与实际 Exposure。  
**例：** `Asset Inventoryに基づいてCVEの対応要否を判断します。`  
**補足：** 明确表示判断依据。

### 7. ～一方で
**Level：N2｜意味：** 另一方面……  
**形：** `普通形 + 一方で`  
**使い方：** 说明 MCP 能力增加与 Context Cost / Attack Surface 的 Trade-off。  
**例：** `Toolを増やすとAgentの能力は広がる一方で、ContextとSecurityのCostも増えます。`  
**補足：** 适合 Trade-off。
