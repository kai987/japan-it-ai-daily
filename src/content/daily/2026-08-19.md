## A. 详细文字版

### 今日最值得看的 5 篇

1. **AWS Continuum**：漏洞检测结果可以返回给 Coding Agent，让 Agent 根据风险继续修改代码，形成 Security Feedback Loop。
2. **Zed Sandbox**：文件写入、`.git` 修改和 Network Access 等高风险能力应由 OS Sandbox 决定允许还是阻止，而不是写一句 System Prompt。
3. **MCP vs Direct API**：如果只有一个 App 和少量 Tool，Direct API 可能更简单；多个 Agent、团队和共享 Tool 时，MCP 的标准化价值才会明显提高。
4. **LLM Observability**：Wantedly 从 Infra Monitoring、Distributed Tracing、RUM 继续走向 LLM Observability，目标都是解释系统为什么产生某个结果。
5. **FHE / HEIR**：加密状态计算适合金融、医疗、内部敏感数据等 Privacy-preserving AI 场景，但仍处于工程化发展阶段。

### 面接で使えるポイント

> AI Agentの安全性は、Promptで禁止するだけでは不十分で、SandboxやRuntime Policyで実行可能範囲を強制的に制限する必要があります。

> MCPは標準化のメリットが運用コストを上回る場合に採用し、単一Appと少数ToolならDirect APIの方が簡単な場合もあります。

### 今日の技术主题：Runtime-enforced Agent Security

成熟的 Agent Security 可以分为 **Instruction → Permission Policy → Sandbox / Runtime Enforcement → Audit / Security Validation**。模型是概率性的，但“这个目录能不能写、这个网络能不能访问”应由确定性 Policy 判断。Sandbox 可以限制 Blast Radius，却不能保证 Agent 生成内容一定正确，因此仍需 Test、Security Scan 和 Human Review。

### 面试复习卡

- `Prompt上の禁止事項だけで安全ですか。` → No / Runtime Enforcement / Sandbox。
- `MCP採用判断の基準は何ですか。` → App数 / Tool数 / Team共有 / Governance。
- `LLM Observabilityは何を見るべきですか。` → Usage / Trace / User Experience / Continuous Improvement。

## B. 重点总结和面试可用的知识点

### AWS Continuum
**中文：** Security Scan 应嵌入 AI Coding 流程，把漏洞结果反馈给 Agent 继续修复。

**日本語：** Security検証をAI Coding Workflowへ組み込み、検出結果をAgentへFeedbackすることで継続的に修正できます。

### Zed Sandbox
**中文：** Prompt 不是 Security Boundary，关键权限必须由 Runtime / OS 强制控制。

**日本語：** Prompt上のInstructionではなく、RuntimeやOS SandboxでFile・Network Accessを強制的に制御することが重要です。

### MCP vs Direct API
**中文：** MCP 适合多 App、多团队共享 Tool 的标准化场景；简单单应用不一定值得引入额外层。

**日本語：** MCPは複数のAI AppやTeamでToolを再利用する場合に価値が高く、単純な構成ではDirect APIが適する場合もあります。

### Wantedly Observability
**中文：** LLM 应进入既有 SRE / Observability 体系，而不是孤立成完全不同的运维世界。

**日本語：** 生成AIもApplicationやRUMと同様に、利用状況を観測して継続改善することが重要です。

### Google HEIR
**中文：** FHE 尝试让模型在不解密数据的情况下计算，为高敏感数据 AI 提供新的 Privacy 层。

**日本語：** FHEではデータを復号せずに計算できるため、Privacyが重要なAI処理への応用が期待されます。
