# A. 详细文字版

今天关注漏洞判定、操作系统隔离、工具连接标准化、用户侧故障追踪和密文计算，逐项说明技术保护到哪里、还有哪些责任未被覆盖。

## 1. 今日最值得看的 5 篇

### ① AWS、Anthropic・OpenAIと連携し「AWS Continuum」をClaude Code / Codex / Kiroへ統合

**来源：AWS Security Blog**

**原文：** https://aws.amazon.com/blogs/security/aws-partners-with-anthropic-and-openai-to-bring-aws-continuum-into-developer-workflows/

AWS 官方宣布将 **AWS Continuum for code vulnerabilities** 接入 Claude Code、Codex、Kiro 的计划。背景是模型发现更多疑似漏洞后，企业仍须判断哪些真正影响自己的环境，并完成验证和修复。文章时点 Continuum 本体为 **Preview**，开发环境集成为 **coming soon**，不能写成已全部上线。

计划中的流程由开发工具发起按需扫描，将发现送入 Continuum。它结合 **IAM 策略、网络拓扑、配置和暴露面** 排序，在沙箱验证，再把带环境上下文的结果交回编码助手调整建议。这样把代码层的可疑模式与实际环境下有意义的问题分开处理。

底层描述为多模型及代理协调的 **agent-team loop**，贯穿发现、优先级、验证和修复。存量代码扫描与新代码建议集成是两个入口；AWS 把编排层视作与身份、策略、观测同等需要管理的基础设施，而不是只替换一个模型。

证据包含设计合作方 Rivian 的评价，但没有修复时间对照、误报率或全漏洞召回实验。限制是不能宣称所有建议已获安全保证。面试可围绕环境上下文如何影响优先级、验证证据如何返回评审展开，并核对预览及计划功能的实际可用范围。

**关注点：★★★★★**

把发现数量推进到环境相关优先级与验证证据，并保留预览及计划边界。

### ② Zed Agent Panel：OS SandboxでAgentを強制的に制限

**来源：Zed**

**原文：** https://zed.dev/blog/sandboxing

Zed 官方说明 **1.14 起默认隔离 agent panel 的 terminal 和 fetch**。限制由操作系统执行，不依赖模型遵守提示；默认禁止项目外写入、`.git` 写入及联网。额外权限需附理由申请，但 `.git` 写权限不能申请，因为可能写入稍后在沙箱外执行的 Git hook。

macOS 使用 **Seatbelt**，Linux 使用 **Bubblewrap 的 namespaces**，Windows 经 WSL；Linux/WSL 需具备非 setuid 的 `bwrap`，非 WSL Windows shell 不受此保护。相比只匹配命令名称，OS 隔离限制的是实际资源访问，避免把命令字符串规则误作完整边界。

文中用 **TOCTOU** 解释批准后、调用 Bubblewrap 前的 symlink 换位：界面批准的路径文字不变，实际指向却已改变。Zed 表示会识别并 **fail-closed**。这是防御设计说明，不是报告该漏洞目前仍可在 Zed 成功利用，也不是建议读者执行攻击。

限制包括普通 edit、ACP 外接代理、LSP/MCP、常规终端及外部程序不在保护范围。生成 `build.rs` 或过程宏后由别的工具运行，仍可能离开沙箱；create_directory 在拒绝后清理前还可能短暂创建目录，官方另有说明。

因而不保留“Zed 中全部操作已隔离”的概括。证据是官方设计介绍，不是独立审计证明没有任何缺陷。面试应逐项说明工具和 OS 覆盖、批准路径的实际对象，以及生成文件后续被谁执行。

**关注点：★★★★★**

说明 OS 强制的价值，也保留工具覆盖及生成物后续执行的盲区。

### ③ MCPは本当に常にDirect APIより優れているのか？

**来源：Zenn**

**原文：** https://zenn.dev/taru_neko/articles/mcp-or-direct-api

Zenn 文章讨论 **MCP 与直接 API 连接** 的选择，反对仅按接入服务数量下结论。一个 AI 应用调用少量 API 时，把自定义实现接到 Function Calling 可能更简单。但 MCP 不会消除 GitHub 等下游 API 的适配工作，还增加服务端建设维护。

它的价值在于多个 Host/Client 共用一致的工具连接。**1应用×4工具×10人，与10应用×4工具×1,000人** 是设计情境例，不是实测盈亏门槛。需共同考虑应用、用户、团队规模以及审计需求，不能写成超过某个接口数就必须使用。

**Host 到 MCP Server 的授权**与 **Server 到 GitHub 的凭据**分属两层。**Enterprise-Managed Authorization（EMA）** 利用企业 IdP 集中管理前者，不自动解决后者。补查[官方说明](https://modelcontextprotocol.io/extensions/auth/enterprise-managed-authorization)，该扩展还依赖客户端支持，不会默认在所有客户端生效。

[7月28日规格变更](https://modelcontextprotocol.io/specification/2026-07-28/changelog)移除协议会话和初始化握手，每次请求带版本及能力元数据，使无状态部署更容易组织。但业务状态不会自动消失，各实现也必须检查兼容版本。限制是原文属于架构思考，没有成本或速度对照实验；实际判断应比较复用和集中管理价值与接入、授权及维护负担。

**关注点：★★★★★**

以共用范围说明 MCP 价值，并区分两层认证边界及实际维护成本。

### ④ Wantedly：ObservabilityをInfraからLLMへ拡張

**来源：＠IT**

**原文：** https://atmarkit.itmedia.co.jp/ait/articles/2608/19/news016.html

＠IT 两页访谈追溯 Wantedly 从 **Heroku 到 AWS、Kubernetes、分布式追踪及 RUM** 的演进。服务约4万家企业、450万用户，公司120人中约50名工程师，属于背景规模，不是监控工具效果数字。

2014年因美国 Heroku 带来的延迟及移动业务需要迁往 AWS，同时保留开发者专注代码的方式，采用 Docker，并引入当时支持容器监控的 Datadog。2016年前后试验 Kubernetes，2018年前推进全面微服务化，让新项目减少对基础设施人员长期驻场的依赖，团队可独立部署。

然而监测到故障不等于能定位原因。团队使用 **Datadog APM 分布式追踪**，将原先分属应用和基础设施的监控平台合并。数据库负载上升的位置未必是发起异常调用的根因，所以要沿跨服务请求调查，而非只看 CPU 或单点警报。

**Wantedly Hire 的 RUM** 将前端操作、页面跳转与后端追踪结合。企业定制招聘流程不同，即便同一画面也可能因不同操作触发问题，RUM 补足 APM 无法单独看清的用户行为上下文，对前端面试尤其具体。

原文还介绍 Bedrock 支持的个人资料、候选人及书类筛选功能，但 **LLM 可观测性仍在推进研究**，不能写成已测出 AI 质量提升。限制是访谈没有故障定位耗时的前后对照；相关文章中其他公司的“5分钟”等数字也不属于 Wantedly，因此不混入此案例。

**关注点：★★★★★**

用 RUM 与 APM 结合的具体例子，解释为什么前端操作和后端链路必须关联。

### ⑤ Google HEIR：AIが暗号化状態のデータを直接処理する

**来源：Publickey**

**原文：** https://www.publickey1.jp/blog/26/googleaiheirai.html

Publickey 介绍 Google 的 **HEIR**：使用 **完全同态加密（FHE）** 的开源 AI 编译器。问题是让处理方不接触明文也能执行计算；方法将模型逻辑变为可处理密文的运算，保护阶段不同于仅在传输中加密。

开发者在 Python 代码用**注解指定需保持秘密的数据**，由编译器转换为 FHE 逻辑，减少逐条手写密码运算的负担。但报道未证明任意 Python、任意巨型模型均可无修改编译，因此不加入这种通用性承诺。

四项应用方向包括推荐、银行卡欺诈检测、基于 **Kitsune** 的网络异常检测及热词检测，属于共同研究和项目介绍，而非读者环境的实测。这里的密文计算也不能理解为可无密钥直接破解或分析所有现有加密通信。

限制是仍在开发，原文没有与明文运算比较延迟、成本及精度。故不保留同速推理、完全解决隐私等外推。面试可从哪些数据应对计算方保密、哪些运算能转换、性能代价如何验证三个具体问题解释采用条件。

**关注点：★★★★★**

区分传输加密与计算中保密，保留 FHE 编译输入范围和性能尚未量化的边界。

## 3. 面接で使えるポイント

### 話題1：AI Coding / Security

**面试问题：**

> AIが多くの脆弱性を挙げたとき、どれから対応しますか。

**约 30 秒自然日语回答：**

> 実際の環境で影響するかを確認して優先順位を付けます。ContinuumはIAMポリシーやネットワークの露出を使い、サンドボックスで検証した結果を開発側へ返す構想です。ただし本体はPreviewで、Codexなどとの統合は予定です。検出数だけで評価せず、重大と判断した理由と再現の根拠をレビューします。既存コード向けの利用とも分けます。

**関連Project（学習用）：** 为虚构漏洞发现附加环境信息，记录优先级为何改变。

**キーワード：** `Continuum` / `IAM` / `Preview`

### 話題2：Agent Security / Sandbox

**面试问题：**

> エージェントにサンドボックスがあれば、生成物も安全ですか。

**约 30 秒自然日语回答：**

> 保護される実行経路を確認する必要があります。ZedはSeatbeltやBubblewrapでterminalとfetchを制限します。ただし、通常の編集やLSPは対象外です。生成されたbuild.rsを外のターミナルで動かせば、別の経路で実行されます。指示だけに頼らず、書き込み先と後で実行する道具の両方を確認します。隔離は保護の一層と考えます。

**関連Project（学習用）：** 在专门测试环境整理不同工具、执行路径的隔离覆盖。

**キーワード：** `Seatbelt` / `Bubblewrap` / `build.rs`

### 話題3：MCP / Architecture

**面试问题：**

> 外部APIを使うAIアプリには、必ずMCPを入れますか。

**约 30 秒自然日语回答：**

> 同じツールをどこまで共有するかで判断します。一つのアプリなら直接APIでも十分ですが、複数のHostで使うならMCPの共通化に価値があります。EMAは企業IdPでサーバーへのアクセスを管理します。ただし、GitHubなど下流の認証情報は別です。接続数だけで決めず、利用者と保守の範囲を整理します。各APIの仕様変更への追従も残ります。

**関連Project（学習用）：** 从两个应用使用同一工具，对照直接 API 与 MCP 的维护位置。

**キーワード：** `MCP` / `EMA` / `IdP`

### 話題4：SRE / LLM Observability

**面试问题：**

> バックエンドの監視だけでは分からない画面の障害を、どう調べますか。

**约 30 秒自然日语回答：**

> 利用者の操作とサーバー側の処理をつなげて調べます。Wantedly HireはRUMで画面遷移や操作を見て、Datadog APMのトレースと組み合わせています。企業ごとに使い方が異なるため、同じ画面でも条件を揃えて確認します。記事には時間短縮の実測はないので、原因を追えたかと調査時間を別に記録します。監視の統合は担当間の連携にも役立ちます。

**関連Project（学習用）：** 将测试页面操作标识与后台追踪关联，复现并定位错误。

**キーワード：** `Wantedly Hire` / `RUM` / `Datadog APM`

### 話題5：Privacy / FHE

**面试问题：**

> 機密データを外部で計算するとき、FHEは何を変えますか。

**约 30 秒自然日语回答：**

> 計算する側に平文を見せず、暗号化したまま演算する選択肢になります。HEIRはPythonで秘密にするデータを指定し、FHE向けにロジックを変換します。Kitsuneの異常検出も応用例です。ただし開発段階で、記事に遅延や費用の比較はありません。対象の演算を変換できるかと、必要な性能を確かめて選びます。秘密にしたい入力も先に決めます。

**関連Project（学習用）：** 用小型数值计算检查秘密输入标注及可转换运算。

**キーワード：** `FHE` / `HEIR` / `Kitsune`

## 4. 今日技术主题

### 安全与可观测性涉及多种边界

调用者权限、OS 允许的操作、谁能读取数据及用户经历的故障，是不同层次。统一 MCP 授权之后仍有下游凭据，隔离 Zed 的 terminal 之后仍有其他执行工具。

```text
调用方授权 → 可执行操作 → 数据访问 → 结果和影响观测
```

Continuum 把环境信息与发现相连，Wantedly 把用户操作与链路相连，HEIR 处理计算方无需看明文的问题。明确解决的是哪一层，才能有依据地解释采用价值。

## 5. 面试复习卡

### Q1

> Zedの隔離がある場合、どの経路が対象外ですか。

**回答ポイント：** 通常の編集、ACP、LSP/MCP、通常ターミナルなどです。生成物を外で実行する経路も確認します。

### Q2

> MCPを入れると下流APIの認証情報は不要ですか。

**回答ポイント：** 不要にはなりません。HostからServerへの認可と、Serverから外部サービスへの認証を分けます。

### Q3

> HEIRの応用例から、平文と同じ性能だと言えますか。

**回答ポイント：** 言えません。記事は開発中の事例紹介で、遅延・費用・精度の比較数値はありません。

# B. 重点知识与面试应用

## 1. AWS、Anthropic・OpenAIと連携し「AWS Continuum」をClaude Code / Codex / Kiroへ統合

1. 本体预览与开发工具未来集成需分开。
2. 代码与实际环境共同决定优先级。
3. 合作方评价不等于量化性能实验。

## 2. Zed Agent Panel：OS SandboxでAgentを強制的に制限

1. 默认隔离对象是 terminal 与 fetch。
2. TOCTOU 关注检查时和使用时指向发生变化。
3. 普通编辑及外部构建不属于统一保护范围。

## 3. MCPは本当に常にDirect APIより優れているのか？

1. 接口数量不足以决定标准化收益。
2. EMA 授权与下游凭据是两个问题。
3. 协议无状态不消除业务状态和版本兼容管理。

## 4. Wantedly：ObservabilityをInfraからLLMへ拡張

1. 独立部署能力需配合跨服务调查机制。
2. RUM 将页面行为与后台追踪连接。
3. 生成 AI 观测仍在研究，不是已量化的效果。

## 5. Google HEIR：AIが暗号化状態のデータを直接処理する

1. FHE 面向保持密文的计算。
2. HEIR 按秘密数据标记转换计算逻辑。
3. 应用介绍不能证明性能与明文等价。

# C. 日本語学习｜JLPT + IT日本語

例句和关联项目是围绕当天主题制作的学习材料，不是原文引文或已证实的企业案例。JLPT 等级为学习参考。

## C-1. JLPT語彙

### 1. 監査（かんさ）
**品詞：** 名詞｜**意味：** 审计｜**目安：N1**  
**コロケーション：** 監査ログ / 監査証跡 / 定期監査  
**文脈：** Runtime-enforced Security 与 DevSecOps 都需要留下可追责的执行记录。  
**例：** `すべてのTool Callを監査できるように履歴を保存します。`  
**中文：** 保存所有 Tool Call 历史以便审计。  
**ニュアンス：** 强调事后检查是否符合规则与责任要求。

### 2. 暗号（あんごう）
**品詞：** 名詞｜**意味：** 密码、加密技术｜**目安：N2**  
**コロケーション：** 暗号技術 / 暗号方式 / 暗号化  
**文脈：** FHE 讨论以密文计算为核心，属于 Privacy-preserving Computing。  
**例：** `機密Dataを暗号化した状態で処理できる方式を検討します。`  
**中文：** 考虑能在加密状态下处理机密数据的方法。  
**ニュアンス：** 「暗号化」对应 encryption。

### 3. 復号（ふくごう）
**品詞：** 名詞｜**意味：** 解密｜**目安：N1**  
**コロケーション：** 復号Key / 復号処理 / 復号せずに処理する  
**文脈：** FHE 的特点是 Server 不需要先把 Data 解密成明文再计算。  
**例：** `Server側でDataを復号せずに推論処理を行います。`  
**中文：** 服务端不解密数据就执行推理处理。  
**ニュアンス：** 与「暗号化」成对出现。

### 4. 脅威（きょうい）
**品詞：** 名詞｜**意味：** 威胁｜**目安：N1**  
**コロケーション：** Security脅威 / 脅威Model / 脅威を分析する  
**文脈：** Agent 使用外部 Tool 时需要做 Threat Modeling。  
**例：** `外部Toolを利用する際の脅威を事前に分析します。`  
**中文：** 预先分析使用外部 Tool 时的威胁。  
**ニュアンス：** 比「危険」更偏攻击者、漏洞或风险源。

### 5. 整合（せいごう）
**品詞：** 名詞｜**意味：** 一致、协调｜**目安：N1**  
**コロケーション：** 仕様との整合 / 整合性を保つ / Data整合性  
**文脈：** MCP Tool Schema 与 Backend API 规格需要保持一致。  
**例：** `MCP Tool SchemaとBackend APIの仕様との整合を確認します。`  
**中文：** 确认 MCP Tool Schema 与 Backend API 规格的一致性。  
**ニュアンス：** 「整合性」常对应 consistency / integrity。

### 6. 強制する（きょうせいする）
**品詞：** 動詞・サ変｜**意味：** 强制｜**目安：N2**  
**コロケーション：** Policyを強制する / 設定を強制する / Ruleを強制する  
**文脈：** Runtime-enforced Security 的关键是规则由执行环境强制，而非靠 Prompt 自觉遵守。  
**例：** `危険な操作の禁止をRuntime Policyで強制します。`  
**中文：** 通过 Runtime Policy 强制禁止危险操作。  
**ニュアンス：** 强调无法由使用者轻易绕过。

### 7. 制御する（せいぎょする）
**品詞：** 動詞・サ変｜**意味：** 控制｜**目安：N2**  
**コロケーション：** Accessを制御する / 実行を制御する / Policyで制御する  
**文脈：** Agent Runtime 要控制 Network、Tool、File 与 Credential Access。  
**例：** `ToolへのAccessをRuntimeで制御します。`  
**中文：** 在 Runtime 控制对 Tool 的访问。  
**ニュアンス：** 比「管理する」更强调系统逻辑层面的控制。

### 8. 比較する（ひかくする）
**品詞：** 動詞・サ変｜**意味：** 比较｜**目安：N3**  
**コロケーション：** 方式を比較する / 性能を比較する / MCPとAPIを比較する  
**文脈：** 当天内容比较 MCP 与 REST API 在抽象层、发现能力和安全边界上的差异。  
**例：** `MCPとREST APIの責務とSecurity境界を比較します。`  
**中文：** 比较 MCP 与 REST API 的职责和安全边界。  
**ニュアンス：** 适合技术选型的客观说明。

### 9. 秘匿する（ひとくする）
**品詞：** 動詞・サ変｜**意味：** 保密、隐匿｜**目安：N1**  
**コロケーション：** 情報を秘匿する / 個人情報を秘匿する / 値を秘匿する  
**文脈：** FHE 与 Privacy-preserving Computing 强调在计算期间仍保持信息隐藏。  
**例：** `個人情報を秘匿したままModel処理を行います。`  
**中文：** 在隐藏个人信息的状态下进行模型处理。  
**ニュアンス：** 比「隠す」正式，偏安全和隐私技术。

### 10. 保護する（ほごする）
**品詞：** 動詞・サ変｜**意味：** 保护｜**目安：N2**  
**コロケーション：** Dataを保護する / 個人情報を保護する / Credentialを保護する  
**文脈：** Encryption、Access Control 与 Runtime Policy 都属于数据保护手段。  
**例：** `機密DataをEncryptionとAccess Controlで保護します。`  
**中文：** 通过 Encryption 和 Access Control 保护机密数据。  
**ニュアンス：** 比「守る」更书面。

### 11. 実行する（じっこうする）
**品詞：** 動詞・サ変｜**意味：** 执行｜**目安：N2**  
**コロケーション：** 処理を実行する / Commandを実行する / Sandboxで実行する  
**文脈：** Runtime Security 决定哪些 Command / Tool 可以真正被执行。  
**例：** `許可されたCommandだけをSandbox内で実行します。`  
**中文：** 只在 Sandbox 内执行被允许的命令。  
**ニュアンス：** 程序和命令语境最自然。

### 12. 拒否する（きょひする）
**品詞：** 動詞・サ変｜**意味：** 拒绝｜**目安：N2**  
**コロケーション：** Accessを拒否する / 実行を拒否する / Requestを拒否する  
**文脈：** Policy Enforcement Point 的作用是实际 Allow / Deny 请求。  
**例：** `Policyに一致しないTool CallはRuntimeで拒否します。`  
**中文：** Runtime 拒绝不符合 Policy 的 Tool Call。  
**ニュアンス：** 比「断る」更适合系统行为。

### 13. 検知する（けんちする）
**品詞：** 動詞・サ変｜**意味：** 检测、感知｜**目安：N1**  
**コロケーション：** 異常を検知する / 攻撃を検知する / 不審Patternを検知する  
**文脈：** LLM Observability 与 Security Monitoring 要实时发现异常 Tool Call。  
**例：** `不審なTool Call Patternをリアルタイムで検知します。`  
**中文：** 实时检测可疑 Tool Call Pattern。  
**ニュアンス：** 强调系统察觉事件。

### 14. 安全（あんぜん）
**品詞：** な形容詞｜**意味：** 安全的｜**目安：N3**  
**コロケーション：** 安全な設計 / 安全な実行環境 / 安全に利用する  
**文脈：** Agent Security 与 FHE 都围绕如何更安全地处理 Tool 与 Data。  
**例：** `Agentを安全に利用できる実行境界を設計します。`  
**中文：** 设计能安全使用 Agent 的执行边界。  
**ニュアンス：** 技术语境也常用「安全性」。

### 15. 可観測（かかんそく）
**品詞：** な形容詞｜**意味：** 可观测的｜**目安：N1**  
**コロケーション：** 可観測なSystem / 状態を可観測にする / 可観測性を高める  
**文脈：** LLM Observability 要让 Agent 内部执行状态能够从外部被观察和追踪。  
**例：** `Agent内部の状態を外部から可観測にします。`  
**中文：** 让 Agent 内部状态可以从外部观测。  
**ニュアンス：** 更常见的名词形式是「可観測性」。

### 16. 適切（てきせつ）
**品詞：** な形容詞｜**意味：** 适当、恰当｜**目安：N2**  
**コロケーション：** 適切なPolicy / 適切な権限 / 適切に制御する  
**文脈：** MCP/API 的选择和 Runtime 权限都应与 Use Case 相匹配。  
**例：** `Use Caseに応じて適切なSecurity Boundaryを選びます。`  
**中文：** 根据 Use Case 选择适当的安全边界。  
**ニュアンス：** 比「いい」客观正式。

### 17. 厳格に（げんかくに）
**品詞：** 副詞｜**意味：** 严格地｜**目安：N1**  
**コロケーション：** 厳格に制御する / 厳格に分離する / 厳格に適用する  
**文脈：** Runtime Policy 应严格执行，不能允许 Prompt 绕过。  
**例：** `ProductionではTool Accessを厳格に制御します。`  
**中文：** 在生产环境严格控制 Tool Access。  
**ニュアンス：** 偏制度和规则的严格。

### 18. あらかじめ（あらかじめ）
**品詞：** 副詞｜**意味：** 预先、事先｜**目安：N1**  
**コロケーション：** あらかじめ定義する / あらかじめ分析する / あらかじめ設定する  
**文脈：** Threat Model、Policy 和 Tool Allowlist 应在上线前预先设计。  
**例：** `外部Tool利用時の脅威をあらかじめ分析します。`  
**中文：** 事先分析使用外部 Tool 时的威胁。  
**ニュアンス：** 比「前もって」更书面。

### 19. 原則として（げんそくとして）
**品詞：** 副詞的表現｜**意味：** 原则上｜**目安：N1**  
**コロケーション：** 原則として拒否する / 原則として許可しない / 原則として分離する  
**文脈：** Zero Trust 与 Runtime-enforced Security 的默认策略通常是 deny by default。  
**例：** `未認可のTool Accessは原則として拒否します。`  
**中文：** 原则上拒绝未授权的 Tool Access。  
**ニュアンス：** 比「基本的に」更制度化。

### 20. 一方で（いっぽうで）
**品詞：** 接続表現｜**意味：** 另一方面、同时（表对比）｜**目安：N2**  
**コロケーション：** 安全な一方で / 便利な一方で / 一方でCostも高い  
**文脈：** FHE、MCP Gateway 与强 Runtime Policy 都存在安全收益和性能/复杂度成本。  
**例：** `FHEはPrivacyを高められる一方で、計算Costが大きくなる場合があります。`  
**中文：** FHE 能提高隐私，但计算成本可能变大。  
**ニュアンス：** 适合说明 Trade-off。

## C-2. IT/AI専門語彙

### 1. Runtime-enforced Security｜Runtime強制型Security
**意味：** 运行时强制安全  
**文脈：** 由执行环境强制权限和策略，而不是依赖 Prompt 自觉遵守。

### 2. MCP｜Model Context Protocol
**意味：** 模型上下文协议  
**文脈：** 标准化 Agent 与 Tool/Data Source 的连接。

### 3. REST API｜REST API
**意味：** REST 接口  
**文脈：** 传统服务接口，与 MCP 在抽象层和 Agent 可发现性上不同。

### 4. LLM Observability｜LLM可観測性
**意味：** LLM 可观测性  
**文脈：** 追踪 Prompt、Model、Token、Latency、Trace 与 Tool Call。

### 5. FHE｜完全準同型暗号
**意味：** 全同态加密  
**文脈：** 允许在密文上进行计算，减少处理过程中暴露明文的需求。

### 6. DevSecOps｜DevSecOps
**意味：** 开发安全运维一体化  
**文脈：** 把 Security Check 与 Policy 纳入 CI/CD 和日常开发流程。

### 7. Policy Enforcement Point｜Policy強制ポイント
**意味：** 策略执行点  
**文脈：** 在 Runtime、Gateway 或 Proxy 处实际允许或拒绝请求。

### 8. Zero Trust｜ゼロトラスト
**意味：** 零信任  
**文脈：** 默认不信任请求或主体，每次访问都基于身份与上下文验证。

## C-3. JLPT文法

### 1. ～ことなく
**Level：N1｜意味：** 不……而……  
**形：** `動詞辞書形 + ことなく`  
**使い方：** 特别适合说明 FHE 不解密数据即可计算。  
**例：** `Dataを復号することなく計算処理を行います。`  
**補足：** 比「～ないで」正式。

### 2. ～恐れがある
**Level：N1｜意味：** 有……风险  
**形：** `動詞辞書形 / 名詞 + の + 恐れがある`  
**使い方：** 用于 Runtime Security 与 Tool Access 的正式风险提示。  
**例：** `Promptだけに制御を任せると、危険なCommandが実行される恐れがあります。`  
**補足：** 正式风险表达。

### 3. ～にとどまらず
**Level：N1｜意味：** 不仅限于……  
**形：** `名詞 / 普通形 + にとどまらず`  
**使い方：** 说明 Agent Security 不只靠 Prompt，还要覆盖 Runtime、Gateway、Audit。  
**例：** `Agent SecurityはPrompt設計にとどまらず、RuntimeでのPolicy Enforcementまで必要です。`  
**補足：** 适合范围扩展。

### 4. ～上で
**Level：N2｜意味：** 在……方面/在……时  
**形：** `動詞辞書形 + 上で`  
**使い方：** 讨论 MCP 或 Agent 在生产使用时的前提和注意点。  
**例：** `MCPを本番利用する上で、認可と監査は重要です。`  
**補足：** 技术说明高频。

### 5. ～に基づいて
**Level：N2｜意味：** 基于……  
**形：** `名詞 + に基づいて`  
**使い方：** 说明 Access Control 依据 Identity / Policy。  
**例：** `User Identityに基づいてTool Accessを制御します。`  
**補足：** 明确表示判断依据。

### 6. ～一方で
**Level：N2｜意味：** 另一方面……  
**形：** `普通形 + 一方で`  
**使い方：** 说明 Privacy / Security 收益与性能或复杂度成本。  
**例：** `FHEはPrivacyを高める一方で、処理Costが増えることがあります。`  
**補足：** 适合 Trade-off。

### 7. ～にかかわらず
**Level：N2｜意味：** 不论……都……  
**形：** `名詞 + にかかわらず`  
**使い方：** 表达无论通过 MCP 还是 REST API 都必须遵守共同安全规则。  
**例：** `接続方式にかかわらず、認証と認可を必ず適用します。`  
**補足：** 适合统一 Policy。
