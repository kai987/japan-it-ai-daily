### 1. [アップデート] AWS AppConfig で AI のモデル設定とプロンプトを管理できるようになったので使ってみた

**原文：** https://dev.classmethod.jp/articles/aws-appconfig-native-ai-model-invocation-prompt-configurations/

**发布时间：** 2026-11-25 09:15:56 JST

在代码里写死模型和系统提示词时，修改一个值也可能触发应用重新构建。AWS AppConfig 新增两种配置档案：提示词以文本保存并可复用，模型调用配置则描述模型 ID、temperature 等推理参数、消息以及供应商专用字段。应用可以通过 AppConfig Data API 获取下发版本。

作者在管理控制台创建了两类档案，实际将提示词升级到版本 2，并以应用侧方式调用 Data API，成功拿到新版文本。模型与提示词可以用不同部署策略下发，例如模型一次切换、提示词分批生效。拿到新配置之后，仍由应用选择调用模型的时机和参数。

原文还记录了一处限制：文档将 model 列为必填，但在作者尝试的注册环节，缺少 model 的 JSON 仍可保存并读回。这个结果只涵盖该次注册，不能据此推断部署与运行时都接受。把模型字段校验和实际推理测试纳入应用的验收，可避免把配置取得成功误当成模型可用。

**推荐理由：** 可拿来讨论模型参数如何小步发布，以及谁负责从配置合法性一路验证到真正的推理。

### 2. GA になった AWS CDK Blocks を試してみた

**原文：** https://dev.classmethod.jp/articles/aws-cdk-blocks-ga-hands-on/

**发布时间：** 2026-11-25 00:46:30 JST

CDK Blocks 将 CDK 构件、应用连接代码和本地实现打包在一起。原文用 Docker 中的 Node.js 22 和东京 AWS 沙箱演示：KVStore 在本地用文件，在 AWS 用 DynamoDB；AsyncJob 在本地用进程内队列，云端则由 SQS、死信队列和 Lambda 组成。

测试作者分别提交一次成功、先失败两次再成功、以及持续失败的作业。本地观察到前两种分别在一次和三次投递后完成，第三种三次后标为失败并进入死信流程。这里的 maxRetries 配成 3，含首次投递。作者还将 synth 生成的 maxReceiveCount 和可见性超时与部署后的 SQS 属性核对，结果一致。

云端案例验证了正常作业、键值读写和自定义块的结果。故障三次的序列主要来自本地测试，不能直接当成云端全量故障实测。清理沙箱后还有两个栈外辅助 Lambda 日志组留存，生产预设也可能保留表和桶。环境差异和资源清单都是投产前需要单独核对的条件。

**推荐理由：** 用同一个作业例子串起本地模拟、生成模板与云端实物，方便说明抽象层以下要验证什么。

### 3. Ladybird の Alpha 版が出たので macOS で Chrome、Safari と比べてみた

**原文：** https://dev.classmethod.jp/articles/reona-ladybird-alpha-macos/

**发布时间：** 2026-11-24 23:59:02 JST

作者在 Apple Silicon 的 macOS 环境中尝试 Ladybird 首个 Alpha。这个浏览器使用独立引擎。作者用自动化打开常用页，另外在有界面的浏览器里检查 YouTube 的画面和声音；自动化采样里，视频播放时间按约五秒的间隔往前走。

同一天各运行三次 Speedometer 3.1，Ladybird Alpha 2026.47.7 的中位数为 21.7，Safari 27.2 为 51.3，Chrome 158 为 60.6。Safari 使用有窗口模式。基准同时涉及脚本、DOM 与布局，单一总分无法定位具体是哪一步拉开了差距。

真实站点测试中，多数所选页面能显示，也观察到了含文字广告的编码问题。测试范围限于给定版本、机器和站点，不能推广到所有页面。作者将常用站点可用、基准性能和 Alpha 的功能成熟度分别评价。

**推荐理由：** 既有带条件的可复核测量，也有页面与视频验证，适合做跨引擎验收的讨论。

### 4. MCPの記録ツールを追記だけで作ると、訂正のたびに重複が残る。AIは「消せない」と正直に言うが、集計は間違える

**原文：** https://zenn.dev/kentaro_tak/articles/mcp-logger-append-only-corrections

**发布时间：** 2026-11-24 23:04:27 JST

原文作者重建了一个只允许通过 MCP 工具访问的 SQLite 记录器，以测试更正能否真正落库。三种写入设计分别是单纯追加、追加并按行 ID 删除，以及按日期和类别覆盖。三种 Claude 模型对每种设计各试三次，共 27 次。每次先写、再更正，随后另开对话重读。

作者检查数据库中是否只剩更正后的单行，并用 SQL 检查统计值。允许追加后删除和允许覆盖的两组各 9 次都修正成功。单纯追加的 9 次则都让统计多计一天；其中有 8 次新对话靠注释读出了正确答案，也看不出统计仍受旧状态影响。

这项实验的适用条件是日期和类别能唯一定位要改的那条记录。对于一天可能有多条的记录，需要区分业务 ID，或者用明确的更正事件重建当前状态。原文只测了一个具体记录领域和限定工具集，未给出并发写入结论。

**推荐理由：** 把模型口头说明、数据库状态和聚合结果都纳入验收，能发现只看代理回答时漏掉的错误。

### 5. ECR/S3からのimage pullの仕組みを深掘りする

**原文：** https://qiita.com/har1101/items/a6e5f0d2039bd0932511?utm_campaign=popular_items&utm_medium=feed&utm_source=popular_items

**发布时间：** 2026-11-25 00:28:45 JST

作者在私有子网启动 ECS 任务时遇到容器镜像拉取超时。环境已经设置用于 ECR API 与 Docker Registry API 的两个接口端点。镜像取得还包括从 S3 下载镜像层；注册表返回用于读取相应层的签名 URL。因此只核对 ECR 连线，容易遗漏真正下载文件的下一段路径。

作者将超时目的地址与 AWS 公布的东京地址段核对，发现它属于 S3。按原文的拓扑，ECR 接口端点依赖私有 DNS、端点网卡及安全组，S3 网关端点则通过路由表的服务前缀列表匹配。作者因此指出任务的出站规则也要允许到 S3 前缀的 HTTPS。

这个案例的限制是只确认了错误地址和配置原因，原文没有给出修改后再次拉取的测量结果。实际排查时应记录下载阶段和受影响的子网，再在相同条件下验证镜像能完整下载和任务进入运行状态。

**推荐理由：** 把镜像元数据和大文件下载拆开定位，解释了为什么注册表可访问时任务仍可能启动失败。

### 2. GA になった AWS CDK Blocks を試してみた

**面试问题：**

> CDK Blocksでジョブを作るとき、手元とAWSで何を試しますか。

**约30秒回答：**

> 手元のキューで、二回失敗して三回目に成功するジョブと、失敗し続けるジョブを流します。三回という上限には最初の配信も含まれ、全部失敗した例はデッドレターキューに移りました。クラウドではエスキューエスの最大受信回数を確認します。ただし、手元で通ったことだけで、クラウドでの再配信の間隔までは分かりません。

**相关项目示例：** 给后台文件转换任务配键值状态与重试，测试第三次投递后失败的去向并核对云端队列属性。

**关键词：** CDK Blocks、KVStore、AsyncJob、maxReceiveCount

**相关项目示例：** 在发布前固定浏览器版本，分别跑跨浏览器登录外的公开页面、媒体播放和基准，并记录运行模式。

### 4. MCPの記録ツールを追記だけで作ると、訂正のたびに重複が残る。AIは「消せない」と正直に言うが、集計は間違える

**面试问题：**

> 日付と種類で一件に決まる記録なら、前の値を置き換えるようにします。記事では追記だけの九回は全部、集計が一日多くなりました。別の会話で正しく答えた場合もあったので、私は保存先に正しい一行だけ残り、エスキューエルの件数も直ることを確かめます。ただし、一日に複数ある記録には別の識別子を使います。

**相关项目示例：** 给工时更正工具加入业务键，并把按天统计的结果纳入自动化回归。

**关键词：** MCP、SQLite、upsert、业务唯一键

### 5. ECR/S3からのimage pullの仕組みを深掘りする

**面试问题：**

> プライベートサブネットのECSでイメージの取得が止まったら、どこを見ますか。

**约30秒回答：**

> まず、失敗した接続先をログで見ます。イーシーアールで目次を受け取っても、実際のレイヤーは署名付きのユーアールエルを使ってエススリーから取ります。記事では、タイムアウト先が東京のエススリーの範囲でした。ルートとタスクの送信許可を見直します。ただし、修正後に同じ条件で起動できるところまで確認します。

**相关项目示例：** 为无公网出口的 ECS 部署做启动检查，分别验证 ECR 元数据访问和通过 S3 网关取层的链路。

**关键词：** ECR、Amazon S3、接口端点、网关端点

## 4. 今日技术主题

### 在最接近结果的地方验收

完成了下发、入队或打开网页，只确认了一次中间操作。可以接着核对应用拿到的配置版本、作业的最终状态、单独的浏览器媒体进度，把每个检查写成具体的可观察条件。

保存更正记录后要重跑报表查询，网关连通后要检查镜像层能不能完整取回。只有复现实验覆盖到相应步骤，才把那个步骤写作已验证。这样一份移交记录既能告诉同事复现什么，也能说清楚下一次还要补哪一项。

## C-1. 新学JLPT词汇

查对全105期的420份文件，本次收录原文用法及参考等级均可确认的三个新词。已有词汇留作复习。

### 1. 寄付（きふ）｜N3

- 词性：名詞・サ変他動詞
- 含义：为帮助组织或事业而提供资金或物品，捐赠。
- 搭配：寄付を募る / 寄付を受け付ける / 団体に寄付する
- 文章语境：原文用来说明独立浏览器的运营资金来源。
- 例句：開発を続けられるよう、利用者から寄付を募っています。
- 例句含义：为了能继续开发，正在向使用者募集捐款。
- 辨析：「寄贈」常用于赠送书籍等具体物品。「寄付」也常用于资金。

### 2. 化ける（ばける）｜N1

- 词性：一段自動詞
- 含义：变成另一副样子。在文字场景指显示成意料之外的字符。
- 搭配：文字が化ける / 記号が別の文字に化ける / 思わぬ形に化ける
- 文章语境：原文用来描述网页字符未按预期显示。
- 例句：古いファイルを別の文字コードで開くと、一部の記号が化けます。
- 例句含义：用另一种编码打开旧文件，一部分符号会变成乱码。
- 辨析：「変わる」泛指改变。「化ける」突出形貌或显示与预期相差明显。

### 3. 引く（ひく）｜N5/N4

- 词性：五段他動詞
- 含义：在此用法中指使用辞典或参考系统查询条目信息。
- 搭配：辞書を引く / 索引を引く / DNSを引く
- 文章语境：文中指查询服务域名，取得对应的 IP 地址。
- 例句：接続を調べるため、まずその名前を社内のDNSで引きました。
- 例句含义：为调查连接问题，先向公司内的 DNS 查询了这个名称。
- 辨析：「引っ張る」指拉动东西，不能直接替换「辞書を引く」中的查阅用法。
