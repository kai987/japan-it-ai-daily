### 1. Claude Code v2.1.289 の主要アップデート - sandbox auto-allow 時の Bash deny ルール修正と agent.spawn の teammate 対応

**原文：** https://dev.classmethod.jp/articles/20261005-cc-updates-v2-1-289/

**发布时间：** 2026-10-05 17:15:59 JST

文章讨论的是 10 月 3 日发布的 Claude Code v2.1.289，技术文章在 10 月 5 日公开。27 项变更分为 1 项新功能、5 项安全修复、19 项缺陷修复和 2 项改进；缺陷修复中 15 项涉及 mods 与插件。核心不是让自动执行更多，而是修复 sandbox 自动允许与显式 deny／ask 规则的优先关系：环境变量前缀中含展开值、或命令前有独立变量赋值时，过去存在规则未生效的情况。原文还列出管理设置相对用户 mod 的优先级、组织 MCP 登录工具说明被插件改写、符号链接及 IDE 入口的 Read deny 修复。这些是不同入口的修复，不能把一次 Bash 测试当作全部已验证。

机制上，autoAllowBashIfSandboxed 让沙箱中的 Bash 操作自动获准，但显式拒绝仍应保留约束。作者在不含原有 .claude 或 Git 设置的新目录中，通过 --settings 指向临时设置、--setting-sources project 排除用户配置，并设置 failIfUnavailable，防止沙箱不可用时退回无沙箱运行。实验拒绝 touch，给待执行操作加上环境变量前缀，以覆盖此次修复的形态；控制组只移除权限拒绝，其余沙箱条件保持一致。这种隔离配置与控制变量比“能否运行”更有解释力。

结果同时检查 JSON 的 permission_denials 与实际文件。拒绝组留下 Bash 拒绝记录，denied.txt 不存在；控制组没有拒绝记录，allowed.txt 存在。两组均显示 error_max_turns，因为 --max-turns 1 限制了交互轮数，不代表两组都因权限失败。这里能核实的是该版本在这一个命令形态下的拒绝行为；文章没有展示跨平台矩阵，也没有逐项复现所有安全修复。面试中应先说明判据，再说明实验覆盖范围。

另一项新功能让 agent.spawn 在 teammate 起动前也触发，e.isTeammate 用于识别该种起动；插件 hook 间统一 agent id，$.agent.list() 增加 idle 和 waiting。由此可以在 mod 中选择模型或拒绝起动，但这些接口说明不等于部署后的策略完整性证明。终端和 artifact 展示层也修复未闭合 script 标签与深层替换导致的冻结问题。学习时应把“发布说明列出的修复”和“作者真正做过的对照实验”分别保存。

**阅读价值：** 适合把“权限规则已配置”落实为可观察的拒绝行为，并区分执行上限退出与工具权限拒绝。

### 2. ECS のタスクをクラウド開発環境として使う

**原文：** https://dev.classmethod.jp/articles/ecs-task-sandbox/

**发布时间：** 2026-10-05 17:37:33 JST

这是一项实际搭建记录：为用户动态创建、删除 ECS 任务，在任务内运行 codercom/code-server，并让浏览器使用开发环境及 Claude Code。作者比较了 SageMaker Code Editor 与 Coder，但没有提供这些替代方案的实现教程。自主 ECS 的价值在于身份管理不必绑定 IAM 或 IAM Identity Center，持久化与备份也不必绑定 EFS；代价是要自行维护更多组件和常驻 Proxy。灵活性是架构选择，不是免费获得托管服务的可靠性。

链路分为四层。静态 Web UI 由 S3／CloudFront 承载；API Gateway 的 Authorizer 检查身份，Lambda 创建或删除任务，并轮询到任务可用；任务 ENI 的 IP 写入 DynamoDB。常驻 ECS Proxy 再核实请求者，读取该用户对应的任务 IP，转发到开发任务。code-server 使用 WebSocket，因此只转发普通 HTTP 不足以满足交互。开发任务在私网运行，外部访问经过 NAT Gateway。

原文展示登录、起动后得到链接，通过 ALB 链接进入开发画面，停止后出现 No running task 且不再能够进入。这说明主要交互链路被走通，但没有并发压力、起动耗时分布、容错或费用的数字。ALB 默认域名缺少合适 TLS 证书；作者讨论自签与客户端信任的临时做法，同时明确它不适合实际部署，需要独立域名。这一限制也与部分扩展的 Service Worker 有关。

持续轮询会让 Lambda 在配置期间一直运行，作者提出改由 EventBridge 驱动来减少执行时间，但实时 UI 状态仍要另行设计。Fargate Spot 和按需任务都可能在维护时停止；动态服务或如 8 小时上限的生命周期机制只是文中的对策建议。企业应用应把备份、任务寿命、重建、Proxy 故障与常驻成本一起评估；不能把“每人一个任务”直接等同于完整的安全审计或可用性保证。

**阅读价值：** 能具体解释从浏览器身份到用户任务地址的链路，也能讨论自主搭建相比托管 IDE 的运维责任。

### 3. ジャンプアカウント運用下でAWS CLI（+ AIエージェント）の認証情報を安全に扱う

**原文：** https://dev.classmethod.jp/articles/aws-vault-mfa-claude-code/

**发布时间：** 2026-10-05 14:26:34 JST

作者的前提是先登录跳板账户，再切换角色进入个人验证账户，同时禁止在本机明文保存访问密钥。1Password 管理控制台登录，但把密钥直接写入 ~/.aws/credentials 不符合规则。最初的 1Password CLI 插件能包装手动 aws 命令，却未能满足文中 Claude Code 子进程复用认证的方式；aws login 配合 export-credentials 可以供代理使用，但过期后要重新认证，跳板认证还会写入 ~/.aws/login/cache，最终没有采用。结论只针对作者的调用方式，不意味着所有插件或认证方式都必然失败。

采用方案拆开两项职责：aws-vault 把长期密钥放入 OS 加密存储，macOS 使用 Keychain；1Password 只发出 MFA 一次性密码。main 配置 MFA，common 通过 credential_process 调用 aws-vault 的 JSON 输出，target 再由 role_arn 与 source_profile 引用 common 切换角色。跳板侧身份和目标角色之间仍需信任策略及权限策略；MFA 条件与最小权限不会因换了密钥存储工具就自动成立。

验证使用 get-caller-identity 检查目标账户以及 assumed-role ARN，之后在同一终端用 AWS_PROFILE=target 启动 Claude Code，文中确认其内部 AWS CLI 能继承该认证链并列出示例 S3 桶。--prompt=osascript 用对话框请求解锁和 MFA，--duration=8h 减少原始会话再认证。这里的 8 小时不能当成最终切换角色密钥的有效期，也不是无人值守运行必定持续 8 小时的承诺。

必须保留原文的限制：切换角色后的、已缩小权限的临时认证仍按 AWS CLI 标准行为缓存到 ~/.aws/cli/cache，文章注明最长 1 小时失效。因此“长期跳板密钥不写入平文”和“任何临时钥匙都不落盘”是两种不同要求。文章没有证明完全消除了运行时暴露。面试中应说明存储、供给、权限、TTL 和缓存五个环节，并据实际组织规则确认这种缓存是否可接受。

**阅读价值：** 适合说明长期钥匙、MFA、角色切换、代理子进程和临时缓存的责任边界，不把加密存储夸大成完全无明文。

### 4. [アップデート] Amazon Quick のアプリでデータセットのライブデータが使えるようになったので、Direct Query と SPICE で比べてみた

**原文：** https://dev.classmethod.jp/articles/20261005-amazon-quick-live-data-in-app/

**发布时间：** 2026-10-05 13:36:02 JST

Amazon Quick Apps 能按自然语言生成应用，此次文章验证数据集实时读取与旧式构建时快照的区别。按文章引用的规格，应用打开时以当前用户权限查询数据集，RLS／CLS 适用于该用户；共享应用并不同时共享数据，需要另授数据集读取权限及同意。作者实际测试是 Enterprise、ADMIN_PRO、东京 ID 区域，却把 Apps 与数据集放在 us-east-1。不能把这一设置描述成东京 Apps 已获支持。

实验从同一 Athena 表创建 Direct Query 和 SPICE 数据集，底层是 S3 的 18 行 CSV；SQL 聚合基线为 18 笔、1,312,000。代理生成应用后，上半部分有 KPI、区域棒图、案件列表，下面是 SPICE 对照；生成约 5 分钟。初始两组均与基线相同。作者指出源数据没有币种，生成界面却加了 ¥，说明数字正确仍可能带有未提供的展示语义。运行权限勾选、SQL 验证同意和预览集成同意也不是同一个确认。

再加入金额 200,000 的一行，重新读取时 Direct Query 变为 19 笔、1,512,000，SPICE 仍为 18 笔、1,312,000；手动 CreateIngestion 完成并重载后，SPICE 才一致。Athena 历史显示每次画面加载发出 3 个查询，对应 3 个 Direct Query 可视化，扫描量从 845 增至 934 字节。页面的最終更新日没有随数据变化，因为它表示应用最后编辑日期。由此可直接验证“实时”的实际触发点，也可推导读取次数和扫描计费的成本关系。

限制包括单表、应用与数据集同账户同区域、每个可视化最多 50,000 行、不支持把主题或 dashboard 作为实时源；东京尚非 Apps 支持区域。规格称 SPICE／S3 Tables 最多缓存 12 小时，但本次看到 SPICE 刷新后立即反映，没有验证缓存持续存在的条件。RLS／CLS 是引用规格，不是作者做过的多用户权限对照。高频读取宜考虑预聚合或 SPICE，但不能只按“更新快”得出普遍优越结论。

**阅读价值：** 能把生成应用的正确性拆成数据更新、读取权限、查询成本和显示语义，并用实际对照解释选择。

### 5. Claude Codeの入力欄でMarkdownが読みにくい問題をmd-promptで解決する

**原文：** https://zenn.dev/nogu66/articles/md-prompt-claude-code-markdown-painting

**发布时间：** 2026-10-05 14:50:11 JST

md-prompt 是给 Claude Code 输入框的 Markdown 下稿加色彩与字体的插件，针对长指令中代码、正文和列表难以区分的问题。原文由 AI 名义撰写，明确说没有亲眼看到输入框，依据是仓库、README、装饰函数与手头测试。因此下文的视觉描述是实现及文档说明，不能写成作者对真实画面的直接观察，也没有效率提升的定量用户实验。

实现利用 Claude Mods 的 function hooks：每次 prompt.edit 接到编辑结果，await next(e) 后保留原对象，向既有 decorations 数组添加新范围。文本与光标不改，其他插件的装饰也保留；闭合符号无法被删除，只能弱化显示。代码块在未闭合时就能加色，未知语言只识别字符串与数字，避免猜测正文是注释。装饰函数对乘法、通配路径和 __init__ 返回空数组，而真正的粗体及内联代码产生位置范围，体现误识别控制。

装饰计算是无状态纯函数，文中报告 7 个文件、374 个测试通过；另以随机生成的 540 个内联样本和 500 个文档对照 commonmark.js 扫描结果。直接落在终端背景上的颜色还检查白底 3.3:1、暗底 4.3:1 以上的比率。这些是该测试集合的判据，不等于所有文字都达到通用无障碍标准，也不能替代真实端末和用户的视觉检查。输入超过 60,000 字符则不装饰，异常时保留原下稿，属于降低编辑损坏风险的边界。

已知限制是 4 行以上粘贴会被 Claude Code 折叠且不触发编辑事件；展开后再输入一个字符才加装饰。背景只能铺在已有字符下，右侧边缘和空行无法形成齐整整块。数式、YAML front matter 和特定注记不处理；function hooks 为 early access，API 可能随版本改变。文中说明 2.1.287 后无额外开关、2.1.285／286 需启用 function hooks，而 README 验证版本是 2.1.285。安装成功、函数测试通过和真实显示可用需要分别验收。

**阅读价值：** 适合前端面试中的纯函数、非破坏性显示、误识别与性能边界，同时保留代码测试和真实视觉验收的区别。

### 4. [アップデート] Amazon Quick のアプリでデータセットのライブデータが使えるようになったので、Direct Query と SPICE で比べてみた

**面试问题：**

> AIで作った業務画面のデータ鮮度を、どう確認しますか。

**约30秒回答：**

> 表示を信じる前に、元データを変えて反映の契機を比べます。Amazon Quickの例ではDirect Queryは再読込みで更新され、SPICEは取り込みの完了まで旧値でした。ただし、表示ごとにAthenaのクエリが走ります。更新頻度だけでなく閲覧数と費用を見て選び、画面の最終編集日をデータの更新時刻と混同しません。

**相关项目：** 用同一数据源的两个数据集构建对照画面，记录新增一行前后、SPICE 更新前后及查询次数。

**关键词：** Direct Query / SPICE / Athena

### 5. Claude Codeの入力欄でMarkdownが読みにくい問題をmd-promptで解決する

**面试问题：**

> 入力内容を装飾するUIで、何を壊さないようにしますか。

**约30秒回答：**

> 送る文字とカーソル位置を保ち、見た目だけを変えます。md-promptはprompt.editでdecorationsを足し、装飾計算を純関数でテストしています。ただし、長い貼り付けは編集イベントが出ない場合があり、コードのテストだけでは画面を保証できません。展開後の入力や端末の見え方も実際に確認します。

**相关项目：** 对照普通通配符和 Markdown 输入测试装饰范围，再实际检查粘贴折叠、展开和异常回退。

**关键词：** prompt.edit / decorations / commonmark.js



## 4. 技术主题：从“操作完成”到“状态可核实”的验收链

机制上先把意图、执行记录和实际状态拆开。Claude Code的退出字段并不替代permission_denials与文件检查；ECS起动成功之后还要找到用户所属的ENI IP，并让WebSocket通过Proxy；Quick生成成功之后要核对数据更新契机和源查询。md-prompt更进一步，把状态不变的文字与可变的decorations分开。它们共同说明：工具给出的成功消息是一份证据，不能覆盖另一层的状态。这里是基于五篇文章的设计归纳，不是这些产品共享同一架构的说法。

好处是故障可以定位到具体边界。权限拒绝用控制组比较，身份用目标账户/角色核实，数据用已知增量与查询历史对照，显示用純函数样本以及端末实测分别检查。原始输入保持不变，也便于重试和审计。把检查点保存下来，能明确哪些检查完成、哪些需要恢复；没有必要把一次测试的范围扩大成企业级可靠性或安全承诺。

限制与日本团队导入：自行部署ECS增加Proxy成本和维护责任，aws-vault并不消除切换角色的临时平文缓存，Quick有区域与单表限制，md-prompt依赖early access API且长粘贴可能没有编辑事件。日本企业试用时，应先明确数据驻留区域、钥匙缓存政策、身份分离、停机恢复与实际利用场景，再设定可观测的验收结果。文中没有提供这些产品在日本企业广泛采用的统计，因此这里仅是导入判断问题。

# C. 日语学习

## C-1. 新学 JLPT 词汇

新词20项已对完整历史查重。优先N1/N2；保留原文中的N3「嬉しい」「普段」与三个技术用语的真实层级，而不把常见表达升格以凑难度。名词、动词、形容词和副词依原文功能学习，例句为独立教学例。

### 1. 平文（ひらぶん）｜IT/AI

- 词性：名詞
- 含义：未经加密、可直接读取的文本或数据
- 搭配：平文で保存する / 平文を残す / 平文のキャッシュ
- 文章语境：AWS 认证原文明确讨论角色临时钥匙的平文缓存。
- 例句：長期キーを暗号化しても、一時キーの平文が残る場合がある。
- 例句译文：即使长期密钥被加密，也可能残留临时密钥的明文。
- 语感区别：不同于一般的本文；信息安全语境读ひらぶん，强调加密状态。

### 2. 契機（けいき）｜N1

- 词性：名詞
- 含义：触发变化的机会或起因
- 搭配：契機となる / 契機に更新する / 処理の契機
- 文章语境：Quick 原文的查询表以契机区分探索、预览和重新读取。
- 例句：画面の再読み込みが、データを問い合わせる契機になる。
- 例句译文：重新加载页面成为发出数据查询的契机。
- 语感区别：契機说明触发点，不代表完成时刻或最终结果。

### 3. 対照（たいしょう）｜N2

- 词性：名詞
- 含义：作为比较依据的另一条件或事物
- 搭配：対照実験 / 対照と比べる / 対照を置く
- 文章语境：Claude Code 原文只去掉 deny 构造控制组。
- 例句：拒否規則を外した対照でも、同じコマンドを使う。
- 例句译文：去除拒绝规则的控制组也使用同一命令。
- 语感区别：対象是被处理对象，対照是用于比较的参照，两者同音不同义。

### 4. 解除（かいじょ）｜N1

- 词性：名詞・サ変動詞
- 含义：解除锁定、限制或约束
- 搭配：ロックを解除する / 制限を解除する / 解除を求める
- 文章语境：aws-vault 验证时需要先解锁，再输入 MFA。
- 例句：ロックを解除してから、必要な認証を進める。
- 例句译文：解锁后进行必要认证。
- 语感区别：和删除不同，解除移除的是约束，保管内容不一定被删除。

### 5. 単独（たんどく）｜N2

- 词性：名詞
- 含义：单独、没有与其他对象组合
- 搭配：単独で動く / 単独の代入 / 単独で判断する

- 语感区别：不同于隔离；単独强调数量或独立行动，隔离强调边界。

### 6. 入れ子（いれこ）｜N1

- 含义：某一结构内部包含同类结构的嵌套
- 搭配：入れ子の構造 / 入れ子部分 / 入れ子をほどく

- 例句译文：嵌套结构内侧也应遵守管理员拒绝规则。
- 语感区别：不同于普通层级，强调结构嵌入另一个结构内部。

- 搭配：書体を変える / 色と書体 / 書体を使い分ける

- 例句译文：以非固定时间停机为前提准备重建流程。
- 语感区别：不是随机保证或永不预告，强调时间安排不固定。

## C-3. 新学语法

### 1. ～たびに｜N3

- 含义：每次发生某动作或事项时，另一个事项也反复发生
- 结构：動詞辞書形＋たびに／名詞＋の＋たびに
- 用法：说明反复触发关系，不能把文章中的一次验证当成所有触发都测量完毕。
- 原文形态：開くたびに
- 原文依据：[アプリを開くたびにデータセットへクエリが発行され](https://dev.classmethod.jp/articles/20261005-amazon-quick-live-data-in-app/)
- 独立例句：画面を開くたびに問い合わせるなら、閲覧数に応じた費用も調べたい。
- 例句译文：若每次打开页面都会查询，也想核对随浏览次数变化的费用。
- 注意：与“につれて”的渐变不同；たびに强调逐次、重复的触发。
