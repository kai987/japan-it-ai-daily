## 4. 今日の技術テーマ

# Long-running Agent Runtime

长期 Agent 的核心变化是 **Session ≠ Process**。Supervisor / Daemon 可以保存 Session State，让 Worker Process 重启后继续任务。优点是支持异步和并行工作；风险是 Concurrency、Workspace Isolation、Secrets、长期 Token / Tool Cost 和遗留 Session。Worktree 可以降低冲突，但不等于完整 Sandbox。

```text
Session Owner
  ↓
Persistent State
  ↓
Worker / Workspace
  ↓
TTL / Budget / Permission
  ↓
Monitoring / Recovery
```

### 优点

**第一，减少无关复杂度。** 通过把职责拆成 `Session Owner` 到 `Monitoring / Recovery` 的明确层次，可以让模型只处理概率性判断，而把权限、验证和停止条件交给确定性系统。

**第二，更容易测量与回滚。** 每一层都能单独记录 Input / Output / Cost / Failure，出现异常时可以定位问题，而不是把所有错误都归因于“模型不够好”。

**第三，更适合团队规模化。** Agent Runtime 要独立管理 Session、Tool、Credential、Network、Workspace、TTL、成本与恢复，因此可以把个人技巧转成可复用的 Platform Rule、CI Check 或 Governance Policy。

### 局限

**系统复杂度会上升。** 多一层 Router、Policy、Sandbox、Trace 或 Evaluation 都会带来开发和维护成本，需要确认它解决的是实际风险，而不是为了“架构完整”而堆层。

**确定性 Guardrail 也可能配置错误。** Policy、Test、Metric 与 Retrieval Rule 都需要版本管理和持续校准，不能因为“不是 LLM”就默认它绝对正确。

### 日本企业落地时的注意点

1. 先明确 **Owner、Data Boundary、Permission、Approval、Audit、Rollback**，再扩大 Agent 自治范围。  
2. 把现有的 **CI/CD、SRE、Security Review、Change Management** 继续保留，不因为接入 AI 就另建一套不可追踪的旁路。  
3. 用日本企业实际关心的 **品質、工数、Cost、Security Incident、Business Outcome** 评价，而不是只统计 AI 使用次数。

面试里可以这样总结：

> Modelとは別に、Session、Tool、Credential、Network、Workspace、TTL、Cost、RecoveryをRuntimeの責務として管理し、実行範囲を明確にします。

2. **工程判断：** AI 成熟后，Tool Selection 不再是主要问题，组织能力和定量成果更关键。
3. **生产化要点：** LLM 运维需要把请求、模型、Token、延迟、Tool Call 与业务结果放在同一可观测链路中。
4. **面试表达：** 说明技术价值时，同时给出适用条件、Trade-off 与验证方法，比只介绍“能做什么”更完整。

### 日本語の知識ポイント

1. **AI導入が進むと、課題はTool選定から人材育成、専門家支援、ROIの定量評価へ移ります。**
2. **Request、Model、Token、Latency、Tool Call、User OutcomeをTraceできるようにし、Costと品質を同じDashboardで確認して継続改善につなげます。**
3. **導入判断では、適用条件とTrade-offを明確にし、実際のWorkloadで評価することが重要です。**
4. **本番運用では、変更履歴、監査性、Rollback手段まで含めて設計する必要があります。**

## C-3. JLPT语法

### 1. ～つつ
**参考：N1**  
**中文：** 一边……一边……  
**接续：** `動詞ます形去ます + つつ`

**中文：** 随着 AIOps 自动化范围扩大，权限边界设计也变得重要。

### 3. ～にとどまらず

### 7. ～にかかわらず

**中文：** 不论……都……
