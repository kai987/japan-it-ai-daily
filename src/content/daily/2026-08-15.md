## 4. 今日の技術テーマ

# Agent Harness

Agent Harness 是让模型真正“作为 Agent 运行”的基础层，负责 Tool Call、Session、Memory、Sandbox、Permission、Agent Loop 与 Evaluation。好处是 Model 与执行逻辑解耦，更易于测试和治理；代价是系统复杂度上升，需要同时处理 Tool Failure、Network Failure、Context Overflow、Cost 和 Recovery。

```text
Input / Goal
  ↓
Harness / Session
  ↓
Model + Tool
  ↓
Sandbox / Permission
  ↓
Trace / Evaluation
```

### 优点

**第一，减少无关复杂度。** 通过把职责拆成 `Input / Goal` 到 `Trace / Evaluation` 的明确层次，可以让模型只处理概率性判断，而把权限、验证和停止条件交给确定性系统。

**第二，更容易测量与回滚。** 每一层都能单独记录 Input / Output / Cost / Failure，出现异常时可以定位问题，而不是把所有错误都归因于“模型不够好”。

**第三，更适合团队规模化。** Agent Runtime 要独立管理 Session、Tool、Credential、Network、Workspace、TTL、成本与恢复，因此可以把个人技巧转成可复用的 Platform Rule、CI Check 或 Governance Policy。

### 局限

**系统复杂度会上升。** 多一层 Router、Policy、Sandbox、Trace 或 Evaluation 都会带来开发和维护成本，需要确认它解决的是实际风险，而不是为了“架构完整”而堆层。

**确定性 Guardrail 也可能配置错误。** Policy、Test、Metric 与 Retrieval Rule 都需要版本管理和持续校准，不能因为“不是 LLM”就默认它绝对正确。

### 日本企业落地时的注意点

1. 先明确 **Owner、Data Boundary、Permission、Approval、Audit、Rollback**，再扩大 Agent 自治范围。  
2. 把现有的 **CI/CD、SRE、Security Review、Change Management** 继续保留，不因为接入 AI 就另建一套不可追踪的旁路。  
3. 用日本企业实际关心的 **品質、工数、Cost、Security Incident、Business Outcome** 评价，而不是只统计 AI 使用次数。

面试里可以这样总结：

> Modelとは別に、Session、Tool、Credential、Network、Workspace、TTL、Cost、RecoveryをRuntimeの責務として管理し、実行範囲を明確にします。

2. **Modelとは別に、Session、Tool、Credential、Network、Workspace、TTL、Cost、RecoveryをRuntimeの責務として管理し、実行範囲を明確にします。**
3. **導入判断では、適用条件とTrade-offを明確にし、実際のWorkloadで評価することが重要です。**
4. **本番運用では、変更履歴、監査性、Rollback手段まで含めて設計する必要があります。**

## C-1. JLPT词汇

### 1. 権限（けんげん）
**词性：** 名詞  
**中文：** 权限  
**参考：N2**  
**搭配：** `権限を制限する` / `実行権限` / `最小権限`  
**技术语境：** Tool-using Agent 与 Sub-agent 的影响范围高度取决于它持有的权限。  
**例句：** `Sub-agentにはTaskに必要な権限だけを与えます。`  
**中文：** 只给 Sub-agent 任务所需权限。  
**细微区别：** 常与最小权限原则一起使用。

### 2. 耐性（たいせい）
**词性：** 名詞  
**中文：** 耐受性、抗性  
**参考：N1**  
**搭配：** `攻撃耐性` / `障害耐性` / `Prompt Injection耐性`  
**技术语境：** Agent Evaluation 需要评估对 Prompt Injection、异常输入与故障的耐受程度。  
**例句：** `Prompt Injection耐性を複数のTest Caseで評価します。`  
**中文：** 用多个测试用例评估 Prompt Injection 抗性。  
**细微区别：** 常与「～に対する耐性」搭配。

### 3. 侵入（しんにゅう）
**词性：** 名詞  
**中文：** 侵入  
**参考：N2**  
**搭配：** `不正侵入` / `侵入経路` / `侵入を防ぐ`  
**技术语境：** Prompt Injection 可以类比为不可信指令通过外部内容进入 Agent Context。  
**例句：** `外部Documentを通じた不正な指示の侵入を防ぎます。`  
**中文：** 防止非法指令通过外部文档侵入。  
**细微区别：** 一般 Security 中也常指系统或网络侵入。

### 4. 逸脱（いつだつ）
**词性：** 名詞  
**中文：** 偏离、脱离规范  
**参考：N1**  
**搭配：** `Policyからの逸脱` / `目的からの逸脱` / `逸脱を検知する`  
**技术语境：** Agent Evaluation 要检查行为是否偏离 System Prompt、Task Goal 或 Policy。  
**例句：** `AgentがTaskの目的から逸脱していないか評価します。`  
**中文：** 评估 Agent 是否偏离任务目标。  
**细微区别：** 正式书面，强调偏离规定或预期。

### 5. 監視（かんし）
**词性：** 名詞  
**中文：** 监控  
**参考：N2**  
**搭配：** `継続監視` / `監視対象` / `監視基盤`  
**技术语境：** Long-running Agent 需要持续监控执行状态、Tool Call 与异常行为。  
**例句：** `Long-running Agentの状態を監視基盤で追跡します。`  
**中文：** 通过监控平台追踪长期运行 Agent 的状态。  
**细微区别：** 比「見る」更强调持续观察。

### 6. 実行する（じっこうする）
**词性：** 動詞・サ変  
**中文：** 执行  
**参考：N2**  
**搭配：** `Commandを実行する` / `Toolを実行する` / `処理を実行する`  
**技术语境：** Agent Harness 的核心工作之一是管理哪些 Tool / Command 可以在何处执行。  
**例句：** `危険なCommandは隔離されたSandboxで実行します。`  
**中文：** 危险命令在隔离的 Sandbox 中执行。  
**细微区别：** 与程序和命令真正执行的语感很强。

### 7. 防止する（ぼうしする）
**词性：** 動詞・サ変  
**中文：** 防止、预防  
**参考：N2**  
**搭配：** `漏えいを防止する` / `誤操作を防止する` / `被害拡大を防止する`  
**技术语境：** Prompt Injection 防御与 Tool Allowlist 都属于预防措施。  
**例句：** `Toolの権限を絞って被害の拡大を防止します。`  
**中文：** 通过缩小 Tool 权限防止损害扩大。  
**细微区别：** 比「防ぐ」更书面、更偏制度性措施。

### 8. 評価する（ひょうかする）
**词性：** 動詞・サ変  
**中文：** 评价、评估  
**参考：N2**  
**搭配：** `性能を評価する` / `実務Taskで評価する` / `耐性を評価する`  
**技术语境：** 当天强调不要只看 Model Benchmark，还要评估 Harness 与 Production-like Task。  
**例句：** `Model性能だけでなくHarnessの安全性も評価します。`  
**中文：** 不仅评估模型性能，也评估 Harness 安全性。  
**细微区别：** 「検証」偏确认是否成立；「評価」偏衡量好坏程度。

### 9. 分割する（ぶんかつする）
**词性：** 動詞・サ変  
**中文：** 拆分、分割  
**参考：N2**  
**搭配：** `Taskを分割する` / `役割を分割する` / `処理を分割する`  
**技术语境：** Sub-agent 设计通常把大型 Task 拆成更小、更明确的职责。  
**例句：** `大きなTaskを複数のSub-agent向けに分割します。`  
**中文：** 把大型任务拆分给多个 Sub-agent。  
**细微区别：** 比「分ける」更技术文档化。

### 10. 追跡する（ついせきする）
**词性：** 動詞・サ変  
**中文：** 追踪、跟踪  
**参考：N1**  
**搭配：** `履歴を追跡する` / `Tool Callを追跡する` / `変更を追跡する`  
**技术语境：** Agent Harness 与 Observability 需要按时间追踪执行路径。  
**例句：** `AgentがどのToolを呼んだかをSession単位で追跡します。`  
**中文：** 按 Session 追踪 Agent 调用了哪些 Tool。  
**细微区别：** 强调随时间持续跟踪。

### 11. 想定する（そうていする）
**词性：** 動詞・サ変  
**中文：** 设想、预估  
**参考：N1**  
**搭配：** `攻撃を想定する` / `本番を想定する` / `失敗を想定する`  
**技术语境：** Prompt Injection 与恶意输入必须作为预期会发生的场景设计。  
**例句：** `外部Documentに悪意ある指示が含まれることを想定して設計します。`  
**中文：** 按外部文档可能含恶意指令的前提来设计。  
**细微区别：** 常用于 Risk Design。

### 12. 委ねる（ゆだねる）
**词性：** 動詞・一段  
**中文：** 交由、委托  
**参考：N1**  
**搭配：** `判断を委ねる` / `権限判断を委ねる` / `すべてを委ねる`  
**技术语境：** Human Control 的边界决定哪些判断可以交给 Agent。  
**例句：** `重要な権限判断をLLMだけに委ねません。`  
**中文：** 不把重要权限判断只交给 LLM。  
**细微区别：** 比「任せる」书面正式。

### 13. 拒否する（きょひする）
**词性：** 動詞・サ変  
**中文：** 拒绝  
**参考：N2**  
**搭配：** `Requestを拒否する` / `実行を拒否する` / `接続を拒否する`  
**技术语境：** Guardrail 与 Tool Allowlist 应在 Runtime 层拒绝违反 Policy 的操作。  
**例句：** `Policyに違反するTool CallはRuntimeで拒否します。`  
**中文：** Runtime 拒绝违反 Policy 的 Tool Call。  
**细微区别：** 比「断る」更正式，也更适合系统行为。

### 14. 必要（ひつよう）
**词性：** な形容詞  
**中文：** 必要的  
**参考：N3**  
**搭配：** `必要な権限` / `必要な対策` / `必要なContext`  
**技术语境：** Context Isolation 与 Least Privilege 都强调只给 Agent 必要信息和权限。  
**例句：** `Sub-agentには必要なContextだけを渡します。`  
**中文：** 只把必要 Context 交给 Sub-agent。  
**细微区别：** 表示客观 Requirement。

### 15. 脆弱（ぜいじゃく）
**词性：** な形容詞  
**中文：** 脆弱的、易受攻击的  
**参考：N1**  
**搭配：** `脆弱な挙動` / `脆弱な設計` / `攻撃に脆弱`  
**技术语境：** Agent Evaluation 会寻找对 Prompt Injection 脆弱的行为模式。  
**例句：** `Prompt Injectionに脆弱な挙動をEvaluationで検出します。`  
**中文：** 通过 Evaluation 检出对 Prompt Injection 脆弱的行为。  
**细微区别：** Security 文档中的高频形容词。

### 16. 過度（かど）
**词性：** な形容詞  
**中文：** 过度的  
**参考：N1**  
**搭配：** `過度な権限` / `過度な自動化` / `過度に依存する`  
**技术语境：** 把过多权限或判断权交给 Agent 会扩大 Blast Radius。  
**例句：** `過度な権限付与は事故時の影響範囲を広げます。`  
**中文：** 过度授权会扩大事故时的影响范围。  
**细微区别：** 比「多すぎる」正式。

### 17. あらかじめ（あらかじめ）
**词性：** 副詞  
**中文：** 预先、事先  
**参考：N1**  
**搭配：** `あらかじめ定義する` / `あらかじめ除外する` / `あらかじめ想定する`  
**技术语境：** Harness 应预先定义 Tool Allowlist、Sandbox 与拒绝规则。  
**例句：** `利用可能なToolをあらかじめAllowlistで定義します。`  
**中文：** 事先用 Allowlist 定义可使用 Tool。  
**细微区别：** 比「前もって」更书面。

### 18. 継続的に（けいぞくてきに）
**词性：** 副詞  
**中文：** 持续地  
**参考：N2**  
**搭配：** `継続的に監視する` / `継続的に評価する` / `継続的に改善する`  
**技术语境：** Agent Evaluation 不是上线前一次性完成，需要持续运行和复测。  
**例句：** `本番の失敗Caseを追加しながら継続的に評価します。`  
**中文：** 一边加入生产失败案例，一边持续评估。  
**细微区别：** 技术报告中比「ずっと」正式。

### 19. 安易に（あんいに）
**词性：** 副詞  
**中文：** 轻率地、简单地  
**参考：N1**  
**搭配：** `安易に任せない` / `安易に信頼しない` / `安易に許可しない`  
**技术语境：** 外部输入与 Agent 输出都不应未经验证就直接信任或执行。  
**例句：** `外部Documentの指示を安易に信頼してはいけません。`  
**中文：** 不能轻率信任外部文档中的指令。  
**细微区别：** 带“没有充分考虑”的负面语感。

### 20. 一方で（いっぽうで）
**词性：** 接続表現  
**中文：** 另一方面、同时（表对比）  
**参考：N2**  
**搭配：** `便利な一方で` / `自律的な一方で` / `一方でRiskもある`  
**技术语境：** Tool-using Agent 提升自动化能力的同时，也扩大 Prompt Injection 的影响面。  
**例句：** `Agentは多くの作業を自動化できる一方で、攻撃時の影響も大きくなります。`  
**中文：** Agent 可以自动化很多作业，但遭受攻击时影响也会变大。  
**细微区别：** 适合说明 Trade-off。

## C-2. IT/AI专业词汇

### 1. Agent Harness
**日本語：** エージェント・ハーネス  
**中文：** Agent 执行框架  
**当天语境：** 管理 Model、Tool、Session、Sandbox 与 Agent Loop。

### 2. Prompt Injection
**日本語：** プロンプトインジェクション  
**中文：** 提示注入  
**当天语境：** 恶意输入诱导 Agent 执行非预期指令。

### 3. Sub-agent
**日本語：** サブエージェント  
**中文：** 子 Agent  
**当天语境：** 承担主 Agent 拆分出的专门子任务。

### 4. Context Isolation
**日本語：** コンテキスト分離  
**中文：** 上下文隔离  
**当天语境：** 不同 Agent 只获得完成自身任务需要的信息。

### 5. Production-like Evaluation
**日本語：** 実務評価  
**中文：** 接近生产环境的评估  
**当天语境：** 用真实任务而非单一 Benchmark 评价 Agent。

### 6. Guardrail
**日本語：** ガードレール  
**中文：** 安全护栏  
**当天语境：** 限制 Agent 输入、输出、Tool 和权限的安全机制。

### 7. Bedrock AgentCore
**日本語：** Bedrock AgentCore  
**中文：** AWS 的 Agent 运行与治理基础设施  
**当天语境：** 用于部署、身份、Gateway、Memory 与可观测性等 Agent 能力。

### 8. Tool Allowlist
**日本語：** Tool許可リスト  
**中文：** 工具白名单  
**当天语境：** 明确允许 Agent 调用的 Tool 集合，以缩小攻击面。

## C-3. JLPT语法

### 1. ～かねない
**参考：N1**  
**中文：** 有可能导致不良结果  
**接续：** `動詞ます形去ます + かねない`  
**使用场景：** 警示 Prompt Injection 或过度权限可能带来严重后果。  
**例句：** `外部入力をそのまま実行すると、機密情報を送信しかねません。`  
**中文：** 直接执行外部输入可能会发送机密信息。  
**注意：** 通常用于负面风险。

### 2. ～にとどまらず
**参考：N1**  
**中文：** 不仅限于……  
**接续：** `名詞 / 普通形 + にとどまらず`  
**使用场景：** 说明 Agent Evaluation 不只测 Model，也要测 Harness、Tool 与 Runtime。  
**例句：** `Agent EvaluationはModel性能にとどまらず、HarnessやToolの安全性まで対象にします。`  
**中文：** Agent 评估不仅限于模型性能，也覆盖 Harness 和 Tool 安全性。  
**注意：** 适合范围扩展。

### 3. ～なくしては
**参考：N1**  
**中文：** 没有……就无法……  
**接续：** `名詞 + なくしては`  
**使用场景：** 强调持续 Evaluation 与 Trace 是生产 Agent 的基础条件。  
**例句：** `継続的なEvaluationなくしては、Agentの安全性を維持できません。`  
**中文：** 没有持续评估，就无法维持 Agent 安全性。  
**注意：** 语气较强。

### 4. ～に応じて
**参考：N2**  
**中文：** 根据……相应调整  
**接续：** `名詞 + に応じて`  
**使用场景：** 按 Task Risk 决定权限、Sub-agent 和 Human Approval。  
**例句：** `TaskのRiskに応じてHuman Approvalの要否を決めます。`  
**中文：** 根据任务风险决定是否需要人工批准。  
**注意：** 强调条件和对应措施。

### 5. ～一方で
**参考：N2**  
**中文：** 另一方面……  
**接续：** `普通形 + 一方で`  
**使用场景：** 说明自主性与安全风险的 Trade-off。  
**例句：** `Sub-agentは並列化に有効な一方で、Contextと権限の管理が複雑になります。`  
**中文：** Sub-agent 有利于并行，但 Context 和权限管理更复杂。  
**注意：** 适合面试回答。

### 6. ～たうえで
**参考：N2**  
**中文：** 在……之后、在……基础上  
**接续：** `動詞た形 + 上で`  
**使用场景：** 先机器 Evaluation 再决定是否扩大 Agent 权限。  
**例句：** `Production-like Taskで評価したうえで、利用範囲を拡大します。`  
**中文：** 在接近生产的任务中评估后，再扩大使用范围。  
**注意：** 强调前一步是决策依据。

### 7. ～にかかわらず
**参考：N2**  
**中文：** 不论……都……  
**接续：** `名詞 + にかかわらず`  
**使用场景：** 表达所有 Agent 都必须遵守的共同安全规则。  
**例句：** `利用するModelにかかわらず、外部入力は信頼できないものとして扱います。`  
**中文：** 无论使用哪个模型，都把外部输入视为不可信。  
**注意：** 适合统一 Policy。
