## 4. 今日の技術テーマ

# Agent Extension Supply Chain Security

标准化 Plugin 提升可移植性，也让 Skill、MCP Server、Manifest、Tool Metadata、Actual Implementation 和 Runtime Permission 组成新的供应链。企业环境应采用 Approved Registry、Version Pinning、Permission Review、Sandbox 和 Runtime Audit。Portability 越高，错误或恶意配置的 Blast Radius 也越大。

```text
Source / Marketplace
  ↓
Allowlist / Signature
  ↓
Install / Version
  ↓
Runtime Permission
  ↓
Audit / Rollback
```

### 优点

**第一，减少无关复杂度。** 通过把职责拆成 `Source / Marketplace` 到 `Audit / Rollback` 的明确层次，可以让模型只处理概率性判断，而把权限、验证和停止条件交给确定性系统。

**第二，更容易测量与回滚。** 每一层都能单独记录 Input / Output / Cost / Failure，出现异常时可以定位问题，而不是把所有错误都归因于“模型不够好”。

**第三，更适合团队规模化。** 安全性不能只交给 Prompt，应叠加最小权限、Runtime 强制、审计日志和必要的人类批准，因此可以把个人技巧转成可复用的 Platform Rule、CI Check 或 Governance Policy。

### 局限

**系统复杂度会上升。** 多一层 Router、Policy、Sandbox、Trace 或 Evaluation 都会带来开发和维护成本，需要确认它解决的是实际风险，而不是为了“架构完整”而堆层。

**确定性 Guardrail 也可能配置错误。** Policy、Test、Metric 与 Retrieval Rule 都需要版本管理和持续校准，不能因为“不是 LLM”就默认它绝对正确。

### 日本企业落地时的注意点

1. 先明确 **Owner、Data Boundary、Permission、Approval、Audit、Rollback**，再扩大 Agent 自治范围。  
2. 把现有的 **CI/CD、SRE、Security Review、Change Management** 继续保留，不因为接入 AI 就另建一套不可追踪的旁路。  
3. 用日本企业实际关心的 **品質、工数、Cost、Security Incident、Business Outcome** 评价，而不是只统计 AI 使用次数。

面试里可以这样总结：

> ModelへのInstructionだけに依存せず、最小権限、Runtimeでの強制、監査ログ、必要に応じたHuman Approvalを組み合わせてDefense in Depthを設計します。

1. **Exit Code 0でもCompliance要件を満たすとは限らないため、実際のArtifactを確認する必要があります。**
2. **PoCの成功だけで判断せず、品質、Cost、Security、Observability、Failure時のRecoveryを含めて実運用で評価します。**
3. **導入判断では、適用条件とTrade-offを明確にし、実際のWorkloadで評価することが重要です。**
4. **本番運用では、変更履歴、監査性、Rollback手段まで含めて設計する必要があります。**

## C-3. JLPT语法

### 1. ～にとどまらず
**参考：N1**  
**中文：** 不仅限于……  
**接续：** `名詞 / 普通形 + にとどまらず`  
**使用场景：** 说明 Plugin Security 不只检查 Code，也覆盖 Source、Signature、Permission 与 Update。  
**例句：** `Plugin SecurityはCode Reviewにとどまらず、署名や配布元の確認まで必要です。`  
**中文：** Plugin Security 不仅限于 Code Review，也需要确认签名和发布源。  
**注意：** 适合范围扩展。

### 2. ～恐れがある
**参考：N1**  
**中文：** 有……风险  
**接续：** `動詞辞書形 / 名詞 + の + 恐れがある`  
**使用场景：** 正式提示 Tool Poisoning 与 Supply Chain Attack 的风险。  
**例句：** `悪意あるTool Descriptionを読み込むと、意図しない操作を実行する恐れがあります。`  
**中文：** 读取恶意 Tool Description 可能执行非预期操作。  
**注意：** 正式风险表达。

### 3. ～かねない
**参考：N1**  
**中文：** 可能导致不良结果  
**接续：** `動詞ます形去ます + かねない`  
**使用场景：** 警示未验证 Plugin / Search Result 被直接使用的后果。  
**例句：** `Sourceを確認せずPluginを導入すると、Supply Chain攻撃を招きかねません。`  
**中文：** 不确认来源就导入 Plugin 可能招致供应链攻击。  
**注意：** 通常用于负面结果。

### 4. ～とは限らない
**参考：N2**  
**中文：** 未必……  
**接续：** `普通形 + とは限らない`  
**使用场景：** 提醒 Popular / Open Source 并不自动等于安全。  
**例句：** `人気のPluginだから安全とは限りません。`  
**中文：** 受欢迎的 Plugin 未必就安全。  
**注意：** 适合 Security skepticism。

### 5. ～に備えて
**参考：N2**  
**中文：** 为……做准备  
**接续：** `名詞 + に備えて`  
**使用场景：** 说明平时维护 Inventory / Rollback 等事故准备。  
**例句：** `緊急Patchに備えてDependency Inventoryを維持します。`  
**中文：** 为紧急 Patch 做准备，维护 Dependency Inventory。  
**注意：** 风险管理常用。

### 6. ～た上で
**参考：N2**  
**中文：** 在……之后、在……基础上  
**接续：** `動詞た形 + 上で`  
**使用场景：** 先确认影响和兼容性，再更新 Framework。  
**例句：** `影響範囲と互換性を確認した上でVersionを更新します。`  
**中文：** 确认影响范围和兼容性后更新版本。  
**注意：** 强调前一步是决策依据。

### 7. ～一方で
**参考：N2**  
**中文：** 另一方面……  
**接续：** `普通形 + 一方で`  
**使用场景：** 说明 Plugin 能力扩展与 Supply Chain Risk。  
**例句：** `PluginはAgentの機能を拡張できる一方で、攻撃面も広げます。`  
**中文：** Plugin 可扩展 Agent 功能，但也扩大攻击面。
