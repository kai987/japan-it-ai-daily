## A. 详细文字版

### 今日最值得看的 5 篇

1. **Next.js Security Patch**：补丁发布前应先确认当前 Version、Lockfile、CI / E2E 和部署流程，正式 Advisory 发布后再按影响范围升级。
2. **Agent Plugins 1.0**：Skill 和 MCP Configuration 可以打包跨 Client 复用，降低重复维护，但也扩大错误 Plugin 的传播范围。
3. **MCP Tool Poisoning**：Agent 根据 Tool Name、Description 和 Schema 判断用途，这些 Metadata 若被恶意 Server 伪装，可能导致破坏性操作。
4. **AgentCore Web Search**：Web Search 可通过 Domain / Date Filter 控制来源和最新性，并作为 MCP Tool 与 Knowledge Base 混合使用。
5. **Codex Conformance Test**：Exit Code 0 只表示 Process 正常结束；涉及 Non-persistence、Security、Compliance 时必须检查真实 Artifact。

### 面接で使えるポイント

> MCP Serverは信頼できる提供元を利用し、破壊的なToolには最小権限、Sandbox、Human Approvalを組み合わせる必要があります。

> Security Requirementは設定値やExit Codeだけでなく、実際のFileやArtifactの挙動を検証することが重要です。

### 今日の技术主题：Agent Extension Supply Chain Security

标准化 Plugin 提升可移植性，也让 Skill、MCP Server、Manifest、Tool Metadata、Actual Implementation 和 Runtime Permission 组成新的供应链。企业环境应采用 Approved Registry、Version Pinning、Permission Review、Sandbox 和 Runtime Audit。Portability 越高，错误或恶意配置的 Blast Radius 也越大。

### 面试复习卡

- `MCP Tool Poisoningとは何ですか。` → Metadata vs Handler / Trust Boundary。
- `Agent Plugin標準化のリスクは何ですか。` → Supply Chain / Permission / Version。
- `CLIのSecurity Requirementをどう検証しますか。` → Behavioral Verification / Artifact Check / Fail Closed。

## B. 重点总结和面试可用的知识点

### Next.js Patch Management
**中文：** 安全补丁不仅是升级 Dependency，还要做影响范围确认、Regression / E2E 和 Staging 验证。

**日本語：** Security PatchではVersion更新だけでなく、影響範囲、回帰テスト、Staging確認まで含めて対応する必要があります。

### Agent Plugins 1.0
**中文：** Skill 与 MCP 标准化减少重复配置，但 Version、Source 和 Permission 需要集中治理。

**日本語：** Agent Pluginの標準化で再利用性は高まりますが、Version、配布元、PermissionのGovernanceが重要になります。

### Tool Poisoning
**中文：** Tool Metadata 不能默认可信，模型自己识别危险 Tool 并不足够。

**日本語：** Tool名やDescription自体が信頼できない可能性があるため、LLM判断だけに依存しないSecurity設計が必要です。

### AgentCore Web Search
**中文：** Domain / Date Filter 让 Web Retrieval 更适合企业对 Source 和 Freshness 的治理。

**日本語：** Domain FilterとPublished Date Filterで、検索SourceとFreshnessを制御できます。

### Codex --ephemeral
**中文：** 自动化工具的成功状态不等于业务/合规要求达成，必须验证真实持久化行为。

**日本語：** Exit Code 0でもCompliance要件を満たすとは限らないため、実際のArtifactを確認する必要があります。
