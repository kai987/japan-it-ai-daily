- 例句译文：因为发现设置错误，重新测量了数据。
- 语感区别：强调重新获得结果，不表示可以把失败记录悄悄删除。

## C-2. IT/AI 专业词汇

1. **durable execution（中断から再開できる実行）**：保存调用和结果，恢复后可从记录重建处理。 浏览器案例的重放限于只读工具，嵌套 SQL 还需结果缓存。

2. **OPFS（オリジン専用ファイルシステム）**：浏览器按来源隔离的私有文件存储。 此案例用 Web Locks 防止多个标签同时占用数据库。

3. **Lambda Web Functions（HTTPサーバー型のLambda）**：一个服务环境中同时处理多个 HTTP 请求的执行形式。 Node.js 单进程的 CPU 串行和 I/O 等待并发必须分开评估。

4. **flue（軽量エージェントフレームワーク）**：用于组织代理会话、状态和工具的框架。 LINE 案例将其用于受限容器内的运维调查，不赋予实际处置的所有权。

5. **mutation testing（ミューテーションテスト）**：主动插入小错误，检查测试是否能发现它们的方法。 LINE 报告用它审视 AI 实现带来的测试质量，而不只看测试数量。

6. **Vitest projects（テスト構成の分離）**：让不同测试组使用各自执行环境的 Vitest 配置。 e-dash 将不需要 DOM 的测试与 jsdom 测试分开，再统一控制 worker。

7. **blob report（統合用テストレポート）**：可在分片测试后合并的中间测试报告。 覆盖率须在合并全部报告后判定，而非各片独立通过就结束。

8. **Markdown content negotiation（Markdownでの応答形式指定）**：通过 HTTP 头要求服务返回 Markdown 正文。 Cloudflare 的搜索只返候选，所选页面仍需单独取回并确认。

## C-3. 新学语法

今日新学语法1项。已核对69期全部学习记录：「～限り」取肯定状态持续时的条件义，与既习「～限りでは」的所知范围及「～ない限り」的否定条件分开。其他可见文型不因换例句成为新学；不足5项如实保留，复习另由共享模块按当日用例选择。

### 1. ～限り｜N2

- 含义：只要某状态仍持续，就在该条件下成立。
- 结构：動詞普通形＋限り／い形容詞＋限り／名詞・な形容詞＋である限り
- 用法：用状态持续划定结论范围。原文限定的是执行环境仍存在的期间，即使没有请求也继续产生内存费用。
- 原文形态：限り
- 原文依据：[メモリの課金はリクエストがなくても環境が残っている限り続きます。](https://zenn.dev/aws_japan/articles/lambda-web-functions-vs-event-functions)
- 独立例句：接続が続いている限り、同じ処理の結果を待ちます。
- 例句译文：只要连接还在持续，就等待同一处理的结果。
- 注意：区别既习的「～限りでは」（所知范围）与「～ない限り」（除非）。这里是肯定状态持续的条件；例句不是产品保证。
