# A. 詳細版

## 1. 今日読むべき5本

### ① Claude Code hooksでAI Agentの実行プロセスを可観測化

**出典:** Zenn
**原文 URL:** https://zenn.dev/alzcb4/articles/8a5ce86949b7ff

Claude Codeのhooksは、Claude Codeのイベントをきっかけに任意のコマンドを実行する仕組みです。記事では`PostToolUse`を中心に、`Edit`、`Write`、`Bash`、MCPツールなどの実行後に標準入力のJSONを受け取り、`~/.claude/settings.json`からPythonのhookを呼び出しています。`hook_event_name`、`tool_name`、`tool_input`を使い、ファイルパスやコマンド、Promptを1行のログへ整形する最小実装が示されています。

実運用では、同じ`actor|label`の内容を20秒以内に繰り返して出さない重複抑制、自分自身のログ出力コマンドを無視する再帰防止、`mcp__codex__...`をCodexとして表示する委譲先の識別を加えます。さらに重要なのは、Toolが正常終了した事実と、期待した副作用が実際に起きたことは別だという点です。実行ログに加えて成果物を読み戻し、期待状態を検証する結果ログを持つ設計が必要になります。

**注目ポイント:** `PostToolUse`は「成功を返した」までしか保証しないため、投稿やファイル更新の後に実物を再取得して成否を判定するObservabilityが重要です。

### ② BM25 を使用して Codex のトークン消費を約30%抑える

**出典:** Zenn
**原文 URL:** https://zenn.dev/knowledgesense/articles/9e55a3bb67729c

ナレッジセンスの記事は、コード探索の前段にBM25を置いたときのCodexの変化を、自社の7,536ファイル、68.8MBのリポジトリで比較しています。通常探索はGlob、Grep、ファイル読み取りを使い、BM25探索はローカルBM25検索と該当範囲の追加読み取りをMCPとして提供しました。低・中・高難度の質問を各4問、毎回新しいセッションで実行し、回答に必要な情報が含まれるかを検証しています。

12問のセッション全体では、通常探索の1,812,066 Tokenに対しBM25探索は1,283,250 Tokenで、29.2%減りました。質問ごとの削減率中央値は28.5%、動作時間短縮率中央値は34.2%でしたが、中・高難度では個別にTokenが増えた質問もあります。BM25は検索語の頻度と珍しさからコード断片を順位付けし、候補のパス、行範囲、短い抜粋を返します。探索の入口を絞り、複数ファイルをまたぐ調査はCodexに任せる役割分担がポイントです。

**注目ポイント:** 7,500ファイル規模では、15,000コード断片のSQLiteインデックスを27秒で構築でき、インデックスの完成サイズは164MBでした。

### ③ Amazon SageMaker AI、オープンソースモデルのServerless Full Fine-tuningに対応

**出典:** AWS What’s New
**原文 URL:** https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-sagemaker-fft/

Amazon SageMaker AIのサーバーレスモデルカスタマイズが、25を超えるオープンソースモデルのフルファインチューニングに対応しました。対象にはgpt-oss、Gemma、Llama、Nemotron、Qwenのモデルファミリーが含まれます。LoRAのように一部の重みだけを更新する手法に加えて、必要な場合はモデル内の全パラメータを更新し、ドメイン固有のパターン、用語、タスク構造をより深く適応させられます。

この機能では、SageMakerがインフラストラクチャのプロビジョニングとトレーニングのオーケストレーションを管理するため、利用者はインフラを自分で構築・管理せずにジョブを実行できます。料金は使用した分に対して発生します。利用可能リージョンは米国東部（バージニア北部）、米国西部（オレゴン）、アジアパシフィック（東京）、欧州（アイルランド）で、SageMaker StudioのJumpStart and ModelsページまたはSageMaker Python SDKから開始できます。

**注目ポイント:** 表面的な文体調整ではなく、専門的な推論パターンや複雑な出力形式、独自データセットの知識を学習させたい場合の選択肢です。

### ④ Next.js 16.3：Instant Navigationsとパフォーマンス最適化

**出典:** Next.js / Vercel
**原文 URL:** https://nextjs.org/blog/next-16-3

Next.js 16.3は、既存アプリを変更せずに開発時メモリ、ビルド、型チェック、Server-side renderingを改善します。Turbopackの`next dev`は最大90%少ないメモリを使い、ディスクキャッシュは`next build`でも標準で有効です。TypeScript 7による型チェック、Node.js streamsを使ったSSRにより、負荷時に最大22%多くのリクエストを処理できるというベンチマークも示されています。AI coding agent向けには、プロジェクトのNext.jsのバージョンに合うドキュメントを指す`AGENTS.md`ブロックも自動管理します。

オプトインのInstant Navigationsでは、`cacheComponents`と`partialPrefetching`を有効にし、Server ComponentsとSuspense、`use cache`を組み合わせます。Instant Insightsは遅いナビゲーションを検出し、Partial Prefetchingはリンクごとに先読みする内容を細かく制御します。さらに、初回訪問でInstant loading shellを返すISR、Navigation Inspector、ナビゲーションの即時表示を検証するPlaywrightの`instant()` helperが追加されました。

**注目ポイント:** Instant Navigationsの挙動は将来のメジャーバージョンで標準になる予定ですが、16.3では明示的なフラグで導入する段階です。

### ⑤ Meta Muse Glimmer：ローカルAI Agent向け30Bオープンモデル

**出典:** gihyo.jp
**原文 URL:** https://gihyo.jp/article/2026/08/muse-glimmer

Metaは2026年8月10日、ローカル環境で常時動作するAI Agent向けのオープンウェイトモデルMuse Glimmerを発表しました。約300億パラメータで、Macや単一のコンシューマー向けGPUを搭載したPCでの動作を想定し、重みはApache License 2.0で公開されています。複数段階の推論、Tool Call、長時間タスク、失敗からの復旧に加え、画像エンコーダーによるスクリーンショット、グラフ、文書の扱い、推論レベルの切り替えに対応します。

フル精度では55GBを超えるメモリーが必要ですが、約4ビット量子化で言語モデル部分を20GB未満に圧縮しました。KVキャッシュ、画像エンコーダー、補助モデルを同時に動かしても、24GBまたは32GBの環境を想定できます。15種類のベンチマーク平均では、性能低下は32GB向けK-Quant-Dynamicが0.2%、24GB向けK-Quant-17GBが1.0%でした。DFlashによる投機的デコーディングでは補助モデルが一度に16 Tokenの候補を生成し、本体が並列検証します。

**注目ポイント:** MCP Atlasでは75.5、SWE-Bench Proでは51.2でしたが、OSWorld-VerifiedとTerminalBench 2.1ではQwen3.6-27Bが上回りました。モデル選定では用途別の評価条件を確認する必要があります。

## 4. 今日の技術テーマ

### Agentに「実行」だけでなく「検索・観測・検証」を組み込む

今日の中心テーマは、Agentへ大きなモデルを与えることだけでなく、必要な情報を絞って渡し、行動を観測し、結果を検証する閉ループ設計です。BM25はRetrievalでContextを絞り、Claude Code hooksは実行経路を記録します。Next.jsの開発ツールやSageMakerの管理機能、Muse Glimmerのローカル実行も、実行基盤を測定・制御可能にする方向で共通しています。

**メリット**

- 不要なファイルやContextを減らし、Token消費と推論の無駄を抑えられる。
- Tool Callの経路と成果物を追跡でき、障害の原因を調べやすい。
- Cloud、Serverless、Localを用途に応じて切り替え、Privacyやレイテンシを設計できる。

**制約・リスク**

- 検索順位が悪いと必要な情報を見落とし、Agentの回答品質を下げる可能性がある。
- Toolの成功ログだけでは副作用の失敗を見逃す。成果物側の再取得と検証が必要である。
- フルファインチューニングやローカル推論では、データ、GPUメモリー、評価条件、運用費が増える。

**日本企業で導入する際の注意点**

まず機密データの分類、保存先、アクセス権限、監査ログの保持期間を決めます。次に、質問別の品質、Token、Latency、失敗時の復旧を同じ評価セットで測定します。CloudとLocalを組み合わせる場合は、あらかじめFallbackと成果物の検証手順を定義し、運用担当者がTraceから影響範囲を把握できるようにします。

## 5. 面接復習カード

### Q1. 実行ログと結果ログはなぜ分けるのですか。

**回答ポイント:** 実行ログはToolが正常終了した事実、結果ログは意図した成果物が利用者から見える状態になった事実を記録する。両方を照合して初めて有効な成功判定になる。

### Q2. BM25をAgentの前段に置くと何が変わりますか。

**回答ポイント:** 関連度の高いパス、行範囲、抜粋を先に返し、Agentの探索候補とContextを絞る。平均的なToken削減を測りつつ、質問ごとの品質と例外も確認する。

### Q3. ローカルLLMとCloud Modelはどう使い分けますか。

**回答ポイント:** データの機密性、必要な精度、Latency、Cost、GPUや運用体制に応じて選ぶ。Localは外部送信を抑えられる一方、モデル更新と計算資源の管理が必要になる。

### 運用（うんよう）｜名詞｜N2

- **意味:** システムやサービスを、実際に使える状態に保ち、継続して管理すること。

## C-2. IT/AI専門用語

- **Observability｜可観測性（かかんそくせい）:** システム内部の状態を、外部から推測・把握できる性質。Claude CodeのhooksでTool実行を記録し、Agentの活動と成果物側の状態を追跡する考え方です。
- **Audit Log｜監査ログ（かんさログ）:** 誰がいつ何を実行したかを、後から確認できるように残す記録。AgentのTool Callや操作結果を記録し、説明責任や調査に役立てます。
- **Context Optimization｜コンテキスト最適化:** モデルに渡す情報を必要な範囲へ整理し、品質やコストを改善すること。BM25で関連するコード断片を先に絞り、Codexへ渡す情報量を抑える方法に関係します。
- **Retrieval｜検索・検索処理:** 大量の文書やコードから、質問に関連する情報を取り出す処理。Codexがコードベースを調査する前段で、BM25を使って候補を取得します。
- **Hybrid Architecture｜ハイブリッド構成:** 異なる実行環境や方式を、役割に応じて組み合わせる設計。機密データはLocal LLM、その他はCloud Modelという使い分けを検討する構成です。
- **BM25｜BM25検索:** 語の出現頻度と珍しさなどから、文書の関連度を順位付けする検索手法。7,000ファイル規模のリポジトリで候補を絞り、CodexのToken消費を約3割削減しました。
- **Local LLM｜ローカルLLM:** 利用者のPCや自社環境など、手元の計算資源で動かす大規模言語モデル。Muse Glimmerは4ビット量子化などにより、24GBまたは32GBメモリーの環境での実行を想定しています。
- **Telemetry｜テレメトリ:** システムの状態や動作を測定し、観測用に送るデータ。Agentの実行イベントやLatencyなどを集め、運用状況や異常を分析するために使います。

## C-3. JLPT文法

### ～にとどまらず｜N1

- **意味:** ある範囲だけで終わらず、それ以上の内容にも及ぶことを示す。
- **接続:** 名詞 / 普通形 + にとどまらず
- **使い方:** 効果や対象が一つの領域だけではないことを、改まって説明するときに使います。
- **例文:** ObservabilityはError確認にとどまらず、CostやSecurityの分析にも役立ちます。
- **例文の意味:** Observabilityはエラーの確認だけでなく、コストやセキュリティの分析にも役立ちます。
- **補足:** 「～だけでなく」より硬く、範囲の広がりを強調します。

### ～かねない｜N1

- **意味:** 悪い結果が起こる可能性がある、と懸念を示す。
- **接続:** 動詞ます形去ます + かねない
- **使い方:** 放置した場合に起こり得る望ましくない結果を、注意喚起するときに使います。
- **例文:** 不要なContextを大量に渡すと、判断精度を下げかねません。
- **例文の意味:** 不要なContextを大量に渡すと、判断の精度が下がる可能性があります。
- **補足:** 「～かもしれない」よりも、悪影響への警戒が強い表現です。

### ～なくしては｜N1

- **意味:** あるものがなければ、後ろの事柄は成立しないことを示す。
- **接続:** 名詞 + なくしては
- **使い方:** 必須条件を強調し、前提が欠けると困難になることを述べます。
- **例文:** 継続的な計測なくしては、Agentの品質改善は難しいです。
- **例文の意味:** 継続的な計測がなければ、Agentの品質を改善するのは難しいです。
- **補足:** 「～なしでは」より改まった、強い条件の表現です。

### ～に応じて｜N2

- **意味:** 状況や条件に合わせて、対応を変えることを示す。
- **接続:** 名詞 + に応じて
- **使い方:** 入力、規模、機密性などの違いに合わせた選択や変化を説明します。
- **例文:** データの機密性に応じてCloudとLocal Modelを使い分けます。
- **例文の意味:** データの機密性に合わせて、クラウドモデルとローカルモデルを使い分けます。
- **補足:** 「～に合わせて」よりも、条件との対応関係を明確にします。

### ～一方で｜N2

- **意味:** 一つの面を述べたあと、対照的な別の面を示す。
- **接続:** 普通形 + 一方で
- **使い方:** 利点と課題など、同じ対象の異なる側面を並べて説明します。
- **例文:** Local LLMはDataを外部に出さない一方で、運用負荷が高くなることがあります。
- **例文の意味:** Local LLMはデータを外部へ出さずに済みますが、その反面、運用の負担が増えることがあります。
- **補足:** 文中でも文頭でも使えます。

### ～たうえで｜N2

- **意味:** 前の行動や確認を終えてから、次の判断や行動をすることを示す。
- **接続:** 動詞た形 + 上で
- **使い方:** 手順や判断の前提を明確にし、先に行う作業を強調します。
- **例文:** Latencyを計測したうえで、利用するModelを決定します。
- **例文の意味:** Latencyを測ってから、利用するモデルを決めます。
- **補足:** 「～てから」よりも、確認を踏まえた判断という硬い印象があります。

### ～とは限らない｜N2

- **意味:** 一般に考えられることが、常に成り立つとは言えないことを示す。
- **接続:** 普通形 + とは限らない
- **使い方:** 単純な因果関係や一般化に注意を促すときに使います。
- **例文:** Parameter数が多ければ実務性能が高いとは限りません。
- **例文の意味:** Parameter数が多くても、実務での性能が高いとは限りません。
- **補足:** 「必ずしも」と組み合わせて使うこともあります。
