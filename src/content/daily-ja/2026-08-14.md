# A. 詳細版

## 1. 今日読むべき5本

### ① Markdownログ検索Local MCP：個人KnowledgeをAgent Context Layerへ

**出典**: Zenn
**原文 URL**: https://zenn.dev/yamk/articles/mdlog-mcp-local-markdown-search

この記事は、日々の技術情報をMarkdownで保存していた筆者が、そのログを対象に小さなローカルMCPサーバーを作った記録です。対象は2026年4月24日から8月13日までの229件で、AI / Web Development Digestが109件、Infra / Security / Data Digestが105件、Weekly Reviewが15件ありました。正本は従来どおりGitで管理するMarkdownのままです。

mdlog-mcpはNode.js上のstdio transportで動き、`mdlog_overview`、`mdlog_list_entries`、`mdlog_search`、`mdlog_get_entry`の4つの読み取り専用Toolを公開します。日付やslugで候補を絞り、AND検索のsnippetを見て、必要な本文だけを分割取得できます。別repositoryから同じログを参照し、現在のrepositoryとの照合や導入案の相談まで続けられる点が、単なる全文検索との差です。

**注目ポイント**

- 大規模なデータベースやembeddingを使わず、Markdownを正本として維持している。
- Overview、一覧、検索、取得という段階的なTool設計で、Agentへ渡すコンテキストを絞っている。
- ユーザースコープで登録する場合は、MCPが取得した本文の送信先と対象ログの機密性を確認する必要がある。

### ② Guren：AI Agent時代のFull-stack TypeScript Framework

**出典**: Zenn
**原文 URL**: https://zenn.dev/7nohe/articles/guren-ai-agent-framework

GurenはBunネイティブのフルスタックTypeScriptフレームワークです。Hono、Drizzle、Inertia.js + React + Vite、Zodを組み合わせ、ルーティング、コントローラ、ORM、認証、フロントエンド統合を一つの開発体験にまとめます。Laravelの規約に近い書き味を保ちながら、既存のデファクトな部品に規約を与える方針です。

特徴は、データベーススキーマからReactのPropsまでのEnd-to-End型安全性と、Agentが読めて機械が検証できる仕組みです。`guren context`はモデル、ルート、ページ、テストの構造を出力し、`guren check`、`guren audit`、`bun run typecheck`が整合性、認証・バリデーション漏れ、秘密情報、型付き契約を検査します。公開された評価では45試行中43件が動作する機能を出荷でき、新APIの3試行ではハーネスあり3/3成功、コスト中央値-29%、ハーネスなし1/3でした。ただし各条件3試行の小規模比較で、統計的な主張はできないとされています。

**注目ポイント**

- `this.validateBody()`や`userOrFail()`など、失敗を正しいHTTPレスポンスへ変換する規約を持つ。
- 規約、型生成、check/audit/typecheckを、Agentの把握・生成・検証ループに接続している。
- Bunで開発しつつ、AWS Lambda、Vercel、Cloudflare Workersへのプラグインを用意している。

### ③ AWS IAM Role Manager：自動設定は最小権限を意味しない

**出典**: DevelopersIO
**原文 URL**: https://dev.classmethod.jp/articles/iam-role-manager-lambda-execution-role/

2026年8月12日にGAとなったIAM Role Managerについて、Lambdaの実行ロールがどのように払い出されるかをAWS CLI、API、CloudTrailで検証した記事です。Role Manager対応サービスは、AWS Elastic Beanstalk、Amazon EventBridge、AWS Lambda、Amazon SageMaker Unified Studio、AWS Secrets Manager、AWS Step Functionsの6つです。Lambdaでは実行ロールの入力項目なしに関数を作成でき、CloudTrailの`AcquireRole`で払い出しが記録されます。

検証した`test-iam-0813`には`PowerUserRole`が割り当てられ、アタッチされた管理ポリシーは`PowerUserAccess`でした。主なステートメントは`iam:*`、`organizations:*`、`account:*`以外のアクションをResource `*`で許可するもので、Lambda専用の最小権限ではありません。関数実行後には`RoleLastUsed`にも利用が記録されました。開発開始を速める初期状態としては便利ですが、本番では専用ロールへ切り替え、アカウント分離、信頼ポリシー確認、GuardDutyやコスト監視を組み合わせる必要があります。

**注目ポイント**

- 自動払い出しは設定作業を減らすが、最小権限を保証しない。
- 同じテンプレートから同じ`PowerUserRole`が使われ、関数ごとの権限分離ができない。
- `PowerUserAccess`の`sts:AssumeRole`により、信頼関係によっては権限昇格経路になり得る。

### ④ Google Classroom × Gemini：Rubric自動生成でもHuman Reviewを残す

**出典**: CodeZine
**原文 URL**: https://codezine.jp/news/detail/29295

CodeZineのニュースは、Google ClassroomにGeminiによるルーブリック自動生成機能が追加されたことを扱っています。取得できた原文では、機能の中心がRubricの自動生成であることが示されています。

同時に、見出しが示すとおり、自動生成したRubricをそのまま確定するのではなく、人によるレビューを残すHuman-in-the-Loopの設計が要点です。自動化の結果を採用する前に、利用者が内容を確認し、必要に応じて修正できる境界を設ける考え方として、Agentの高リスク操作にも応用できます。

**注目ポイント**

- 生成機能を導入しても、最終判断を人から切り離さない。
- 「生成できること」と「そのまま利用してよいこと」を分けて設計する。
- 教育現場のRubricのように、判断基準を扱う機能ではレビュー経路が重要になる。

### ⑤ QAをやめて、QAをはじめる──欠陥検出0件が続いた組織で、品質保証の重心を3回動かした話

**出典**: LayerX Engineering Blog
**原文 URL**: https://tech.layerx.co.jp/entry/quit-qa-start-qa

LayerXのAi Workforce事業部では、5月下旬以降、テストを続けているにもかかわらず欠陥検出0件のリリースが続き、6月には確認型テスト252件で検出0件でした。しかし本番のインシデントがなくなったわけではなく、環境差分、設定、運用、基盤、外部サービス連携へリスクが移っていました。JSTQBの「テストは欠陥があることは示せるが、欠陥がないことは示せない」という原則が、0件の解釈を戒めています。

QAの重心は、2025年10月の観測、2025年12月の検出、2026年の観測・検出・価値の検証へと3回動きました。コードレビューの指摘をCIのガードレールへ移したことや、AIモデルの進化・セルフレビューによる混入減少は仮説であり、因果関係を示すデータはまだありません。今後は手動の重複確認を圧縮し、CIの回帰テスト、探索的テスト、仕様・ユースケースへの批評、リリース後の観測設計に価値を置きます。

**注目ポイント**

- 欠陥検出0件は品質完成の証明ではなく、リスクの位置を観測し直す契機である。
- QAを全プロジェクトの直列化点にせず、品質リスクと残存リスクを判断できる状態を設計する。
- 仕様どおりかの確認が自動化されるほど、ユーザー価値を測る基準・観測・証跡が重要になる。

## 2. カテゴリ別サマリー

### AI / Agent

①のローカルMCPは、既存のMarkdownから必要なコンテキストだけを段階的に渡すContext Gatewayの実例です。②のGurenは、Agentが読める規約と機械検証をフレームワークへ組み込みます。④は、自動生成してもHuman Reviewを残す境界設計を示します。

### Frontend / Web

②では、GurenがInertia.js、React、Viteをフロントエンド統合として採用し、コントローラからReactのPropsまで型をつなぎます。今回の他の記事に、別のFrontend / Web実装を詳しく扱う項目はありません。

### Cloud / Backend

③は、AWS Lambdaの作成時にIAM Role Managerがロールを払い出す挙動を、CloudTrail、IAM API、CloudWatch Logsで確認しています。自動設定を本番へ持ち込む前に、実際のポリシーと信頼関係を読むことがBackend運用の要点です。

### 日本企業 Tech Blog / enterprise engineering signals

⑤はLayerXのAi Workforce事業部におけるQAの実践で、組織の状況に応じて観測・検出・価値の検証へ投資配分を変えています。日本企業の開発組織では、ツール導入数ではなく、リスクを観測し判断できる仕組みとしてAgent、IAM、QAを接続する視点が重要です。

## 3. 面接で使えるポイント

### 1. MCPで社内ナレッジを扱う設計

**質問**: MCPで社内の技術ログをAgentに参照させるとき、どのように安全性とコンテキスト量を管理しますか。
**回答例（約30秒）**: まずMarkdownなどの正本は変えず、一覧、検索、本文取得を読み取り専用Toolとして分けます。Overviewで全体を確認し、日付や検索語で対象を絞り、必要な本文だけを渡します。機密ログを対象にせず、ユーザースコープで登録する場合は送信先とアクセス範囲も確認します。
**関連プロジェクト**: mdlog-mcp
**キーワード**: MCP、読み取り専用、Context Gateway

### 2. AIコーディングの検証

**質問**: AIが生成したコードをレビューする際、何を機械化しますか。
**回答例（約30秒）**: 生成量を増やすだけでなく、規約と型付き契約を先に整えます。そのうえで、ルート・コントローラ・ページの整合性、バリデーション、認証、秘密情報をcheckやaudit、typecheckで検査し、CIで失敗を止めます。人は機械で表せない仕様や価値の判断に集中します。
**関連プロジェクト**: Guren
**キーワード**: TypeScript、型安全性、Automated Validation

### 3. AWSの自動IAM

**質問**: 自動生成されたLambda実行ロールを本番でそのまま使わない理由は何ですか。
**回答例（約30秒）**: 自動設定は作成を速くしますが、実際のPowerUserRoleはPowerUserAccessを持ち、Lambda専用の最小権限ではありません。まずポリシー、信頼関係、AssumeRole経路を確認し、開発アカウントで検証します。本番では関数専用ロールをIaCで管理し、広すぎるロールのデプロイを拒否します。
**関連プロジェクト**: LambdaのIAM Role Manager検証
**キーワード**: IAM Role、Least Privilege、sts:AssumeRole

### 4. Human-in-the-Loop

**質問**: 生成AIの出力に人のレビューを残すべき操作は、どう分類しますか。
**回答例（約30秒）**: 影響範囲と不可逆性で分類します。Rubricのような判断基準や、本番データ変更、権限付与は自動生成できても確定は人が行う設計にします。低リスクな下書きは自動化し、高リスクな操作は検証結果と根拠を表示してから承認を求めます。
**関連プロジェクト**: Google Classroom × GeminiのRubric自動生成
**キーワード**: Human-in-the-Loop、Human Review、承認フロー

### 5. QAの重心移動

**質問**: テストで欠陥が見つからなくなったとき、QAは何を改善しますか。
**回答例（約30秒）**: 0件を品質完成とみなさず、本番インシデントや環境差分を観測します。重複する手動確認を減らす一方で、CIの回帰テスト、探索的テスト、リリース後の指標設計を増やします。QAが全案件のボトルネックにならないよう、品質を判断できる基準と証跡を各チームに組み込みます。
**関連プロジェクト**: Ai Workforce事業部のQA活動
**キーワード**: 観測、探索的テスト、残存リスク

## 4. 今日の技術テーマ

### Agentの自動化を「検証可能な委譲」にする

今日の5本に共通するテーマは、Agentに作業を委譲しても、コンテキスト、権限、出力、品質判断を人と機械の境界で制御することです。MCPは必要な情報を絞って渡し、Gurenは規約と型・監査で生成物を検証し、IAMの記事は自動払い出しが最小権限ではないことを示します。Google ClassroomのニュースとLayerXのQA論考は、生成やテストの結果を人が判断できる状態を残す点でつながります。

**メリット**

- Agentが読む範囲と実行できる操作を小さくできる。
- 型、Policy、CI、監視によって、レビュー前に機械的な不整合を検出できる。
- 人は低リスクの反復作業から解放され、仕様・価値・残存リスクの判断に集中できる。

**制約・リスク**

- 自動検証が通っても、仕様の誤りや価値の不足までは保証しない。
- 広いIAMロールや過剰なコンテキストは、漏えいや権限昇格の経路になり得る。
- AIと同じコンテキストで作ったテストが、通るケースだけを検査する確証バイアスを生む可能性がある。

**日本企業で導入する際の注意点**

まず対象データを公開前提のログや開発用アカウントに制限し、個人情報・秘密情報の扱いを決めます。次に、読み取り専用Tool、最小権限、関数専用Role、CIのPolicy検査を小さく導入します。高Risk操作は承認フローを残し、導入後は成功率だけでなく、インシデント、残存リスク、運用負荷を観測します。自動化を増やすこと自体ではなく、誰がどの証跡に基づいて判断するかをあらかじめ定義することが重要です。

## 5. 面接復習カード

### Q1. MCPで検索結果を全件渡さないのはなぜですか？

**回答ポイント**: まずOverviewで全体を把握し、日付・slug・カテゴリ・検索語で絞り込み、必要なsnippetや本文だけを渡す。コンテキスト量と機密情報の露出を抑えられる。

### Q2. PowerUserRoleはなぜ最小権限ではありませんか？

**回答ポイント**: `PowerUserAccess`は広範なアクションを`Resource: "*"`で許可し、関数ごとの権限分離もない。開発用の初期状態にとどめ、本番は専用Roleへ切り替える。

### Q3. QAの欠陥検出0件をどう解釈しますか？

**回答ポイント**: 欠陥がない証明ではない。テスト外の環境・設定・運用リスクを観測し、手動確認、CI回帰、探索的テスト、リリース後の価値検証へQAの重心を組み替える。

# C. 日本語学習｜JLPT + IT日本語

## C-1. JLPT語彙

### 権限（けんげん）｜名詞｜N2

**意味**: ある操作や情報にアクセスできる資格・範囲。
**コロケーション**: 権限を付与する、最小権限、参照権限
**記事文脈・メモ**: AgentやAWSの実行ロールが、どの操作を許されるかを説明する語です。
**例文**: AgentにはTaskに必要な権限だけを付与します。
**例文の意味**: エージェントにはタスクに必要な権限だけを与えます。
**ニュアンス**: 「権利」よりも、システム上の操作許可を指す場面で使います。

### 漏えい（ろうえい）｜名詞｜N1

**意味**: 秘密や情報が、意図せず外部へ流れ出ること。
**コロケーション**: 情報漏えい、Secret漏えい、漏えい対策
**記事文脈・メモ**: AIの出力やMCPが取得する文書に、機密情報を含めないための議論で使います。
**例文**: Secretの漏えいRiskを下げるため、出力内容を検査します。
**例文の意味**: 秘密情報が漏れるリスクを下げるため、出力内容を検査します。
**ニュアンス**: 「漏洩」とも書きますが、技術文書では「漏えい」も一般的です。

### 承認（しょうにん）｜名詞｜N2

**意味**: 内容を確認したうえで、正式に認めること。

## C-2. IT/AI専門用語

- **Context Gateway（コンテキストゲートウェイ）**: Agentへ渡す情報を選別し、アクセス経路を管理する中間層。MCPや検索を使い、必要なKnowledgeだけをAgentのコンテキストへ渡す設計を指します。
- **Automated Validation（自動検証（じどうけんしょう））**: 人手を介さず、テストや型チェックなどで成果物を確かめる仕組み。Gurenのcheck・audit・typecheckや、CIのガードレールで生成Codeを検証します。
- **Least Privilege（最小権限）**: 利用目的に必要な最小限の権限だけを与えるセキュリティ原則。AWS IAM RoleやAgentのTool Accessを、必要な操作範囲に限定する考え方です。
- **Human-in-the-Loop（ヒューマン・イン・ザ・ループ）**: 自動処理の途中に人の確認や判断を組み込む方式。高RiskなAgent操作や、Google ClassroomのRubric自動生成でも人のレビューを残す考え方です。
- **Development Convention（開発規約（かいはつきやく））**: ファイル配置や命名など、開発者が共通して守るルール。Gurenは規約を一意にして、Agentが生成先を迷いにくい構造を目指します。
- **IAM Role（IAMロール）**: AWSリソースやサービスが引き受けて使う権限のまとまり。IAM Role ManagerはテンプレートからRoleを払い出しますが、LambdaではPowerUserRoleになる検証が紹介されています。
- **Read-only Tool（読み取り専用Tool）**: データの参照はできるが、作成・変更・削除を行わないツール。mdlog-mcpは一覧・検索・本文取得の4つの読み取り専用Toolを公開します。
- **Policy as Code（ポリシー・アズ・コード）**: セキュリティや運用のルールをコードとして定義し、機械的に適用・検査する方法。AgentのTool AccessやCIのPolicy違反を自動検知する設計に関係します。

## C-3. JLPT文法

### ～にとどまらず｜N1

**意味**: ある範囲だけでなく、さらに広い範囲に及ぶことを表す。
**構造**: 名詞 / 普通形 + にとどまらず
**使い方**: 技術の用途や効果が、最初に想定した範囲を超えることを説明します。
**例文**: MCPはTool Callingにとどまらず、Knowledge Accessの統制にも利用できます。
**例文の意味**: MCPはツール呼び出しだけでなく、ナレッジへのアクセス制御にも使えます。
**メモ**: 「～だけでなく」より改まった表現です。

### ～かねない｜N1

**意味**: 好ましくない結果になる可能性がある。
**構造**: 動詞ます形去ります + かねない
**使い方**: 現在の方法を続けた場合に起こり得るリスクを警告します。
**例文**: 自動生成されたIAM Roleをそのまま使うと、過剰権限を許可しかねません。
**例文の意味**: 自動生成されたIAMロールをそのまま使うと、過剰な権限を許してしまう恐れがあります。
**メモ**: 悪い結果への懸念を、断定せずに示す表現です。

### ～なくしては｜N1

**意味**: それがなければ、後ろの事柄は成立しない。
**構造**: 名詞 + なくしては
**使い方**: 自動検証や人の承認を、高リスク運用の前提条件として述べます。
**例文**: 自動検証とHuman Approvalなくしては、高RiskなAgent運用は難しいです。
**例文の意味**: 自動検証と人の承認がなければ、高リスクなエージェント運用は困難です。
**メモ**: 「～なしでは」より強く、不可欠であることを表します。

### ～とは限らない｜N2

**意味**: 必ずしもそうだとは言えない。
**構造**: 普通形 + とは限らない
**使い方**: 自動生成された設定や、観測された結果を過信しないように述べます。
**例文**: 自動生成されたPolicyが最小権限になっているとは限りません。
**例文の意味**: 自動生成されたポリシーが最小権限であるとは必ずしも言えません。
**メモ**: 例外や不確実性を示す、実務で頻出する表現です。

### ～に基づいて｜N2

**意味**: 判断や行動の根拠として、情報や基準を用いる。
**構造**: 名詞 + に基づいて
**使い方**: Policyや観測データなど、明確な根拠に沿って制御するときに使います。
**例文**: 社内Security Policyに基づいてAgentのTool Accessを制御します。
**例文の意味**: 社内セキュリティポリシーを根拠に、エージェントのツールアクセスを制御します。
**メモ**: 「～を参考にして」より、根拠との結びつきが強い表現です。

### ～たうえで｜N2

**意味**: 前の行為を終え、その結果を踏まえて次の行為をする。
**構造**: 動詞た形 + 上で
**使い方**: 自動検証を済ませてから、人が本番変更を判断する順序を示します。
**例文**: CIで検証したうえで、本番変更を人間が承認します。
**例文の意味**: CIで検証を終えてから、本番変更を人間が承認します。
**メモ**: 手順や前提を明確にする書き言葉です。

### ～一方で｜N2

**意味**: 二つの対照的な側面を並べて示す。
**構造**: 普通形 + 一方で
**使い方**: Agent導入の生産性と、権限管理の負担を同時に説明します。
**例文**: Agentは開発を高速化できる一方で、権限管理を厳密にする必要があります。
**例文の意味**: エージェントは開発を速くできる反面、権限管理を厳密にする必要があります。
**メモ**: 利点と課題をバランスよく示すときに便利です。
