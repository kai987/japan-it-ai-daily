### ① AIレビューの「OK」はどこまで信じていいか、わざとバグを5個仕込んで測ってみた

**出典：Zenn**

**原文：** https://zenn.dev/nomurasan/articles/planted-bugs-llm-judge-calibration

著者は記事の公開前レビューへ意図的な誤りを混ぜ、LLMの判定がその誤りを指摘するか調べました。対象はコードではなく、一本の記事と一つのレビュー経路です。数値の改変、存在しない五十回の独立試行、適用範囲の過大化、矛盾、根拠表を消した結論の五種類に、意味を変えない言い換え二種類を加えています。置換箇所が一つであることもスクリプトで検査しました。

十一役のうち四役を実行しましたが、意図的な誤りを直接見るのは根拠確認役です。機密漏えいや見つけやすさを調べる役の合格を、そのまま内容誤りの見逃しとは数えられません。gpt-oss-120bは七変種×四役、Codexは二変種×四役を予定し、再試行を含む呼び出しは上限四十に対して三十八でした。

判定ラベルだけなら五つ中三つが却下されても、埋めた箇所を正しく特定したものは一つでCodexによる指摘でした。別の段落を理由に却下した結果を検出成功にはできません。架空の五十試行は、有効な六判定が合格しました。一方、Codexでは初回八件中六件が環境エラーとなり、二件を再試行で回復しても四件は判定なしです。これを合格や見逃しに混ぜず、両モデルの順位も付けません。

二つの対照は合格しましたが、一回の実験で誤検知率ゼロを保証できません。面接では総合点に加え、指摘箇所と意図した誤りの照合、実行不能の別集計、正常な対照を含む校正を説明できます。定期運用や実際のコードレビューへの効果は今回の実証範囲外です。

**注目ポイント：★★★★★**

合否の数と、狙った誤りの検出を分ける評価方法です。

### ② CodexとClaudeを同じリポジトリで働かせたら、色々壊れた——1人+2AIの事故対策の全部

**出典：Zenn**

**原文：** https://zenn.dev/hilopon/articles/two-ai-git-ops-accident-prevention

一人が二〜三体のAIを使った約一か月半の記録です。残ったindex.lockによる再試行、途中変更の持ち主が分からない再開、同じファイルへの接近などが起きました。能力が重なるだけでは、作業の所有者や外部へ反映する責任は決まりません。

著者は `.locks/名前.md` に開始時刻と作業範囲を記し、受信箱は一依頼一ファイルにしました。依頼には完了条件を含め、終了時は保管場所へ移します。二時間を古いロックの目安にしていますが、これは協力するエージェントの運用ルールです。原子的な排他制御や自動失効を実装した証拠ではありません。

pushやブラウザーでの公開は一つの担当に集約し、別担当が実行できても転送します。再開時には残った差分、受信箱、ログを確認し、学びは既存記録を消さず追記します。index.lockは実行中のGit処理がないと確認してから扱うべきで、繰り返し削除する方法にはしません。

著者自身、この原稿の作業中にロック手順を破ったと記しています。Gitはコミットした履歴を追えても、全未コミット操作を自動保存するわけではありません。したがって効果の数値や事故ゼロは主張できません。面接では担当、終了条件、再開手順を説明し、チームではbranchやCIなど強制できる境界も併用する判断へつなげられます。

**注目ポイント：★★★★★**

道具の共有より先に、変更の所有者と引き継ぎを設計できます。

### ③ 「トークン単価50％減でもAI請求額が跳ね上がる」なぜ？　Uberは4月で年間予算が枯渇

**出典：＠IT**

**原文：** https://atmarkit.itmedia.co.jp/ait/articles/2608/29/news009.html

＠ITはIDCの分析とWashington Post Intelligenceの報告を紹介し、token消費を成果の代理にする運用を問題にしています。Airbnbは処理量や品質を見る方向を示し、Uberの年間予算が四月に尽きた例も報道として挙げます。匿名fintechの混合単価が前年比五割下がった話は、全モデルの料金が一律半額になったという統計ではありません。

単価が下がっても、エージェントの反復や導入範囲が増えれば総額は増えます。異常を見つける開発側に予算を止める権限がなく、財務側は請求後に気付くという責任の空白が焦点です。消費量を競う評価は、有益な作業と不要な再試行を区別できません。

2026年四月の中東・トルコ・アフリカ調査では61％が前年のクラウドAI予算を超過し、その超過組の83％は幅が15％未満でした。83％の分母は全組織ではありません。記事は早期統治の効果として解釈しますが、介入実験や他条件を統制した因果推定は示していません。五月の千四百人以上のITリーダー調査も価格体系の予算化の難しさを扱う別調査です。

提案は最初の支出前に処理単位の責任者を一人置き、実効的な決定権を与え、四半期の財務計画で消費差異を検討することです。独立AI予算枠を持つCEO二割という数字も別レポートの集計で混ぜません。面接では成果一件の費用と品質、反復数、停止や見直しの担当をセットで説明できます。

**注目ポイント：★★★★★**

単価、量、成果、意思決定の担当を一緒に説明できます。

### ⑤ OpenAI、Cursorへのモデル提供を11月12日に終了　SpaceXによる買収が理由

**出典：ITmedia NEWS**

**原文：** https://www.itmedia.co.jp/news/article/2608/30/2000000945/

ITmediaはOpenAIが八月28日にCursorへのモデル提供契約の終了を発表し、十一月12日を停止日として提案したと報じています。SpaceXによる買収後の支配権変更条項を行使したという説明です。これはCursorのサービス内でOpenAIモデルを呼ぶ契約の話で、Cursor自体の終了ではありません。

OpenAIは利用規約を守る確信が持てないことを理由とし、過去の契約違反を挙げています。これらはOpenAI側の説明として扱い、本文だけで第三者が法的事実を確定したとは書きません。最長の通知期間を設ける一方、次期Astraなど今後のモデルは提供しない方針を示しました。

Cursor側CEOはOpenAIがトラフィックの約5％だと述べ、協議を続けるとしています。5％は発言に基づくサービス全体の指標で、各企業の重要業務への影響率ではありません。Anthropic側はClaude支援を継続すると表明しましたが、モデルを置換すれば同じ品質になる証拠ではありません。

面接では提供元を抽象化するだけでなく、依存するモデル機能、指示、ツール呼び出し、評価例を棚卸しする判断につなげます。停止日は発表時点の提案であり、実施済みとして扱いません。契約変更への技術的備えと、法的判断や当事者の非難を混同しないことが重要です。

**注目ポイント：★★★★★**

## C-1. JLPT語彙

### 1. 根拠（こんきょ）
**品詞：** 名詞｜**意味：** 判断や説明を支える理由や資料。｜**目安：N2**  
**コロケーション：** 根拠を示す / 根拠と突き合わせる / 根拠に乏しい / 判断の根拠  
**文脈：** 回答から元資料へたどれるように示します。  
**例：** `AIの判定を採用する前に、判断の根拠が実データと一致しているか確認します。`  
**ニュアンス：** 回答から元資料へたどれるように示します。

### 2. 矛盾する（むじゅんする）
**品詞：** 名詞・サ変動詞｜**意味：** 二つの説明が同時には成り立たない。｜**目安：N2**  
**コロケーション：** 説明が矛盾する / 前後で矛盾する / 仕様と矛盾する / 矛盾を指摘する  
**文脈：** 数値と結論が矛盾する箇所を照合します。  
**例：** `生成された説明が仕様書と矛盾していないか、別のCheckで検証します。`  
**ニュアンス：** 数値と結論が矛盾する箇所を照合します。

### 3. 条項（じょうこう）
**品詞：** 名詞｜**意味：** 契約や規則の個々の決まり。｜**目安：N1**  
**コロケーション：** 契約条項 / 解除条項 / 条項を確認する / 条項を適用する  
**文脈：** 支配権の変更に関する条項が使われました。  
**例：** `外部AI Providerを採用する前に、契約終了や支配権変更に関する条項も確認します。`

## C-2. IT/AI専門語彙

### 1. LLM-as-a-Judge｜LLMによる自動評価
**意味：** LLMを用いて文章や出力を評価する方法。  
**文脈：** 合否だけでなく、理由が対象の誤りを捉えたか確かめます。

### 2. Planted Bug Calibration｜既知バグを仕込んだ評価較正
**意味：** 既知の誤りを意図的に入れて検出の仕方を調べる校正。  
**文脈：** 当日の実験は文章が対象で、コードの不具合検出率ではありません。

### 3. Multi-Agent Coordination｜マルチエージェント協調
**意味：** 複数エージェントの担当と依頼、実行順を調整すること。  
**文脈：** 文書ロックと受信箱は協力の約束であり、強制的な排他制御とは異なります。

### 4. Token Economics｜トークノミクス／トークン経済
**意味：** tokenの単価と消費量を、得られる成果や総費用に結び付ける考え方。  
**文脈：** 安くなっても反復や導入範囲が増えれば総額は上がります。

### 5. Model Hardware Standard (MHS)｜モデル・ハードウェア標準
**意味：** AIとプログラム可能な物理機器をつなぐ共通仕様の研究プレビュー。  
**文脈：** 接続と自然言語の安全情報を提供し、追加の安全評価は今後の計画です。

### 6. Standardized Driver｜標準化ドライバ
**意味：** 異なる機器を共通の操作形式で扱うための接続部品。  
**文脈：** 計測値取得と設定値変更などをモデルへ伝えます。

### 7. Model Provider Abstraction｜モデルプロバイダー抽象化
**意味：** 提供元固有の呼び出しを共通の境界へまとめる設計。  
**文脈：** API差を抑えても、モデルの品質やツール動作は再評価が必要です。

### 8. Change-of-Control Clause｜支配権変更条項
**意味：** 買収などで支配権が変わった場合の扱いを定める契約条項。  
**文脈：** 当事者の説明と独立した法的認定を区別します。

## C-3. JLPT文法

### 1. ～にとどまらず
**Level：N1｜意味：** ある範囲だけでなく、さらに広い範囲にも及ぶこと。  
**形：** `名詞 + にとどまらず / 動詞辞書形 + にとどまらず`  
**使い方：** 前の範囲から後ろへ話題を広げます。  
**例：** `AIレビューでは合否ラベルの確認にとどまらず、指摘内容が実際の欠陥を特定しているかまで検証します。`  
**補足：** 前の範囲から後ろへ話題を広げます。

### 2. ～かねない
**Level：N1｜意味：** 望ましくない事態が起こる可能性があること。  
**形：** `動詞ます形去ます + かねない`  
**使い方：** 動詞のます形から「ます」を除いて付けます。通常は悪い結果に使います。  
**例：** `複数Agentが同じ作業範囲を同時に更新すると、変更を上書きしかねません。`  
**補足：** 動詞のます形から「ます」を除いて付けます。通常は悪い結果に使います。

### 3. ～に至るまで
**Level：N1｜意味：** 範囲が最後の細かな対象まで広がることを強調する。  
**形：** `名詞 + に至るまで`  
**使い方：** 「～から～に至るまで」の形で、接続から監視までの広い責任を示せます。  
**例：** `MHSは顕微鏡からロボットアームに至るまで、多様な機器を共通の方式で扱うことを目指しています。`  
**補足：** 「～から～に至るまで」の形で、接続から監視までの広い責任を示せます。

### 4. ～に伴って
**Level：N2｜意味：** ある変化と一緒に別の変化が起こる。  
**形：** `名詞 + に伴って / 動詞辞書形 + のに伴って`  
**使い方：** AI利用の拡大と管理上の課題の関係を説明します。  
**例：** `AI Agentの利用拡大に伴って、Token Costの責任分担も明確にする必要があります。`  
**補足：** AI利用の拡大と管理上の課題の関係を説明します。

### 5. ～に基づいて
**Level：N2｜意味：** 情報や規則などを根拠として行動・判断すること。  
**形：** `名詞 + に基づいて / 名詞 + に基づく + 名詞`  
**使い方：** 何を判断の土台にしたのかを明確にします。  
**例：** `実際のUsageとBusiness Outcomeに基づいて、AgentごとのBudgetを設定します。`  
**補足：** 何を判断の土台にしたのかを明確にします。

### 6. ～わけではない
**Level：N2｜意味：** ある説明から推測されることが、必ずしも成り立たないと示す。  
**形：** `普通形 + わけではない / 名詞・な形容詞 + な + わけではない`  
**使い方：** 一部のモデル提供終了は、製品全体の終了を意味するわけではありません。  
**例：** `AIが差し戻したからといって、仕込んだバグを正しく検出したわけではありません。`  
**補足：** 一部のモデル提供終了は、製品全体の終了を意味するわけではありません。

### 7. ～を踏まえて
**Level：N2｜意味：** ある事実や条件を考慮したうえで次の判断をする。  
**形：** `名詞 + を踏まえて / 名詞 + を踏まえた + 名詞`  
**使い方：** 実験の範囲を踏まえて、導入する役割を決めます。  
**例：** `Evaluation結果と契約条件を踏まえて、複数ProviderへのFallbackを設計します。`  
**補足：** 実験の範囲を踏まえて、導入する役割を決めます。
