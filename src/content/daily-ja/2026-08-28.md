### ① AIエージェント向けのWebと実行環境は、人間向けと何が違うのか──Cloudflareが示す設計の前提

**出典：DeveloperZine / CodeZine**

**原文：** https://codezine.jp/article/detail/29480

CodeZineのCloudflare説明会レポートは、人間の画面操作を前提としたWebと、機械的に情報や処理へアクセスするエージェントの違いを扱います。同社Radar観測ではHTMLへのHTTP要求の60.4%がボット、39.6%が人間です。これは同社の観測範囲・コンテンツ種別の比率で、全インターネット利用者の六割がAIという意味ではありません。

発表ではAIエージェント通信が2025年六月〜2026年五月末の約一年で約1,700%増加し、人間のサイト訪問も業種別に減ったと説明しています。ただし観測上の変化と、AIだけが原因という因果は区別します。人間の利用も残るため、実行基盤とアクセスされるコンテンツの両方を整える立場です。

**確認範囲：** CodeZineの後続ページは会員登録が必要で、四要件と製品の対応表全体は確認できませんでした。表を推測せず、公開された[Agents Weekの原発表](https://blog.cloudflare.com/agents-week-welcome/)と[Precursorの技術説明](https://blog.cloudflare.com/introducing-precursor/)から以下を補足します。

Precursorはログイン時など一点のChallengeを補い、HTMLへ注入するJavaScriptでポインター、キー操作の時機、フォーカス・表示状態を集めます。エッジ側で信号の整合性を評価し、セッション全体のbot scoreへ反映します。単発の人間らしい操作を通した後の行動も見る仕組みです。公式はキーの内容ではなく時機・リズムを扱い、信号を利用者の永続プロフィールに結び付けないと説明しています。

これはEnterprise Bot Managementの任意の補完機能で、公式説明は一般的な検知精度の保証ではありません。七月の原発表が存在するため、八月27日を初発表日とはしません。面接では一要求の判定とセッションの行動、許可されたエージェントと不正利用を分け、誤検知や利用者の負担も確認する視点へつなげられます。

**注目ポイント：★★★★★**

Webの機械利用を、流量の分母とセッション単位の検証から説明できます。

### ② Devinにどこまで任せられる？ 使いどころを一段ずつ広げる「任せ方の3タイプ」

**出典：DeveloperZine / CodeZine**

**原文：** https://codezine.jp/article/detail/29221

Devinの解説は、作業の種類より「どこまで任せるか」を三段階で整理します。人が一件ずつ起動して非同期に任せる、トリガーで自動起動する、多数の独立作業を並列化する、という順です。段階を上げても受入基準、禁止事項、CIを中心とした検証の型は維持します。

公開部分が詳しく扱う最初の段階では、影響が限定的で戻せること、機械的に合否を判断できること、効果を測りやすいことを重視します。一リポジトリ・一機能、三時間程度の小さな修正やテスト追加は例で、所要時間の保証ではありません。

テスト追加なら、新規テストと既存テストの成功に加え、対象ファイルの行カバレッジ80%以上などの具体的な基準を置きます。ただし80%は例示です。本体を書き換えてテストを通す、アサーションのない呼び出しで数字を稼ぐ、モックの戻り値だけを確かめる、という失敗を禁止事項で明確にします。必要な本体修正は別PRにします。

CIの緑は一次判定であり、テストが意味のある振る舞いを確かめたかまで自動的に保証しません。公開本文はチケット販売の内製チームの事例を紹介しますが、効果の定量比較はここにはありません。後続のタイプ2・3の詳細事例と他製品比較は会員限定のため未確認で、推測による実績や優劣は補いません。

面接では非同期、起動、並列数を別々の拡張軸として説明できます。まず受入条件と変更可能な範囲を固定し、出てきたPRのテスト内容を評価してから任せる範囲を広げます。

**注目ポイント：★★★★★**

自動化の範囲とテストの意味を、受入基準の具体例で説明できます。

### ③ AI時代に拡大するAPIアタックサーフェス　いかに保護するか

**出典：＠IT**

**原文：** https://atmarkit.itmedia.co.jp/ait/articles/2608/28/news009.html

Gartnerの六月執筆、八月掲載の記事は、AIでAPIの作成と利用が増え、防御対象の把握が追いつきにくくなる問題を扱います。LLMへの接続もMCPを通じた他サービスの操作もAPIに依存し、正規の資格情報による不正利用は単純な接続拒否だけでは見分けられません。

最初の対策は、自社APIと第三者依存の両方を発見することです。実行トラフィックを分析するだけでなく、コードリポジトリから開発中のAPIも調べます。そのうえで業務重要度、データの機密性、外部露出、エージェントからの利用を分類し、守る順番を決めます。

脅威モデルには人間のアクセスだけでなく、エージェントの利用経路も含めます。設定の検査を開発パイプラインへ入れ、運用中の変更も継続確認します。DDoS、WAF、bot対策、API脅威保護は異なる層を扱い、OAuthを用いた認可とGateway、IAMの対象拡張を組み合わせます。OAuthそのものが不正行動を検出する製品だという説明にはしません。

証拠はアナリストの設計提言で、特定製品を入れて攻撃を何%減らしたという比較実験ではありません。APIキーの窃取は情報流出だけでなく利用料金にも影響し得ますが、この記事の数字から自社損失を推定しません。面接ではAPI台帳、実行経路、認可、継続監視をつなぎ、公開した後も状態を追う説明ができます。

**注目ポイント：★★★★★**

APIを公開して終わりにせず、発見から認可と運用までの責任を説明できます。

### ④ Claude Code v2.1.247 の主要アップデート - /claude-api cost-optimize ツール追加と Sonnet 5 の auto-compact 1M 化

**出典：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/20260827-cc-updates-v2-1-247/

Claude Code v2.1.247には `/claude-api cost-optimize` が追加され、API利用のキャッシュ、token量、batch、effort、モデル選択を計測して見直す流れが紹介されています。`/claude-api` のAdmin API対応も広がりました。ただし著者が実際に選んだGenUリポジトリでは調査とレポート生成になり、期待した呼び出し費用の最適化とは異なったと明記しています。

この差を残すことが重要です。記事は操作不足の可能性も挙げますが、実測の削減額や品質維持を証明していません。レポートが表示されたことを費用改善の成功とは扱いません。SendFeedbackも下書きを作る機能で、`/feedback` で人が確認して送信する手順です。

Sonnet 5の1Mセッションではauto-compactが約934Kから約967Kへ変更されます。すべてのモデルや全設定に当てはめず、文脈保持の余裕と精度保証を分けます。数MBのhookエラーでPrompt is too longとなる問題や、初回404で止まるサブエージェントも修正され、後者はフォールバックとエラー種別・status・request ID・model名の返却を使います。

marketplace名の制御・不可視文字を拒否し、表示文字列をエスケープします。ネットワークパスや制御文字を含む危険なリンクをプレーンテキストへ変える修正もあります。dotfile管理のsettings.jsonシンボリックリンク削除やZedのkeymap全上書きなど、更新の確認対象は費用機能以外にもあります。

証拠は変更履歴と一つの試用結果です。面接では監査の提案、コードの変更、同条件での費用と品質の測定を別段階にし、実際に何が改善したかを確認できます。

**注目ポイント：★★★★★**

宣伝上の用途と試用で起きたことを区別し、費用改善を実測で評価できます。

### ⑤ OpenAI、公開プラグインでSkills Over MCPを早期サポート ——提出時にMCPサーバーからスキルを取り込み

**出典：gihyo.jp**

**原文：** https://gihyo.jp/article/2026/08/openai-plugin-support-skill-over-mcp

gihyo.jpの記事は、MCPのツールと使い方のスキルを同じサーバー側で管理し、版のずれを減らす **Skills Over MCP** の早期対応を説明します。対象はSaaS提供者が公開プラグインを提出する流れで、個人用スキルの保管サービスとは異なります。

提出画面の `Scan Tools` が、その時点の `SKILL.md` と関連ファイルを取り込み、ドラフトへコピーします。サーバー側を更新したら、再スキャン、確認、新版提出、審査・公開が必要です。利用のたびに最新版を読み込む方式ではなく、説明を同じ場所で管理しても実装との意味的な一致が自動保証されるわけではありません。

SEP-2640はDraftで、安定版MCPの全面採用ではありません。`io.modelcontextprotocol/skills` の宣言、`skills/list`、`skills/get`、`resources/read` と `skill://` URIで一覧とファイルを扱います。[現行の公式取り込み仕様](https://developers.openai.com/plugins/build/mcp-server#import-skills-from-the-mcp-server)は `capabilities.extensions` 配下の宣言、各ファイルのSHA-256、frontmatterと一覧の一致を要求しています。

公式は取得可能性、digest、パスの安全性やサイズを検証し、失敗すればtoolsは返ってもドラフトのskillsは更新しないと説明しています。五スキル・十ページなどの上限もある限定的な静的取り込みで、一般的な実行時配信とは違います。取得したコードの実行や権限拡張を、配信元の指示だけで許可しません。

面接では共同管理、取り込み時点、公開版を分け、ツール仕様を変更した際にスキルも再提出したかを確認する手順を話せます。内容整合性の評価には、実際の代表タスクでの検証が別途必要です。

**注目ポイント：★★★★★**

ツールと手順の共同管理を、公開時の版管理と検証へ結び付けられます。

## C-1. JLPT語彙

### 1. 権限（けんげん）
**品詞：** 名詞｜**意味：** 特定の操作を行うことが認められた範囲。｜**目安：N2**

**文脈：** 「付与する」は権限を与えること、「制限する」は範囲を狭めることです。

**ニュアンス：** 「付与する」は権限を与えること、「制限する」は範囲を狭めることです。

### 2. 認証（にんしょう）

## C-3. JLPT文法

### 1. ～ことなく
**Level：N1｜意味：** ある行為や状態を伴わずに、別のことを行う。  
**形：** `動詞辞書形 + ことなく`  
**使い方：** 必要な境界を崩さず処理することを述べます。  
**例：** `すべてのTool Definitionを常時読み込むことなく、必要なSkillを呼び出せます。`  
**補足：** 必要な境界を崩さず処理することを述べます。

### 2. ～にとどまらず
**Level：N1｜意味：** ある範囲だけでなく、さらに広い範囲にも及ぶこと。  
**形：** `名詞 / 普通形 + にとどまらず`  
**使い方：** 前の範囲から後ろへ話題を広げます。  
**例：** `API Securityは認証にとどまらず、認可やInput Validation、監査まで設計する必要があります。`  
**補足：** 前の範囲から後ろへ話題を広げます。

### 3. ～かねない
**Level：N1｜意味：** 望ましくない事態が起こる可能性があること。  
**形：** `動詞ます形去ます + かねない`  
**使い方：** 動詞のます形から「ます」を除いて付けます。通常は悪い結果に使います。  
**例：** `Agentに広すぎるWrite権限を与えると、意図しない変更を実行しかねません。`  
**補足：** 動詞のます形から「ます」を除いて付けます。通常は悪い結果に使います。

### 4. ～に応じて
**Level：N2｜意味：** 条件や変化に合わせて、対応を変えること。  
**形：** `名詞 + に応じて`  
**使い方：** 名詞に接続し、条件と対応の関係を示します。  
**例：** `Taskの内容に応じて利用するSkillを切り替えます。`  
**補足：** 名詞に接続し、条件と対応の関係を示します。

### 5. ～一方で
**Level：N2｜意味：** 同じ事柄の、対照的な二つの側面を述べること。  
**形：** `普通形 + 一方で`  
**使い方：** 前後は逆の評価や異なる側面でもつなげられます。  
**例：** `Agentic Webは作業を自動化できる一方で、APIのAttack Surfaceも広がります。`  
**補足：** 前後は逆の評価や異なる側面でもつなげられます。

### 6. ～た上で
**Level：N2｜意味：** 先の行為を済ませ、それを前提として次を行う。  
**形：** `動詞た形 + 上で`  
**使い方：** 検証してから利用するという手順を述べます。  
**例：** `Userを認証し、Roleを確認した上でAPI Actionを許可します。`  
**補足：** 検証してから利用するという手順を述べます。

### 7. ～に基づいて
**Level：N2｜意味：** 情報や規則などを根拠として行動・判断すること。  
**形：** `名詞 + に基づいて`  
**使い方：** 何を判断の土台にしたのかを明確にします。  
**例：** `RoleとSecurity Policyに基づいて利用可能なAPIを制御します。`  
**補足：** 何を判断の土台にしたのかを明確にします。
