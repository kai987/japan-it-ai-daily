# A. 詳細版

## 1. 今日読むべき5本

### ① DeepSeek Harness 0.1：「Everything is a Plugin」

**出典：** gihyo.jp
**原文 URL：** https://gihyo.jp/article/2026/08/deepseek-harness-developer-preview

DeepSeekは2026年8月13日、MITライセンスのDeepSeek Harness 0.1を開発者プレビューとして公開しました。AIモデルをツール、実行環境、セッション管理などと組み合わせるエージェントハーネスを、モデル・ツール・スキル・セッション・サンドボックス・ファイルシステム・エージェントループ・オーケストレーション・UIまでPluginとして実装する設計です。Web UIに加えて、単発処理向けのheadless方式にも対応します。

中核のCordisはPluginの追加・削除と依存関係を管理し、設定から機能を差し替えたり拡張したりできます。標準、コード、最小構成、作成の4モードがあり、OpenAIやAnthropic、社内ゲートウェイ、セルフホスト環境も接続できます。Codex CLIやClaude Codeへの委譲、追記型のセッションログ、Trajectoryビュー、セッションの再開・分岐・検索・再生も特徴です。

**注目ポイント：** 「Everything is a plugin」により、モデル交換ではなく実行基盤全体の構成を管理できる点。Web UIだけでなく`dsh --profile headless "run the tests"`のようなCLI運用を想定している点も実務的です。

### ② Prompt Injection：AgentがWebを読むこと自体がAttack Surfaceになる

**出典：** Zenn
**原文 URL：** https://zenn.dev/oubakiou/articles/ed98acbf4630b3

Claude Code、Codex、Gemini CLIなどにURLを読ませると、未知のWebコンテンツがコンテキストへ入ります。そこにChatML由来のマーカー、不可視Unicode、指示上書き文言があれば、Agentが攻撃者の指示を正規の指示と区別できず、ファイル書き込み・コミット・任意コマンド実行へ誘導される可能性があります。GHSA-wpqr-6v78-jr5gでは、Gemini CLI 0.39.1未満のheadless/`--yolo`利用時の問題が、CVSS 10.0 Criticalとして示されています。

記事のguarded skillは、取得専用の子プロセスを最小権限で動かし、WebFetch/WebSearch相当だけを許可します。Unicode不可視文字やLLMチャットマーカーを静的に除去し、サニタイズ済みJSONだけを親へ返す二段構えです。ただし自然文の悪意や隔離機構のゼロデイは防げず、実行時間もwebsearchでClaude子が約23〜26秒、Codex子が約12〜16秒と増えます。

**注目ポイント：** サニタイザは完全防御ではなく、Allowlist、Sandbox、ネットワーク制限、ユーザー確認を重ねるDefense in Depthとして理解する必要があります。

### ③ Claude Code 2.1.232：Sub-agent ForkとSessionをまたぐ協調

**出典：** DevelopersIO
**原文 URL：** https://dev.classmethod.jp/articles/20260814-cc-updates-v2-1-232/

Claude Code v2.1.231とv2.1.232は2026年8月13日に公開され、修正17件、改善12件、セキュリティ12件、新機能6件など計50件の変更がありました。v2.1.232では`subagent_type: "fork"`が既定で有効になり、サブエージェントが会話全体とプロンプトキャッシュを引き継ぎます。対話セッションでteammate以外のAgent起動は既定でバックグラウンド実行となり、`@`で別セッションを名前指定して`SendMessage`を送れるようになりました。

安全面では、PowerShellの`$PSDefaultParameterValues`を悪用する権限バイパス、WindowsのGit BashとCygwin形式シンボリックリンクを使うバイパス、ネストしたgitリポジトリの信頼継承が修正されました。MCP OAuthサインインや30秒ハング、Bedrock・Vertexのストリームアイドルタイムアウトも修正されています。なお、`sandbox.ripgrep`はプロジェクト設定から上書きできなくなりました。

**注目ポイント：** forkは前提の再入力とプロンプトキャッシュの取りこぼしを減らしますが、文脈共有が権限共有を意味しないよう、Session・Tool・Credentialを分けて設計する必要があります。

### ⑤ Amazon Bedrock AgentCore 入門 - AI エージェントを自作しながら「ハーネス」の仕組みを学んでみた

**出典：** DevelopersIO
**原文 URL：** https://dev.classmethod.jp/articles/agentcore-hands-on-study-agent-harness/

Amazon Bedrock AgentCoreは、AWS基盤上でAIエージェントを構築するマネージドサービスです。記事では、ハーネスをエージェントの本体、ランタイムを実行インフラ、モデルを頭脳、ToolをLambdaやAPI、GatewayをTool利用の入口、Memoryをセッション記憶領域として整理しています。小規模なテストは従量課金で、紹介されたハンズオンは1ドル未満でしたが、Memoryやストレージには固定料金が発生する場合があります。

約30分の構成では、東京リージョン`ap-northeast-1`でCloudWatchアラームを読むLambdaを約2分でデプロイし、Gatewayを作成してLambdaをMCP Targetとして登録します。その後、Bedrockモデルを使うHarnessを作成し、IAM認証、Memory無効、Gateway接続を設定します。ファイルシステム、VPC、ECRコンテナ、環境変数、ライフサイクル、許可Tool、最大イテレーションやタイムアウトなども設定対象です。

**注目ポイント：** Agentの賢さではなく、Harness・Runtime・Gateway・IAM・Toolの境界を実際に構築して理解できる点。Gatewayのサービスロールを事前作成し、名前のPrefixを信頼ポリシーに合わせる回避策も重要です。

## 2. カテゴリ別サマリー

### AI / Agent

DeepSeek HarnessはCordisでモデル、Tool、Session、Sandbox、UIをPluginとして組み立てます。Claude Codeのforkは会話とプロンプトキャッシュを共有し、Bedrock AgentCoreはHarness・Runtime・Gateway・ToolをAWS上で接続します。Agentをモデル単体ではなく、実行環境と状態管理を含むシステムとして捉えるのが共通点です。

### Frontend / Web

Gemini 3.7 Flashは少ないプロンプトから機能的なWebレイアウトやアプリを生成し、スクリーンショット・画像・デザインシステムを基にしたUI再現を改善しました。DeepSeek HarnessもWeb UIを提供します。Prompt Injectionの記事が示すように、WebはUIだけでなく、Agentが読む外部コンテンツの攻撃面でもあります。

### Cloud / Backend

Bedrock AgentCoreのGatewayはLambdaをMCP TargetとしてAgentに公開し、IAMロールで呼び出し境界を作ります。CloudWatchアラームを読むread-only Lambda、`ap-northeast-1`、CloudFormation、Gatewayサービスロールという構成は、AWS上のAgent Runtimeを小さく検証する例です。Claude CodeでもBedrock・Vertexのストリームアイドルタイムアウト修正が取り上げられています。

### 日本企業 Tech Blog / enterprise engineering signals

DevelopersIOの記事はClaude Codeの更新を、実務でのfork、セッション間連携、MCP、Windows権限、サンドボックス運用の観点から整理しています。Bedrock AgentCoreの記事も、東京リージョン、IAM、CloudFormation、リソースのクリーンアップまで含む導入手順を扱っており、企業導入では機能だけでなく権限・運用・費用を一体で設計する必要を示します。

## 3. 面接で使えるポイント

### テーマ1：Agent Harnessをどう設計するか

**面接質問：** Agent Harnessとモデルの責務をどう分けますか。
**30秒回答：** モデルは推論や生成を担いますが、HarnessはTool、Session、Sandbox、権限、ログ、オーケストレーションを管理する実行基盤です。モデルを交換しても安全な境界と監査性を保てるよう、Runtime側に実行ポリシーを置き、実務Taskで段階的に評価します。
**関連プロジェクト：** DeepSeek HarnessのPlugin構成、Bedrock AgentCoreのHarness作成
**3つのキーワード：** `実行基盤` / `セッション管理` / `サンドボックス`

### テーマ2：Prompt Injectionへの対策

**面接質問：** Webを読むAgentのPrompt Injectionリスクをどう抑えますか。
**30秒回答：** 外部コンテンツを信頼せず、取得処理を最小権限の子プロセスへ分離します。Tool Allowlist、Sandbox、ネットワーク制限、静的サニタイズ、監査ログ、人間の確認を重ね、モデルの指示追従だけに安全性を委ねません。
**関連プロジェクト：** guarded skillのWeb取得経路
**3つのキーワード：** `最小権限` / `隔離` / `Defense in Depth`

### テーマ3：Sub-agentとSessionの設計

**面接質問：** fork型Sub-agentを使うとき、何を分離して管理しますか。
**30秒回答：** forkは会話とプロンプトキャッシュを引き継げるため、前提の再入力を減らせます。一方で、共有するContextと、個別に制限するTool・Credential・Workspaceを分け、Sessionログと権限承認を追跡できるようにします。
**関連プロジェクト：** Claude Code v2.1.232のforkとセッション間連携
**3つのキーワード：** `Context共有` / `権限境界` / `監査ログ`

### テーマ4：モデルの実務評価

**面接質問：** 新しいLLMを本番に採用する基準は何ですか。
**30秒回答：** ベンチマークだけで決めず、実務に近い評価セットで品質、失敗率、レイテンシ、コスト、安全性を比較します。推論レベルやモデルをTaskのリスクに応じて切り替え、知識カットオフやタイムアウトも運用条件として確認します。
**関連プロジェクト：** Gemini 3.7 FlashのCoding・Web・Agent評価
**3つのキーワード：** `実務評価` / `レイテンシ` / `コスト`

### テーマ5：AWSでAgentを小さく始める

**面接質問：** Bedrock AgentCoreの導入検証をどのように始めますか。
**30秒回答：** read-onlyのLambdaをToolとして用意し、GatewayとIAMで呼び出し範囲を限定してからHarnessへ接続します。東京リージョンなどの前提、Memoryやストレージの費用、タイムアウトと許可Toolを確認し、テスト後はリソースをクリーンアップします。
**関連プロジェクト：** CloudWatchアラーム確認LambdaのAgentCoreハンズオン
**3つのキーワード：** `Gateway` / `IAM` / `read-only Tool`

## 4. 今日の技術テーマ

### Agentを「モデル」ではなく「制御された実行系」として設計する

5本に共通するテーマは、LLMの出力品質だけでなく、Tool・Context・Session・Runtime・権限を制御することです。Harnessはモデルと外部操作の間に実行境界を置き、Agentが何を読み、何を実行し、どの履歴を残すかを決めます。

**メリット：**

- モデルを交換してもTool Allowlistや監査ログを再利用できる。
- Sub-agentやGatewayを組み合わせて、Taskを分割しやすい。
- read-only ToolやSandboxにより、失敗時の影響範囲を限定できる。

**制約・リスク：**

- 隔離やサニタイズは完全防御ではなく、自然文の悪意やゼロデイを残す。
- 子プロセス、LLM取得、評価を挟むため、直接実行より遅くなる。
- Context共有、Memory、ログ、ストレージを増やすほど費用と管理負荷が増える。

**日本企業で導入する際の注意点：**

- IAM、認証、リージョン、データ保存先、ログの閲覧者を先に定義する。
- 重要操作にはHuman Approvalを置き、モデルの判断だけに委ねない。
- 本番に近い失敗ケースを継続的に追加し、権限・費用・レイテンシも含めて評価する。

## 5. 面接復習カード

### Q1. Prompt InjectionがAgentにとって危険な理由は？

**回答ポイント：** Web本文がContextに入り、攻撃者の指示が正規の指示と混ざるため。Tool Allowlist、Sandbox、サニタイズ、Human Approvalを重ねる。

### Q2. Harnessはモデルと何が違う？

**回答ポイント：** モデルは推論する部品、HarnessはTool、Session、Runtime、権限、ログ、オーケストレーションを制御する基盤。

### Q3. LLMのベンチマークをそのまま採用判断に使える？

**回答ポイント：** 使えない。実務Taskで品質、失敗率、知識の鮮度、レイテンシ、コスト、安全性を評価し、運用条件と照合する。

| 防止する | ぼうしする／動詞・サ変 | 起こらないように前もって抑える。 | 漏えいを防止する／誤操作を防止する／被害拡大を防止する | 権限や隔離で事故の発生・拡大を抑える。 | Toolの権限を絞って被害の拡大を防止します。 |
| 評価する | ひょうかする／動詞・サ変 | 性能や安全性を基準に照らして判断する。 | 性能を評価する／実務Taskで評価する／耐性を評価する | ベンチマークと実務TaskでHarnessも比べる。 | Model性能だけでなくHarnessの安全性も評価します。 |
| 分割する | ぶんかつする／動詞・サ変 | 一つを複数の部分に分ける。 | Taskを分割する／役割を分割する／処理を分割する | 大きな仕事をSub-agentに割り当てる。 | 大きなTaskを複数のSub-agent向けに分割します。 |
| 追跡する | ついせきする／動詞・サ変 | 移り変わりや履歴をたどって把握する。 | 履歴を追跡する／Tool Callを追跡する／変更を追跡する | Sessionログから操作や呼び出しをたどる。 | AgentがどのToolを呼んだかをSession単位で追跡します。 |
| 想定する | そうていする／動詞・サ変 | 起こり得る事態を前もって考える。 | 攻撃を想定する／本番を想定する／失敗を想定する | 外部Documentの悪意ある指示を設計時に考慮する。 | 外部Documentに悪意ある指示が含まれることを想定して設計します。 |
| 委ねる | ゆだねる／動詞・一段 | 判断や処理を他者に任せる。 | 判断を委ねる／権限判断を委ねる／すべてを委ねる | 重要な権限判断をLLMだけに任せない。 | 重要な権限判断をLLMだけに委ねません。 |
| 拒否する | きょひする／動詞・サ変 | 要求や実行を受け入れない。 | Requestを拒否する／実行を拒否する／接続を拒否する | RuntimeやPolicyが危険なTool Callを止める。 | Policyに違反するTool CallはRuntimeで拒否します。 |
| 必要 | ひつよう／な形容詞 | 目的達成に欠かせないこと。 | 必要な権限／必要な対策／必要なContext | Agentへ渡す権限やContextを必要な範囲に絞る。 | Sub-agentには必要なContextだけを渡します。 |
| 脆弱 | ぜいじゃく／な形容詞 | 攻撃や外部の影響を受けやすいこと。 | 脆弱な挙動／脆弱な設計／攻撃に脆弱 | Prompt InjectionやSandbox突破に弱い状態。 | Prompt Injectionに脆弱な挙動をEvaluationで検出します。 |
| 過度 | かど／な形容詞 | 程度が必要以上に大きいこと。 | 過度な権限／過度な自動化／過度に依存する | 自動化や権限を必要以上に広げるリスク。 | 過度な権限付与は事故時の影響範囲を広げます。 |
| あらかじめ | あらかじめ／副詞 | その時になる前に、前もって。 | あらかじめ定義する／あらかじめ除外する／あらかじめ想定する | AllowlistやPolicyを実行前に定める。 | 利用可能なToolをあらかじめAllowlistで定義します。 |
| 継続的に | けいぞくてきに／副詞 | 途切れず、長期にわたって。 | 継続的に監視する／継続的に評価する／継続的に改善する | 失敗Caseを評価に加え、運用を更新し続ける。 | 本番の失敗Caseを追加しながら継続的に評価します。 |
| 安易に | あんいに／副詞 | 深く考えず、簡単に。 | 安易に任せない／安易に信頼しない／安易に許可しない | 外部Web本文やモデルの判断を無条件に信頼しない。 | 外部Documentの指示を安易に信頼してはいけません。 |
| 一方で | いっぽうで／接続表現 | 二つの面を対比して別の側面を示す。 | 便利な一方で／自律的な一方で／一方でRiskもある | Agentの利便性と攻撃時の影響を対比する。 | Agentは多くの作業を自動化できる一方で、攻撃時の影響も大きくなります。 |

## C-2. IT/AI専門用語

- **Agent Harness（エージェント・ハーネス）：** モデル、Tool、実行環境、Sessionなどを組み合わせる基盤。DeepSeek HarnessやAgentCoreで、実行と管理の境界を作ります。
- **Prompt Injection（プロンプトインジェクション）：** 外部コンテンツの指示でモデルやTool呼び出しを不正に誘導する攻撃。Web取得時の不可視Unicodeなどが例です。
- **Sub-agent（サブエージェント）：** 親から仕事を委譲される補助Agent。Claude Codeのforkは会話とプロンプトキャッシュを引き継ぎます。
- **Context Isolation（コンテキスト分離）：** Agentごとに参照できる会話・データ・権限を分ける設計。外部入力の影響範囲を限定します。
- **Production-like Evaluation（実務評価）：** 本番に近いデータ、手順、制約で検証すること。Geminiのベンチマークを実務Taskで補います。
- **Guardrail（ガードレール）：** 危険な入力・操作・出力を検知または制限する機構。Allowlist、Sandbox、Human Approvalを含みます。
- **Bedrock AgentCore：** AWS上でHarness、Runtime、Tool連携を構築するマネージドサービス。LambdaをGateway経由で接続します。
- **Tool Allowlist（Tool許可リスト）：** Agentが呼べるToolを事前に列挙する制御。Prompt Injection時の到達範囲を狭めます。

## C-3. JLPT文法

### ～かねない（N1）

- **意味：** 悪い結果になる可能性がある。
- **構造：** 動詞ます形去ます + かねない
- **使い方：** 危険な結果を強く警告するときに使います。
- **例文：** 外部入力をそのまま実行すると、機密情報を送信しかねません。
- **例文の意味：** 外部入力をそのまま実行すると、機密情報を送信する可能性があります。
- **注意：** 好ましくない結果に用いるのが基本です。

### ～にとどまらず（N1）

- **意味：** ある範囲だけでなく、さらに広い範囲に及ぶ。
- **構造：** 名詞 / 普通形 + にとどまらず
- **使い方：** 対象や影響の広がりを説明するときに使います。
- **例文：** Agent EvaluationはModel性能にとどまらず、HarnessやToolの安全性まで対象にします。
- **例文の意味：** Agent評価はモデル性能だけでなく、HarnessやToolの安全性まで対象にします。
- **注意：** 「だけでなく」より書き言葉らしい表現です。

### ～なくしては（N1）

- **意味：** それがなければ、後のことは成立しない。
- **構造：** 名詞 + なくしては
- **使い方：** 必須条件を強調して、困難や不可能を述べます。
- **例文：** 継続的なEvaluationなくしては、Agentの安全性を維持できません。
- **例文の意味：** 継続的な評価がなければ、Agentの安全性は維持できません。
- **注意：** 改まった文章や主張に適しています。

### ～に応じて（N2）

- **意味：** 状況や程度に合わせて。
- **構造：** 名詞 + に応じて
- **使い方：** リスクや条件に合わせて対応を変えるときに使います。
- **例文：** TaskのRiskに応じてHuman Approvalの要否を決めます。
- **例文の意味：** タスクのリスクに応じて、人間の承認が必要かどうかを決めます。
- **注意：** 基準や程度との対応を明確にします。

### ～一方で（N2）

- **意味：** ある面ではそうだが、別の面では対照的なこと。
- **構造：** 普通形 + 一方で
- **使い方：** 利点と課題を並べて説明するときに使います。
- **例文：** Sub-agentは並列化に有効な一方で、Contextと権限の管理が複雑になります。
- **例文の意味：** Sub-agentは並列化に有効ですが、Contextと権限の管理は複雑になります。
- **注意：** 同じ主体の異なる側面を対比します。

### ～たうえで（N2）

- **意味：** あることをした後、その結果を踏まえて次の行動をする。
- **構造：** 動詞た形 + 上で
- **使い方：** 評価や確認を先に行い、次の判断につなげます。
- **例文：** Production-like Taskで評価したうえで、利用範囲を拡大します。
- **例文の意味：** 実務に近いタスクで評価してから、利用範囲を広げます。
- **注意：** 前段階を踏まえる意味が「た後で」より明確です。

### ～にかかわらず（N2）

- **意味：** 条件や違いに関係なく。
- **構造：** 名詞 + にかかわらず
- **使い方：** どのモデルや条件でも共通する扱いを示します。
- **例文：** 利用するModelにかかわらず、外部入力は信頼できないものとして扱います。
- **例文の意味：** 利用するModelに関係なく、外部入力は信頼できないものとして扱います。
- **注意：** 規則や方針の説明に向く硬い表現です。
