### 1. Claude Code v2.1.287 の主要アップデート - Claude Mods の追加とシェル書き込みの安全策強化

**原文：** https://dev.classmethod.jp/articles/20261002-cc-updates-v2-1-287/

**公開時刻：** 2026-10-02 20:47:23 JST

10月2日公開の記事は、10月1日リリースのClaude Code v2.1.287を整理し、Claude Modsの最小例を紹介しています。ModsはJavaScript／TypeScriptをClaude Codeの内部で動かす拡張です。別プロセスのシェルhook、プロンプトを使うskill、外部MCPサービスと同じ実行境界ではありません。更新項目を覚えるだけでなく、イベント処理の後で元の実行を続けるか、拡張にどの権限が渡るかを読み取る記事です。

first-modは、plugin.json、modulesを指定するhooks.json、register.jsで構成されます。register(on)から、session.startで/tallyを登録し、tool.callで共有変数callsを増やします。tool.callは再描画を要求した後にnext(e)で処理を続けます。一方、command.runの/tally処理は自分の結果を返し、nextを呼びません。ui.renderはspinnerの表示を加えてから次へ渡します。記録だけを目的とする処理でも、nextの扱いを誤ると元の処理を止め得ます。呼出回数が表示されても、成果物が正しくできたとは限らない点も区別します。

検証の前提はv2.1.287とmacOS／Linuxのbashまたはzshです。claude plugin validate ./first-modはコードを実行しない静的な検査です。筆者はその後、非対話モードで/tally、--plugin-dir、--max-turns 1を指定し、0回という応答を得ています。この実行で確認したのは起動時の登録とコマンド応答で、ツールの呼出計数や対話画面の全経路を実測した結果ではありません。Step 7のspinnerの説明は公式チュートリアルに基づいています。型の説明が食い違う場合には、使用中のバージョンが書き出すTypeScript定義も照合します。

Modsはサンドボックス化されておらず、利用者の権限でファイルやネットワークにアクセスできます。信頼できる配布元かを確認したうえで、プラグイン単位の無効化、--safe-mode、disableAllHooks、管理設定による停止を確かめます。旧環境変数CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=0は無視されます。シェルの修正では、危険な削除、コミット済みシンボリックリンクを介した外部への書込、保護された認証情報への書込の確認が強化されています。またOTELでプロンプトを記録する場合は、promptだけでなく新しいprompt_textも伏せる必要があります。1Mコンテキストの既定値は記事内で変更履歴と当時の文書の差が示されているため、一律の動作保証としては採用していません。

**読む価値：** 拡張の実行権限、静的な検査、実際のイベント処理を分けると、導入できたことや回数表示を作業成功と取り違えずに済みます。

### 2. 共変量に欠損があるとChronos-2の予測はどう変わるか

**原文：** https://dev.classmethod.jp/articles/how-chronos-2-forecast-changes-when-covariates-are-missing/

**公開時刻：** 2026-10-02 16:15:17 JST

同じamazon/chronos-2を使っても、chronos-forecasting、AutoGluon-TimeSeries、Dartsの予測が違う理由を、共変量の欠損処理から調べた記事です。OpenMLのBike Sharing Demand version 2を使い、台数を目的変数、温度を共変量にしています。過去は2011年1月1日から2012年12月30日までの17520時間ですが、データは17355行で165時間が欠けています。予測は2012年12月31日の24時間で、未来の時刻はそろい、温度だけがすべてNaNです。時刻の行がないことと、行内の値がないことを切り分けるのが出発点です。

過去の時刻が欠けた場合、chronos-forecastingは時間行を補いません。Dartsは行を加えてNaNを維持し、AutoGluonは行を加えたうえで温度を直近の値で補います。既存行のNaNも前二者は残し、AutoGluonは補完します。未来の時間行が欠けると基本的にエラーになりますが、行があり温度だけが欠ける条件では挙動が異なります。前二者はNaNを残し、AutoGluonは未来内の直近値を使い、すべて欠損なら過去の中央値へ戻ります。記事の過去の補完例は8.20、未来の全欠損の補完値は20.5です。

環境はPython 3.11、chronos-forecasting 2.3.2、AutoGluon-TimeSeries 1.6.3、Darts 0.41.0、torch 2.10.0、pandas 2.3.3などで、CPUを使用しています。Dartsは入力8192、出力24、float32、分位点0.1／0.5／0.9を指定し、50%分位の点予測を12月31日の実測と比べています。元の処理でのMAE／RMSE／MAPEは、順に36.48／57.88／71.33%、84.76／130.00／174.85%、46.58／66.28／93.09%でした。この数値は単一の予測日と前処理条件の結果で、各ライブラリの一般的な優劣を示すランキングではありません。

次に時間単位のreindexで165行を追加し、台数の欠損は残して、温度をffill().bfill()で補っています。未来の温度には過去の中央値20.5を与えます。そろえた入力では三者の評価値が小数二桁で84.76／130.00／174.85%に一致しました。ただし、一致したことと精度が改善したことは別で、chronos-forecastingとDartsの本比較の誤差は大きくなっています。本稿の設計上の整理としては、モデルの違いを疑う前に、時刻・NaN・補完後の配列を保存して比べます。記事は一つのデータセットと一日分の評価であり、他の期間やバージョンまで同じ結果になるとは限りません。

**読む価値：** 欠けた時刻、NaN、誤差の比較から、同じモデルを使う場合にも実際の入力を先に照合する理由が分かります。

### 3. [アップデート] Amazon GuardDuty の有効化を AWS Organizations の宣言型ポリシーで一元管理できるようになりました

**原文：** https://dev.classmethod.jp/articles/guardduty-org-enablement-policies/

**公開時刻：** 2026-10-02 17:00:10 JST

GuardDutyの有効化をOrganizationsの宣言型ポリシーGUARDDUTY_POLICYで管理できるようになりました。管理アカウントまたは委任管理者が作成し、root・OU・アカウントに付けます。対象に入った新規アカウントや、OUへ移動したアカウントも設定を引き継ぎます。階層の上位と下位はマージされ、同じ保護プランはアカウントに近い設定が優先されます。この階層間のマージと、リージョン設定の置換を混同しないことが重要です。

defaultはGuardDutyが使える全リージョンに効きます。地域名のブロックはその地域のdefaultを丸ごと置き換えるため、追加したい機能だけを書く方式ではありません。defaultを省略すると、明示した地域だけが管理対象になります。他の機能を有効にするブロックではfoundationalも必要です。記事の設定はdefaultにFoundationalとS3 Protection、東京のブロックには両方を再指定してEKS Protectionを加えています。記事が示す対応範囲は商用リージョンとGovCloudです。

筆者は、既にS3やRDSの自動有効化がある検証用組織で、メンバー一つだけにアタッチしています。東京のコンソールから委任管理者が作成し、管理アカウントが委任ポリシーを更新します。最初は権限不足で作成できず、既存のStatementを残して5件追記すると作成できました。約1分で対象の表示がPolicy managedに変わり、S3は管理対象、既存RDSは有効なままで対象外でした。大阪ではdefaultのS3が管理され、東京だけのEKSには同じ表示が付きませんでした。これは一つのアカウントの設定確認で、全組織の移行や検知率を測った実験ではありません。

特に注意するのは、ポリシータイプを初めて有効にした時点で、従来の組織の自動有効化がすべて止まることです。まだアタッチしていなくても、ポリシーに書かない保護プランにも影響します。rootやOUの適用先と現在使う全プランを確認し、IaCの管理対象も決めます。また、デタッチは現在の有効状態を残し、タイプを無効にすると旧自動有効化が再開します。どちらも既に動く検出を自動で停止しません。disabledを明示する操作とは別です。defaultではリソースのない地域にもグローバルイベント処理の料金が生じ得るので、対象と費用、戻し方を確認したうえで移します。

**読む価値：** 一部のアカウントへの適用でも組織の自動有効化が変わります。移行と解除の具体的な動作から、保護範囲と費用を考えられます。

## C-2. IT/AI専門用語

1. **Claude Mods（クロード・モッズ）**：Claude Codeの内部で動くJavaScript／TypeScriptの拡張です。 外部hookとは実行境界が異なり、利用者の権限で動きます。

2. **next(e)（イベントを次へ渡す関数）**：イベントの後続処理へ渡すための呼出です。 tool.callは計数後に続け、/tallyは独自の結果を返します。

3. **covariate（共変量）**：目的変数以外で予測に使う変数です。 Chronos-2の例は温度を使い、欠損処理も記録します。

4. **reindex（時間索引の付け直し）**：指定した索引に行をそろえ、欠けた行を追加する処理です。 本例では165時間を追加します。行の追加と値の補完は別です。

5. **ffill / bfill（前方／後方からの補完）**：前または後の有効値で欠損を補う処理です。 温度をffill().bfill()でそろえ、目的変数の欠損は残します。

6. **GUARDDUTY_POLICY（ガードデューティーのポリシータイプ）**：OrganizationsでGuardDutyの有効化を管理するポリシータイプです。 最初の有効化で旧自動有効化が止まるため、アタッチ先以外も確認します。

7. **regional override（リージョン別の上書き）**：特定地域でdefault全体を置き換える設定です。 追加機能だけのマージではなく、基本機能も指定し直します。

8. **two-layer testing（二層テスト）**：劣化を防ぐ確認と、改善の試験を分ける構成です。 LayerXはスコアの差分と利用者の声を使い、公開報告に閾値はありません。

9. **App Switcher snapshot（アプリ切替のスナップショット）**：アプリの切替画面で表示される、そのアプリの画像です。 Money Forwardはバックグラウンド移行時に機密情報を全面で隠します。

10. **overlay（オーバーレイ）**：元の画面の上に重ねて表示する層です。 ここでは画像の情報を隠すための層で、認証や保存の保護とは別です。
