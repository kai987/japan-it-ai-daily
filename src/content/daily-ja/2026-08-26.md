## 1. 今日読むべき5本

### ① MCP最新Roadmap：Agent Identity、非同期Task、Progressive Tool Discovery

**出典：＠IT**

**原文：** https://atmarkit.itmedia.co.jp/ait/articles/2608/25/news095.html

MCPの8月22日のロードマップは、自律的な処理を企業で運用するための五領域を示しています。長い処理では一回の要求と応答だけで進捗や途中の指示を扱いにくく、セッションをサーバーに保持する構成では負荷分散も複雑になります。

先に完了した変更と今後の計画は別です。公式によると7月28日の仕様で、プロトコルのセッションと初期化ハンドシェイクが廃止され、`server/discover` による対応機能の確認と一覧結果のキャッシュが導入されました。TasksはSEP-2663の公式拡張です。新計画はTasksの本体仕様への移行やWebhook・チャネルを整え、進捗通知などとの組み合わせを検討します。

通信ではローカルにもStreamable HTTP over stdioを広げ、認可ではDPoPやWorkload Identity Federation、権限委譲を扱います。多数のツールを最初から提示する問題には段階的な機能発見を、`tools/call` の複数の出力表現には明確な共通契約を目指します。五つ目はSDKの仕様適合性と文書・APIの使いやすさです。

ただしこれは次期リリース以降への優先順位で、全クライアントへの導入完了を示す発表ではありません。関連SEPは優先審査されますが、領域外も自動却下ではありません。面接では対応仕様、SDK、拡張を確認し、将来の計画を現在の設計条件に混ぜない説明ができます。[公式ロードマップの発表](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)も確認しています。

**注目ポイント：★★★★★**

仕様の実装状況と計画を区別し、通信・認可・ツール発見の設計を説明できます。

### ② Next.js 16.3とCritical RCE Patch

**出典：Publickey / GitHub Advisory**

**原文：** https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36

Next.jsの公式アドバイザリ **GHSA-p293-qw3h-jr36 / CVE-2026-75604** は、Windowsファイルシステムを使うサーバー上での未認証のリモートコード実行を扱います。影響説明はPages Router、およびCache Componentを使わないApp Routerのアプリケーションを対象としています。開発者のPCのOSだけで判定せず、配備先を確認する必要があります。

対象範囲は `>=13.4 <15.5.24` と `>=16.0 <16.3.3`、修正版は15.5.24と16.3.3です。分類はCWE-22で、パスが許可した範囲の外へ解決される問題です。ただし公表文は攻撃の具体的な処理経路を説明していないため、未確認の内部機構を補いません。

深刻度はCritical、CVSSは9.0です。ネットワーク経由、権限・利用者操作不要という条件に加え、攻撃の複雑さはHighとされています。公式は影響するWindows配備に既知の回避策がないとし、更新を求めています。この修正を他のすべての脆弱性への保証とは扱いません。

面接では、実行版・OS・ルーター構成を資産台帳と照合し、更新後の配備物と主要画面の回帰を確認する手順を説明できます。後半は適用時の判断であり、この記事が実施した検証結果ではありません。

**注目ポイント：★★★★★**

フロントエンドの依存更新を、実際のサーバー構成と配備確認へ結び付けられます。

### ③ Claude Code Runtime Governance

**出典：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/20260825-cc-updates-v2-1-245/

DevelopersIOはClaude Code v2.1.240〜v2.1.245の変更を整理しています。対象は公開された五バージョンで、v2.1.244はnpm未公開、v2.1.242はCHANGELOG記載なしです。63件中60件がv2.1.243に集中しており、単に番号の数で変更量を数えません。

`modelPicker` は `options` に必須の `model`、任意の `label`・`description` を並べ、`replaceBuiltInOptions` で標準一覧の追加か置換かを決めます。著者は一時設定で二行の順序と置換を確認しました。VertexやBedrockのIDも使える設定ですが、選択画面の整理自体を強制的な利用禁止とは読みません。

APIキー・クラウドプロバイダー利用者向けの `promptCacheTtl` と `subagentPromptCacheTtl` は、主会話を一時間、サブエージェントを五分と分けられます。`/usage` のLoopsには回数、総トークン、一回当たり、最終実行が出ます。長いTTLの効果は再利用の間隔次第で、この記事は費用削減率を測っていません。

実行基盤ではAPI無応答に約三分でタイムアウトして一度再試行し、非対話・SDKのリモートMCPは再接続または失敗報告へ修正されました。終了コード0でもプロキシ403などのネットワーク拒否詳細を失わない修正もあります。受信ソケットは三十秒以内に完全な一行が来なければ切断する破壊的変更で、送信内容を作ってから接続する必要があります。

公式変更履歴に基づく配布サイズ約340→75MB、セッション当たり約40〜70MB削減と、著者のmodelPicker操作確認は証拠の種類が異なります。v2.1.245はglibc 2.44起動クラッシュの修正です。面接では設定の見やすさ、課金計測、失敗の見える化を別々に検証できます。

**注目ポイント：★★★★★**

設定変更と計測結果を分け、運用中の失敗を観測する着眼点を持てます。

### ④ MCP Tool DefinitionのContext Cost

**出典：Zenn**

**原文：** https://zenn.dev/kazu_aiengineer/articles/mcp-server-tool-definition-token-cost

Zennの実測は、MCPのツール定義だけでどれだけ入力を使うかを調べています。七サーバーの `tools/list` をOpenAI形式のfunction JSONへ直し、`o200k_base` で数えた結果は131ツール・23,964トークンです。二十万の窓で割った約12%は、この構成と計数法による近似です。

Node 24.14.1、Python 3.13.12で一覧だけを取得し、クラウド操作は実行していません。Azure MCP 3.0.0-beta.37が14,709で全体の61%を占めます。デモ用server-everythingも含むため、除外時は六サーバー・118ツール・22,806になります。説明とschemaに加えJSONの外枠があり、二つの内訳を足すだけでは総量になりません。

同じAzureでも `single` は一ツール298、既定 `namespace` は68ツール14,709、`consolidated` は132ツール24,338、`all` は449ツール122,221でした。allはsingleの約410倍です。consolidatedは当時の文書の128ツール制限を四つ超え、推奨文言だけでは判断できない結果です。`--namespace storage` や `--tool` で用途を絞る方針が示されます。

ツール数とサイズも比例しません。sequential-thinkingは一つで858、memoryは九つで953で、説明の長さとschemaの複雑さが影響します。ただしClaudeは別のトークナイザーで、実クライアントの接頭辞や整形、絞り込み・遅延読み込みも違います。この数値を実際の請求額や毎回のClaude入力と同一視しません。面接では版と計数法を固定し、選択の正確さも保ちながら提示範囲を調整できます。

**注目ポイント：★★★★★**

コンテキストの費用を、ツール数ではなく定義・版・クライアントの挙動で説明できます。

### ⑤ AI Vulnerability DiscoveryとTriage

**出典：＠IT**

**原文：** https://atmarkit.itmedia.co.jp/ait/articles/2608/25/news036.html

＠ITはEpoch AIのCVE可視化データを取り上げ、Mythos Preview発表後の公開件数の増加を報じています。主要21組織でHigh・Criticalの公開が六月約1,550、七月約2,500となり、七月は発表前の月間記録の約五倍、六月比約60%増でした。全世界の脆弱性の存在数を数えた値ではありません。

集計は発見日ではなく公開日です。誰がCNAとして番号を付け、どの修正に割り当てるかにも左右されます。Linuxが2024年二月にCNAとなって、過去版へ移植した修正にも多く割り当てた例は、制度運用が時系列を変える理由です。全CNAを扱うデータと主要組織の比較範囲も区別します。

MythosやProject Glasswingの時期と増加が重なることは、AIがすべての増加を引き起こした証拠ではありません。公式が述べる発見能力と、公開統計の相関は別です。件数が増えるほど、真偽の確認、影響判定、通知、修正、配布の処理能力が重要になります。

記事はCVSSだけでなく、使用製品、外部到達性、認証条件、重要業務、悪用の有無を資産台帳やSBOMと合わせるよう提案しています。代替策も脆弱性ごとに成立を確かめる必要があり、今日のNext.js公告に既知の回避策がない条件を上書きしません。面接では件数の多さに反応するだけでなく、自社の影響を絞って優先する説明ができます。

**注目ポイント：★★★★★**

統計の増加と自社の危険度を分け、資産情報から優先順位を決められます。

3. 件数の増加はAIの因果効果を証明しません。

### 1. 推し進める（おしすすめる）
**品詞：** 動詞・一段｜**学習目安：** N1  
**意味：** 計画や改革、仕事などを、積極的に前へ進める。  
**コロケーション：** 改革を推し進める / 計画を推し進める / 統一を推し進める  
**使い方：** 当日Top 1の原文表記「推し進め」。計画、改革、方針などを目的語にし、進める側の積極性を表す。  
**オリジナル例文：** 現場の意見を確かめながら、画面の共通化を推し進めます。  
**ニュアンス：** 「進める」より、力を入れて進展を促す意味が強い。  
**原文の出典：** [Top 1](https://atmarkit.itmedia.co.jp/ait/articles/2608/25/news095.html)

### 2. 切り上げる（きりあげる）
**品詞：** 動詞・一段｜**学習目安：** N2  
**意味：** 続けていることを、ある時点で終える。また、数値を上の位へ繰り上げる。  
**コロケーション：** 作業を切り上げる / 調査を切り上げる / 端数を切り上げる  
**使い方：** 当日Top 3の原文表記「切り上げ」。作業については終える時点に重点があり、すべての目標達成を意味するとは限らない。  
**オリジナル例文：** 一定時間で調査を切り上げ、分かった点と未確認点を共有します。  
**ニュアンス：** 「完了する」は必要なことを終える意味だが、「切り上げる」は区切りを付ける意味が強い。  
**原文の出典：** [Top 3](https://dev.classmethod.jp/articles/20260825-cc-updates-v2-1-245/)

### 3. 依存（いぞん）
**品詞：** 名詞｜**意味：** 他のものがあることを前提に成り立つ関係。｜**目安：N1**  
**コロケーション：** 依存関係 / 特定Versionへの依存 / 外部Serviceへの依存  
**文脈：** 利用中の依存ライブラリと稼働版を照合します。
