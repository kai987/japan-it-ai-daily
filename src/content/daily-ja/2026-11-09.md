### 1. [アップデート] Web Answer on Amazon Bedrock AgentCore がリリースされました！

**原文：** https://dev.classmethod.jp/articles/bedrock-agentcore-web-answer-try-harness/

**公開時刻：** 2026-11-08 16:53:36 JST

Bedrock AgentCoreのWeb Answerは、自然文の質問から検索を計画し、複数の検索とページの読み込みを経て、出典付きの文章を一度の呼び出しで返します。Gatewayに接続すると、HarnessなどからMCPツールとして使えます。Web Searchでは見出し、URL、抜粋などの候補を受け取り、どれを読んで答えにするかをエージェントが決めます。Web Answerの接続機能では、対応するバージョンでドメインや公開日を絞れます。

著者はClaude Haiku 5.5を使うHarnessを組み、会社情報やイベント、記事の新しさを確かめました。最新記事の問いでは、Web Answerが一回、Web Searchが五回呼ばれ、Harnessの入力トークンはそれぞれ2,185と39,195でした。どちらも実際の11月3日の記事には届いていません。日付とドメインで絞った別の問いでも、著者ページで数えた対象12本のうち、答えに含まれた本人の記事は4本でした。

出典付きのツール出力をもとに書き直すとき、出典が最終回答に残るとは限りません。書評を著者本人の記事に数えた誤りも、ツール出力ではなくHarnessがまとめる段階で入りました。出典を残す指示を追加すると、会社情報の再試行ではリンクが表示されました。ただし比較は五問を各条件で一回ずつ試したもので、精度や費用を一般化できる測定ではありません。

**読む価値：** 検索結果の欠落と、回答をまとめる段階の誤りを、同じ実例から別々に見られます。

### 2. 並列 Claude Code セッションは何回ぶつかったか：2週間のログを hook に再生して数えた

**原文：** https://zenn.dev/dooly6276/articles/9863fac3b3e3c2

**公開時刻：** 2026-11-09 09:59:44 JST

Gitのworktreeを分けても、同じマシンにあるポートやプロセスは共有されます。著者のclaude-bulkheadはClaude CodeのPreToolUseフックで、シェルの実行前に構文を読みます。プロセスの持ち主、ポートの空き、メモリ残量、作業中のGitツリーを調べ、競合が見つかったときは理由と代わりの操作を返します。例えば無差別にNodeを終了する操作を止め、対象セッションのPIDを探すよう促します。

著者のMacの二週間分のログは7.0GBで、シェル命令は約10万件ありました。読み取り専用のbulkhead scanで過去の命令をフックに通し直すと、39秒で507件が阻止候補になりました。最大同時セッション数は13です。候補のうち25件は、別のセッションが編集中のツリーで全変更をステージし、そのコミットに相手の変更が混ざる場面でした。

ただし、同じ分に同じツリーで作業していたかはログから組み立て直せても、実行当時のポートとメモリの状態は残りません。そのため、この二種類の判定は再生から外しました。507件は作者のログでの再判定数で、実際に防げた事故数ではありません。フックは命令を調べるためのもので、他のプロセスから隔離するサンドボックスとは役割が異なります。

**読む価値：** ブランチを分けるだけでは見えない共有資源を列挙し、履歴から検証できる範囲を決められます。

### 3. AWS Network Firewall の Reject と Alert のドメインリストを Allow と組み合わせ、ルールの評価順序ごとに確かめてみた

**原文：** https://dev.classmethod.jp/articles/network-firewall-domain-list-reject-alert-rule-order/

**公開時刻：** 2026-11-08 14:33:38 JST

東京リージョンの一台のEC2から、HTTPとHTTPSの八つのURLをcurlでたたきました。ドメインはHTTPのHostとTLSのSNIで見分け、Allow、Reject、Alertの三つのルール群を使います。アクション順序ではAllowが不一致時のdropを加えます。厳格な順序ではその暗黙の拒否がないため、記事は確立後の通信を落とすDrop establishedと、同じ段階を記録するAlert establishedを設定しました。

今回のcurlの結果は、順序を変えても同じです。許可したドメインは200を返し、RejectのドメインはTCPリセットになり、監視対象とリスト外は15秒でタイムアウトしました。ところが接続をflow_idで照合すると、アクション順序ではAllowのdropとRejectまたはAlertが同じ接続に重なっていました。厳格な順序では、このdropのログは重なりませんでした。

最後のアクセスから約75秒後の取得で、最初のアクション順序は7件、厳格な順序は34件でした。後者では確立した接続の後続パケットも記録されています。ただし、取得の時点は文書が示すCloudWatch Logsへの平均配信時間より早く、欠けたHTTPの記録が後から届く可能性があります。少数の試行で見た差なので、運用では取得時間をそろえ、クライアントの結果とログを一緒に確かめます。

**読む価値：** 同じ接続結果でも、ルール評価とログの見え方は変わります。観測時刻を含めて比較できます。

### 4. CloudWatch が PromQL 対応したので、Amazon Managed Grafana から接続してみた

**原文：** https://dev.classmethod.jp/articles/cloudwatch-promql-endpoint-amazon-managed-grafana/

**公開時刻：** 2026-11-08 14:42:05 JST

EKSのアプリがリクエストごとに加算するカウンターを、CloudWatchエージェント経由のOTLPで送りました。著者はEKS 1.37とAmazon Managed Grafana 13.2で、CloudWatchデータソースからPromQLを実行し、ダッシュボードに描画しています。Metrics InsightsとMetrics Searchも選択できますが、OTLPで取り込んだメトリクスはPromQLで読みます。ログのLogs Insights、トレースのApplication Signalsは別経路です。

CloudWatch用データソースをメトリクスの監視エンドポイントに固定すると、記事の環境ではログのDescribeLogGroupsが404になりました。既定に戻すと、サービスごとの宛先に分かれます。PromQLが選べないManaged Grafana 12.4の環境では、AMPデータソースからCloudWatchの監視エンドポイントに接続する方法があります。署名はSigV4で、プラグイン名がAMPでも、接続先にAMPの保存先を用意することは求められません。

接続が通ることに加えて、必要な期間を一回の問い合わせで見られるかも確かめます。記事が比較した仕様では、CloudWatchの範囲は最大七日、AMPは最大95日です。保持期間とクエリ範囲は別々の制約です。七日ごとの比較はパネルを時間でずらす手がありますが、今回示したのは接続と表示の手順で、クエリ速度や価格の実測比較ではありません。

**読む価値：** 同じPromQLを使う場合も、保存先、プラグインの互換性、クエリ範囲で運用が変わります。

### 5. 「文字数 < 6 はスキップ」という英語前提の閾値が、和文の重複削除を壊していた話

**原文：** https://zenn.dev/recdnd/articles/kiln-dedupe-cjk-threshold-bug

**公開時刻：** 2026-11-09 09:00:12 JST

テキスト整形ツールkilnで、同じ中国語の短い行が何度入力されても残ることを、著者が六行の入力例で示しました。一方、長めの英語の同内容を使った例では重複が消えました。見出し番号や箇条書き記号などを残すため、文字列の長さが六未満の行を無条件に通す処理がありました。この処理が、三文字で内容が伝わる中国語の行にも効いていました。

重複判定に届いた行では、階層を表すlevelと正規化した文字列の組がキーになり、既出のキーをSetで確認します。短い行はその前に出力へ追加されます。長さによって入口を分けているので、Setのキーだけを調べても原因は見つかりません。また、全言語で下限を下げると、英語文書で残したい短い記号列にも影響します。

著者は処理を変更せず、デモのCJK行を六文字以上にそろえて回避し、既知の問題を記録しました。この入力制約でデモは通りますが、短い行の実装は同じです。言語や混在行に応じた扱いは提案の段階です。回帰テストを作るなら、消すべき短文と保存したい箇条書きを両方含め、文字数だけでは区別しにくい例を確認します。

**読む価値：** 実装の入口、例外の意図、回避策の範囲を小さな失敗例から追えます。

### 1. 空く（あく）｜N3

- 品詞：動詞・五段・自動詞
- 意味：使われていた場所や時間などが、使える状態になる。
- 連語：ポートが空く / 席が空く / 時間が空く
- 記事文脈：並列開発の記事では、使われていないポートをフックが案内します。
- 例文：テスト用のポートが空いてから、開発サーバーを起動します。
- 例文の意味：テスト用のポートが使える状態になったら、開発サーバーを立ち上げます。
- ニュアンス：「ポートが空く」は利用可能になること。「ポートを空ける」では人が利用状態を変えることを表します。

### 2. 残る（のこる）｜N5/N4

- 品詞：動詞・五段・自動詞
- 意味：処理や変化があった後も、その場にある。
- 連語：ログに残る / 出典が残る / 記録が残る
- 記事文脈：Web Answerの記事では、出典が最終回答にそのまま残るとは限りません。
- 例文：ツールの出力をまとめ直した後も、元の記事へのリンクが残るか確かめます。
- 例文の意味：ツールの文章を書き直した後も、元のページに行けるか確認します。
- ニュアンス：自然に残った結果を表す自動詞です。意識して保存する動作なら「出典を残す」を使います。参考レベルはN4です。

## C-2. IT/AI専門用語

1. **MCP（モデルと外部ツールを接続するプロトコル）**：ツールの発見と呼び出しの共通仕様。 AgentCore GatewayはWeb Answerを呼び出せるツールとして公開します。

2. **PreToolUse（ツール実行前のフック）**：実行直前に入力を調べられる拡張点。 並列セッションの命令と共有資源の競合を実行前に確かめます。

3. **TLS SNI（TLS接続時に示すサーバー名）**：クライアントがTLSの接続開始時に伝えるサーバー名。 実験ではHTTPSのドメイン判定に使います。

4. **OTLP（OpenTelemetry Protocol）**：観測データを送るためのプロトコル。 EKSからCloudWatchにカウンターを送る経路で使います。

5. **SigV4（AWS署名バージョン4）**：AWS APIリクエストを認証する署名方式。 GrafanaのデータソースからCloudWatchを呼ぶ際に使います。

6. **Set（集合）**：同じ値を一つとして扱うデータ構造。 kilnは階層と正規化テキストから作ったキーを照合します。
