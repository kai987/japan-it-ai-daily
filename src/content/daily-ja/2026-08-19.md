### テーマ 1：AWS、Anthropic・OpenAIと連携し「AWS Continuum」をClaude Code / Codex / Kiroへ統合

**質問：**

> この仕組みを本番環境で安全に利用する場合、どのようなSecurity Controlが必要ですか。

**30秒回答：**

> Security検証をAI Coding Workflowへ組み込み、検出結果をAgentへFeedbackすることで継続的に修正できます。 ModelへのInstructionだけに依存せず、最小権限、Runtimeでの強制、監査ログ、必要に応じたHuman Approvalを組み合わせてDefense in Depthを設計します。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

### テーマ 2：Zed Agent Panel：OS SandboxでAgentを強制的に制限

**質問：**

> この仕組みを本番環境で安全に利用する場合、どのようなSecurity Controlが必要ですか。

**30秒回答：**

> Prompt上のInstructionではなく、RuntimeやOS SandboxでFile・Network Accessを強制的に制御することが重要です。 ModelへのInstructionだけに依存せず、最小権限、Runtimeでの強制、監査ログ、必要に応じたHuman Approvalを組み合わせてDefense in Depthを設計します。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

**3つのキーワード：** `最小権限` / `実行境界` / `監査ログ`

### テーマ 3：MCPは本当に常にDirect APIより優れているのか？

**質問：**

> このContext / Retrieval設計を本番で使う場合、何を評価しますか。

**30秒回答：**

> MCPは複数のAI AppやTeamでToolを再利用する場合に価値が高く、単純な構成ではDirect APIが適する場合もあります。 必要な情報だけを渡すScope設計とAccess Controlを分けて考え、検索漏れ、Context Cost、回答品質を実Workloadで評価します。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

**3つのキーワード：** `コンテキスト管理` / `検索精度` / `権限制御`

### テーマ 4：Wantedly：ObservabilityをInfraからLLMへ拡張

**質問：**

> AI Systemの運用状況をどのように観測し、改善につなげますか。

**30秒回答：**

> 生成AIもApplicationやRUMと同様に、利用状況を観測して継続改善することが重要です。 Request、Model、Token、Latency、Tool Call、User OutcomeをTraceできるようにし、Costと品質を同じDashboardで確認して継続改善につなげます。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

**3つのキーワード：** `可観測性` / `トレーシング` / `継続改善`

### テーマ 5：Google HEIR：AIが暗号化状態のデータを直接処理する

**質問：**

> Privacy-preserving AIを本番で利用する場合、どの点を評価しますか。

> FHEではデータを復号せずに計算できるため、Privacyが重要なAI処理への応用が期待されます。 暗号化によるData Protectionだけでなく、計算Cost、Latency、対応Operation、Key Managementを確認し、機密性と実用性能の両方を実Workloadで評価します。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

**3つのキーワード：** `データ保護` / `暗号化処理` / `性能評価`

4. **本番運用では、変更履歴、監査性、Rollback手段まで含めて設計する必要があります。**
