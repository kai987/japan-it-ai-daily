### ① Claude Code v2.1.257: Fable 5.1追加と権限すり抜け修正まとめ

**出典：Qiita**

**原文：** https://qiita.com/picnic/items/ba95f05d2b78799f238b

Claude Code v2.1.257はFable 5.1の追加と権限周辺の修正を含みます。プロジェクトとローカル設定のdefaultMode bypassPermissionsは無視され、既にautoに適用されていた扱いへ揃います。ユーザー・管理設定や起動オプションは別の設定源です。共有リポジトリの設定だけで承認省略を強制させない変更で、更新後の自動処理が停止する条件を点検する必要があります。

複合コマンド内のask漏れ、pluginの宣言パスのsymlink越境、BashのRead/Edit denyに対するリダイレクトや読み取りコマンド、shellの解釈差、末尾ドットのホスト、Remote Controlの拒否誤処理などを修正しています。[公式履歴](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)と照合しましたが、Qiitaのcriticalという一括表現を公式の脆弱性等級とは扱いません。実被害件数や全修正のCVSSは本文で確認できないためです。

autoのContainment Escapeは、環境が想定動作として認めないmetadata認証情報取得、通信制限回避、他tenant到達を自動承認しない規則です。作業範囲外の初回read確認とblockReadsOutsideWorkingDirectoriesも加わります。注意表示と完全blockを同一視しません。管理denyの再読込漏れや第三者providerへ余分なAuthorizationを送る問題も別に修正されます。

Fable 5.1は1M文脈、記事時点入力10/出力50ドル、cache read0.25ドル/Mtokenです。ただしgatewayのfable/bestは互換のためFable 5を維持し、明示選択が必要な条件があります。復帰、cache、hidden thinking時の接続維持、VS Codeのarchiveも変更対象です。これはreleaseの解説で、著者による全機能の再現試験ではありません。面接では実効設定、承認・拒否の両例、接続先へ送る認証を確認します。

**注目ポイント：★★★★★**

設定の保存場所と、実際に適用される権限を区別できます。

### ② VS Code上で開発のセカンドオピニオンを別のAIエージェントから得られる「Rubber Duck」機能が実験的実装

**出典：Publickey**

**原文：** https://www.publickey1.jp/blog/26/vs_codeairubber_duck.html

VS Code1.135のRubber Duckは、開発を進める主Agentとは別のモデルから意見を得る実験機能です。計画で入った誤りが実装とテストへ引き継がれる問題に対し、同じモデルの自己確認だけで終えないことを目指します。名称は、説明しながら自分の考えを整理するrubber duck debuggingに由来します。

四月にCopilot CLIへ入った試行がVS Codeへ広がり、Copilot Agent Hostのsessionで /rubber-duck を使います。すべてのチャットモードで同じ動作をする機能とは説明されていません。別モデルを使えば判断の偏りを変えられる可能性がありますが、誤りが統計的に独立する保証はありません。

記事は八月の1.132〜1.135の変更として、編集可能なMarkdown差分、統合browserへのコメント、ローカルHTML変更時の自動再読込も併記しています。これらを全て1.135で初登場した機能へまとめないようにします。

検出率、モデルの組合せ別精度、追加費用、待ち時間の実験は本文にありません。面接では早い計画段階で前提をもう一度問い、意見が違った箇所を仕様と実行結果へ戻して調べる判断を説明できます。意見が一致することも、多数決も、正しさの根拠そのものにはしません。

**注目ポイント：★★★★★**

別の意見を、仕様やテストで判断する流れへつなげます。

### ③ Amazon Bedrock で Claude Fable 5.1 が利用可能になったので Converse API から呼び出してみた

**出典：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/bedrock-claude-fable-5-1-converse/

著者は九月二日、us-east-1、AWS CLI2.36.36でFable5.1をConverseとInvokeModelから呼びました。前提はData Retention APIのaws_reviewです。モデルIDを渡さずaccount単位で切り替え、provider_data_shareから変更後を読み直しています。[AWS発表](https://aws.amazon.com/blogs/machine-learning/introducing-claude-fable-5-1-on-aws/)はCovered Modelとして最大三十日の保持とAmazon担当者のレビューを説明し、providerとの共有を要しない点を分けています。

Global推論profileで短い挨拶を送り、入力32、出力14、latencyMs2062を得ました。US Geoでも成功しています。In-RegionはモデルカードでN/Aなので、地域から呼ぶことと、その地域内だけで推論することは同じではありません。モデル自身の名乗りだけで実モデルを証明せず、要求のprofileを確認します。

鶏牛の頭三十・脚七十四という同一問題を、effort既定highとmaxで各一回比較しました。InvokeModelで出力382/956、thinking0/410、壁時計8,362/13,724msでした。maxはより深く考える設定ですが、一回ずつの結果から品質上昇率や一定の遅延倍率は出せません。contentの並びも変わるためtypeでtextを選びます。

cacheはsystem695tokenにcheckpointを付け、最初write695、約二秒後read695を観測しました。入力377tokenへ減らすと両回read0でwriteもありません。最小512、最大四checkpoint、TTL五分/一時間というモデル条件と一致する例です。面接では利用条件、応答構造、cache計上を分け、モデル変更の設定と実測を説明できます。

**注目ポイント：★★★★★**

保持設定、effort、cacheの実測を別々に確認できます。

### ④ AIエージェントがRedshiftを操作してDWH構築や集計分析など可能に、Amazon RedshiftがAgent Toolkit for AWSと統合

**出典：Publickey**

**原文：** https://www.publickey1.jp/blog/26/airedshiftdwhamazon_redshiftagent_toolkit_for_aws.html

RedshiftとAgent Toolkit for AWSの統合は、自然言語の依頼からDWH作成、集計、運用へつなぐため、Redshift固有の知識とAPI操作手段を用意する更新です。skillが判断材料を渡し、MCP serverがAWS APIへ接続します。両者は役割が違います。

Redshift skillsにはPostgreSQLと異なるSQL、ProvisionedとServerless、運用上の注意、guardrail、API参照が含まれます。既存のSQL知識だけでRedshiftを操作すると、方言や構成差を取り違えるためです。skillが説明する注意点は、IAMやデータベースの実際の許可を自動で変更するものとは限りません。

[AWSの発表](https://aws.amazon.com/jp/about-aws/whats-new/2026/08/redshift-agenttoolkit-for-ai-assisted-datawarehouse-mgmt/)も、コーディングAgentとRedshiftをつなぐ統合として説明しています。本文に大規模データでの正答率、実行料金の削減、誤更新の検証はありません。APIが呼べることから任意のDWH設計が正しいとは言えません。

面接への応用では、まずschemaと対象データを読み、集計の粒度とSQLを確かめ、実行前に走査量や変更範囲を確認する流れが考えられます。これらは記事の機能を使う際の設計判断です。自然言語から操作までの接続と、業務として合格する結果の評価を分けます。

**注目ポイント：★★★★★**

skillの知識と、MCPの実行手段を分けて説明できます。

### ⑤ AAIF、MCPのガバナンスとA2Aの現状、AIエージェントにオープン標準が必要な理由を説明 ——9月10・11日に「AGNTCon + MCPCon Japan 2026」を渋谷で開催

**出典：gihyo.jp**

**原文：** https://gihyo.jp/article/2026/09/aaif-mcp-a2a-briefing

gihyoは八月25日のAAIF説明会を取材しています。推論、計画、行動、観察を繰り返すAgentは、長時間の作業や委譲を通じて外部へ影響します。その基盤に、実装できる公開protocol、個別の参加許可に依存しない拡張、中立的governanceが必要だという説明です。

MCPの技術判断はprojectのmaintainer側で行い、AAIF boardは予算、投資、新projectなどを担当します。boardがMCP仕様へ投票するわけではありません。MCPとA2Aはproject、横断的なidentityや信頼性、商取引などの議論はworking groupで、組織上の役割も異なります。

A2Aは異なるAgentが能力を知り、通信と仕事の委譲を行うprotocolで、商取引専用ではありません。三月公開の1.0、150以上の組織、Growth段階というのは発表時点の説明です。x402はHTTP上の決済を扱い、別Foundationなので目的も運営も同じではありません。

SDK月間約五億download、server二万二千以上、約250会員、価格九割減とtoken五十倍は発表資料の値で、独立利用者数や個社の費用倍率ではありません。日本企業の現場データを生かすには、標準と自社形式・権限・業務規則の間を埋める投資が必要だと述べています。九月10〜11日の会議は予定として案内され、開催済み実績にはしません。面接ではMCP、A2A、決済と組織統治を分けて説明できます。

**注目ポイント：★★★★★**

protocolの役割と、仕様を決める主体を切り分けます。

### 話題1：Claude Code / Security

**質問：**

> 権限の仕様が変わる更新を、どう確認しますか。

**30秒回答：**

> 設定の場所と、許可・拒否の動作を比べます。Claude Codeでは、プロジェクトのbypassPermissionsが無視され、複合コマンド内のask漏れも修正されました。ただし管理設定や起動時の指定は別です。自動処理が確認待ちになる箇所を調べ、必要な操作だけを通す設定にします。単純なコマンドだけでなく、リダイレクトや設定の再読み込み後も拒否が効くか確かめます。

**関連Project（学習用）：** 設定源別に有効権限を整理する。

**キーワード：** `defaultMode` / `bypassPermissions` / `permissions.ask` / `設定源`

### 話題2：AI Coding / Evaluation

**質問：**

> 別のAIモデルにレビューさせれば、品質は保証できますか。

**30秒回答：**

> 見方を増やす助けになりますが、保証にはしません。VS CodeのRubber Duckは、Copilot Agent Hostから別モデルへ意見を求める実験機能です。計画の段階で前提を問い直せば、後の手戻りを減らせる可能性があります。ただし二つの意見が一致しても正しいとは限りません。指摘を仕様とテストで確かめ、追加の確認にかかる時間も含めて使い方を決めます。

**関連Project（学習用）：** 別モデルの指摘をテスト条件へ変える。

**キーワード：** `Rubber Duck` / `Copilot Agent Host` / `計画` / `セカンドオピニオン`

### 話題3：AWS / LLM / Compliance

**質問：**

> 新しいモデルでキャッシュが効くか、どう確かめますか。

**30秒回答：**

> 同じ入力を送り、書き込みと読み取りのtokenを見ます。Fable 5.1ではsystemの695tokenが初回に書き込まれ、次の要求で読み取られました。377tokenへ減らすと命中せず、最小512という条件も確認しています。ただし一組の測定で全業務の削減率は出せません。実際の入力で再利用率と期限切れを調べ、保持や費用の条件も確認します。

**関連Project（学習用）：** cache write/readを二条件で比べる。

**キーワード：** `cache checkpoint` / `695` / `512` / `cacheReadInputTokens`

### 話題4：AWS / Agent Skills / MCP

**質問：**

> データウェアハウスをAIに操作させるとき、スキルは何を担いますか。

**30秒回答：**

> 製品の知識と注意点を伝えます。RedshiftのスキルにはPostgreSQLとのSQLの違いや、ProvisionedとServerlessの説明があり、実際のAPI呼び出しはMCP側が担います。ただしスキルを読めば権限や集計が正しくなるわけではありません。対象の表と集計の粒度を確認し、実行前にSQLと変更範囲を見ます。結果は既知の集計と比べます。

**関連Project（学習用）：** 集計SQLの粒度を説明する。

**キーワード：** `Redshift skills` / `PostgreSQL` / `MCP` / `集計の粒度`

### 話題5：MCP / A2A / Governance

**質問：**

> MCPとA2Aを、どのように使い分けて考えますか。

**30秒回答：**

> ツール接続と、エージェントへの委譲を分けます。MCPは外部ツールやデータの利用、A2Aは相手の能力を知り、別のエージェントへ仕事を渡すための仕組みです。A2Aは商取引専用ではなく、決済のx402とも別です。ただし標準を採用しても、自社の権限やデータ形式は残ります。委譲する範囲と完了条件を決め、失敗時の責任も確認します。

**関連Project（学習用）：** protocol別の責任を図にする。

**キーワード：** `MCP` / `A2A` / `x402` / `完了条件`

## C-3. JLPT文法

### 1. ～にとどまらず
**Level：N1｜意味：** ある範囲だけでなく、さらに広い範囲にも及ぶこと。  
**形：** `名詞 + にとどまらず / 動詞辞書形 + にとどまらず`  
**使い方：** 前の範囲から後ろへ話題を広げます。  
**例：** `MCPの価値はTool接続にとどまらず、IdentityやGovernanceの共通化にも広がっています。`  
**補足：** 前の範囲から後ろへ話題を広げます。

### 2. ～を余儀なくされる
**Level：N1｜意味：** 外部の事情で、望まない行動や変更をせざるを得なくなる。  
**形：** `名詞 + を余儀なくされる`  
**使い方：** 名詞につなげる硬い表現です。資源不足で切り替えが必要になる状況などを述べます。  
**例：** `Project設定のbypassPermissionsに依存していたTeamは、設定方法の変更を余儀なくされます。`  
**補足：** 名詞につなげる硬い表現です。資源不足で切り替えが必要になる状況などを述べます。

### 3. ～に至るまで
**Level：N1｜意味：** 範囲が最後の細かな対象まで広がることを強調する。  
**形：** `名詞 + に至るまで`  
**使い方：** 「～から～に至るまで」の形で、接続から監視までの広い責任を示せます。  
**例：** `AI AgentはWeb検索からCode実行、送金に至るまで現実の操作を行う可能性があります。`  
**補足：** 「～から～に至るまで」の形で、接続から監視までの広い責任を示せます。

### 4. ～たうえで
**Level：N2｜意味：** 前のことを済ませ、それを前提として次の行動をすること。  
**形：** `動詞た形 + 上で / 名詞 + の上で`  
**使い方：** 単なる順序だけでなく、必要な準備・確認の意味を含みます。  
**例：** `実装計画を立てたうえで、別ModelにSecond Opinionを依頼します。`  
**補足：** 単なる順序だけでなく、必要な準備・確認の意味を含みます。

### 5. ～にあたって
**Level：N2｜意味：** あることを始める際に、必要な準備や条件を述べる。  
**形：** `名詞 + にあたって / 動詞辞書形 + にあたって`  
**使い方：** 利用にあたって保持条件と組織の方針を確認します。  
**例：** `Fable 5.1を利用するにあたって、AccountのData Retention設定を確認します。`  
**補足：** 利用にあたって保持条件と組織の方針を確認します。

### 6. ～に伴って
**Level：N2｜意味：** ある変化と一緒に別の変化が起こる。  
**形：** `名詞 + に伴って / 動詞辞書形 + のに伴って`  
**使い方：** AI利用の拡大と管理上の課題の関係を説明します。  
**例：** `AI Agentの利用拡大に伴って、IdentityとAuditの重要性も高まります。`  
**補足：** AI利用の拡大と管理上の課題の関係を説明します。

### 7. ～一方で
**Level：N2｜意味：** 同じ事柄の、対照的な二つの側面を述べること。  
**形：** `普通形 + 一方で / 名詞・な形容詞 + である + 一方で`  
**使い方：** 前後は逆の評価や異なる側面でもつなげられます。  
**例：** `Modelの単価が下がる一方で、Agentの利用量はかえって増える可能性があります。`  
**補足：** 前後は逆の評価や異なる側面でもつなげられます。
