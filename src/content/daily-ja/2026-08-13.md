# A. 詳細版

## 1. 今日読むべき5本

### ① Claude Team / ChatGPT Business / Gemini Enterpriseを企業統制の観点で比較

**出典:** DevelopersIO
**原文 URL:** https://dev.classmethod.jp/articles/summer-project-2026-ai-plans-admin-governance-comparison/

この記事はClaude Team、ChatGPT Business、Gemini Enterprise Standardを実際に契約し、組織向けAIの統制を管理画面から比較しています。個人利用と違い、組織では機能の解放範囲、外部SaaSへの接続・操作、入力データの扱い、エージェントの処理制限を確認する必要があります。Claude Teamは全ユーザー・セッションに適用する「組織の指示」を設定でき、ChatGPT BusinessとGemini Enterprise Standardは通常チャットへの共通指示という点では異なる設計でした。

外部接続では、Claudeのコネクタ、ChatGPTのアプリ、Geminiのデータストアを管理でき、サービスによっては操作単位で常時許可・実行時確認・ブロックを選べます。コーディングエージェントでは、Claude Teamがコマンド、パス、MCPサーバー、Hooks、Sandboxなどを管理者設定で細かく制御できる一方、ChatGPT Businessは機能・接続先中心、Gemini Enterprise StandardはAntigravityの環境・外部アクセス・ログ中心という違いが整理されています。

**注目ポイント:** 製品の優劣を一律に決めるのではなく、組織が「何を許可し、何を防ぐか」を先に定義してから選ぶことが重要です。

### ② NVIDIA NeMo Switchyard：Taskに応じてLLMを動的Routing

**出典:** DevelopersIO
**原文 URL:** https://dev.classmethod.jp/articles/nvidia-nemo-switchyard-v020-rust-first-touch/

NeMo Switchyard v0.2.0は、ルーティングエンジンをPythonからRustへ書き直し、standaloneの`switchyard-server`として提供します。OpenAI Chat Completions、Responses、Anthropic Messagesの3形式を受け付け、設定は`llm_clients`、`targets`、`routes`の3層です。`cargo install switchyard-server`で導入でき、記事の実測ではDockerイメージのビルドが84秒、イメージサイズが187MBでした。

LLM classifierのcapabilityモードは、weakモデルがタスクを完遂できる確率`p_solve`を推定し、`base_threshold`と`threshold_step`でstrongまたはweakへ振り分けます。記事のワークロードでは`base_threshold = 0.75`が適し、`recent_turn_window = 4`により判定レイテンシの中央値が17.5秒から3.1秒になりました。別のescalationモードはweakから開始し、詰みの証拠が2回連続した場合にstrongへ固定しますが、対話時のストリーミングを失う制約があります。

**注目ポイント:** ルーティングの価値は難問を必ず見抜くことより、定型作業を高価なモデルへ一律に送らないことにあります。閾値は実トラフィックで再較正し、tier分布をログで観測します。

### ③ Claude Code Self-hosted Environment：EC2をAgent実行環境にする

**出典:** DevelopersIO
**原文 URL:** https://dev.classmethod.jp/articles/claude-code-self-hosted-runner/

Claude Code v2.1.224で、Claude Code on the Webのセッション実行環境としてセルフホスト環境が利用可能になりました。2026年8月12日時点ではTeamとEnterprise向けのパブリックベータです。通常はAnthropic管理インフラで実行されるセッションを自社ネットワーク内へ移すことで、内部サービス、データベース、レジストリへ接続し、コンパイラや社内CLIをランナーイメージに事前導入できます。

構成は、組織設定で作るEnvironment、共有クレデンシャルであるEnvironment secret、自社ホスト上の常駐Runner、開発者が開始するSessionから成ります。EC2例ではprivate subnet、NAT Gateway、Ubuntu 24.04、m8i-flex.large、インバウンドなし、HTTPS中心のアウトバウンド、SSM接続を使いました。一方、リポジトリや成果物は自社に留まっても、プロンプト・レスポンス・ツール結果は推論のためAnthropicへ送られ、トランスクリプトもAnthropic側に保存されます。

**注目ポイント:** セルフホストが移すのはセッションの実行部分であり、キュー、オーケストレーション、UIというコントロールプレーンではありません。ネットワーク設計だけでなく、ランナーイメージ・運用・秘密情報の管理費用も評価します。

### ④ Nemotron 3.5 Lightning：常駐Agent向けオープンモデル

**出典:** ITmedia AI＋
**原文 URL:** https://www.itmedia.co.jp/aiplus/article/2608/12/2000000503/

NVIDIAは2026年8月11日（現地時間）、30BパラメータのオープンモデルNemotron 3.5 Lightningを公開しました。OpenClawやHermes Agentのような常時稼働型エージェント向けに設計され、入力に応じて処理役の一部だけを動かすMoEアーキテクチャを採用しています。推論時のアクティブパラメータは3Bです。

小型モデルの出力を大型モデルで検証する推測的デコーディングと、重みを低ビット化する量子化によって高速生成を狙います。Artificial Analysis Intelligence Indexは24ポイントで、約4倍のパラメータ数を持つgpt-oss-120bと同等と評価され、前世代から9ポイント改善しました。出力速度は毎秒約670トークンで、重みだけでなく学習データとレシピもOpenMDW-1.1ライセンスでHugging Faceなどから提供されます。

**注目ポイント:** 総パラメータ数だけでなく、推論時のアクティブ量、生成速度、ライセンス、常駐エージェントの運用コストを併せて見る必要があります。

### ⑤ Grok Bot：Agentが実際の業務アプリを操作

**出典:** ITmedia AI＋
**原文 URL:** https://www.itmedia.co.jp/aiplus/article/2608/12/2000000505/

米SpaceXAIは8月11日（現地時間）、AIエージェントGrok Botの早期ベータ版を公開しました。Botはクラウド上のコンピュータからGmailやCRMへサインインし、人間と同じ画面操作で仕事を完了します。承認が必要な場面だけユーザーに確認を求め、SuperGrok Heavy、Cursor Ultra、Cursor Teams Premiumの契約者向けに、macOS、Windows、iOS、Linux（Debian／Ubuntu、x64の.deb）をサポートします。Androidは非対応です。

APIやMCPが整備されていないツールにも画面操作で対応し、ユーザーの作業を見せると手順をルーティンとして保存します。数回のタスクから語り口や例外パターンを覚え、放置スレッドの追跡や引き継ぎの催促も行うとされています。複数Botを並行稼働させ、受信箱、経費、採用、バグ修正などの担当Botを「チーフ・オブ・スタッフ」役が束ねる構成も紹介されています。

**注目ポイント:** 画面操作の汎用性が高いほど、ログイン情報、承認境界、誤操作時の停止条件、Bot間の受け渡しを厳格に設計する必要があります。

## 2. カテゴリ別サマリー

### AI / Agent

Grok Botは業務アプリを画面操作し、Nemotron 3.5 Lightningは常時稼働エージェント向けの実行モデルを目指します。Switchyardはタスクごとにモデルを選び、Claude Codeはツール実行を伴う開発エージェントとして自社環境にも配置できます。共通するのは、単一モデルの性能だけでなく、実行権限・コスト・監査を含むシステム設計が必要だという点です。

### Frontend / Web

今回の5本には、FrontendフレームワークやWeb UI実装そのものを主題にした記事はありません。ただしGrok Botの画面操作は、API連携がないWeb業務アプリを扱うComputer-using Agentの実例として、UIを自動化の接点にする方向を示しています。

### Cloud / Backend

Claude CodeのSelf-hosted Runtimeは、EC2をprivate subnetに置き、NAT Gateway経由のアウトバウンド通信でセッションを実行する構成です。NeMo SwitchyardはRustサーバーをDockerで動かし、複数のLLMクライアントとターゲットをルートとして束ねます。どちらも、実行環境と外部推論サービスの境界を明示するBackend設計が中心です。

### 日本企業 Tech Blog / enterprise engineering signals

DevelopersIOの3本は、AIサービスの管理画面、ルーターの実測、EC2上のセルフホスト構成を実際に試した記録です。特に企業導入では、ベンチマークだけでなく、ログ、ネットワーク、権限、運用コストを自社ワークロードで測る姿勢が重要なシグナルになっています。

## 3. 面接で使えるポイント

### 1. AIサービスの企業導入

**質問:** 企業向けAIサービスを選ぶとき、モデル性能以外に何を比較しますか。
**回答（約30秒）:** まず許可する機能と防ぎたい操作を定義し、SSOやユーザー管理、外部サービスの接続・書き込み権限、監査ログ、データの保存先を比較します。コーディングエージェントならコマンドやファイル、MCPの制御も確認します。製品を一律に評価せず、組織のリスクと既存環境に合うかで段階的に選びます。
**関連プロジェクト:** Claude Team / ChatGPT Business / Gemini Enterpriseの統制比較
**キーワード:** AI Governance、Least Privilege、Audit Log

### 2. LLMルーティング

**質問:** なぜ一番高性能なLLMをすべてのタスクに使わないのですか。
**回答（約30秒）:** エージェントはファイル閲覧や定型修正など多数の呼び出しを行うため、すべてを高価なモデルへ送るとコストが増えます。タスクの完遂確率を見積もってweakとstrongを切り替え、失敗の兆候が出たら昇格させます。ただし閾値はモデルと実トラフィックに依存するので、ログを見ながら再較正します。
**関連プロジェクト:** NVIDIA NeMo Switchyard v0.2.0
**キーワード:** Model Routing、p_solve、Escalation

### 3. セルフホスト実行環境

**質問:** Claude Codeのセッションをセルフホストする利点と注意点は何ですか。
**回答（約30秒）:** 自社ネットワーク内で実行できるため、内部サービスや社内CLIを使い、チェックアウトや成果物を自社インフラに留められます。一方で、推論に必要な会話内容はAnthropicへ送られ、ランナーの構築、更新、ネットワーク管理も自社負担です。データ境界と運用費を分けて評価します。
**関連プロジェクト:** EC2上のClaude Code Self-hosted Runner
**キーワード:** Self-hosted Runtime、Outbound HTTPS、Data Boundary

### 4. 常駐エージェント向けモデル

**質問:** Nemotron 3.5 Lightningの設計上の特徴を説明してください。
**回答（約30秒）:** 30BのMoEモデルですが、推論時に動くアクティブパラメータは3Bです。推測的デコーディングと量子化で速度とコストを抑え、OpenClawやHermes Agentのような常時稼働エージェントを想定しています。モデルサイズだけでなく、アクティブ量、出力速度、ライセンスを評価します。
**関連プロジェクト:** Local LLMを使う常駐Agent基盤
**キーワード:** MoE、量子化、OpenMDW-1.1

### 5. Computer-using Agentの導入

**質問:** 画面操作型エージェントを業務に導入する際のリスクは何ですか。
**回答（約30秒）:** APIがないアプリも扱える反面、ログイン情報を使った誤操作や意図しない書き込みが起こり得ます。まず読み取り中心の小さな業務で試し、承認が必要な操作を明確にします。操作ログ、停止条件、権限分離、人間への引き継ぎを用意してから範囲を広げます。
**関連プロジェクト:** Grok BotによるCRM更新・経費処理の検証
**キーワード:** Computer-using Agent、Approval、Permission Management

## 4. 今日の技術テーマ

### 「モデル」ではなく実行システム全体を設計する

今日の中心テーマは、LLMを単体のチャット機能としてではなく、ルーター、ランタイム、ツール、監査、承認を含む実行システムとして設計することです。Switchyardはタスクごとにモデルを選び、Nemotronは常駐処理のコストを抑え、Claude Codeのセルフホストは実行場所を選び、Grok Botは画面操作を実行します。

**メリット:** タスクに合うモデルを選べるためコストを抑えやすく、社内ネットワークや既存アプリを活用できます。権限とログを設計すれば、利便性と監査可能性も両立できます。
**制約・リスク:** ルーティング判定の誤り、モデル更新による分布変化、画面操作の誤入力、会話データの外部送信が起こり得ます。セルフホストではインフラ運用も増えます。
**日本企業で導入する際の注意点:** まずデータ分類と許可操作を定義し、最小権限・Sandbox・承認フロー・Audit Logを組み合わせます。実トラフィックの品質と費用を測り、低リスクの部署や読み取り業務から段階的に導入します。

## 5. 面接復習カード

### Q1. Model Routingの閾値はどう決めますか？

**回答ポイント:** モデルの組み合わせと実際のタスク分布でp_solveを測り、品質・コスト・レイテンシを比較して決める。固定の既定値を盲目的に使わず、モデル更新後も再較正する。

### Q2. セルフホストしても、すべてのデータが社内に留まりますか？

**回答ポイント:** いいえ。チェックアウト、成果物、シークレット、変更ファイルは自社側に置けるが、プロンプト、レスポンス、ツール結果は推論のためAnthropicへ送られ、トランスクリプトはAnthropic側に保存される。

### Q3. エージェントに最小権限を適用する理由は何ですか？

**回答ポイント:** ファイル、コマンド、外部サービスへのアクセスを必要な範囲に限定し、誤操作や情報漏えいの影響を小さくするため。高リスク操作には事前禁止または人間の承認を置く。

| 制御する | せいぎょする・動詞・サ変 | N2 | 動作や範囲を目的に合わせて管理する。 | Accessを制御する／権限で制御する／Runtimeで制御する | 外部接続やコマンドをポリシーで管理する。 | 外部Serviceへの接続をRuntime Policyで制御します。 |
| 導入する | どうにゅうする・動詞・サ変 | N2 | 新しい仕組みを運用に取り入れる。 | AIを導入する／段階的に導入する／組織へ導入する | 小さな範囲からエージェントを使う。 | Computer-using Agentは小さな範囲から段階的に導入します。 |
| 判断する | はんだんする・動詞・サ変 | N2 | 情報を比較して決める。 | 難易度を判断する／Riskを判断する／判断基準を設ける | Routerがモデルを選ぶ。 | RouterがTaskの難易度を判断し、利用するModelを選びます。 |
| 想定する | そうていする・動詞・サ変 | N1 | 起こり得る状況を前もって考える。 | 本番利用を想定する／障害を想定する／最悪Caseを想定する | 本番の境界や障害を設計に含める。 | 本番利用を想定してNetworkと権限の境界を設計します。 |
| 伴う | ともなう・動詞・五段 | N1 | ある事柄と同時に別の事柄が起こる。 | Riskを伴う／変更に伴う／導入に伴って | 自動化の拡大とリスクを対比する。 | 自動化の範囲拡大には新しいSecurity Riskが伴います。 |
| 委ねる | ゆだねる・動詞・一段 | N1 | 判断や仕事を他者に任せきる。 | 判断を委ねる／運用を委ねる／すべてを委ねる | 高リスク判断をLLMだけに任せない。 | 高Riskな判断をすべてLLMに委ねるべきではありません。 |
| 損なう | そこなう・動詞・五段 | N1 | 価値や状態を悪くする。 | 安全性を損なう／信頼性を損なう／品質を損なう | 過度な自動化の危険を述べる。 | 過度な自動化がSystemの安全性を損なう可能性があります。 |
| 切り替える | きりかえる・動詞・一段 | N2 | 状況に応じて別のものへ変える。 | Modelを切り替える／経路を切り替える／環境を切り替える | Riskに応じてモデルを変える。 | TaskのRiskに応じて利用するModelを切り替えます。 |
| 妥当 | だとう・な形容詞 | N1 | 条件や目的に照らして適切なこと。 | 妥当な判断／妥当な設定／妥当性を評価する | 本番用の権限設定を評価する。 | この権限設定が本番用途として妥当か確認します。 |
| 厳格 | げんかく・な形容詞 | N1 | 規則や条件を緩めず適用するさま。 | 厳格な権限管理／厳格なPolicy／厳格に制御する | 外部操作エージェントの制限に使う。 | 外部操作が可能なAgentには厳格な権限管理が必要です。 |
| 段階的 | だんかいてき・な形容詞 | N2 | 段階を踏んで少しずつ進めるさま。 | 段階的な導入／段階的に拡大する／段階的なRollout | 検証後に利用範囲を広げる。 | Agentの利用範囲を段階的に拡大します。 |
| あらかじめ | あらかじめ・副詞 | N1 | その時になる前に、前もって。 | あらかじめ決める／あらかじめ制限する／あらかじめ想定する | 高リスク操作を実行前に禁止する。 | 高Riskな操作はあらかじめPolicyで禁止します。 |
| 原則として | げんそくとして・副詞的表現 | N1 | 基本となるルールに従えば。 | 原則として禁止する／原則として許可しない／原則として分離する | 本番リソースへの直接アクセスを認めない。 | Production Resourceへの直接Accessは原則として許可しません。 |
| 一律に | いちりつに・副詞 | N1 | すべてを同じように扱って。 | 一律に禁止する／一律に適用する／一律に判断しない | 全タスクを高性能モデルへ送らない。 | すべてのTaskを一律に高性能Modelへ送る必要はありません。 |
| 一方で | いっぽうで・接続表現 | N2 | 異なる二つの側面を対比する表現。 | 便利な一方で／柔軟な一方で／一方でRiskもある | 自動化の利点とリスクを並べる。 | Computer-using Agentは便利な一方で、権限管理が複雑になります。 |

## C-2. IT/AI専門用語

| Term | 日本語 | 意味・記事文脈 |
|---|---|---|
| Permission Management | 権限管理（けんげんかんり） | 利用者やエージェントの操作・アクセス範囲を管理する仕組み。 |
| Audit Log | 監査ログ | 誰がいつ何を実行したかを後から確認する記録。 |
| Model Routing | モデルルーティング | タスクに応じて呼び出すLLMを選び分ける仕組み。 |
| Sandbox | サンドボックス | 影響範囲を隔離してコードやコマンドを実行する環境。 |
| Least Privilege | 最小権限（さいしょうけんげん） | 作業に必要な最小限の権限だけを与える原則。 |
| Computer-using Agent | コンピュータ操作エージェント | 画面を見てクリックや入力を行い、アプリを操作するエージェント。 |
| Self-hosted Runtime | セルフホスト実行環境 | 自社管理のネットワークやホスト上で処理を実行する環境。 |
| Policy Enforcement | ポリシー強制 | 組織ルールをシステムとして利用者へ適用すること。 |

## C-3. JLPT文法

| 文法 | レベル | 意味 | 構造 | 用法 | 例文 |
|---|---|---|---|---|---|
| ～にとどまらず | N1 | ある範囲を越えて、それだけでなく。 | 名詞 / 普通形 + にとどまらず | 対象が広いことを改まって示す。 | AI GovernanceはModel選定にとどまらず、ToolやNetworkの権限管理まで含みます。 |
| ～かねない | N1 | 悪い結果が起こる可能性がある。 | 動詞ます形去ます + かねない | 好ましくない可能性への注意を述べる。 | Agentに過剰な権限を与えると、重大な情報漏えいを招きかねません。 |
| ～なくしては | N1 | それがなければ成り立たない。 | 名詞 + なくしては | 必須条件を強調する。 | 監査と権限制御なくしては、企業でのAgent運用は難しいです。 |
| ～に応じて | N2 | 状況や程度に合わせて。 | 名詞 + に応じて | 条件に合わせて対応を変える。 | TaskのRiskに応じて利用可能なToolを変更します。 |
| ～一方で | N2 | 一つの面とは別の面では。 | 普通形 + 一方で | 利点と欠点などを対比する。 | 自動化は生産性を高める一方で、誤操作のRiskも増やします。 |
| ～に基づいて | N2 | 根拠や基準にして。 | 名詞 + に基づいて | ポリシーやデータを根拠にする。 | 組織Policyに基づいてAgentのAccess範囲を制御します。 |
| ～にかかわらず | N2 | 条件に関係なく。 | 名詞 + にかかわらず | 共通して守るルールを示す。 | 利用するModelにかかわらず、機密情報の送信Policyを守る必要があります。 |

## C-4. 今日の必修

**必修語彙:** 制御する、想定する、委ねる、損なう、妥当、厳格、あらかじめ、原則として、一律に、一方で

**必修文法:** ～にとどまらず、～かねない、～なくしては、～に応じて、～一方で
