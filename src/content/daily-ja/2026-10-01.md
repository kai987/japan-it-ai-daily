### 1. GuardDuty AI Protectionは日本語のプロンプトインジェクションを本当に防げるのか？

**原文：** https://dev.classmethod.jp/articles/guardduty-ai-protection-bedrock-guardrails-tier-verification/

**公開時刻：** 2026-09-30 17:39:17 JST

GuardDuty AI Protectionの紹介と、Bedrock Guardrailsへの依存を確かめた実機検証です。モデルを呼ぶ認証情報の悪用、異常なトークン消費、プロンプトインジェクションなどが背景にあります。注目するのはPromptInjection.Directです。このFindingでは、内容の判定をGuardrailsが行い、GuardDutyがその結果を記録します。異常呼び出しのAnomalousModelInvocationやコスト収奪のCostHarvestingと、同じ判定方式だと考えないことが出発点です。

環境は東京リージョンのEC2からSSMで接続し、AWS CLIでConverse APIを呼ぶ構成です。スクリプトはAPACのClaude 3.5 Sonnetモデル、GuardrailのDRAFT版、traceを指定し、Prompt AttacksをHighに設定しています。Classicで試したのは正常な日本語質問、英語・日本語のDAN、英語・日本語のBase64入力です。英語DANは遮断されましたが、日本語DANとBase64の2件はNo actionでした。日本語DANではモデルが拒否しても、Guardrailの介入とは区別しています。

次にCross-Region inferenceを有効化してStandardへ切り替え、先ほど通った3件を再実行すると、すべてguardrail_intervened／Guardrail blockedになりました。遮断イベントとGuardDutyのFindingも示されています。ただし、正常質問と英語DANは2回目の実行を省略しています。比較表だけを見て5件の完全な再測定と説明するのは不正確です。入力言語と符号化を変えた結果が、前段の設定に左右されたことが今回の確認範囲です。

採用条件には処理先も入ります。Standardはリージョンをまたぐ処理が前提で、APACでは日本国外へルーティングされる可能性があります。国内限定の要件なら、この構成をそのまま使えるとは限りません。ClassicにWord Filtersを追加する案は記事の提案で、その案の効果は再測定されていません。また、少数の攻撃例での成功は、未知の変種への耐性や誤検知率、業務での速度を保証しません。

面接では、防御した層と記録した層を分ける説明ができます。本稿の設計上の整理は、設定版・入力言語・符号化・応答を一緒に残し、検知範囲とデータ所在を照らし合わせることです。原文の実測と運用への提案を分ければ、機能名だけで安全だと断言せず、調べる場所を具体的に示せます。

**読む価値：** 防御と記録の役割、モデル自身の拒否との違い、処理先の条件を一つの検証例で説明できます。

### 2. Claude Code と Miro を繋いで Web アプリの全画面を自動キャプチャして画面遷移図を作ってみた

**原文：** https://dev.classmethod.jp/articles/shoma-connect-claude-code-and-miro-to-auto-capture-all-web-app-screens-and-create-screen-transition-diagram/

**公開時刻：** 2026-09-30 23:59:10 JST

ReactとDjangoで作ったアプリを、Claude Code・Playwright・Miroで棚卸しした開発事例です。ローカルで起動済みのReact／TypeScript／antdとDjango REST Frameworkが前提です。報告された成果は54画面のキャプチャと68本の動線です。手作業なら半日から1日という記述は見積もりで、比較実験による短縮率ではありません。

画面の洗い出しではApp.tsxのRouteだけでなく、メニューのonClickと各ページのnavigate()も読みます。25本のルートには、location.stateで選択中のプロジェクトを受け取る画面があり、直リンクでは開けませんでした。メニューからモーダルを開く操作や、5つのタブごとに異なる画面状態もあります。さらに、入口となる操作がない画面を2つ発見しています。ルートを列挙しただけでは画面を網羅したことにならず、直リンク・クリック操作・モーダルを分けて扱っています。

Playwrightでログインして各状態を撮影した後、画像と説明とコネクタをMiroへ置きます。REST APIでは対象チームにアプリをインストールし、boards:readとboards:writeを付けて認可します。別チームのボードへのアクセスは403になるため、権限の名前だけでなく認可先を確かめる必要があります。1時間の期限設定にも注意し、この記事ではコピーしたトークンを会話へ貼らず環境変数から渡しています。

配置方法はRESTスクリプトを選びました。座標を計算して繰り返し実行できるのが利点です。記事で比較したMCPの逐次画像作成では1枚につき2回、54枚では100回を超える呼び出しになります。MCPは既存ボードの手直しに向くという整理ですが、canvas_create_from_svgの一括作成は未検証です。この比較をMCP全体の性能評価へ広げることはできません。

面接で使える知識は、ルートと画面状態と到達経路を切り離して確認することです。画面が生成できたかを見るだけでなく、権限別の状態や描画待ちの条件も一覧にすると、撮影の抜けを調べやすくなります。これは本稿の運用提案です。原文は全権限・全業務状態のカバレッジを測っておらず、54枚の完成を完全な検証と同一視しません。

**読む価値：** React固有の状態と到達性を説明し、生成物の検証と認可先の確認へつなげられます。

### 3. [小ネタ] 日本語版Windows EC2のユーザーデータに日本語コメントを書いたら、スクリプトが1行も実行されなかった

**原文：** https://dev.classmethod.jp/articles/202609-windows-userdata-japanese-comment-parse-error/

**公開時刻：** 2026-09-30 14:44:31 JST

日本語コメントを変えたらEC2の初期設定が1行も走らなくなった、という障害調査です。対象はWindows Server 2025日本語版、EC2Launch v2.5.2、Windows PowerShell 5.1.26100、システムロケールCP932です。CloudFormationのUserDataをLFで渡していました。Start-Transcriptの出力も作られないため、スクリプトの中だけを見ていると原因の見当がつきません。

EC2Launchのagent.logから、生成されたUserScript.ps1とerr.tmpのパスをたどると、対応するtryがないというParserErrorが見つかりました。構文解析で失敗したため、実行の直前に置いたログ処理すら動いていません。postReadyUserDataの段階完了表示と、初期設定が正しく実行されたことは別です。

生成ファイルはBOMなしUTF-8ですが、Windows PowerShell 5.1はシステムのANSIコードページとして読みます。この環境ではCP932でした。原文のバイト列では、コメント末尾「る」の8Bと次のLF、0x0Aが組になり、改行が消えます。その結果try {がコメントに巻き込まれ、9行のスクリプトが8行として読まれました。行末のバイト次第で挙動が変わるため、日本語コメントなら必ず同じ位置で壊れるという意味ではありません。

対策はASCIIだけのコメント、CRLF、powershellタグ直後のBOM、ASCII罫線の挿入です。CRLFなら実行行は残りますが、コメントの文字化けは残り得ます。BOMは目に見えず、罫線も削除すると再発します。作者自身も罫線を消して再び失敗しました。持続的な対策としては、手元のエディタ設定だけでなく、起動エージェントが書いたファイルの目印と改行を確かめる必要があります。

補足の[Microsoft公式仕様](https://learn.microsoft.com/ja-jp/powershell/module/microsoft.powershell.core/about/about_character_encoding?view=powershell-5.1)でも、BOMがないWindows PowerShellのスクリプトはANSIとして解釈されると確認できます。PowerShell 6以降の既定とは分けて考えます。今回の環境をすべてのWindowsへ一般化せず、外部エラーファイル、読み取り側のコードページ、実バイトの順に調べる知識として使えます。本稿がEC2を再起動して独立再現した結果ではありません。

**読む価値：** 実行前の構文解析と実行中の失敗を区別し、文字コードと行末のバイトから原因を説明できます。

### 4. LayerXのFDEインターンに参加した話

**原文：** https://tech.layerx.co.jp/entry/2026/09/30/200852

**公開時刻：** 2026-09-30 20:08:52 JST

LayerXのFDEインターンによる技術経験の報告です。活動期間は2026年5〜7月で、9月30日は記事の公開日です。授業の都合で顧客と直接やり取りできなかった筆者が、貸借対照表のOCR、Box連携、ワークフロー移行などを担当しました。新製品の発表や定量的な顧客効果の報告とは分けて読みます。

OCRでは小さい文字と「-」「▲」、透かし文字が重なる数値が問題でした。既存のAzure OpenAIによる処理に対し、pypdfによるテキスト抽出と、Azure AI Document IntelligenceのocrHighResolutionを検討しています。スキャンPDFが多いという入力条件から、直接抽出は見送りました。高解像度OCRは小さい文字と記号を改善した一方、透かしも認識し、数値に余計な文字が入る問題は残りました。

確認した出力では数値自体は残っていたため、後段でLLMが検査し、数値として成立しない部分を整形するノードを追加しました。今回扱った書類ではほとんど対応できたという定性的な結果です。件数や正解率、符号の保持率は示されていません。数字の欠落や取り違えがある場合にも文字を取り除くだけで直る、という証拠ではありません。入力の違いに応じて、後処理の前提を確かめる必要があります。

別の仕事では固定手順の旧版から、LLMが状況に応じて行動を選ぶ版へ移行し、既存のBoxツールで複数ファイルを動的に扱う仕組みを作りました。ただし、顧客への提案までは関わっていません。FDE自身の仕事を自動化する取り組みでは、作成したワークフローをエージェントが実行・検証・修正できるようツールを整えています。SlackログとGitHub Pull Requestを定期取得して検索可能にする仕組みも、前提や過去の経緯を探すための基盤です。

面接での説明は、ツールの比較より先に業務入力を確かめるところから始められます。スキャンかテキストか、数値が壊れているか文字だけが紛れたかで対策は変わります。本稿の提案は、原本の金額と符号を照合し、OCRと整形の誤りを別々に検査することです。原文にない正解率や顧客導入成果を補わず、成立した条件と未測定の範囲を残します。

**読む価値：** 入力形式と誤り方から選択を説明し、後処理の前提と未測定の効果を明示できます。

### 5. [アップデート] Cloud Run のカスタムURL機能が Preview になりました

**原文：** https://dev.classmethod.jp/articles/update-cloud-run-custom-url/

**公開時刻：** 2026-09-30 12:37:35 JST

Cloud RunのカスタムURLを作成し、アクセスと制約を試した記事です。Public Previewとして、サービスに選んだcloud.runのサブドメインを付けます。run.appの既定URL、自分のドメインを用意するカスタムドメインとは別の方式で、DNS設定や外部ロードバランサを用意せず共有できます。記事の見出しと本文では公開日の記述が一致しないため、本稿では確定できた9月30日の記事公開時刻とPreviewという状態を採用します。

新規サービスの作成画面と、既存サービスのネットワーキングからマッピングを追加し、複数のURLで同じサービスにアクセスできることを確認しています。CLIではgcloud beta run domain-mappings createを使います。サブドメインはGoogle Cloud全体で早い者勝ちで、6〜63文字などの命名制限があります。IAPを有効化したあとにカスタムURLでも制限が働いたことは、この設定例の確認結果です。

運用上の焦点は入口の独立性です。既定HTTPSエンドポイントを無効化しても、カスタムURLの設定は連動せず残ります。一時停止や直接変更もできません。別名へ変えるなら新しいURLを先に作ってから旧URLを消せますが、同じ名前を別サービスへ移すには削除と再作成が必要です。削除すると他の人がすぐ取得できるため、名前を保持した無停止切替が保証されるわけではありません。

内部、または内部とCloud Load Balancingにingressを限定したサービスでは利用できません。記事では内部へ変えるとNot Foundになりましたが、名前自体は残りました。サービス削除でもマッピングは自動解放されません。補足の[Google公式仕様](https://docs.cloud.google.com/run/docs/custom-urls?hl=ja)でも、この独立したライフサイクルと削除後の再取得リスクを確認しています。Previewの支援範囲やGoogleによる取り消し・再割り当ての可能性もあり、永続的なブランドドメインと同じ扱いにはできません。

面接では、入口が作りやすくても閉じ方は別に確認する、と説明できます。本稿の提案はサービスとすべての入口を一覧にし、既定URLとカスタムURLの両方で認証と撤去後の応答を確かめることです。原文はこの全体手順の測定や、移行時の可用率・応答時間を示していません。作成結果、仕様、運用への提案を分けて使います。

## C-2. IT/AI専門用語

1. **PromptInjection.Direct（直接プロンプトインジェクションのFinding）**：Guardrailsによる直接のプロンプト攻撃判定をGuardDutyが記録するFinding。 判定する役割と記録する役割を分けます。

2. **Cross-Region inference（リージョン間推論）**：処理がリージョンをまたいでルーティングされる仕組み。 Standardの処理先を、国内限定の要件と照合します。

3. **location.state（画面遷移で渡す状態）**：遷移時に次の画面へ渡す状態。 直リンクでは必要な選択状態がない画面がありました。

4. **Playwright（ブラウザ操作自動化）**：ブラウザを操作してクリックや撮影を自動化するツール。 今回の撮影は起動済みのローカルアプリで行っています。

5. **Miro REST API（MiroのHTTP操作API）**：スクリプトからボードの画像やテキスト、接続を作るAPI。 54枚を規則的に配置し、再実行できる形にしました。

6. **BOM（バイトオーダーマーク）**：ファイル先頭で文字コードなどを知らせるバイト列。 テンプレート全体でなく、書かれるスクリプトの先頭を確認します。

7. **CP932（日本語のコードページ）**：日本語Windowsで使う従来のコードページ。 UTF-8と区切り方が違うことが今回の原因です。

8. **ocrHighResolution（高解像度OCR機能）**：Azure AI Document Intelligenceの高解像度OCR機能。 小さい文字や符号を改善しても、透かしの混入が残りました。

9. **pypdf（PDF処理ライブラリ）**：PDFの既存テキストなどを読み取るライブラリ。 スキャン中心の入力では、テキスト抽出だけで対応できません。

10. **cloud.run（Cloud RunのカスタムURL用ドメイン）**：選んだ共有サブドメインをサービスへ対応付ける入口。 既定run.appの無効化とは独立しています。

## C-3. 新規文法

過去50期の四表現と93文法identityを照合しました。新規は原文にある名詞＋次第だの条件依存と、だけでの最小条件の2件です。後者はN3の実用例として選びました。既習文型は別の復習層で補い、例文を変えて新規件数を増やしません。

### 1. ～次第だ｜N2

- 意味：結果がある条件によって決まることを表します。
- 接続：名詞＋次第だ／次第で／次第なので
- 使い方：結果を左右する条件を示します。今回なら、改行が消えるかどうかを行末のバイトから説明します。
- 原文出現形：行末のバイト次第なので
- 原文根拠：[原因：どの行で起きるかは行末のバイト次第なので、コメントを書き換えると結果が変わります。](https://dev.classmethod.jp/articles/202609-windows-userdata-japanese-comment-parse-error/)
- 独自例文：改行が消えるかどうかは、行末のバイト次第です。
- 例文の意味：すべてのコメントで同じ結果になるのではなく、末尾の内容が影響します。
- 注意：動詞のます形＋次第の『すぐに』とは別の用法です。名詞につながり、依存する条件を表します。

### 2. ～だけで｜N3

- 意味：ある動作だけで結果につながることを表します。
- 接続：動詞辞書形＋だけで／名詞＋だけで
- 使い方：少ない操作で結果が変わることを説明します。機能を有効化した環境など、ほかの前提条件は消えません。
- 原文出現形：ClassicからStandardに切り替えるだけで
- 原文根拠：[まとめ：Content filters tierをClassicからStandardに切り替えるだけで、日本語DANとBase64の攻撃パターンをブロック。](https://dev.classmethod.jp/articles/guardduty-ai-protection-bedrock-guardrails-tier-verification/)
- 独自例文：設定を変えるだけで、今回の三つの入力は遮断されました。
- 例文の意味：その検証環境では、追加の実装をせずに結果が変わりました。
- 注意：N3の実用例として選んでいます。既習の『だけでなく』という追加とは働きが違います。すべての攻撃への保証にはしません。
