### 1. [アップデート] AWS AppConfig で AI のモデル設定とプロンプトを管理できるようになったので使ってみた

**原文：** https://dev.classmethod.jp/articles/aws-appconfig-native-ai-model-invocation-prompt-configurations/

**公開日時：** 2026-11-25 09:15:56 JST

モデルを切り替えるたびにアプリを配り直す運用を見直すため、著者はAppConfigの新しい構成プロファイルを試しました。AIプロンプト用の設定には本文をテキストとして保存できます。モデル呼び出し用の設定ではモデルID、温度やトップP、メッセージ、提供元ごとの追加項目をまとめます。

コンソールで設定を作り、プロンプトだけを第2版にして配信したところ、読み手を模したData APIの呼び出しで第2版を取得できました。二つの設定に別々の配信戦略を使えるため、適用した版をアプリの記録から確認できるようにしておくと、評価を進めやすくなります。

ただし、モデルを実際に呼び出すのは設定を受け取ったアプリです。記事では、仕様書で必須とされるモデル項目を省いても、登録した値がコンソールから読み出せました。その確認は保存段階に限られます。欠けた設定を配信した後の動作や推論結果は別の試験で調べます。

**読む価値：** プロンプトの変更を試す際に、配信と読み取りの間にどんな確認を置くべきかが分かります。

### 2. GA になった AWS CDK Blocks を試してみた

**原文：** https://dev.classmethod.jp/articles/aws-cdk-blocks-ga-hands-on/

**公開日時：** 2026-11-25 00:46:30 JST

CDK Blocksを使うと、開発用の実装とAWSで使う構成を同じBlockから選べます。この記事では、Node.js 22でキーと値を保存するKVStore、ジョブを送るAsyncJobを試しました。キーと値は手元ではファイルに、東京のAWS環境ではDynamoDBに保存されます。

手元では、すぐ終わるジョブ、二度失敗するジョブ、失敗し続けるジョブを順に投入しました。三回までという設定は最初の配信を含みます。前二つは処理を完了し、最後は三回で失敗と記録されDLQへ移ることをログで確認しました。生成したAWSテンプレートと本物のSQSでも最大受信回数三回が一致しました。

AWSのサンドボックスでは正常系のジョブやキーの読み書きが動きました。ただし、手元のキューとSQSのタイミングや故障対応が常に同じという測定ではありません。削除後にはスタック外のロググループが残りました。本番のプリセットは表とバケットの保持方針も異なります。

**読む価値：** ローカルで作業を素早く確認し、その後どの設定をクラウドで確かめるか具体化できます。

### 3. Ladybird の Alpha 版が出たので macOS で Chrome、Safari と比べてみた

**原文：** https://dev.classmethod.jp/articles/reona-ladybird-alpha-macos/

**公開日時：** 2026-11-24 23:59:02 JST

独自のブラウザエンジンを持つLadybirdの初期版を、著者がmacOSで試しました。Appleシリコン向けの版で、いくつかの日本語サイトを開いて表示を確認しています。動画はブラウザ操作の自動化で再生位置を取り、有画面の環境でも映像と音を確かめました。

三つのブラウザを同じ日に三回ずつSpeedometer 3.1にかけた結果、中央値はLadybirdが21.7、Safariが51.3、Chromeが60.6でした。Safariだけはウィンドウを出して測っています。合成スコアには、JavaScriptの実行に加えて画面の要素を更新する処理やレイアウトも含まれます。

試した範囲ではページの多くが表示できましたが、広告の文字が化ける例も出ています。ただし、この測定は限られた環境でのAlpha版の観察です。応答の速さの差を一つの処理へ帰属させたり、すべてのサイトでの利用を判断したりはできません。

**読む価値：** Web標準の試験数、応答のベンチマーク、実際の閲覧で得られる判断材料を分けて読めます。

### 4. MCPの記録ツールを追記だけで作ると、訂正のたびに重複が残る。AIは「消せない」と正直に言うが、集計は間違える

**原文：** https://zenn.dev/kentaro_tak/articles/mcp-logger-append-only-corrections

**公開日時：** 2026-11-24 23:04:27 JST

日々の記録を残すMCPツールに、後から間違いを直す役割を持たせる実験です。著者はSQLiteの小さな保存先を用意し、追記のみ、追記と行IDによる削除、日付と種類による置き換えを比べました。三つのモデルと三つの方式の組を各三回試しています。

訂正を依頼した後、結果を返答で判断せず、正しい内容の行が一つだけ残ったかを数えています。削除と置き換えを許した二方式はどちらも九回中九回成功しました。追記のみでは九回とも集計が一日多くなり、新しい会話でメモを読んで正答した八回でも集計値は変わりませんでした。

ただし、置き換えは訂正する対象が日付と種類の組で一意に決まる場合の案です。一日に何件も登録する記録では、項目のIDなど別の識別方法が必要になります。実験では対象を一種類に限定しており、複数の利用者が同時に訂正する動作は測っていません。

**読む価値：** AIの返答だけで記録の修正を確かめる危うさが、行の状態と集計を比べることで分かります。

### 5. ECR/S3からのimage pullの仕組みを深掘りする

**原文：** https://qiita.com/har1101/items/a6e5f0d2039bd0932511?utm_campaign=popular_items&utm_medium=feed&utm_source=popular_items

**公開日時：** 2026-11-25 00:28:45 JST

プライベートサブネットのECSタスクがイメージを取得できず、著者はタイムアウトの行き先を調べました。ECRのAPI用とレジストリ用のインターフェースエンドポイントは用意されていました。レジストリからマニフェストを受け取った後、実際のレイヤーは署名付きURLでS3から取る仕組みです。

表示された宛先は、AWSの公開一覧にある東京のS3アドレスの範囲でした。S3のゲートウェイエンドポイントを使う経路はルートテーブルで決まり、タスクの送信ルールにもサービスのプレフィックスを許可する必要があります。ECRには別に、インターフェースの名前解決と受信条件があります。

ただし、記事が示したのは通信の失敗箇所を絞った根拠です。設定変更後の取得時間やタスク開始の実測は載っていません。運用時はタイムアウトの行から経路をたどり、修正後の起動を同じイメージとサブネットで確かめます。

**読む価値：** ECRへ名前解決できるかの確認から一歩進めて、レイヤーが届くまでの経路を考えられます。

**関連プロジェクト例：** 集計ジョブの小さな試作で、再配信の履歴とサンドボックスの削除後に残るものを確認する。

### 1. 寄付（きふ）｜N3

- 品詞：名詞・サ変他動詞
- 意味：団体や事業を助けるために、お金や品物を提供することです。
- 連語：寄付を募る / 寄付を受け付ける / 団体に寄付する
- 記事文脈：独自ブラウザの運営を支える資金の種類として出てきます。
- 例文：開発を続けられるよう、利用者から寄付を募っています。
- 例文の意味：開発の費用をまかなうため、使っている人にお金を出してもらうよう呼びかけています。
- ニュアンス：「寄贈」は本など具体的な物品を贈る場面にもよく使われます。「寄付」は金銭による支援にも自然です。

### 2. 化ける（ばける）｜N1

- 品詞：一段自動詞
- 意味：別の姿や形になることです。文字の話では、意図と異なる文字に見えることを指します。
- 連語：文字が化ける / 記号が別の文字に化ける / 思わぬ形に化ける
- 記事文脈：ウェブページの文字が想定どおりに表示されない問題に使っています。
- 例文：古いファイルを別の文字コードで開くと、一部の記号が化けます。
- 例文の意味：古いファイルの読み方を変えると、元と違う記号が見えることがあります。
- ニュアンス：「変わる」は変化一般に使えます。「化ける」は姿が大きく変わったり、予期しない見え方になったりする場面に合います。

### 3. 引く（ひく）｜N5/N4

- 品詞：五段他動詞
- 意味：この用法では、辞書や参照先を使って必要な項目の情報を求めることです。
- 連語：辞書を引く / 索引を引く / DNSを引く
- 記事文脈：サービスの名前をDNSで問い合わせ、対応するIPアドレスを得る場面です。
- 例文：接続を調べるため、まずその名前を社内のDNSで引きました。
- 例文の意味：どこに接続する名前か調べるため、社内のDNSへ問い合わせました。
- ニュアンス：「引っ張る」は物を手前へ動かす語です。「辞書を引く」のような参照の用法にはそのまま置き換えられません。

## C-2. IT/AI専門用語

1. **AppConfig Data API（配信済み設定の取得API）**：アプリが環境へ配信された設定を取得します。 記事ではプロンプトの第2版を読めることを確認しました。
