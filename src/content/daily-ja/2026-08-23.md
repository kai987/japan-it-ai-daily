### ① 「AI-DLC の紹介」というタイトルでゆるWeb勉強会@札幌で登壇しました #ゆるWeb札幌

**出典：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/yuruweb-31-iwasa/

DevelopersIOの登壇報告は、8月22日の札幌の勉強会で紹介した **AI-DLC** を、開発の考え方と `awslabs/aidlc-workflows v2` という実装に分けて説明します。AIが計画を作り、人が承認して進める枠組みです。著者は会場で答え切れなかった質問を、発表後にソースと文書で調べ直しています。導入効果を測定した企業事例ではありません。

v1にもフェーズとステージはあり、v2で初めて追加されたわけではありません。記事の比較では、3フェーズからInitializationとIdeationを含む5フェーズ、十数ステージから33ステージ、単一エージェントから14体の分担へ変わります。進行判断もLLM依存から、決定論的なTypeScriptエンジンによる状態遷移へ移ります。機械的に確認できる範囲と、人が承認する判断を整理し直す変更です。

学びは **`team.md` と `project.md`** に有効なルールとして残り、履歴はaudit shardや各ステージのmemory.mdへ分けます。cidマーカーで重複を避け、`org.md` と矛盾する学びを除く仕組みはあります。ただし著者が確認した範囲では、ファイルサイズの上限や自動整理は見つかっていません。次回に全量を読む構成なので、長期運用では人による整理が必要になり得ます。

人が書きたい部分については、compose/recomposeでステージをSKIPする、承認時にRejectして書き直す方法が考えられますが、ファイル単位のAI・人の担当指定は確認されていません。仕様も `requirements.md`、`components.md`、`contract-summary.md`、`stories.md` などへ分かれます。`OUTCOMES.md` は完了時の引き継ぎ資料で、統合仕様書を自動生成する機能ではありません。

面接では、多数のエージェントを置くこと自体より、責務、進行条件、承認対象、知識の寿命を説明できます。14体なら品質が上がるという部分は著者の期待であり、比較試験による保証ではありません。

**注目ポイント：★★★★★**

状態遷移の制御と、蓄積するルールの保守を具体的に説明できます。

### ② Claude Code v2.1.238～2.1.239：Reliability / Security / Hidden Billing

**出典：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/20260822-cc-updates-v2-1-239/

Claude Code **v2.1.238～v2.1.239** のまとめは、98件の変更を修正59、改善20、新機能8、セキュリティ8、性能2、破壊的変更1として整理します。中心はRemote Control、セッション間メッセージング、フルスクリーン操作、プラグイン配布です。数は著者による更新内容の分類で、98件の実験を独立に再現したという意味ではありません。

**Remote Control** は一時的なHTTP403を最大3分許容し、継続拒否では拒否元を示すようになります。瞬断時の認証更新、遠隔のモデル選択やStopが端末へ届かない問題、メッセージの消失、クラッシュ後の再利用、タイトル同期の暴走も修正対象です。長いSessionStart/Setupフックの間もkeepaliveを送る変更があり、単に通信を再試行するだけでなく操作状態を双方で一致させる改善です。

著者はMacの `/remote-control` からQRコードでiPhoneへ接続し、送った指示が端末へ反映される流れを確認しています。ただしローカルプロセスは動き続ける必要があり、端末を閉じればオフラインです。記事時点では対象プラン、claude.aiへの通常ログイン、直接接続、組織設定などの条件があり、APIキーやBedrock経由と同一の利用条件ではありません。スマートフォンから見えることをクラウドへ実行場所が移ったことと混同しません。

Bedrockでは、プロキシがContent-Typeを削除するとストリーミングが非ストリーミングで再実行され、課金対象呼び出しが増える問題を修正しています。SSO起動時の事前確認もHTTPS_PROXYを尊重します。セッション間通信では受信拒否やキュー超過による破棄を送信者へ知らせ、無言の消失を減らします。長時間のメモリ増加、WebFetchの期限切れページ保持、異なるパスの継続先混同、Linuxのworktree設定参照も修正対象です。

**`keybindingFlavor: readline`** はCtrl+Wを空白までの削除へ変え、次版で単語移動・削除にも広がります。既定のclassicは維持されます。一方、フルスクリーンのCtrl+L/Cmd+K二度押しによる会話消去は削除され、消去には `/clear` が必要です。マスク入力の貼り戻し・履歴保存や、フォーカスを戻すクリックが承認へ化ける問題も修正されています。

**`headersHelper`** は短命トークン等のヘッダーを作り、カタログと同一オリジンのアーカイブ取得に使えます。インストール・更新時に内容を表示して実行を確認し、プロジェクト由来の設定には信頼確認と資格情報の継承制限があります。費用見積もりのUS-only推論1.1倍反映、支出上限時の即時失敗、goalのチェック間隔調整なども、記事では運用条件に関わる改善として扱います。

**注目ポイント：★★★★★**

遠隔操作の表示、実行プロセス、課金につながる再送を切り分けられます。

### ③ NeMo Switchyard Prefill Router

**出典：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/dgx-spark-switchyard-prefill-router-vs-judge/

**NeMo Switchyardのprefill router** は、judgeに判定文を書かせる代わりに、凍結したLLMが依頼文を読む際のhidden statesから候補モデルの正解確率を予測する方式です。層・poolingを選び、標準化と **PCA、小さなMLP** へ通します。生成型judgeは根拠付きJSONを出せますが生成時間と形式崩れがあり、予測型は文章生成を省く一方、根拠や会話の途中経過を同じようには扱いません。

学習ラベルが人の好みなのか実測正誤なのかで、予測する意味も変わります。prefill方式は候補ごとの正誤を学び、特徴を出すencoderと対象モデルを分けられるため、対象が閉じたモデルでも構成できます。論文の11モデル評価では最良単体とoracleの差を45.6%回収し、費用74.3%削減と報告されていますが、分布外では精度が11.43ポイント低下します。これは論文条件の結果で、著者のローカル実験の値ではありません。

著者の学習はDeepSeek V4 Flash-0731の実測正誤を持つLiveCodeBench167問と、既存judgeから蒸留した合成1,608問です。評価を未学習237件、weakが二回失敗しstrongが通る14問、日常の単発47問へ分けます。合成ホールドアウト210件には学習側に同じ生成バッチの類似問題があるため、全体AUCだけでは難しさを学んだと断定しません。実測ラベルの27問や見極め14問を別に見ます。

Qwen3.6-35Bの構成はAUC0.938、生成judgeは0.903。237件を2,000回再標本化した差の95%区間は0.002～0.070で、他encoderの差はゼロをまたぎました。14問のstrong振り分けはjudge5/14に対しprefill10～12/14です。一方、単発47問は31～38問で、常にstrongとする31/47の基準から大きく離れません。順位を付ける力があっても確率が0.4～0.6へ縮み、0.80のしきい値で過度にstrongを選ぶ較正の問題が残ります。合成だけで学ぶとコード課題を一律に難しいとする傾向もあり、実測ラベルの役割が重要です。

v0.2.0にprefillの正式route typeはまだありません。PR97、140、174/185/186を経て、当時の **PR506** は特定コミット `8a9d3509` の特徴抽出との一致だけを契約し、PCA、MLP、checkpoint読み込み、ルーティングは未実装です。著者は互換HTTP応答を返すshimをjudgeの位置へつなぎ、`threshold_step = 0` で試しています。本番設定には入れていません。

87判定の試験ではjudge82/87に対しshim38/87。冒頭依頼が同じ40件では、会話途中の結果を読むjudgeが40/40、依頼文だけを読むprefillが0/40でした。p50約0.9～1.0秒と1.93秒の比較も、62GBのBF16/HF eagerと21GBのNVFP4/vLLMという条件差があります。高速化の値だけで置換を決められません。

DGX Sparkの128GB共有メモリでは、QwenのHF読み込みがGPU・ホスト側確保の合計で失敗し、21.8GBのNVFP4/vLLM経路へ変更しています。この経路は層添字と量子化が違い、PR506とテンソル一致ではありません。別の基準抽出ではparity testとcheckpoint再読込が通りましたが、将来の形式互換は次の実装次第です。面接では実測ラベル、分布を分けた固定評価、encoderの配置を先に用意し、会話途中の判断は別方式に残す設計を説明できます。

**注目ポイント：★★★★★**

AUC、確率の較正、会話情報、実装の提供段階を分けて評価できます。

### ④ GPT-5.6 Sol API値下げとUsage Governance

**出典：ITmedia AI＋**

**原文：** https://www.itmedia.co.jp/aiplus/article/2608/23/2000000700/

ITmediaは8月23日、**GPT-5.6 Sol** のAPI料金が8月21日に値下げされたと報じました。標準処理の100万トークン当たり入力は5ドルから4ドル、出力は30ドルから20ドルで、20%と約33%の引き下げです。公式changelogでもこの価格と、少なくとも11月21日までのプロモーションであることを確認できます。恒久料金や、その翌日からの価格は確定していません。

記事の短いコンテキスト条件は入力272,000トークン以下です。キャッシュ済み入力0.40ドル、キャッシュ書き込み5ドルも別項目で、閾値を超える長い入力ではリクエスト全体の入力が2倍、出力が1.5倍となり、8ドルと30ドルになります。Batch/Flexは短い標準条件の半額、Fastは2倍として紹介されています。同じ「一回」でも入力長、出力長、キャッシュ、処理区分で額が変わります。

ChatGPT WorkとCodexの対象クレジット消費量も順次下がりますが、ChatGPT Pro、Plus、Businessに含まれる利用量の変更とは分けられています。TerraとLunaは今回の対象外です。APIキー別のUsage/Costs表示とAPI、組織・プロジェクトの支出制御も紹介されますが、単価低下だけで各社の月額が一定割合減るとは言えません。

面接では、期間付きの単価表を処理区分ごとに記録し、実際の入力・出力・キャッシュ利用量へ適用する見積もりを説明できます。これは価格発表であって、モデルの回答品質が変化したことを示すベンチマークではありません。

補足確認：[OpenAI API changelog](https://developers.openai.com/api/docs/changelog) の8月21日項目。ここでは記事当時の条件を扱い、将来の料金を保証しません。

**注目ポイント：★★★★★**

単価、入力長、処理区分、期限を分けた見積もりを説明できます。

### ⑤ Bedrock × VLM外観検査：Strong Model + Cheap Model + REVIEW

**出典：DevelopersIO**

**原文：** https://dev.classmethod.jp/articles/bedrock-vlm-visual-inspection-generated-prompt/

Bedrockの外観検査記事は、欠陥の専門分類名より見た目を表す語が検出に効いた経験から、**検査仕様そのものをVLMに生成させる**構成を試します。Claude Opus 5が正常・異常サンプルから欠陥説明、正常特徴、inspection_prompt、output_schemaを作り、画像ごとの検査はNova 2 LiteまたはClaude Haiku 4.5へ任せます。仕様の生成は対象ごとに一度、検査は毎画像という費用の違いを利用します。

位置はbboxの数値座標ではなく、画像へ焼き込んだ **3×3または4×4のセル名** で返します。OK/REVIEW/NGの三値と三回多数決を使い、過半数がなければ目視へ回します。グリッド文字が傷を隠さない大きさも必要です。Python/Pillowのローカル経路と、Canvasで加工してLambdaからConverse APIを呼ぶWeb経路があり、後者はLambdaへPillowを載せません。

東京区で検査は `jp.` の推論プロファイルを使いますが、仕様生成のOpus 5は当時 `global.` です。国内ルーティングが必要なら利用可能な別モデルを検討する必要があります。NEU-DETは元200×200を600×600へ拡大し、正常例は欠陥のない領域の切り出しで、本物の同製品正常品とは異なります。別の錆写真への適用でも一セルのずれが残り、同じ製品・撮影条件のサンプルが必要という制約があります。

**Converse APIのcontent順序** の比較では、一枚の縦傷画像、4×4、Nova 2 Lite、temperature=0で各八回試し、画像前に対象を示す短文がない場合0/8、ある場合8/8でした。順序が効く理由は著者の解釈で、全画像に対する保証ではありません。欠陥の参照画像を同時に渡す別比較では、参照にしかない欠陥を検査画像へ混同しました。参照なしで入力が4,023から2,122トークンへ減り、その例では誤検出も減りました。

グリッド比較は欠陥四枚・正常二枚、三回多数決、Nova 2 Liteです。最初の仕様一本では4×4で見逃しゼロでしたが、仕様を三本ずつ作ると平均recallは3×3が45%、4×4が71%、4×4内でも44～100%へ変動しました。分割数と生成された文面が同時に変わるため、最初の結果をグリッドだけの効果にできません。仕様を作った後、正解付き画像で評価して選ぶ工程が必要です。

モデル比較ではNovaが低コントラスト欠陥を見逃し、Haikuが一部をREVIEWへ回しました。処理は一枚あたりNova1.1～1.5秒、Haiku3.4～4.9秒で、三回分のトークンはそれぞれ約4,500/400、6,100/1,000です。Novaの当時の単価と一ドル150円で0.34～0.54円、仕様生成は47～111秒でした。確認できなかったHaiku/Opusの地域単価は推定で埋めていません。

評価中のJSONパース失敗はゼロでしたが、それを検出漏れゼロと混同しません。新しい一部Claudeではtemperature指定がエラーになり、Fableは当該アカウントの保持設定で使えませんでした。用途は一次スクリーニングや抜き取りで、高速な全数ライン検査の代替を実証したものではありません。面接ではモデルだけでなく仕様生成、入力構造、サンプルと人への差し戻しを評価単位にできます。

**注目ポイント：★★★★★**

プロンプト生成のばらつきと検査精度を、分離した評価工程で扱えます。

### 話題4：AI Cost / Governance

**質問：**

## C-3. JLPT文法

### 1. ～にとどまらず
**Level：N1｜意味：** ある範囲だけでなく、さらに広い範囲にも及ぶこと。  
**形：** `名詞 / 普通形 + にとどまらず`  
**使い方：** 前の範囲から後ろへ話題を広げます。  
**例：** `Workflow設計では正常系にとどまらず、失敗時のRetryやFallbackも定義します。`  
**補足：** 前の範囲から後ろへ話題を広げます。

### 2. ～かねない
**Level：N1｜意味：** 望ましくない事態が起こる可能性があること。  
**形：** `動詞ます形から「ます」を取る + かねない`  
**使い方：** 動詞のます形から「ます」を除いて付けます。通常は悪い結果に使います。  
**例：** `Criticalな処理を完全にAgent任せにすると、予期しないStateへ進みかねません。`  
**補足：** 動詞のます形から「ます」を除いて付けます。通常は悪い結果に使います。

### 3. ～なくしては
**Level：N1｜意味：** ある条件がなければ、後のことは実現しない。  
**形：** `名詞 + なくしては`  
**使い方：** 検証や権限確認を、必要な前提として強調する表現です。  
**例：** `明確なState定義なくしては、Workflowの再現性を高められません。`  
**補足：** 検証や権限確認を、必要な前提として強調する表現です。

### 4. ～に応じて
**Level：N2｜意味：** 条件や変化に合わせて、対応を変えること。  
**形：** `名詞 + に応じて`  
**使い方：** 名詞に接続し、条件と対応の関係を示します。  
**例：** `Taskの難易度に応じてModelを切り替えます。`  
**補足：** 名詞に接続し、条件と対応の関係を示します。

### 5. ～た上で
**Level：N2｜意味：** 先の行為を済ませ、それを前提として次を行う。  
**形：** `動詞た形 + 上で`  
**使い方：** 検証してから利用するという手順を述べます。  
**例：** `VLMの結果を確認した上で、人間が最終判断します。`  
**補足：** 検証してから利用するという手順を述べます。

### 6. ～一方で
**Level：N2｜意味：** 同じ事柄の、対照的な二つの側面を述べること。  
**形：** `普通形 + 一方で`  
**使い方：** 前後は逆の評価や異なる側面でもつなげられます。  
**例：** `State Machineは再現性が高い一方で、自由度が下がることがあります。`  
**補足：** 前後は逆の評価や異なる側面でもつなげられます。

### 7. ～にかかわらず
**Level：N2｜意味：** ある条件が違っても、同じことが成り立つこと。  
**形：** `名詞 + にかかわらず`  
**使い方：** 後ろには条件に左右されない行動や規則を置きます。  
**例：** `利用するModelにかかわらず、実行履歴を必ず保存します。`  
**補足：** 後ろには条件に左右されない行動や規則を置きます。
