## 3. 面接で使えるポイント

### テーマ 1：GitHub Copilot Cloud Agent × Microsoft Teams

**質問：**

> AIを組織全体へ導入するとき、個人利用と何が違いますか。

**30秒回答：**

> Team向けCoding Agentでも、Repository PermissionとPull Request Reviewを維持することが重要です。 個人の便利さだけでなく、共通Policy、Permission、Audit、Education、Usage Measurementを整え、最終的には業務KPIで効果を確認する必要があります。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

**3つのキーワード：** `ガバナンス` / `利用状況` / `業務成果`

### テーマ 2：Liquid AI DSpark：Speculative Decoding

**質問：**

> 複数Modelや推論方式を使い分ける場合、どのように判断しますか。

**30秒回答：**

> Speculative DecodingではDraft Modelが候補Tokenを生成し、Target Modelがまとめて検証することでLatencyを改善できます。 Benchmarkだけで決めず、Task Quality、Latency、Cost、Failure Rateを同じ評価セットで比較し、必要なら弱いModelから強いModelへ段階的に切り替えます。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

**3つのキーワード：** `モデル選択` / `レイテンシ` / `コスト最適化`

### テーマ 3：AWS DevOps Agent × GitHub MCP：障害調査後はIssue作成だけを許可

**質問：**

> このContext / Retrieval設計を本番で使う場合、何を評価しますか。

**30秒回答：**

> AIOpsでは調査とIssue作成だけをAgentへ任せ、Code変更やProduction反映を人間に残す責任分界が有効です。 必要な情報だけを渡すScope設計とAccess Controlを分けて考え、検索漏れ、Context Cost、回答品質を実Workloadで評価します。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

**3つのキーワード：** `コンテキスト管理` / `検索精度` / `権限制御`

### テーマ 4：Claude Code Supervisor：SessionとCLI Processを分離

**質問：**

> Agent Runtimeを本番運用するとき、どのような要件を管理しますか。

**30秒回答：**

> Long-running AgentではSession Managementが必要で、Git worktreeは競合回避には有効ですが完全なSecurity Sandboxではありません。 Modelとは別に、Session、Tool、Credential、Network、Workspace、TTL、Cost、RecoveryをRuntimeの責務として管理し、実行範囲を明確にします。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。

**3つのキーワード：** `実行基盤` / `セッション管理` / `サンドボックス`

### テーマ 5：建設業界でAI活用が深化：ボトルネックは人材・Expert・ROIへ

> AI Systemの運用状況をどのように観測し、改善につなげますか。

> AI導入が進むと、課題はTool選定から人材育成、専門家支援、ROIの定量評価へ移ります。 Request、Model、Token、Latency、Tool Call、User OutcomeをTraceできるようにし、Costと品質を同じDashboardで確認して継続改善につなげます。 そのため、PoCだけで判断せず、実際のWorkloadで段階的に検証しながら導入することが重要だと考えています。
